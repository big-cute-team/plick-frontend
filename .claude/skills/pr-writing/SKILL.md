# PR 본문 쓰기

리뷰어는 이 PR을 처음 본다. 무엇을 왜 고쳤는지, 믿어도 되는지를 본문만 읽고 판단할 수 있어야 한다.
문체는 `doc-style` 스킬을 따른다. 볼드와 em dash를 쓰지 않고 필수만 남긴다.

## 틀

절 제목과 순서를 그대로 쓴다. 임의로 절을 늘리거나 이름을 바꾸지 않는다.

```markdown
### 1. 구현 사항

### 2. 문제 상황

### 3. 해결 방법

### 4. 검증

### 5. TODO
```

빈 절은 지우지 말고 한 줄로 채운다. "없음"이나 "이번 PR에서 새로 만난 문제는 없다"처럼 쓴다.
절이 비어 있는 것 자체가 정보다. 검증 절만은 비울 수 없다.

## 절별로 무엇을 담나

1. 구현 사항. 이 PR이 무엇을 하는지 한두 문단이나 불릿으로. 티켓 키와 붙인 엔드포인트, 건드린 화면과
   패키지를 여기서 밝힌다. 리뷰어가 diff를 열기 전에 읽을 지도다.

2. 문제 상황. 왜 이 작업이 필요했는지, 작업 중 무엇에 막혔는지. 기존 코드의 결함, 계약과 화면의 어긋남,
   목데이터가 만들던 구멍처럼 사실을 쓴다. 없으면 없다고 쓴다.

3. 해결 방법. 2에서 쓴 문제를 어떻게 풀었는지. 판단이 갈렸던 자리는 왜 그쪽을 골랐는지 한 줄 덧붙인다.
   승격 같은 이동은 표가 읽기 쉽다. 버린 대안까지 늘어놓지는 않는다.

4. 검증. 무엇을 실제로 돌렸는지 사실만 쓴다. 통과한 명령(build, check-types, lint, format:check),
   브라우저로 밟은 경로와 결과, 회귀로 확인한 다른 화면. 못 밟은 분기는 못 밟았다고 쓰고 이유를 붙인다.
   ⚠️ 돌리지 않은 걸 돌렸다고 쓰지 않는다. 이 절이 리뷰어가 유일하게 검증할 수 없는 부분이다.

5. TODO. 이 PR에서 일부러 남긴 것과 후속 티켓 몫. 계약 공백, 아직 목인 화면, 나중에 승격할 조각처럼
   다음 사람이 이어받을 실마리를 쓴다. ADR의 "남은 것"과 겹쳐도 된다.

## 제목과 나머지

제목은 커밋 메시지 첫 줄과 같게 쓴다. `feat(web): KAN-322 기사 세부 API 이식` 형태다. 티켓이 있으면
Jira 키를 넣고 없으면 뺀다.

base는 `develop`이다. `gh pr create --base develop`.

본문 맨 밑에 그 세션 ADR을 링크한다. 상세한 회고는 ADR이 맡고 PR 본문은 판단과 검증만 담는다.

🚫 병합은 하지 않는다. PR 생성과 CI 확인까지가 클로드 몫이고 `gh pr merge`는 금지다.

## 예시

```markdown
### 1. 구현 사항

모바일에서 검증된 `GET /api/v1/articles/{articleId}`를 데스크톱 웹 기사 세부에 이식한다 (KAN-322).
상세 계약 타입과 fetcher, 배지 줄 컴포넌트를 공용 패키지로 승격했다.

### 2. 문제 상황

목록은 KAN-321에서 실계약으로 넘어갔는데 상세만 목 배열에 남아 있었다. 목록에서 기사를 누르면 실제
id(`8032`)로 이동하는데 목엔 `h1` 같은 문자열 id밖에 없어 전부 404로 떨어졌다.

사이드바의 관련 기사와 실시간 인기, 본문 밑 추천 기사, 댓글은 대응 BE 엔드포인트가 없다.

### 3. 해결 방법

`getArticle`을 서버 컴포넌트에서 await 한다. 단발 읽기라 TanStack Query를 쓰지 않는다.

| 조각            | 이동                                        |
| --------------- | ------------------------------------------- |
| `ArticleDetail` | mobile `_types` → `@plick/domain/types`     |
| `getArticle`    | mobile `_services` → `@plick/core/articles` |

계약 공백은 목으로 채우지 않고 준비 중 문구와 빈 상태로 뒀다. 모바일 KAN-283과 같은 원칙이다.

### 4. 검증

- web·mobile 빌드, check-types, lint, format:check 통과
- dev(:3000) + 로컬 BE: 실기사 렌더, 404·400 → not-found, 330px 오버플로 없음, 콘솔 에러 없음
- 회귀: 모바일 기사 세부·릴스 크레스트, 웹 릴스 팀 칩 정상
- 로그인 상태의 `likedByMe`는 BE가 Noop이라 항상 false여서 눈으로 못 밟았다

### 5. TODO

- 관련·인기·추천 API가 생기면 준비 중 문구를 목록으로 되살린다
- 댓글 목록은 댓글 읽기 API 이식 티켓 몫이다
- 웹 홈 핫이슈가 아직 목이다. `articles/hot` 이식 때 `HotArticle`이 따라 올라간다

[ADR 0054](docs/adr/0054-web-article-detail-api.md)
```
