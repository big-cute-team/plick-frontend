# 문서 문체

읽는 사람은 나와 팀원이다. 지침 문서는 짧을수록 읽히고, 강조가 없을수록 진짜 중요한 게 보인다.

## 적용 범위

적용한다: CLAUDE.md, `.claude/` 아래 커맨드와 스킬과 서브에이전트 정의, README, PR 본문, 코드 주석.

PR 본문은 이 문체에 더해 `pr-writing` 스킬의 5절 틀을 쓴다. 여기는 어떻게 쓰나, 거기는 무엇을 담나다.

적용하지 않는다: `docs/` 아래 전부. ADR과 핸드오프는 성격이 정반대다. 거기는 시행착오를 다 적고
초보자가 읽어도 완전히 이해되게 자세히 쓴다. 규칙은 CLAUDE.md `작업 기록` 절에 있다.

인용도 예외다. 외부 문서나 에러 메시지를 그대로 옮길 때는 원문을 건드리지 않는다.

## 하지 않는 것

볼드 강조를 쓰지 않는다. 문장마다 굵은 글씨가 박히면 아무것도 강조되지 않는다. 중요한 내용은 강조가 아니라
순서로 드러낸다. 먼저 쓰면 중요한 것이다.

em dash(—)를 쓰지 않는다. 문장을 끊거나 부연을 붙일 자리에는 하이픈(-)을 쓴다. AI가 쓴 글의 가장 흔한 흔적이다.

곁가지를 쓰지 않는다. 몇 번 삽질했는지, 어떤 대안을 검토했다가 버렸는지는 결론에 영향을 주지 않으면 뺀다.
같은 말을 다른 표현으로 반복하지 않는다. (`docs/`는 반대다. 거기는 삽질도 다 적는다.)

과장 형용사를 쓰지 않는다. 강력한, 매끄러운, 견고한, seamless, robust 같은 말은 정보가 없다.
"결론적으로", "~할 수 있습니다" 같은 상투구도 마찬가지다.

소제목을 문단마다 달지 않는다. 세 문단짜리 내용에 소제목 세 개가 붙으면 목차가 본문보다 길어진다.

## 하는 것

담백한 `~했다`체로 쓴다. 막힌 데는 막혔다고 쓴다.

한 문장에 한 가지만 담는다. 조건이 여럿이면 문장을 나눈다.

표와 불릿은 항목이 실제로 병렬일 때만 쓴다. 흐름이 있는 내용은 문단으로 쓴다.

전문용어는 처음 나올 때 한 줄로 푼다.

경고 표시(⚠️)는 어겼을 때 남의 데이터가 깨지거나 되돌리기 어려운 곳에만 쓴다. 문서당 한두 개면 충분하다.

기존 문서를 고칠 때도 같이 정리한다.
