# KAN-421 LCP 개선 — 결과 (2026-08-31)

측정 조건은 [before/measurements.md](before/measurements.md)와 동일하다
(prod standalone 빌드, 로컬 BE, 익명, Lighthouse 13.4.1 모바일 에뮬 + simulated slow 4G,
페이지당 5회 중앙값). 저장소에는 단계·페이지별로 중앙값에 해당하는 런의 리포트
(JSON+HTML) 1쌍씩만 남겼다 — 5회 원값은 아래 표와 measurements.md에 있고, 전체 원본
30쌍은 용량(33MB) 때문에 로컬 `_workspace/perf-raw/`에 보관한다.

- LCP 5회 원값: 홈 after-font 6.23/5.78/5.55/6.23/5.71, after 6.23/6.23/5.56/6.30/5.55.
  릴스 after-font 5.48/5.41/5.41/5.41/4.96, after 5.48/5.70/5.85/5.71/5.48. (before는
  before/measurements.md)
- LCP: 홈 14.89 → 6.23 s (−58%), 릴스 14.75 → 5.70 s (−61%). 런 노이즈(±0.4 s)를 감안하면
  after-font와 after는 동일하다 — 움직인 건 전부 폰트 단계다.
- 폰트 전송량: 2,058,735 B (외부 2단 폭포수) → 291,982 B (같은 오리진 + preload), −86%.
- 요청: jsdelivr CSS 1건 삭제, 외부 폰트 오리진 의존 0. before에서 콜드 연결 런의 FCP가
  11.7 s까지 튀던 분산도 사라졌다.

## 변경별 귀속

| 항목                                            | 효과                                                       |
| ----------------------------------------------- | ---------------------------------------------------------- |
| #2 `next/font/local` 셀프호스팅(Std 서브셋)     | LCP −9 s대, FCP −0.5 s, 전송량 −1.77 MB — 이번 개선의 전부 |
| #3 `pbs.twimg.com` preconnect                   | 폰트 단계에 포함 측정(트윗 이미지 연결 선행)               |
| #1 첫 릴 슬라이드 eager + fetchPriority         | 잠재 — 현재 발행 데이터 전건 imageUrl null이라 경로 미발동 |
| #4 홈 히어로 fetchPriority 차등(high 1 + low 4) | 잠재 — 동일 사유                                           |

`#1`·`#4`가 수치에 안 잡히는 이유와 측정 중 사고(빌드 병렬 실행으로 after 1차 오염)는
[ADR 0111](../../adr/0111-kan-421-lcp-font-selfhost.md)에 기록했다.

## after 측정 환경

- 커밋: 코드 변경 완료 시점(브랜치 `feature/KAN-421-lcp`)
- after-font: 1단계(폰트·preconnect)만 반영한 빌드
- after: 1+2단계 전부 반영한 빌드. 1차 측정은 측정 중 `.next` 재생성으로 정적 자산이
  404가 나며 오염돼 폐기했고, 서버 재구성 후 CSS 200 확인하고 재측정한 값이다
