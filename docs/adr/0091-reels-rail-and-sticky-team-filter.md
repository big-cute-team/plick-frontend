# 0091. 릴스 레일 배경 제거와 팀 필터 sticky

같은 세션에서 받은 두 가지 UI 피드백을 처리했다. 릴스 우측 아이콘 뭉치의 검은 배경을 없애고
아이콘을 살짝 키우는 것, 그리고 홈과 웹 기사 리스트에서 스크롤을 내려도 팀 필터가 화면에
남아 있게 하는 것이다.

## 릴스 액션 레일

모바일 릴스의 우측 레일(좋아요·댓글·공유)에는 KAN-296에서 깐 검은 알약 배경이 있었다.
밝은 사진 위에서 아이콘 대비를 확보하려고 scrim 70% 알약을 아이콘 뭉치 뒤에 깔았던 건데,
쓰다 보니 배경이 오히려 눈에 걸린다는 피드백을 받았다. 알약 div를 통째로 걷어내고
아이콘을 32→34, 31→33으로 키웠다. 배경이 사라진 만큼 존재감을 아이콘 크기로 조금
보충한 셈이다. 가독성 걱정은 레일에 원래 걸려 있던 `drop-shadow-media`가 맡는다.
사진 위 흰 아이콘에 그림자가 있어서 배경 없이도 웬만한 밝은 사진에서는 읽힌다.

웹 릴스의 레일은 손대지 않았다. 웹은 아이콘마다 원형 칩을 까는 다른 디자인이고
데스크톱에서는 페이지 배경 위에 서는 surface 톤이라, 같은 피드백이 웹 칩에도
해당하는지는 따로 확인받는 게 맞다고 봤다.

## 팀 필터 sticky

홈 리스트를 한참 내린 뒤 다른 팀으로 갈아타려면 맨 위까지 도로 올라가야 했다. 필터
탭이 문서 흐름에 그냥 놓여 있어서다. 탭 컨테이너에 `sticky`를 걸어 모바일은 스크롤
영역 상단(top-0), 웹은 GNB 바로 아래(top-16, `SiteHeader`의 h-16과 짝)에 붙였다.
웹 탭은 홈과 기사 리스트가 공용(`PostFeed`)이라 한 번 고치면 두 화면에 다 적용된다.
밑으로 지나가는 리스트가 비치지 않게 `bg-bg`를 깔고, GNB(z-40) 아래로 들어가게
z-10을 줬다.

걸리는 데가 하나 있었다. 두 앱 다 당겨서 새로고침 때문에 콘텐츠가 `transform:
translateY()` 껍데기 안에 들어 있다. transform이 있는 조상은 `position: fixed`를
깨뜨려서 sticky도 같이 깨지는 게 아닌가 싶었는데, sticky는 가장 가까운 스크롤
컨테이너 기준으로 동작해서 transform 조상의 영향을 받지 않는다. 실제로 모바일
스크롤 영역과 웹 문서 스크롤 양쪽에서 브라우저로 확인했고 멀쩡히 붙어 있었다.
당기는 동안에는 탭도 translateY를 따라 같이 밀려 내려가는데, 콘텐츠와 한 몸으로
움직이는 거라 오히려 자연스럽다.

sticky가 풀리는 범위도 확인했다. sticky는 부모 박스 안에서만 붙어 있는데, 탭의
부모(소식 섹션·피드 컬럼)가 리스트 끝까지 이어지고 그 아래 남는 콘텐츠(소개 문구
정도)가 한 화면보다 훨씬 짧아서, 맨 밑까지 내려도 탭은 화면에 남는다.

## 검증

- check-types, lint, web·mobile 클린 빌드 통과.
- 모바일 홈(:3001): 리스트를 끝까지 내려도 탭이 스크롤 영역 상단에 붙어 있고,
  그 상태에서 첼시 탭을 눌러 필터가 바뀌는 것 확인.
- 웹(:3000): 홈과 `/articles` 모두 스크롤 후 탭 top이 64px(GNB 바로 아래)에 붙고,
  내린 상태에서 맨시티로 전환되는 것 확인. 330px 폭에서 가로 오버플로 0.
- 릴스(:3001/reels): 레일 자식이 버튼 3개뿐(배경 div 제거)이고 좋아요 아이콘이
  34로 커진 것 확인.
- 브라우저 패널이 hidden이라 클릭·스크린샷 대신 JS로 DOM 수치를 읽어 검증했다.
