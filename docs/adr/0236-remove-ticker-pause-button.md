# 0236. 홈 실검·경기 띠의 멈춤 버튼을 뺐다 (KAN-707)

## 티켓

KAN-707은 한 줄짜리 요청이었다. 홈 상단 실검과 자동으로 넘어가는 상자들에 붙어 있는 멈춤·재생 버튼을 없애고,
그냥 항상 애니메이션이 돌게 해 달라는 것이다.

"자동으로 넘어가는 박스들"이 어디까지인지부터 확인했다. 홈에서 시간이 지나면 저절로 내용이 바뀌는 건 세 군데였다.
실검 띠(`HomeTrendTicker`), 오늘 경기·LIVE 띠(`HomeLiveTicker`), 그리고 VS 카드 안의 마감 카운트다운(`ParticipationStatus`).
앞의 둘은 `@plick/ui`의 `RotatingLine` 하나를 공유하고, 웹과 모바일이 같은 컴포넌트를 쓴다. 카운트다운은 1분마다
남은 시간을 다시 계산하는 시계라서 멈춤 버튼 같은 게 없고 이번 티켓과 무관했다. 결국 손댈 곳은 `RotatingLine` 한 파일이었다.

## 전에는 어땠나

`RotatingLine`은 KAN-703 홈 개편([ADR 0233](0233-vs-hub-and-prediction-fixes.md))에서 만든 공용 컴포넌트다. 실검은 4.5초,
경기는 5.5초 간격으로 한 항목씩 아래로 밀어 넘기고, 오른쪽 끝에 버튼 두 개를 뒀다. `N/M` 카운터를 누르면 다음 항목으로
넘어가고, 그 옆의 `멈춤`을 누르면 자동 전환이 서고 글자가 `재생`으로 바뀌었다. `aria-pressed`로 눌린 상태를 알렸다.

멈춤 버튼은 접근성 가이드(WCAG 2.2.2, 5초 넘게 저절로 움직이는 콘텐츠에는 멈출 수단을 둔다)를 따라 넣었던 것이다.
그런데 실제로 화면에 올려 보니 모바일 폭 좁은 띠에 `3/10 멈춤` 같은 글자 버튼이 붙어 있는 게 눈에 거슬렸고, 사용자 입장에서
그걸 눌러 실검을 세워 둘 이유가 거의 없다는 피드백이 왔다. 그래서 티켓이 생겼다.

## 어떻게 바꿨나

`paused` 상태와 그 토글 버튼을 지웠다. 효과(effect)의 의존성 배열에서도 `paused`를 빼서 자동 전환이 서는 조건은
세 가지만 남았다.

- 항목이 하나뿐이면 돌릴 게 없으니 타이머를 안 건다
- 화면 밖(IntersectionObserver)이거나 탭이 숨겨졌거나(`document.hidden`) 움직임 줄이기 설정(`prefers-reduced-motion`)이면 틱을 건너뛴다
- 마우스를 올려 두거나 안쪽 링크에 키보드 포커스가 있는 동안은 타이머 자체를 걷는다

세 번째는 남겨 두기로 했다. 티켓은 "항상 애니메이션"이라고 했지만, 호버 중에도 넘어가면 누르려던 링크가 손가락
밑에서 달아난다. 그건 멈춤 버튼처럼 눈에 보이는 제어가 아니라 손을 떼면 바로 다시 도는 잠깐의 정지라서 취지와
어긋나지 않는다고 봤다. 모바일에는 호버가 없으니 사실상 영향이 없고, 데스크톱 웹에서만 마우스를 올린 동안 선다.
움직임 줄이기 설정도 그대로 둔다. 그건 사용자가 OS에서 이미 내린 결정이고, 멈춤 버튼이 없어진 상태에서 자동 전환을
끌 유일한 길이라 접근성 측면의 최소 장치로 남긴다.

버튼이 하나로 줄어들자 둘을 감싸던 `div`가 필요 없어져 `N/M` 버튼이 바로 띠의 자식이 됐다. 글자 크기와 색 클래스
(`text-caption text-text-3`)는 감싸던 쪽에서 버튼으로 옮겼다. 접근성 라벨 `실검 다음 항목, 3/10`은 그대로다.
JSDoc은 "사용자가 직접 멈추는 버튼은 두지 않는다"고 고쳐 적어 다음에 누가 다시 넣으려 할 때 티켓을 찾아가게 했다.

## 검증

`pnpm check-types`, `@plick/ui` 린트, 단위 테스트 286개가 통과했다. E2E 시나리오에 멈춤 버튼을 집는 로케이터는 없었다
(`tests/e2e`를 `멈춤`·`자동 넘김`·`aria-pressed`로 뒤졌다).

화면 확인은 한 번 막혔다. 사용자가 띄워 둔 모바일 dev 서버(:3031)가 Next 16의 dev 잠금을 잡고 있어 새 dev 서버가
"Another next dev server is already running"으로 바로 죽었고, 그 서버에 붙은 BE에는 실검 API가 없어 띠 자리에
"순위를 불러오지 못했어요"만 떴다. 전에 쓴 길([리디자인 검증 환경](0171-haechukimo-redesign.md) 때와 같다)대로
`API_BASE_URL=https://plick.co.kr/be`로 production build를 돌리고 `next start`를 3061 포트에 올려 prod BE에서
실검을 읽어 확인했다.

375px 폭에서 띠 오른쪽에는 `5/6` 카운터 하나만 남았고 `멈춤` 글자는 없다. 접근성 트리에서 `자동 넘김`
라벨이 사라진 것과 `실검 다음 항목, N/6` 버튼이 남아 있는 것을 확인했다. 6초 기다렸더니 카운터가 `5/6`에서
`1/6`으로 넘어가 자동 전환은 그대로 돈다. 콘솔에는 게스트 상태의 401과 404만 있었고 이번 변경과는 무관하다.

## 남은 것

웹(데스크톱)은 같은 `RotatingLine`을 쓰니 코드상 함께 바뀌었지만 브라우저로는 모바일만 밟았다. 호버 중 정지를
남긴 판단은 피드백이 오면 뒤집을 수 있다. 그때는 `hovered`·`focused` 상태까지 걷어 내면 된다.
