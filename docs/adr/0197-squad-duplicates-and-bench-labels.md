# 선수 중복과 벤치 팀 구분 수정

2026-10-14

경기 라인업에서는 벤치 선수를 한 표에 이어 붙이고 팀을 ARS, LIL 같은 약어로만 보여 줬다. 팀 프로필에서는 같은 선수가 여러 행에 나타났고, 선수 프로필의 같은 팀 선수 목록에도 중복이 보였다. 기록 탭의 `규율`이라는 제목도 사용자가 요청한 `파울`로 바꾸기로 했다.

작업은 develop에서 `codex/fix-football-rosters-and-labels` 브랜치를 만들어 시작했다. 기존 작업 파일은 그대로 두고 이번 수정과 검증 결과를 이 문서에 기록한다.

벤치는 공용 `LiveCrest`를 재사용해 팀 엠블럼과 전체 팀명을 제목에 넣었다. 기존에는 한 표의 작은 팀 약어 열을 매번 읽어야 했지만, 이제 아스날 벤치와 릴 벤치가 별도 섹션이다. 데스크톱에서는 두 열, 좁은 화면에서는 한 열로 이어진다. 팀을 제목에서 알 수 있으므로 행의 팀 약어 열은 없앴고, 선수 링크와 포지션, 평점은 유지했다. 벤치가 비어 있는 팀은 빈 제목을 만들지 않는다.

선수단은 `getTeamSquadTable`이 응답 행을 그대로 변환하고 있었다. 이 함수의 결과를 웹과 모바일 팀 프로필, 선수 프로필이 함께 사용한다. 화면별로 중복을 지우면 팀 내 득점 순위나 같은 팀 선수 추천에서 빠뜨리기 쉬워서 공통 fetcher가 반환하기 전에 합치기로 했다. 합치는 규칙은 순수 함수 `mergeSquadMembers`로 두었다.

선수 이름이나 등번호는 같은 사람이 아니어도 겹칠 수 있으므로 `playerId`를 기준으로 삼았다. 같은 id가 반복되면 처음 나온 순서를 유지한다. 대회 기록도 `competitionId`로 합친다. 시즌 누적값을 더하면 6골이 18골이 되는 식으로 부풀기 때문에 합산하지 않는다. 먼저 나온 null이 아닌 값을 유지하고, 뒤 행에만 있는 대회와 누락 필드는 보충한다. 0은 실제 기록일 수 있으므로 누락으로 취급하지 않는다. 응답에 최신 행을 판별할 시각이 없어서 서로 다른 유효 값 중 어느 쪽이 최신인지는 추정하지 않는다. 입력 배열과 객체도 변경하지 않는다.

기록 묶음의 `규율`은 공통 도메인 함수에서 `파울`로 바꿨다. 웹과 모바일, 골키퍼와 필드 선수 구성이 모두 이 함수를 쓰므로 한 곳에서 적용된다. 세부 파울, 피파울, 경고, 퇴장 수치는 그대로다.

검증에서는 중복 세 행을 한 명으로 합친 뒤 선수단, 팀 내 순위, 같은 팀 선수 목록에 한 번씩만 나오는지 확인했다. 다른 대회 보존, null 보충, 0 유지, 이름과 등번호가 같은 다른 id 보존, 입력 불변성도 검사했다. 단위 테스트 97개와 훅 테스트 40개, 전체 린트와 타입 검사가 통과했다.

운영의 공개 맨체스터 시티 선수단 API는 확인 시점에 502를 반환했다. 로컬 프로필에서도 경기 데이터 로드 실패가 보여 실제 응답의 중복 발생 원인까지 확인하지는 못했다. 화면 검증은 임시 로컬 경로에 실제 컴포넌트와 중복 예시 데이터를 넣어 진행했다. 1280px에서는 팀별 벤치가 나란히 놓였고, 330px에서는 위아래로 놓였다. 두 크기 모두 문서의 scrollWidth와 innerWidth가 같아 가로 넘침이 없었다. 선수단은 돈나룸마와 후뱅 디아스가 한 행씩 나오는 것을 확인했다. 검증용 경로는 확인 후 삭제했다.

처음 웹 빌드는 샌드박스의 컴파일 단계에서 진행되지 않아 중단했다. 권한을 허용한 환경에서 `pnpm build`를 다시 실행하자 웹과 모바일 모두 통과했다. 전체 `pnpm format:check`, 변경 앱 파일의 컨벤션 훅, `git diff --check`도 통과했다. 운영 응답이 복구된 뒤 실제 선수단 데이터로 다시 보는 것은 남아 있다.

이후 사용자가 dev 모바일에는 이미 팀별 벤치 제목이 있다고 짚어 줘서, 운영 대신 dev 웹과 모바일의 같은 경기(`/live/matches/1635612`)를 직접 비교했다. 모바일은 기존부터 `BenchList`에 홈과 원정 라인업을 각각 넘겼고 `벤치 아스날`, `벤치 릴` 제목이 실제 화면에도 나왔다. 웹만 한 표에 팀 약어를 넣는 구현이었다. 따라서 벤치 구분 수정은 데스크톱에만 필요하며 모바일 벤치 코드는 변경하지 않았다.

dev 선수단 API(`/be/api/v1/teams/2/squad`)는 정상 응답했다. 총 91행이지만 고유 선수 id는 26개였고, 돈나룸마(id 1622)와 디아스(id 567)는 각각 4행이었다. 이 응답으로 백엔드가 중복 행을 반환한다는 점을 확인했다. 백엔드 내부의 조인이나 캐시 중 어느 단계에서 생겼는지는 이 검증만으로 단정하지 않았다. 실제 응답을 수정한 병합 함수에 넣자 26명으로 정리됐고, 득점 상위 목록은 홀란 6골, 셰르키 4골, 세메뇨 2골로 나왔다.

dev 모바일 팀 프로필에서도 돈나룸마 4행과 득점 순위의 홀란 3행을 확인했다. 돈나룸마 프로필의 동료 목록은 룰리와 디아스가 반복됐고 기록 제목은 아직 `규율`이었다. 벤치 구분과 달리 선수 중복 및 문구 문제는 모바일에도 있다. 이번 브랜치의 공통 데이터 처리와 문구 수정이 배포되면 두 앱에 같이 적용된다.

사용자가 로컬 확인을 요청한 뒤에는 웹(:3000)과 모바일(:3001)을 dev API에 연결해 다시 실행했다. 실제 경기 데이터로 웹 라인업의 `아스날 벤치`, `릴 벤치` 제목을 확인했고, 모바일 맨시티 선수단의 골키퍼 목록에는 돈나룸마, 베티넬리, 룰리가 각각 한 행씩 나왔다. 예시 데이터뿐 아니라 dev 응답을 사용하는 로컬 화면에서도 수정 결과를 확인했다.
