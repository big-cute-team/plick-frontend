# 0038. 홈화면 디테일 수정 — 캐러셀을 릴스 임베딩 전략으로 통일 (KAN-297)

날짜: 2026-07-24
브랜치: `feature/KAN-297-home-detail-fixes`

## 무엇을 했나

릴스 최종 임베딩 전략(KAN-296, [ADR 0037](0037-reels-final-embed-strategy.md))이 자리를 잡고 나니
홈화면 곳곳이 옛 방식 그대로 남아 어색해졌다. 이번 세션은 그 어긋난 디테일 여덟 개를 티켓 하나로
몰아서 정리한 작업이다.

1. 헤더(TopBar) 알림 아이콘 제거
2. 캐러셀 릴스 임베드 가로 꽉 차게
3. 캐러셀 배경을 팀별 그라데이션 대신 릴 배경색(`bg-reel-bg`) 고정으로
4. 임베드가 카드보다 크면 단순히 잘리고, 작으면 세로 중앙정렬
5. 캐러셀 임베드를 사진 포함 전체 게시물로
6. "지금 올라온 소식" 스켈레톤의 사진 자리 삭제
7. 하단바에서 검색·알림 탭 제거
8. 모든 트위터 임베드 상호작용 제거

작업 중에 캐러셀 카드 테두리 추가 요청이 들어왔다가 결과를 보고 다시 빼기로 해서, 최종본에는
테두리가 없다.

## 캐러셀 카드 재작성 (2~5번)

핵심은 `HotHeroCard`를 릴(`ReelItem`)과 같은 구조로 다시 쓴 것이다.

원래 카드는 `MediaThumb`(팀 컬러 그라데이션) 위에 `TweetEmbed`의 기본 `fill` 레이아웃을 얹는
구조였다. `fill`은 카드가 박스를 벗어나면 미디어(사진)를 숨기고 그래도 넘치면 `transform: scale`로
줄이는 방식이라, 사진 없는 요약 카드에 맞는 전략이었다. 그런데 티켓이 원하는 건 정반대다 —
"사진 포함한 전체 게시물"을 보여주되 "크면 단순하게 잘려서 보이게".

이건 릴스가 KAN-296에서 정착시킨 `layout="reel"`이 이미 하는 일이다. 미디어를 숨기지도 줄이지도
않고 자연 높이·전폭으로 세우는 레이아웃이라, 캐러셀에서도 그대로 갖다 썼다. 카드 쪽은
`overflow-hidden`인 박스에 임베드를 `[justify-content:safe_center]`로 세웠다.

`safe center`가 이 요구사항을 CSS 한 줄로 해결해 준다. 그냥 `center`는 내용이 컨테이너보다 클 때
위아래가 똑같이 잘려나가 카드 머리(작성자 줄)가 안 보이는데, `safe`가 붙으면 넘치는 순간
정렬이 `start`로 바뀐다. 즉 작으면 정확히 세로 중앙(4번), 크면 위에서부터 그려지다 카드 바닥에서
잘린다(역시 4번). 릴스에서 검증된 패턴이라 고민 없이 재사용했다.

가로(2번)는 따로 할 게 없었다. react-tweet 카드는 `width: 100%, max-width: 550px`인데 모바일
카드 폭이 그보다 좁아 항상 꽉 찬다.

배경(3번)은 `MediaThumb`을 걷어내고 카드 자체에 `bg-reel-bg`를 깔았다. 릴스와 같은 토큰이라
다크 `#151E26`, 라이트 `#FFFFFF`로 테마를 따라가고, 임베드 카드 배경을 릴 배경에 맞추는
`.reel-embed` CSS 오버라이드(ADR 0037)도 클래스만 붙여 그대로 얻었다 — 카드와 임베드가 한 색으로
이어지고 테두리만 남는 그 모양이다. 팀별 그라데이션이 사라지면서 `NO_TEAM_COLOR_VAR` 폴백도
이 카드에서는 필요가 없어졌다.

사진(imageUrl)이 있는 기사는 릴과 똑같이 사진이 카드를 가득 덮고(`object-cover`), 사진도 원문
링크도 없으면 통일 배경색이 그대로 남는다.

### 테두리 — 넣었다 뺐다

작업 중에 카드 테두리를 "토큰 중 밝은 색상으로" 넣어 달라는 요청이 왔다. 처음엔 border 계열에서
제일 강한 `border-strong`을 썼는데, 알파가 16%라 어두운 바탕에서 사실상 안 보였다. 스크린샷으로
확인하고 색 토큰 중 밝은 `text-4`(다크 `#5e6b80`, 라이트 `#98a1ae`)로 바꿨더니 이번엔 또렷하게
보였는데, 결과물을 보고 나서 없는 게 낫겠다는 판단이 돌아와 도로 뺐다. 최종 카드는 테두리 없이
`overflow-hidden` 라운드 박스만 남는다. 임베드 카드 자체 테두리(`--tweet-border`)는 그대로라
트윗 영역의 윤곽은 유지된다.

### 링크 구조가 단순해졌다

옛 카드는 임베드의 링크·액션을 막을 수 없다는 전제(X Display Requirements) 위에서, 임베드가 보일
때 기사 세부 Link를 하단 40%로 좁혀 위쪽 탭은 임베드가 받게 하는 타협을 하고 있었다(ADR 0035).
이번에 임베드 상호작용을 전역으로 꺼 버리면서(아래 8번) 그 타협이 통째로 필요 없어졌다 — 투명
Link가 항상 카드 전체를 덮고, 어디를 눌러도 기사 세부로 간다.

### 코너 라운드 맞추기

PR을 올리고 나서 카드(rounded-hero, 22px)와 임베드 카드(react-tweet 기본 12px)의 코너 둥근
정도가 달라 이질감이 있다는 피드백이 왔다. react-tweet의 12px는 CSS 변수가 아니라 모듈 CSS에
박힌 고정값이라, 캐러셀 임베드 래퍼에 `hero-embed` 클래스를 하나 더 얹고 globals.css에서
`border-radius: var(--radius-hero)`로 덮었다. 특이도는 릴 배경 오버라이드와 같은 수법
(부모 클래스 + `.react-tweet-theme` 이중)으로 이겼다. 릴스 쪽 임베드는 화면 폭을 그대로 쓰는
맥락이라 건드리지 않았다.

## 임베드 상호작용 전역 차단 (8번)

`globals.css`의 `.react-tweet-theme` 오버라이드에 `pointer-events: none` 한 줄을 넣었다.
react-tweet의 모든 내부 링크(프로필, Follow, 답글, 마음, 원문)가 앱 전체에서 죽는다 — 홈 캐러셀,
릴스, 기사 세부의 flow 임베드 모두.

원래 "임베드의 링크·액션은 X Display Requirements상 막을 수 없다"는 주석이 여러 곳에 있었는데,
제품 판단이 바뀌었다. 임베드는 원문을 보여주는 읽기 전용 미디어고, 탭은 항상 우리 화면(카드 링크,
릴 시트)이 받는 게 낫다는 쪽이다. TweetEmbed의 JSDoc도 그에 맞게 고쳤다.

pointer-events는 CSS 상속이라 자식 전부에 먹고, 클릭이 임베드를 투과해 아래 레이어로 떨어진다.
캐러셀에서는 임베드 위에 얹힌 투명 Link가 받아 기사 세부로 가는 걸 브라우저에서 확인했다.

## 나머지 자잘한 것들 (1, 6, 7번)

- TopBar: BellIcon 버튼과 `notif` prop을 지웠다. 홈과 MY 페이지가 `notif={3}` 목값을 넘기고
  있었는데 알림 기능 자체가 없어 자리만 차지했다.
- NewsItemSkeleton: `size-14` 썸네일 박스를 지웠다. 실데이터 이미지가 전부 비어 실제 줄
  (`NewsItem`)은 이미 텍스트만 그리는데(KAN-284), 스켈레톤만 사진 자리를 그려 로딩 전후가
  어긋났다.
- TABS: 검색·알림 탭을 뺐다. 둘 다 라우트가 없는 죽은 링크였다. 홈·릴스·MY 세 탭이 남는다.

`NO_TEAM_COLOR_VAR` 주석의 "홈 리스트와 릴스가 같은 폴백을 쓴다"도 이제 릴스가 안 쓰므로
"홈 리스트와 기사 세부"로 바로잡았다.

## 검증

- `check-types`, `lint` 통과.
- 브라우저(모바일 뷰포트)에서 다크·라이트 모두 확인 — 캐러셀 임베드가 사진째 카드를 채우고
  바닥에서 잘리는 것, 테두리 가시성, 하단바 3탭, 헤더 정리, 임베드 탭이 기사 세부로 가는 것까지.
