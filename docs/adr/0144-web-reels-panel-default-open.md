# 0144. 웹 릴스 세부 패널을 처음부터 열어 두기 (KAN-483)

2026-09-15. 브랜치 `feature/KAN-483-web-reels-panel-default-open`.
관련: [ADR 0143](0143-live-dot-new-badge.md) 직전 세션,
`apps/web/app/reels/_components/ReelDetailPanel.tsx`의 KAN-219·KAN-323 주석(패널 개폐 애니메이션 구조).

## 티켓은 한 줄이었다

KAN-483은 "[FE] 웹 릴스 수정"이라는 제목에 본문이 "웹 릴스에서 댓글 패널, 열려있는게 디폴트로."
한 줄이다. 지금 웹 릴스는 릴 한 장이 뷰어를 채우고, 제목 영역이나 댓글 버튼을 눌러야 오른쪽에서
세부 패널(기자 줄·본문·해시태그·투표·댓글)이 미끄러져 들어온다. 데스크톱은 폭이 남아도는데
댓글을 보려면 한 번 눌러야 하니, 처음부터 열어 두자는 얘기다.

## 한 글자 수정으로 끝날 줄 알았다

`ReelsWorkspace`가 `const [detailOpen, setDetailOpen] = useState(false)`로 개폐 상태를 들고 있으니
`false`를 `true`로 바꾸면 끝이라고 생각했다. 그런데 패널 컴포넌트 주석을 읽다가 걸렸다. 이
패널은 데스크톱(lg 이상, 1024px)에서는 뷰어 옆 인라인 카드로 서지만, lg 미만에서는
`fixed inset-0` 전체 화면 오버레이로 뜬다. 좁은 폭에서 릴과 나란히 둘 수 없어 릴 위를 덮는
구조다. 여기서 기본값을 `true`로 두면 좁은 창으로 들어온 사람은 릴을 못 보고 댓글 패널부터
만난다.

웹은 데스크톱용이지만 lg 미만 대응이 있다. `SwitchToMobileBanner`(KAN-379) 주석에 "이 앱도 좁은
화면에서 깨지지는 않지만 릴스처럼 모바일에 맞춰 만든 화면은 모바일 도메인이 낫다"고 적혀 있고,
자동 리다이렉트는 일부러 안 한다. 그러니 좁은 폭도 멀쩡해야 한다. 기본 열림은 데스크톱에만
줘야 했다.

## 서버는 창 폭을 모른다

"데스크톱이면 열림, 아니면 닫힘"을 어디서 정하느냐가 문제였다. 릴스 페이지는 첫 페이지를 서버
컴포넌트가 받아 `initial`로 내려주고, `ReelsWorkspace`는 클라이언트 컴포넌트지만 SSR로 첫 HTML이
그려진다. 서버는 요청을 보낸 브라우저의 창 폭을 모르니 열림·닫힘 중 하나를 골라 HTML을 만들
수 없다.

생각해 본 방법이 셋이다.

첫째, `useState(() => window.matchMedia(...).matches)`처럼 초기값을 클라에서 계산하기. 서버에는
`window`가 없으니 서버는 `false`, 클라는 `true`가 되어 하이드레이션이 어긋난다. 하이드레이션은
서버가 그린 HTML에 리액트가 이벤트만 붙이는 과정이라 첫 렌더 결과가 서버와 같아야 하고, 다르면
경고가 뜨고 클래스 같은 속성은 서버 값이 그대로 남는다. 상태는 `true`인데 DOM은 닫힌 클래스인
채로 시작하는 꼴이다. 버렸다.

둘째, `useState(false)`로 두고 마운트 뒤 이펙트에서 `matchMedia`로 `true`를 넣기.
`SwitchToMobileBanner`가 이 방식이다. 배너는 첫 렌더에 아무것도 안 그리다가 나중에 켜지는 거라
괜찮지만, 패널은 폭 0에서 29.5rem으로 300ms transition이 걸려 있다. 데스크톱에서 들어올 때마다
패널이 닫힌 채 그려졌다가 하이드레이션 뒤 미끄러져 들어온다. 서버가 첫 릴을 이미 들고 있어
데이터는 처음부터 있는데 패널만 늦게 열리는 게 어색했다. 반대로 `useState(true)`에 좁은 폭에서
닫는 이펙트를 두면 좁은 창에서 오버레이가 잠깐 덮였다가 빠진다. 어느 쪽이든 한쪽에서 깜빡인다.

셋째, 결정을 CSS에 맡기기. 이 패널은 이미 `lg:` 접두사로 인라인·오버레이를 가르고 있다. 그러니
"아직 사용자가 안 건드린 상태"를 하나 더 두고, 그때는 열림 클래스도 닫힘 클래스도 아닌
"lg 이상이면 열림, 미만이면 닫힘" 클래스를 준다. 서버가 내리는 HTML이 어느 폭에서도 맞으니
하이드레이션이 어긋날 일이 없고 transition도 안 탄다. 이걸 골랐다.

## 상태를 세 값으로

`detailOpen`을 `boolean | null`로 바꿨다. `null`이 미정이다. 패널에는 `undecided` prop으로
넘기고, 패널은 세 갈래로 클래스를 고른다.

- 닫힘: `pointer-events-none translate-x-full lg:w-0 lg:translate-x-0` (전과 같다)
- 열림: `translate-x-0 lg:w-[29.5rem]` (전과 같다)
- 미정: `pointer-events-none translate-x-full lg:pointer-events-auto lg:w-[29.5rem] lg:translate-x-0`

미정 줄을 풀면, 좁은 폭에서는 오른쪽 밖으로 밀려나 있고 클릭도 안 먹고, lg 이상에서는 폭
29.5rem으로 서 있고 클릭이 먹는다. 열림·닫힘 줄을 `lg:` 기준으로 합쳐 놓은 것이다.

미정을 그대로 두면 안 되는 게 `aria-hidden`이다. 이건 CSS로 못 가르니 미정일 때는 열림 취급
(`false`)이 되고, 좁은 폭에서 화면 밖에 있는 패널이 스크린리더에는 보인다. 그래서
`ReelsWorkspace`가 마운트 뒤 이펙트에서 `matchMedia("(min-width: 1024px)")`로 실제 값을 확정한다.
`setDetailOpen((v) => v ?? matches)`라 사용자가 그 사이 눌렀으면 덮어쓰지 않는다. 확정되면 보통
`boolean`이고, 미정 클래스와 확정 클래스가 같은 폭에서는 같은 화면을 그리니 확정 순간에 아무것도
안 움직인다. 이후 열고 닫기는 전과 똑같이 `true`·`false`다.

쿼리 값은 `_constants/reels.ts`에 `REELS_PANEL_DESKTOP_QUERY`로 뒀다. Tailwind `lg`가 64rem이고
패널 CSS가 그 선으로 갈리니 JS 판정도 같은 선이어야 한다. 이미 있던 `PULL_VIEWPORT_QUERY`
(`max-width: 1023px`)의 반대편이다.

## 확인한 것

`pnpm --filter web lint`와 `check-types`를 통과했다. dev 서버를 띄워 브라우저 패널로 봤다.

- 1440px: 들어오자마자 패널이 열려 있고(폭 472px, `aria-hidden="false"`), 클래스는 확정된 열림
  줄로 바뀌어 있다. `curl`로 받은 SSR HTML에는 미정 줄이 들어 있다. 하이드레이션 경고 없음.
- 800px: 들어오면 릴만 보이고 패널은 `translate: 100%`, `aria-hidden="true"`, 클릭 불가로 확정돼
  있다. 댓글 버튼을 누르면 오버레이가 뜨고 Escape로 닫힌다.
- 1440px에서 Escape로 닫으면 폭 0이 되어 뷰어가 폭을 되찾고, 댓글 버튼으로 다시 열린다.

## 남긴 것

창 폭을 확정한 뒤 브레이크포인트를 넘나들며 리사이즈해도 상태는 따라가지 않는다. 데스크톱에서
열어 둔 채 창을 줄이면 오버레이가 되고, 좁은 창에서 닫힌 채 키우면 닫힌 채다. 전에도 그랬고
`SwitchToMobileBanner`처럼 `change` 이벤트를 듣는 건 사용자가 고른 개폐를 창 크기가 뒤집는
셈이라 안 넣었다.
