# 0225. 경기 상세에 승부예측 탭과 작성 시트를 붙인다 (KAN-696, 웹과 모바일 함께)

## 티켓

KAN-696은 "[FE] 웹 경기 상세 예측 탭과 예측 등록, 수정, 취소 연동"이다. 경기 상세에 승부예측 탭을 붙이고
요약(`GET /matches/{id}/prediction`)으로 상태 줄, 분포, 내 예측을 그리고, 등록·수정(`PUT`)과 취소(`DELETE`)를
연결한다. 완료 조건은 상태 다섯 가지 화면, `revealed: false`면 `?%`와 `?명 예측`, 공백 뺀 5자 이상 300자
이하에서만 등록 버튼, 경기별 임시 저장, 게스트는 연동 안내와 비로그인은 로그인 뒤 픽 유지, 금칙어 400은
시트 유지, 마감 409는 토스트 뒤 LOCKED 전환, 등록 응답으로 재조회 없이 갱신, 도박 연상 표현 금지, dev API
검증이다.

티켓은 웹 한 장이었는데 시안에 앱 v2와 홈(웹) v2가 둘 다 있어 모바일도 같은 PR에서 함께 했다. KAN-695의
API 층(타입, 읽기 fetcher, 쿼리 키, 오류 분류)이 `@plick/domain`과 `@plick/core`에 공용으로 있어서 모바일은
서버 액션 둘만 복제하면 됐다. 화면 하나를 두 앱에 한 번에 올리는 게 어긋남을 가장 적게 만든다고 봤다.

## 어디에 무엇을 두었나

- `@plick/domain/prediction`에 화면 표기 헬퍼를 더했다. 픽 라벨(`맨시티 승`, `무승부`), 상태 줄(UPCOMING은
  `9월 14일 22:30 열림`, LOCKED `예측 마감`, SETTLED `결과 1 - 2 맨시티 승`, VOID `경기 취소, 적중 기록
제외`, OPEN은 없음), 적중 표기, 분포 칸 값, 임시 저장 값 파싱. 순수 함수라 `tests/unit`에 테스트를 붙였다.
- `@plick/core/prediction-draft`가 임시 저장의 localStorage 읽기 쓰기 지우기다. 키는 KAN-695가 만들어 둔
  `plick:pred-draft:{matchId}`이고 값은 `{ pick, opinion }`이다.
- `@plick/ui/PredictionBar`가 3분할 바다. 두 앱이 같은 자리에 같은 모양을 그려 처음부터 공용으로 뺐다
  (ADR 0011 게이트). 높이와 최소 폭만 `size`로 가르고 모서리는 `rounded-tile` 토큰이라 웹에서는 각지다.
- 앱마다 `_hooks/usePredictionSummary`, `usePredictionCompose`, `usePredictionCancel`과 `_constants/predictions`,
  `live/_components/Prediction*`(탭 본체, 작성 시트·팝업, 로그인·연동, 취소 확인, 잠금 지면, 내 예측 상자)이
  있다. 모바일에는 `_services/prediction-actions.ts`를 웹에서 복제했는데 이번 티켓이 쓰는 PUT과 DELETE
  둘만 옮겼다.
- 토큰에 `--color-accent-soft`(#f4f8f6, 내 예측 상자 면)와 바 등장 애니메이션 `--animate-seg`,
  `--animate-seg-label`을 더했다.

## 예측 탭은 언제 생기나

가이드 §3은 "빅6 밖 경기, API 404면 예측 탭을 만들지 않는다"고 했다. 탭 목록이 요약 응답에 걸린다는 뜻이다.
경기 상세 페이지는 KAN-683에서 익명 ISR(20초)로 바뀌어 요청마다 쿠키를 읽을 수 없다. `cookies()` 한 줄이
들어가면 페이지가 동적 렌더로 돌아가 CloudFront 문서 캐시가 깨진다. 그래서 서버는 토큰 없이 요약을 받아
씨앗으로 내린다. 그 값으로 탭이 있는지(null이면 없음)와 첫 그림을 정하고, 클라 훅이 마운트되면 `/be`
프록시로 다시 받는다. 프록시가 Bearer를 실어 주니 그때 내 예측과 분포가 그 사람 기준으로 온다. 기사 상세의
토론 집계(`useArticleDebate`)가 KAN-681에서 간 길과 같다.

이 구조에서 예측한 사람은 처음 한 프레임을 `?%` 균등 바로 보고 응답이 오면 실제 비율로 바뀐다. 바에
`transition: flex-grow`가 걸려 있어 그 변화가 퍼지는 움직임으로 보인다. 가이드가 "예측 직후 `?%`에서 실제
비율로 바뀔 때는 transition이 처리한다"고 적어 둔 그 경로를 첫 로드도 같이 탄다.

탭 표는 두 앱 `_constants/live.ts`의 `matchTabsFor(status, hasPrediction)`가 돌려준다. 상태별로 미리 만든
배열을 돌려줘 렌더마다 새 배열이 생기지 않는다. 연기·취소 경기는 탭 없이 안내만 그리는 지면이라 예측 탭을
붙이지 않았다. 가이드 §3은 VOID에도 프리뷰, 순위, 뉴스, 예측을 두는데 지금 CANCELLED 지면은 "취소된
경기예요" 한 줄이라 탭 줄 자체가 없다. 거기까지 바꾸는 건 이 티켓 밖이라 남겼다.

웹은 KAN-683에서 탭 본문을 전부 그리고 비활성은 `hidden`으로 두는데(크롤러가 라인업·스탯을 읽게), 예측
탭은 뉴스처럼 열 때만 그린다. 내 예측이 실리는 유저별 지면이라 서버 HTML에 둘 이유가 없고, 숨긴 채 그리면
바 등장 애니메이션이 안 보이는 사이에 끝난다.

## 등록 응답으로 바로 덮기와 BE 분포 캐시

티켓은 "등록 응답이 요약과 같은 모양이므로 재조회 없이 화면 갱신"을 요구한다. KAN-695의
`invalidateAfterPredictionWrite`는 요약까지 넷을 무효화하는데, 그걸 그대로 쓰면 등록 직후 요약을 다시
받는다. BE는 분포를 30초 캐시하니 그 응답에는 내 표가 빠진 옛 분포가 올 수 있고, PUT 응답으로 덮어 둔
숫자를 옛 숫자가 다시 덮는다. 그래서 등록 훅은 요약은 `setQueryData`로 응답을 덮기만 하고 의견, 홈 카드,
내 기록 셋만 무효화한다. 요약은 30초 폴링이 다음 차례에 맞춘다. 취소는 204라 덮을 값이 없어 core의 함수
그대로 넷을 다시 받는다. 취소 뒤 요약은 `revealed: false`로 돌아오니 옛 분포가 보일 일도 없다.

폴링은 OPEN과 LOCKED에서만 돈다. 정산·취소·미개장은 바뀔 게 없다.

## 작성 시트와 분기

작성은 앱이 바텀 시트, 웹이 440px 가운데 팝업이다. 시안은 웹 팝업을 누른 위치 근처에 띄우는데 다른 팝업과
같이 가운데에 뒀다. 스크롤 위치마다 자리가 달라지는 것보다 늘 같은 자리가 낫다고 봤다.

로그인 분기는 서버에 보내기 전에 `useAuth`로 먼저 가른다. 세션이 없으면 로그인 시트(소셜 버튼이 바로
선다), 게스트면 "계정 연동 후 예측할 수 있어요", 소셜이면 작성 시트다. 세션을 아직 모르는 동안
(`isSessionPending`)은 작성 시트를 열고 서버 응답이 같은 분기를 다시 탄다. 서버 액션은 쿠키가 없으면 BE까지
가지 않고 401을, 게스트 토큰이면 BE가 403을 주고, `classifyPredictionError`가 그걸 `login`과 `link-account`로
갈라 준다. 댓글의 `LoginPromptDialog`는 안내 뒤 로그인 화면으로 보내는 두 단계인데 시안은 시트에서 소셜
버튼을 바로 누르게 그려 `PredictionAuthSheet`를 따로 뒀다.

"로그인 뒤 고른 픽 유지"는 임시 저장으로 풀었다. 소셜 로그인은 OAuth 인가 페이지로 나가는 하드
내비게이션이고 콜백은 홈으로 돌려보내서 메모리 상태가 전부 사라진다. 작성 시트가 글자를 칠 때마다 픽과
본문을 경기별 localStorage에 적어 두니, 다시 경기로 들어와 "의견 남기기"를 누르면 그대로 선다. 임시
저장은 새로 쓸 때만 하고 수정 모드는 내 예측 본문이 원본이라 적지 않는다. 등록과 취소가 성공하면 지운다.

실패 종류별 처리는 KAN-695가 만든 `keepsComposerOpen`과 `refetchesSummaryAfter`를 그대로 썼다. 금칙어와
길이는 시트를 닫지 않고 입력란에 1px 진한 테두리와 문구를 띄우고, 마감과 미개장은 훅이 요약을 다시 받고
탭이 토스트를 띄운 뒤 시트를 닫는다. 모바일 토스트는 KAN-447의 전역 스토어를 썼고 웹은 그 스토어가 없어
탭이 문구와 일련번호를 들고 `PredictionToast`에 넘긴다.

## 잠금 지면

OPEN에서 예측하지 않은 사람에게 의견 자리는 잠금 지면이다. 서버가 `locked: true`로 빈 목록을 주므로 실제
의견 본문은 DOM에 없다. 회색 막대로 된 가짜 행 네 개에 `blur(6px)`를 걸어 "여기 의견이 있다"는 실루엣만
만들고, 그 위에 안내 문구와 "의견 남기기" 버튼을 세웠다. 블러 아래는 `aria-hidden`과 포인터 이벤트 꺼짐이라
스크린리더와 탭은 문구와 버튼만 만난다. 바깥 상자의 클릭도 작성을 여는데 접근성 이름과 키보드 동선은
안쪽 진짜 버튼이 맡는다.

의견 목록 자체(정렬, 픽 필터, 행, 공감, 신고)는 KAN-697 몫이라 잠금이 풀린 뒤의 목록 자리는 비워 뒀다.
의견 머리글 "의견"과 예측 전의 "투표하기" 버튼만 먼저 뒀다.

## mock에서 본 것과 못 본 것

dev BE에는 소셜 토큰이 없어 쓰기를 못 때린다(KAN-695 때와 같다). 그래서 BE를 `SPRING_PROFILES_ACTIVE=mock`
8081로 띄우고 두 앱을 `API_BASE_URL=http://localhost:8081`로 붙였다(`.claude/launch.json`에 `backend-mock`,
`mobile-dev-mock`, `web-dev-mock`). mock 경기 상세는 900001(종료, 예측 SETTLED 적중), 900002(라이브,
LOCKED), 900003(예정, OPEN 미예측) 셋만 있어서 그 셋의 화면을 두 앱에서 봤다. 900004(OPEN 예측함),
900007(VOID), 900008(UPCOMING)은 예측 요약은 있지만 경기 상세가 404라 경기 페이지 자체가 안 뜬다. 그
셋의 상태 줄과 바는 `tests/unit/prediction-status.test.mjs`의 순수 함수 테스트로만 확인했다.

900003에서 작성 흐름을 끝까지 밟았다. 픽 없이 세 글자만 치면 등록 버튼이 회색이고, 시트를 닫았다 열면
픽(원정)과 글이 임시 저장에서 살아나고, 다섯 글자를 넘기면 초록이 되고, 등록하면 시트가 닫히며 바가
`?%` 균등에서 28, 16, 56으로 퍼지고 원정 칸에 체크, 내 예측 상자가 서고 localStorage 키가 지워진다.
수정을 누르면 시트가 내 픽과 글을 채운 채 `수정` 라벨로 열리고, 취소를 누르면 "예측을 취소할까요?"
시트가 뜨고 확정하면 204 뒤 잠금 지면으로 돌아간다.

mock의 두 성질이 검증을 방해했다. 하나는 저장을 안 한다는 것. 등록 응답은 내 예측이 실린 요약이지만 다음
GET은 다시 미예측이라, 창 포커스가 바뀔 때의 재조회(`refetchOnWindowFocus`, staleTime 0)가 돌면 화면이
미예측으로 돌아간다. 처음엔 등록 뒤 2초쯤 지나 내 예측 상자가 사라져 당황했는데 네트워크 타임라인을 보니
브라우저 패널의 클릭과 스크린샷이 포커스 이벤트를 내고 있었다. 그래서 수정과 취소 시트는 포커스를 건드리지
않는 `javascript_tool`의 합성 클릭으로 등록 직후에 열어 확인했다. 다른 하나는 `/users/me`가 누구에게나
`isGuest: false`를 준다는 것. 게스트 쿠키로 들어가도 소셜로 보여 "계정 연동 후 예측할 수 있어요" 분기는
mock으로 재현되지 않았다. 로그인 시트와 연동 시트는 컴포넌트를 눈으로 보지 못했고, 분기 조건(`useAuth`의
`isLoggedIn`, `isGuest`와 `classifyPredictionError`의 `login`, `link-account`)만 코드로 확인했다. 금칙어
400과 마감 409도 mock에 없어 입력란 오류 표시와 토스트는 못 봤다. 분류 자체는 KAN-695의 테스트가 든다.

합성 클릭이 결함 하나를 드러냈다. 처음 작성 시트는 `pick`과 `opinion`을 따로 `useState`로 들고 `update`
함수가 클로저의 현재 값으로 둘을 합쳐 임시 저장을 썼다. 스크립트가 픽 클릭과 입력 이벤트를 같은 태스크에서
연달아 보내자 두 번째 핸들러가 아직 재렌더 전의 `pick: null`을 읽어 방금 고른 픽을 덮었다. 사람 손으로는
이벤트가 태스크 하나씩 떨어져 안 나던 일이지만 React 배치에 기대는 코드인 건 맞아서, 픽과 본문을 한 state로
합치고 함수형 갱신으로 바꾼 뒤 임시 저장은 `useEffect`가 그 state를 보고 쓰게 했다.

같은 재조회가 또 하나를 알려 줬다. 수정 시트가 열린 채 요약이 다시 와 `myPrediction`이 바뀌면 시트의
`mine` prop이 바뀌어 수정 모드가 새로 쓰기 모드로 뒤집혔다. mock에서는 저장을 안 해 늘 그랬고 실제 BE에서는
다른 기기에서 취소했을 때나 일어날 일이지만, 시트는 여는 순간의 내 예측을 들고 가는 게 맞다. 탭이 시트를
열 때 `mine`을 값으로 박아 넘기게 바꿨다.

웹을 330px로 줄여 보니 상태 줄이 깨졌다. "결과 2 - 1 Tottenham 승", "적중", "1,284명 예측" 셋이 한 줄
flex에 있어 글자 단위로 꺾였다. 줄을 `flex-wrap`으로 바꾸고 적중 표기와 참여 수에 `shrink-0`과
`whitespace-nowrap`을 줘 상태 줄만 두 줄로 내려가게 했다. 모바일도 같은 구조라 같이 고쳤다.
