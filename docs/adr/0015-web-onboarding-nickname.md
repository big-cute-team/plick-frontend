# 0015 — 데스크톱 웹 온보딩 닉네임 단계 (KAN-247)

회원가입(KAN-246) 다음 순서인 온보딩 1단계, 닉네임 설정 화면(피그마 W8, node 225-2)을 데스크톱 웹에 붙였다. 소셜 가입을 마치면 넘어오는 화면이고, 스텝 표시가 `1 / 2`라 팀 선택(2단계)이 뒤에 하나 더 붙는 흐름이다.

## 카드는 또 하나였지만 AuthCard는 아니었다

처음엔 바로 직전에 만든 `AuthCard`를 재활용할 수 있지 않을까 했다. 둘 다 다크 배경 한가운데 카드 하나를 띄우는 모양이니까. 그런데 뜯어보니 속이 완전히 달랐다. AuthCard는 로고 + 태그라인 + 소셜 버튼이라는 고정된 세로 나열인데, 닉네임 카드는 스텝 표시 → 제목 → 입력 → 하단 버튼이고, 무엇보다 버튼이 카드 맨 아래에 딱 붙어 있다. 그래서 카드 껍데기(가운데 정렬 + 다크 배경 + `border-border bg-elevate-2` 카드)라는 *패턴*만 같고 알맹이는 새 컴포넌트로 갔다. 공용 카드를 하나 더 추상화해서 억지로 끼워 맞추는 것보다, 지금은 화면 전용으로 두는 게 맞다고 봤다.

## 피그마 값을 실제 px로 되돌리기

데스크톱 시안은 0.45 배율 프레임이라 늘 값을 0.45로 나눠 실제 px를 구한다. 카드 폭이 252 → 560px이었는데, 로그인·회원가입 카드(`max-w-auth` 460px)보다 눈에 띄게 넓었다. 온보딩은 단계가 더 남았으니 같은 폭이 반복될 것 같아서 `--container-onboarding: 560px`(`max-w-onboarding`)를 토큰으로 새로 하나 팠다. 웹 전용 CSS에 숨기지 않고 토큰으로 올려 두는 게 이 저장소 규칙이기도 하다.

제목 "닉네임을 정해주세요"는 25px, 행간 1.35, 자간 -0.4px으로 나왔는데 이게 `text-headline` 토큰(24px)과 값이 정확히 맞았다. 토큰 주석에 "온보딩 제목·릴 제목"이라고 적혀 있던 게 바로 이거였다. 반가운 순간.

카드 높이가 한 군데 걸렸다. 시안은 min-height 680px에 버튼을 `flex-1` + `justify-end`로 바닥에 밀어 두는 구조라, 이 높이가 없으면 카드가 내용만큼만 쪼그라들어 버튼이 안내 문구 바로 밑에 붙는다. 색·간격은 토큰만 쓰라는 규칙이 있지만 이건 색/간격 토큰이 아니라 이 카드 한 장의 레이아웃 치수라, 임의 bracket(`min-h-[680px]`) 대신 Tailwind v4의 숫자 유틸 `min-h-170`(170 × 4px = 680px)으로 적고 컴포넌트 주석에 이유를 남겼다.

## 이미 있는 걸 다시 만들지 않기

체크 아이콘("사용 가능한 닉네임이에요" 앞)은 새로 그릴 뻔했는데, 모바일 온보딩(A5)에서 이미 `@plick/ui/icons`의 `CheckIcon`(node 96-6 벡터 그대로)으로 올라와 있었다. 그대로 가져다 썼다. 프리필 값 "김도완"도 웹 목데이터의 `CURRENT_USER.nickname`이 이미 그 값이라 손댈 게 없었다 — 소셜 가입에서 넘어온 이름을 채워 두는 자리다.

빌드하고 보니 모바일 앱에 `/onboarding/nickname`·`/onboarding/team` 라우트가 이미 있었다(KAN-176). 카피("닉네임을 정해주세요", "댓글과 반응에 표시될 이름이에요", "사용 가능한 닉네임이에요", "다음"), `aria-label="닉네임"`, "비어있지 않으면 사용 가능"이라는 목 검증, `NICKNAME_MAX_LENGTH = 10`까지 모바일과 그대로 맞췄다. 같은 API를 나중에 소비할 화면이라 어긋나면 곤란하다. 상수 파일은 앱이 다르니 웹 쪽(`onboarding/nickname/_lib/constants.ts`)에 따로 두되 값만 동일하게.

## 검증에서 챙긴 것

입력은 `"use client"` 컨트롤드로 만들어, 비면 테두리가 `border-border`로 돌아가고 안내 문구가 사라지며 "다음"이 `disabled`(opacity-40)로 죽는다. 포커스 땐 `focus-within:border-accent`로 빈 칸도 초록 테두리가 돈다. 데스크톱(1280)에서 시안과 대조하고, 모바일 330px에서 가로 오버플로 0(`scrollWidth == innerWidth`)·겹침 없음을 확인했다. 가운데 카드 한 장이라 다열→1열 같은 재구성이 없어 반응형은 폭만 유연하게 두면 자연히 따라왔다. 다크가 기본이고 라이트는 `data-theme="light"`로 토글해 봐도 색이 전부 토큰으로 자동 전환됐다.
