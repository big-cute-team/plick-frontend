# ADR 0004 — 릴 세부 바텀시트 · 코드 조직 컨벤션(\_lib 분리·절대경로)

- **상태(Status):** Accepted
- **날짜(Date):** 2026-07-09
- **범위:** `apps/mobile` 릴 세부 바텀시트 (KAN-168, PR #17) + 이 과정에서 정비한 코드 조직 컨벤션(타입·상수·유틸 분리, `@/` 절대경로).
- **관련:** [ADR 0003 릴스 화면](0003-reels-screen-and-conventions.md), [ADR 0002 모바일 홈 레이아웃](0002-mobile-home-layout.md), 디자인 토큰은 `@plick/tokens/theme.css`

> ADR 0002·0003처럼 "무엇을 만들었나"보다 **"어떻게 만들었고, 왜 그렇게 했고, 어디서 막혔나"**에 집중한다.
> 전반부는 시트 인터랙션 설계(특히 "칩·제목을 하나의 요소로 움직이기"에 도달한 과정), 후반부는 함께 정비한 **코드 조직 컨벤션**을 다룬다.

---

## 1. 목표와 범위

- 피그마 `V2 기사 세부`(node 75-6)를 재현: 릴 화면에서 **제목·기자 박스나 댓글 아이콘을 탭하면 세부 상자가 밑에서 올라오는** 바텀시트.
- 닫기: **시트 윗부분(기자 줄)을 잡고 아래로 드래그**하거나 **X 버튼** → 내려가며 사라진다.
- 시트 내용: 상단 미디어 영역 위 칩·제목 → 기자 줄(그랩 존) → 본문 → 해시태그·출처 링크 → 댓글(답글 들여쓰기) → 댓글 입력바.

## 2. 시트 개폐·드래그 — motion 상태 머신

라이브러리 없이 CSS `transform` + 포인터 이벤트로 구현. 상태는 `useReelDetailMotion` 훅에 모았다.

- **슬라이드 업/다운**: `translateY(100%) ↔ translateY(0)` 전환. 단, 마운트 직후 바로 `0`을 주면 transition이 안 걸린다 → **rAF 두 번**(첫 페인트에 `100%`를 그린 뒤 다음 프레임에 `shown=true`)으로 애니메이션을 확실히 재생.
- **닫힘 언마운트**: X/드래그로 `shown=false` → `translateY(100%)`로 내려간 뒤 `onTransitionEnd`(transform 완료)에서 `mounted=false`. 애니메이션이 끝나야 DOM에서 빠진다.
- **드래그 판정은 ref로**: `onPointerMove`는 연속 발생하는데, 리렌더 전 state는 stale하다. `draggingRef`·`dragYRef`로 최신값을 읽어 판정(임계 100px 초과 시 닫기). 포인터 캡처(`setPointerCapture`)로 손가락이 그랩 존을 벗어나도 move/up을 계속 받는다.

## 3. 핵심 결정 — 칩·제목을 "하나의 요소로" 시트와 함께 이동

가장 많이 갈아엎은 부분. 요구는 "**제목 태그가 원래 자리에 있다가, 시트가 켜지면 시트 라인을 따라 같이 올라가고, 새 제목이 생기는 게 아니라 그 요소 하나가 움직이는**" 것.

- **v1(폐기):** 시트 상단에 칩·제목 오버레이를 **새로 그림**. → 시트를 끝까지 끌어내리면 뒤 릴의 원래 제목과 겹쳐 **제목이 둘** 보였다.
- **v2(폐기):** 칩·제목을 시트에 붙여 한 몸으로 이동 + 뒤 릴 제목을 `invisible` 처리. → 겹침은 없지만 여전히 "복제 후 숨김"이라 요구("새로 생기지 말고")와 어긋남.
- **v3(채택):** **릴에 원래 있던 칩·제목 요소 그 자체**를 `translateY`로 시트 라인 위 도킹 지점까지 올린다. 새로 그리지 않는다.

v3를 위해 **개폐·드래그 상태를 부모(`ReelsFeed`)로 끌어올려** 시트(`ReelDetailSheet`)와 릴(`ReelItem`)이 같은 `motion`을 공유하게 했다. 두 요소가 같은 타이밍(`SHEET_TRANSITION`)·같은 `dragY`로 움직여야 한 몸으로 보인다.

- **도킹 거리 측정**: 탭 시점에 릴 섹션·제목의 `getBoundingClientRect()`로 "제목 하단이 시트 상단 라인에서 `SHEET_TITLE_GAP`(18px) 위"에 오도록 이동 거리(음수)를 계산(`titleLiftDistance`).
- 시트 높이 비율(`SHEET_HEIGHT_RATIO=0.73`), 갭, 트랜지션을 **상수 단일 출처**로 두어 시트와 제목이 동일 값을 참조.

### 3-1. 버그 두 개 (드래그 중)

1. **제목이 원래 자리 밑으로 내려감** → 놓으면 튕겨 올라옴. 원인: 오프셋 = `lift + dragY`인데 `dragY`가 `|lift|`를 넘으면 양수가 돼 제 위치 아래로 감. **해결: `clampTitleOffset = Math.min(0, lift + dragY)`** — 도킹 지점(위)~원래 자리(0) 사이로만.
2. **드래그하면 상단에 어두운 밴드가 "사진처럼" 떠오름.** 원인: 시트 상단 미디어 스크림이 화면 top에 **고정**돼, 시트·제목이 내려가면 홀로 남았다. 요구는 "그냥 아무 현상도 안 일어나게" → **standalone 스크림 제거**(제목은 릴 자체 배경 + drop-shadow로 가독성 확보). 아무것도 안 뜨는 게 정답이었다.

> 교훈: "떠 있는 별도 레이어"는 이동 유닛과 **같은 transform을 공유하거나 아예 없어야** 한다. 어중간하게 고정돼 있으면 드래그 때 유령처럼 분리돼 보인다.

## 4. 코드 조직 컨벤션 — 타입·상수·유틸 `_lib` 분리

시트 작업 뒤 받은 피드백("상수·타입·유틸이 컴포넌트에 섞여 있다", "각 경로에서 쓰는 걸 전부 따로 분리해라")을 계기로 규칙화하고 앱 전체에 적용했다.

### 4-1. 역할별 파일

컴포넌트 파일에 타입/상수/순수함수를 **인라인으로 두지 않는다.** `_lib`에 역할별로:

| 파일           | 담는 것                                                       |
| -------------- | ------------------------------------------------------------- |
| `types.ts`     | 타입·인터페이스 (여러 컴포넌트 공유·중복 타입은 반드시 여기)  |
| `constants.ts` | 상수·설정값 + BE가 붙어도 유지되는 참조 데이터(팀 레지스트리) |
| `utils.ts`     | 순수 헬퍼 함수 (공용 포맷 유틸은 `app/_lib/format.ts`)        |
| `mock.ts`      | 목데이터(나중에 fetch로 교체될 가짜 데이터) — 상수와 **구분** |
| `useXxx.ts`    | 훅 하나 = 파일 하나                                           |

- 배치: **2개 이상 화면 공용 → `app/_lib/`**, **한 라우트 전용 → 그 라우트의 `_lib/`**(예: `app/reels/_lib/`). 컴포넌트 콜로케이션(ADR 0003 §5-2)과 같은 원칙.
- **`constants` vs `mock` 구분이 핵심**: `TEAMS`(팀 레지스트리)·`STAGE_META`처럼 백엔드가 붙어도 유지되는 참조 상수는 `constants.ts`로, `POSTS`처럼 fetch로 교체될 가짜 데이터는 `mock.ts`로 나눴다. 기존엔 `mock.ts`에 뒤섞여 있었다.
- **예외**: 한 컴포넌트 안에서만 쓰는 자명한 사적 타입(그 컴포넌트 로컬 `IconProps`·`Theme`·`Tab`)은 인라인 허용. 옮기면 오히려 노이즈다.

### 4-2. 실제 이동 예

- 공용 `app/_lib/`: `constants.ts` 신설(`TEAMS`·`TEAM_ORDER`는 mock에서, `STAGE_META`는 format에서), `format.ts`는 포맷 유틸만, `mock.ts`는 목데이터만.
- 홈 `(home)/_lib/`: `types.ts`(두 컴포넌트에 **중복 정의되던 `Filter`** 단일화), `constants.ts`(캐러셀 `CARD_W`·`GAP`).
- 릴스 `reels/_lib/`: `constants.ts`(`SHEET_*`)·`utils.ts`(`titleLiftDistance`·`clampTitleOffset`)·`types.ts`(`ReelDetailMotion`·`TitleMotion`)로 분리, 훅은 `useReelDetailMotion.ts`만 남김. (초기엔 상수+유틸이 섞인 `sheet.ts` 하나였다가 쪼갬)

## 5. `@/` 절대경로 alias

"왜 모든 import가 상대경로냐, alias 설정 안 했냐"는 지적 — 확인하니 **`tsconfig`에 `baseUrl`/`paths`가 아예 없었다**(create-next-app이 보통 넣는 `@/`가 초기 세팅 때 누락). 그래서 전부 `../../_lib/…`였다.

- **각 앱 tsconfig에 개별 설정**(경로 타깃이 앱마다 다르므로 per-app): `apps/mobile`·`apps/web` 모두 `baseUrl: "."` + `"@/*": ["./app/*"]`. → `@/` = 각 앱의 `app/` 디렉터리.
- **전환 규칙**: 부모 탐색(`../`·`../../`)은 `@/…`로, **같은 폴더 형제(`./`)는 그대로**(절대경로로 바꾸면 더 길고 관용에 어긋남). 패키지 import(`next/`·`react`·`@plick/*`)는 불변.
- mobile의 `../` import **52개(17파일)**를 codemod(부모 경로만 골라 앱 루트 기준으로 재작성)로 전환. `@/(home)/_lib/…`처럼 **라우트 그룹 괄호가 든 경로도 정상 해석**됨을 빌드로 확인.
- web은 아직 보일러플레이트(상대경로 0개)라 alias만 세팅.

## 6. 하드원 교훈

### 6-1. Turbopack의 stale HMR 에러 🔴 (재발)

파일을 옮기고/지우는 리팩터링 도중, dev 콘솔에 `Can't resolve './sheet'` 류 에러가 **수백 줄** 떴다. 하지만 **클린 `pnpm build`는 통과**했고 실기 동작도 정상이었다. 편집 중간 상태(예: `sheet.ts`를 참조하던 순간)가 Turbopack에 누적된 것.

> 교훈: **클린 빌드가 소스 오브 트루스**(ADR 0002 §6-1). dev 콘솔 에러가 클린 빌드와 어긋나면 dev 캐시를 의심하고, `.next` 삭제 후 서버 재시작으로 확정한다. (이번에도 재시작하니 에러 0.)

### 6-2. 리팩터링·인프라 변경이 티켓 브랜치에 섞임

KAN-168 브랜치에 시트 퍼블리싱 + `_lib` 분리 + alias 전환 + 문서까지 담겼다. 커밋은 논리 단위로 나눴지만(퍼블리싱/리팩터/alias/docs), 순수 구조 변경·인프라(alias)는 **별도 PR로 분리하는 편이 리뷰에 낫다**. 다음엔 티켓 작업과 전역 리팩터를 브랜치부터 나눈다.

## 7. 검증 방법

- **클린 빌드**: 커밋마다 `pnpm --filter mobile build`(또는 전체 `pnpm build`) + `lint` + `check-types`.
- **실기 렌더**: dev(:3001) 모바일 뷰포트에서 — 시트 개폐(제목/댓글 아이콘·X·드래그), 드래그 중 제목이 원래 자리에서 클램프(밑으로 안 감), 큰 드래그 닫힘/작은 드래그 스냅백. 포인터 이벤트를 스크립트로 주입해 `translateY`·도킹 갭(18px)까지 수치 검증.
- **리팩터 회귀**: `_lib` 분리·alias 전환은 동작 불변이 목표라, 영향 큰 홈(팀 필터·캐러셀)·릴스(시트)를 dev 클린 재시작 후 재확인(콘솔 에러 0).
- **CI**: `Lint · Types · Build` 전 커밋 통과.

## 8. 남은 일

- 릴 세부 상호작용 실제 동작: 댓글 작성/좋아요·답글, 출처 링크, 공유. 현재 입력바·버튼은 표시만.
- 시트 제스처 다듬기: 속도(velocity) 기반 닫기 판정, 스크롤 영역과 그랩 존 제스처 충돌 점검.
- alias·`_lib` 분리 컨벤션은 [`CLAUDE.md`](../../CLAUDE.md) "컨벤션" 섹션에 박제 — 다음 화면부터 처음부터 `@/`·`_lib` 구조로 시작.
- (ADR 0003에서 이어짐) mock 데이터와 피그마 수치 정합성 정리.
