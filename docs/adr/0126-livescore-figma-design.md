# 0126. 라이브 스코어 실디자인 13장을 피그마에 그렸다

## 배경

백엔드에 라이브 스코어가 들어왔다. 컨플루언스에 API 명세([API 명세] 라이브 스코어)와 캐시 설계([설계] 라이브 스코어 캐시)가 올라왔고, 6개 API(경기 목록·경기 상세·선수 경기 스탯·팀 스쿼드·순위표·선수 시즌 스탯)가 전부 dev까지 배포된 상태였다. 로컬 BE의 `MatchController.java`에서도 명세 그대로 6개 엔드포인트를 확인했다.

FE 쪽은 `/live` 탭이 "준비 중" 플레이스홀더만 있는 상태(KAN-435)라, 구현에 들어가기 전에 필요한 지면부터 정리했다. 결론은 화면 3장 + 상세 탭 3개 + 시트 3개에 상태 변형까지 13장이었다. 피그마에 임시 디자인(S1~S6, node 751:2 근처)이 있긴 했는데, 실시간 채팅·뉴스 탭처럼 이번 API 범위에 없는 게 섞여 있고 토큰도 우리 것이 아니라서, 실제 UI 환경(다크 고정, 그린 시그널 토큰, AppShell 크롬)에 맞춘 실디자인을 새로 그리기로 했다.

## 무엇을 그렸나

피그마 Plick 파일의 "제품 디자인" 페이지에 섹션 "LIVE 스코어 · 실디자인"(node 1051:1360)을 만들고 13장을 3줄로 배치했다.

- ① LIVE 탭: L1 경기 목록(라이브·예정·종료·연기 카드 혼합, 날짜 스트립, 대회별 그룹핑), L2 경기 없는 날 빈 상태, L3 순위표(빅6 강조, 챔스권 존 표시, 마이팀 행 하이라이트), L4 외부 API 실패(MATCH_UPSTREAM_ERROR) 에러 상태
- ② 경기 상세: L5 프리뷰(킥오프 전 — 결장자·상대전적·리그 순위·직전 경기 선발), L6 라이브 요약(득점·타임라인), L7 라인업(피치 배치 + 평점 배지 + 벤치), L8 팀 스탯(비교 막대), L9 종료(FT)
- ③ 시트: L10 선수 경기 스탯 바텀시트, L11 팀 스쿼드, L12 선수 시즌 스탯 시트(대회별), L13 무출전 빈 상태

명세의 함정들을 디자인에 미리 박아 뒀다. 직전 경기 선발 카드에는 "예상 라인업이 아니라 직전 경기의 확정 선발"이라는 문구를 명시했고(명세가 FE 표기를 요구), 스탯 탭에는 전반·후반 분리 미제공 안내, 목록·상세에는 20~30초 폴링 안내, 스쿼드에는 이적 반영 지연 안내, 시즌 스탯 무출전은 404가 아니라 빈 배열이라 빈 상태 지면을 따로 뒀다.

## 어떻게 그렸나

use_figma(플러그인 API 실행)로 코드에서 그렸다. 실제 UI 환경을 맞추려고 세 가지를 저장소에서 가져왔다.

- 색·간격·라운드는 `packages/tokens/theme.css`의 다크 토큰 값을 그대로 썼다(bg #0b0d12, elevate rgba(148,163,184,.09), accent #2fd97f, radius-card 16, px-edge 20 등).
- 하단 탭 5종(홈·LIVE·릴스·VS·MY)과 햄버거, 로고 워드마크는 `@plick/ui` icons.tsx·Logo.tsx의 SVG 패스를 `createNodeFromSvg`로 그대로 심었다. 아이콘을 도형으로 다시 그리면 반드시 어긋나서, SVG 원본 임포트가 정답이었다.
- 구단 로고는 피그마 파일에 이미 있던 임시 디자인의 이미지 해시를 재사용했다. 플러그인 API는 외부 URL 이미지를 못 가져오는데, 파일 안에 있는 노드의 `imageHash`는 fills로 복사할 수 있다. 파일 전체에서 IMAGE fill 노드를 긁어 Logo/LIV~MUN 6개 해시를 찾아 크레스트 컴포넌트로 만들었다.

공용 크롬(상태바, 상단바 2종, 탭바, 크레스트 7종)은 로컬 컴포넌트로 만들어 13장에 인스턴스로 깔았다. 종료 화면(L9)과 시트 배경(L10·L12·L13)은 완성된 프레임을 clone해서 칩·문구만 바꾸는 식으로 아꼈다.

## 막힌 곳

- 폰트: 앱은 Pretendard인데 피그마 환경에 없었다. `listAvailableFontsAsync`로 확인하고 Noto Sans KR(Regular·Medium·Bold·Black)로 대체했다. 실제 구현은 어차피 next/font의 Pretendard를 쓰니 디자인 파일의 폰트 대체는 감수했다.
- 컨플루언스 MCP가 두 페이지를 병렬 호출하면 같은 페이지를 두 번 돌려줬다. Redis 문서는 단독 재호출로 받았다.
- 파일의 변수 컬렉션은 html.to.design 임포트 잔재라 바인딩할 만한 토큰 체계가 아니었다. 토큰 정본은 어차피 코드(theme.css)라, 변수 바인딩 대신 hex 직접 지정으로 갔다.

### 구현 전체 흐름

라우트는 셋이다. `/live`(목록, 경기 서브탭)와 `/live/standings`(순위 서브탭), `/live/matches/[matchId]`(상세), `/live/teams/[teamId]`(스쿼드). 서브탭을 URL로 승격하는 건 홈 팀 필터(KAN-350)와 같은 관례다. 날짜는 `/live?date=YYYY-MM-DD` 쿼리로, 없으면 오늘(KST). 선수 시트 둘(L10·L12)은 라우트가 아니라 컴포넌트 상태다.

데이터 레이어는 `api-integration` 스킬 구분을 따른다.

- TanStack Query(폴링 필요): 목록과 상세. `refetchInterval`은 조건부다 — 목록은 응답에 LIVE 경기가 있을 때만 20~30초, 상세는 `header.status === "LIVE"`일 때만(없으면 false). 종료·예정 화면에서 헛폴링하지 않는다.
- 서버 컴포넌트 fetch(단발 읽기): 순위표, 스쿼드. 폴링이 없고 서버 캐시 TTL(1시간·24시간)이 신선도를 보장한다.
- 시트 둘은 열릴 때만 fetch: `useQuery({ enabled: open })`.
- 전부 Anonymous라 인증 배관(mobile-auth-read-plumbing)은 이번 범위에 없다.

배치는 레이어 규칙대로. 타입은 `app/_types/live.ts`(모바일 전용으로 시작 — web 이식이 생기면 ADR 0011 게이트로 `@plick/domain` 승격 판단), fetcher는 `app/_services/`, 쿼리 훅은 `app/_queries/`, 화면 전용 컴포넌트는 `app/live/_components/`에 co-locate. 기존 `live/page.tsx` 플레이스홀더를 교체하면서 noindex 메타도 실콘텐츠 기준으로 다시 쓴다(기존 주석에 예고돼 있다).

### 구현 주의점

명세와 디자인에서 나온 함정들이다. 구현 때 하나씩 대조한다.

- 팀명·선수명은 전부 영문 그대로, 한글은 대회명뿐이다. 번역하려 들지 않는다.
- 로고·사진은 API-Football CDN URL을 FE가 직접 로드한다. 빅6는 기존 `TeamCrest`(로컬 webp)를 쓰고, 빅6 밖 팀과 선수 사진만 CDN을 쓰는 게 디자인 의도다. CDN 이미지는 `next/image` 최적화 없이 img로 가거나 remotePatterns에 `media.api-sports.io`를 추가한다. 로드 실패 폴백은 디자인의 이니셜 제네릭 크레스트.
- `teamId` null = 빅6 아님. 마이팀 강조·스쿼드 진입 가능 여부의 기준이다.
- 킥오프 전 `score`는 null → "-" 표기. `elapsed`도 라이브 아니면 null.
- `statusDetail`로 HT(하프타임)·PEN 등을 표기한다. POSTPONED·CANCELLED 카드 상태가 따로 있다(L1의 연기 카드).
- 스코어 정본은 `header.score`다. `goals` 요약과 어긋나면 score를 믿는다.
- `events`의 `playerName`은 null일 수 있다 — 이름 없는 타임라인 행을 깨지지 않게 렌더한다.
- `stats`의 value는 문자열 혼재("61%", "7", "1.04")다. 막대 비율 계산은 파싱 유틸로 하고, 파싱 실패 시 막대만 생략하고 값은 그대로 보여준다. 전반·후반 분리는 원본에 없다.
- 라인업 `grid`는 "줄:칸" 좌표다(GK가 1줄). 홈은 피치 아래쪽, 어웨이는 위쪽으로 반전해 그린다. grid null = 벤치. `rating` null = 무출전.
- 프리뷰 `lastLineups`는 예상 라인업이 아니라 직전 경기 확정 선발이고, 이 표기를 화면에 명시하는 게 명세 요구사항이다. 상대가 빅6 밖이면 그 팀 것은 아예 없다 — 한 팀만 렌더되는 경우를 처리한다.
- 상세의 각 블록(preview·events·lineups·stats)은 null일 수 있다. 서버가 조각 실패 시 그 조각만 빼고 내리는 구조(Redis 설계)라, 블록별 조건부 렌더가 기본이다.
- 시즌 스탯 무출전은 404가 아니라 `competitions: []`다 → L13 빈 상태.
- 에러 매핑: 400(date 형식) · 404 MATCH_NOT_FOUND/TEAM_NOT_FOUND(빅6 밖 id 포함) → not-found 처리, 502 MATCH_UPSTREAM_ERROR → L4 재시도 UI.
- 날짜 계산은 KST 고정이다. 클라 타임존에 기대지 말고 Intl 기반 KST 유틸로 오늘·날짜 스트립을 만든다.
- 바텀시트는 새로 만들기 전에 기존 시트·스크림 패턴(TopBarMenu 등)을 먼저 뒤져 재사용을 판단한다.
- 평점 색은 디자인 기준 7.5 이상 accent, 미만 warn, null "-"이다.
- 컨벤션 공통: 토큰 유틸만, px-edge, 다크 기준, 서버 컴포넌트 기본, JSDoc, barrel 금지, `@/` 절대경로.

### 실 구현 계획 (스토리 = PR 단위)

각 스토리는 `develop`에서 `feature/KAN-<번호>-<설명>` 브랜치, `/wire-api` 절차(계약 검증은 be-verify 위임), PR은 pr-writing 5절 틀, 세션 ADR 기록까지가 한 사이클이다. 티켓 번호는 각 세션 시작 때 발급하거나 사용자가 준다.

1. 데이터 레이어 + 경기 목록 — L1·L2·L4. GET /matches 배선, `_types/live.ts`·fetcher·`useMatchesQuery`(조건부 폴링), 서브탭·날짜 스트립·MatchCard 4상태, 빈 상태·에러 상태. 가장 크고 이후 스토리의 토대라 먼저 간다.
2. 경기 상세 뼈대 + 프리뷰 + 요약 — L5·L6·L9. GET /matches/{id} 배선, 상태별 화면 분기(SCHEDULED/LIVE/FINISHED), 내부 탭 뼈대, 헤더·득점·타임라인·프리뷰 4블록.
3. 라인업·스탯 탭 + 선수 경기 스탯 시트 — L7·L8·L10. grid 피치 렌더, 스탯 비교 막대, 시트 + GET /matches/{id}/players/{pid}(열릴 때 fetch).
4. 순위표 — L3. GET /standings, `/live/standings` 서버 컴포넌트, 빅6 강조·존 표시. 독립적이라 2·3과 순서를 바꿔도 된다.
5. 스쿼드 + 시즌 스탯 — L11·L12·L13. GET /teams/{id}/squad·/players/{id}/season-stats, 진입점은 순위표 빅6 행(+팀 허브 연결 여부는 이때 결정), 무출전 빈 상태.

범위 밖: 명세의 후속 후보(마이팀 다음 경기 카드, 리그 득점 순위)는 계약 미정이라 뺐다. web(데스크톱) 이식은 모바일 5스토리가 끝난 뒤 `/web-wire-api`로 별도 트랙.
