# 0039. 릴스 화면 디테일 수정 (KAN-299)

KAN-299 티켓으로 릴스 화면의 디테일 다섯 가지를 손봤다. 저장 아이콘 제거, 팀태그를 구단 로고
이미지로 교체, 루머 단계에 CONFIRM 타입 선반영, 루머 단계를 칩 배경 없이 글자만으로, 그리고
좌측 정보 블록 위치와 하단 스크림 범위 조정이다.

## 브랜치를 다시 판 이야기

사실 이 작업은 한 번 엎었다. 처음에 develop 위에서 바로 코드를 고쳐 두고 커밋을 안 한 상태로
세션이 끝났는데, 다음 세션에서 "develop 기준으로 새 브랜치 파서 처음부터 다시 적용해 달라"는
피드백을 받았다. 우리 규칙상 develop에 직접 커밋하면 안 되는데, 작업 트리가 develop 위에 그대로
얹혀 있으니 이대로 커밋하면 브랜치 이력이 지저분해질 판이었다.

그래서 기존 변경분을 `git stash push -u`로 통째로 백업해 두고(untracked인 새 파일까지 `-u`로
포함), develop에서 `feature/KAN-299-reels-detail-fixes` 브랜치를 새로 판 다음, 티켓 항목
순서대로 커밋을 쪼개서 다시 적용했다. stash는 삭제가 아니라 보관이라 혹시 빠뜨린 게 있으면
꺼내 볼 수 있다. 결과적으로 티켓 항목 하나가 커밋 하나로 대응돼 리뷰어가 항목별로 따라가기
쉬워졌다.

## 1. 저장 아이콘 제거

우측 액션 레일(ReelActionRail)에서 저장 버튼을 뺐다. KAN-276 때부터 저장 여부는 BE 계약에
아예 없어서 항상 빈 아이콘으로만 그려지던 자리였다. 계약에 없는 기능을 UI만 먼저 두는 건
사용자를 속이는 셈이라 티켓에서 빼기로 결정했고, 아이콘 import와 버튼 한 줄을 걷어냈다.

## 2·4. 팀태그 로고 + 배경 없는 단계 글자 — ReelBadges

원래 릴 하단에는 PostChips가 팀 이름과 루머 단계를 알약 모양 텍스트 칩 두 개로 그렸다.
티켓은 팀태그를 실제 구단 로고 이미지로 바꾸고, 루머 단계는 버튼처럼 보이는 알약 배경을
걷어내고 로고 우측에 글자만 남기라고 했다.

이 둘은 한 컴포넌트 교체로 묶인다. 릴 전용 `ReelBadges`를 새로 만들어 `TeamCrest`(실제 구단
로고 webp를 그리는 공용 컴포넌트)와 단계 글자를 나란히 그리게 했고, ReelItem에서 PostChips를
이걸로 갈아 끼웠다. 기사 세부 화면은 여전히 PostChips를 쓴다. 릴은 사진 위라 로고가 잘 어울리고,
세부는 서피스 배경 위 텍스트 칩이 맞아서 두 표현을 분리해 두는 게 낫다고 봤다.

단계 글자색은 PostChips의 칩 글자색 매핑(RUMOUR=accent, IN_PROGRESS=warn, OFFICIAL=info)을
그대로 따라가 두 화면의 색 언어가 어긋나지 않게 했다. 매핑을 공용으로 뽑을까 잠깐 고민했지만,
칩은 배경·테두리까지 세트고 릴은 글자색 하나라 공유할 면적이 작아 각자 두는 쪽으로 정리했다.

## 3. CONFIRM 단계 선반영

루머 단계에 CONFIRM 타입을 추가했다. 주의할 점은 이게 BE에 아직 없는 예정 단계라는 것이다.
BE enum과 DB에는 RUMOR·IN_PROGRESS·OFFICIAL만 있고 CONFIRM은 나중에 들어온다. 그래서 FE는
타입만 미리 넓혀 두는 선반영이다.

건드린 곳이 네 군데다. 도메인 타입(`RumorStage`)에 리터럴 추가, `STAGE_META`에 라벨 추가,
PostChips의 `PostStage`(ui는 domain에 의존하지 않아 리터럴을 별도 선언한다)와 칩 스펙 추가,
그리고 모바일 `STAGE_BY_BE_VALUE` 매핑 테이블에 `CONFIRM: "CONFIRM"` 한 줄. 마지막 매핑이
빠지면 BE가 CONFIRM을 내려보내기 시작해도 모르는 값으로 취급돼 null로 떨어지고 배지가 안
그려진다. 이 테이블은 원래 BE의 미국식 `RUMOR`를 영국식 `RUMOUR`로 바꾸려고 있는 건데,
모르는 값을 조용히 버리는 안전망 역할도 겸해서 새 단계는 여기 등록해 줘야 통과한다.

CONFIRM의 색 스펙은 아직 디자인에서 안 나왔다. 일단 accent(초록)를 빌려 쓰고 주석으로
남겨 뒀다. 스펙이 나오면 칩 클래스와 ReelBadges 글자색 두 곳만 바꾸면 된다.

## 5. 좌측 요소 위치와 스크림 범위

티켓의 마지막 항목은 두 가지였다. 우측 아이콘 레일은 그대로 두고 좌측 요소(배지·제목·기자
줄)만 살짝 아래로, 그리고 하단 음영(스크림)은 팀 로고·루머 단계 줄까지만 어둡게.

위치는 정보 블록의 `pb-27`을 `pb-22`로 줄여 해결했다. 우측 레일은 `bottom-27`로 자기 좌표를
따로 가지고 있어서 안 움직인다. 좌측만 20px쯤 내려와 화면 하단에 더 붙는다.

스크림은 원래 릴 높이의 60%까지 올라오는 그라데이션이었는데, 배지 줄이 로고 이미지로 바뀌면서
그 위까지 어두울 필요가 없어졌다. 높이를 42%로 줄이고 그라데이션 정지점도 다시 잡았다.
기존은 98% → 82%(42% 지점) → 45%(66% 지점) → 투명으로 완만하게 빠졌는데, 새 버전은
98% → 88%(55% 지점) → 55%(80% 지점) → 투명으로, 배지 줄까지는 진하게 유지하다가 그 위에서
빠르게 사라진다. 어두운 면적은 줄었지만 글자가 앉는 구간의 농도는 오히려 올라가 가독성은
유지된다. 시트가 열릴 때 제목과 같은 translateY로 따라 올라가는 동작은 그대로다.

`pnpm check-types`와 `pnpm --filter mobile build` 클린 빌드를 통과했고, dev 서버(:3001)를
모바일 뷰포트(375x812)로 띄워 릴스 화면을 눈으로 확인했다. 저장 아이콘이 빠진 3버튼 레일,
아스날 로고 옆 파란 OFFICIAL 글자, 배지 줄까지만 닿는 스크림이 의도대로 나왔고 콘솔 에러는
없었다.
