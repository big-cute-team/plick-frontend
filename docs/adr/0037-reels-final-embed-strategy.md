# 0037. 릴스 최종 임베딩 전략 — 통일 배경·정적 뒤 레이어·도킹 스크림 (KAN-296)

## 배경

KAN-284([ADR 0035](0035-null-photo-tweet-embed-fallback.md))에서 사진이 null인 릴에 원문 트윗을
임베드로 붙였다. 그때는 "사진 자리를 대신한다"는 관점이라, 트윗 카드를 박스에 가두고 넘치면
`useTweetFit`으로 사진(미디어)을 숨겨 전문 텍스트를 살리는 식이었다. X Display Requirements가 본문
수정을 금지해서 나온 고육지책이었다.

KAN-296은 이 임베딩을 "최종" 형태로 정리하는 티켓이다. 티켓 본문은 세 가지를 요구했다.

1. 릴스의 모든 배경색을 통일한다. 다크면 `#151E26`, 라이트면 `#FFFFFF`.
2. 릴 맨 위부터 태그(칩) 윗선까지를 영역으로 삼아, 임베드 카드가 그 영역보다 크면 위에 붙이고
   작으면 세로 가운데 정렬한다. 가로는 꽉 채운다.
3. 제목과 우측 아이콘 뒤에 가독성용 어두운 음영을 넣는다.

그런데 막상 붙여 보니 티켓 문장만으로는 안 잡히는 지점이 많았고, 사용자가 화면을 보면서 준 피드백이
방향을 여러 번 틀었다. 그 과정을 그대로 남긴다.

## 시작은 엉뚱한 데서 — react-tweet가 안 깔려 있었다

작업 들어가기 직전에 `Module not found: Can't resolve 'react-tweet'`가 떴다. 원인은 단순했다.
`react-tweet`가 `apps/mobile/package.json`엔 있는데(KAN-284 때 추가) 로컬 `node_modules`엔 없었다.
그 브랜치를 pull한 뒤 `pnpm install`을 안 돌렸던 거다. 설치 한 번으로 끝났다. 코드 문제가 아니라
환경 문제였다.

## 배경색 통일 — 새 토큰을 판다

배경을 단색으로 통일하라는 건 명확했다. 다크 `#151E26`은 기존 `--plk-bg`(#0b0d12)와도, 미디어
배경 `--plk-media-bg`와도 다른 값이라 새 토큰이 필요했다. `packages/tokens/theme.css`에
`--plk-reel-bg`를 다크 `#151E26`, 라이트 `#FFFFFF`로 넣고 `@theme inline`에 `--color-reel-bg`를
매핑해 `bg-reel-bg` 유틸을 만들었다. 하드코딩 hex를 화면에 박지 않는 게 이 저장소 규칙이라 토큰을
먼저 판다.

여기서 사용자가 하나 더 얹었다. "임베딩 배경과 릴스 전체 배경색을 똑같이 해줘. 다크·라이트 둘 다."
트윗 카드(react-tweet의 `.react-tweet-theme`)는 자체 배경색(`--tweet-bg-color`)을 갖는데, 이걸
릴 배경과 같은 `--plk-reel-bg`로 맞춰 카드가 바탕과 한 색으로 이어지고 테두리만 남게 했다.
`globals.css`에 `.reel-embed .react-tweet-theme.react-tweet-theme` 선택자로 덮었다. 클래스를
두 겹 겹친 건 라이브러리 theme.css의 라이트/다크 선택자를 특이도로 이기기 위해서다(KAN-284 때
쓴 것과 같은 트릭). 기사 상세(flow 임베드)는 일반 페이지 배경(`--plk-bg`) 위라 그대로 두고,
릴 안(`.reel-embed`)에서만 배경을 갈아끼웠다.

## 진짜 문제 — "이미지가 안 떠"

배경을 갈고 임베드를 `layout="flow"`로 바꿔 붙였는데 사용자가 "이미지가 안 떠 여전히"라고 했다.
여기서 이 티켓의 핵심을 뒤늦게 이해했다. `flow`도 `fill`도 카드가 상한을 넘으면 `withoutMedia`로
트윗의 사진을 빼 버린다. 릴 트윗은 대개 사진이 크고 카드가 길어서, 결국 항상 사진이 빠진 채
텍스트만 남았다. 사용자가 말한 "이미지"는 릴 배경 사진(imageUrl, BE에선 전부 null)이 아니라
트윗 안의 사진이었다.

그러니까 "최종 임베딩 전략"은 사진을 숨기던 걸 그만두는 거였다. 티켓 2번의 "크면 위에 붙이고"가
바로 그 얘기다. 사진을 빼서 영역에 욱여넣는 대신, 사진째 원본 크기로 보여주고 영역보다 크면 위에
붙여 넘치는 건 그냥 뒤로 흘려보낸다. 그래서 `TweetEmbed`에 `layout="reel"`을 새로 만들었다.
미디어를 숨기지도 축소하지도 않고 `EmbeddedTweet`를 자연 높이·전폭으로 그대로 세운다.
전문을 다 담으려 사진을 빼던 flow/fill과 정반대 방향이다.

`useTweetFit`(스케일·미디어 숨김 훅)은 릴에서 손을 뗐다. 홈 핫이슈 카드(HotHeroCard)가 아직
`fill`을 쓰므로 훅 자체는 남겨 뒀다.

## 정렬 — safe center 한 줄

티켓 2번의 "크면 위, 작으면 가운데"는 CSS `justify-content: safe center` 한 줄로 떨어졌다.
`safe`는 콘텐츠가 컨테이너보다 크면 가운데 정렬 대신 시작(위)으로 붙는 오버플로 정렬 키워드다.
정확히 요구사항이다. 영역 아래선은 "칩 윗선까지"라 정보 블록 높이를 ResizeObserver로 재서
`bottom`에 넣었다. 제목이 1~3줄로 자라면 블록이 커지고 영역이 그만큼 줄어든다.

## 사진이 있으면 사진을 — MediaThumb를 걷어냈다

사용자가 "모든 릴스에 사진이 있으면 사진이 보이게 해줘"라고 했다. 기존 릴은 `MediaThumb`(팀 컬러
그라데이션 + 옵셔널 img)로 배경을 깔았는데, 배경을 단색으로 통일하는 이상 팀 그라데이션은 걷어내야
했다. 그래서 릴에서 `MediaThumb`를 떼고, 섹션 자체를 `bg-reel-bg`로 깐 뒤 `imageUrl`이 있으면
그 위에 `<img>`를 풀 커버로 얹고, 없으면 트윗 임베드를 놓는 구조로 바꿨다. BE 실데이터의 imageUrl은
아직 전부 null이라 실제로는 늘 임베드가 뜨지만, 사진이 오면 사진이 우선한다.

`<img>`를 직접 쓰니 `@next/next/no-img-element` 린트 경고가 떴다. `MediaThumb`는 `@plick/ui`
패키지라 린트 설정이 달라 경고가 없었는데, 앱 안에서 직접 `<img>`를 쓰면 걸린다. 릴 이미지 호스트가
유동이라 next/image를 못 쓰는 건 `MediaThumb`와 같은 사정이라, 같은 이유를 달아
`eslint-disable-next-line`로 껐다.

## 애니메이션 빼고, 자르지 말고

여기서 피드백이 또 왔다. "임베딩 컴포넌트에 애니메이션 적용돼 있는데 없애줘. 그냥 뜨게 해줘.
그리고 컴포넌트가 태그 윗부분으로 잘려버리는데, 자기 크기만큼 다 차지하게 해줘. 뒤에 겹쳐도 되니까."

두 가지였다.

- 애니메이션 제거: 시트 개폐에 맞춰 임베드 영역 높이를 트랜지션시키던 `SHEET_MEDIA_TRANSITION`을
  통째로 걷어냈다(상수도 삭제). 이제 임베드는 그냥 뜬다.
- 클립 제거: 영역에 걸어 둔 `overflow-hidden`을 뺐다. 카드가 영역보다 크면 잘리는 대신 자기 높이만큼
  그대로 서서 칩·제목 뒤로 흘러넘친다. 섹션 자체에 `overflow-hidden`이 있어 옆 릴로 새는 건 막힌다.

## 우측 아이콘 스크림 — 방사형으로 다시

티켓 3번의 "우측 아이콘 뒤 음영"은 처음엔 KAN-284 때처럼 `inset-y-0`로 오른쪽 전체 높이에 가로
그라데이션을 깔았다. 사용자가 "우측 아이콘 뭉치의 음영이 맨 꼭대기까지 처리되는데, 맨 아래부터 딱
아이콘 뭉치까지만 자연스럽게, 상당히 어둡게" 해 달라고 했다.

아이콘 레일(ReelActionRail)의 위치를 브라우저에서 직접 쟀다. 뭉치가 릴 바닥에서 210px~471px
구간에 있었다. 그래서 우하단(100% 100%) 앵커의 방사형 그라데이션으로 바꿨다. 바닥 코너에서
아이콘 뭉치 위까지만 어둡고 그 위로는 투명으로 사라진다. 처음엔 페이드가 너무 빨라 맨 위 아이콘
(하트)이 밝은 트윗 사진 위에서 안 받쳐졌다. 세로 반지름과 정지점을 아이콘 뭉치 끝까지 닿게 키워
뭉치 전체가 어둡게 깔리도록 맞췄다.

## 결정적 전환 — "임베드는 맨 뒤 고정 레이어"

시트를 열어 보니 도킹된 제목이 정적 임베드의 트윗 텍스트 위에 그냥 겹쳐 지저분했다. 나는 이걸
문제로 보고, 시트가 열리면 임베드를 아예 감추는 쪽으로 손봤다. 그랬더니 사용자가 방향을 명확히
잡아 줬다.

"제목과 트위터 임베드 카드가 같은 레이어에 있는 느낌이 아니라, 임베드가 뒤에 있는 느낌으로 해줘.
디테일 패널이 열려도 뒤의 컴포넌트는 아무 일도 안 일어나는 느낌이어야 해. 지금은 패널이 열리면
임베드 카드 높이가 짧아지는데, 임베드는 그런 영향을 안 받는 맨 뒤 레이어여야 해."

그러니까 겹치는 건 문제가 아니라 의도였다. 임베드는 배경, 제목과 시트는 그 위를 덮는 앞 레이어다.
서로 다른 층으로 읽히는 게 목표다. 그래서 임베드에서 시트 관련 분기를 전부 걷어냈다. `titleMotion`에
따라 높이를 줄이던 것도, 감추던 것도 다 뺐다. 임베드는 늘 `bottom: infoHeight`로 제자리에 고정이고,
`infoHeight`는 제목이 translateY로 떠도(트랜스폼은 offsetHeight에 안 잡힌다) 안 변하니 진짜로
아무 반응을 안 한다. 시트가 위를 슬라이드로 덮고, 제목이 위로 도킹될 뿐이다.

측정도 정보 블록 높이 하나로 줄었다. 시트용으로 재던 섹션 높이(`sectionHeight`)는 필요가 없어져
지웠다.

## 마지막 손질 — 스크림을 세게, 제목과 함께 올리기

"제목과 아이콘 뒤 음영이 더 강했으면 좋겠어. 그리고 디테일 패널을 열었을 땐 제목 뒤 음영이 제목과
같이 올라갔으면 좋겠어."

두 가지를 반영했다.

- 세기: 우측 방사형과 하단 선형 스크림의 정지점 알파를 전반적으로 올리고 하단 스크림 높이를
  60%로 키웠다. 라이트(흰 배경)에서 흰 글자가 읽히려면 어차피 이 고정 다크 스크림에 기대야 해서
  더 진해도 손해가 없다.
- 함께 올리기: 하단 제목 스크림에 제목 블록과 똑같은 `translateY(titleMotion.offset)`와 같은
  트랜지션을 걸었다. 시트가 열려 제목이 도킹 지점까지 올라가면 스크림도 같은 거리·같은 타이밍으로
  따라 올라가 도킹된 제목 뒤를 그대로 받친다. 정적인 임베드는 그 아래에서 스크림에 덮여 어둑하게
  깔리고, 제목만 또렷하게 뜬다. 앞뒤 레이어가 확실히 갈린다.

## 우측 아이콘 배경을 다시 갈아엎다 — 방사형 스크림을 접고 검은 알약으로

강하게 만든 우측 방사형 스크림을 보고 사용자가 "음영처리가 좀 더럽다"고 했다. 요청은 셋이었다.
제목 뒤 음영은 그대로 두고, 우측 아이콘 패널을 아래로 내려 밑선을 제목(정확히는 기자 이름 줄)에
맞추고, 우측은 그라데이션 음영이 아니라 아이콘 뭉치 배경에만 검은색을 자연스럽게 깔라는 거였다.

그래서 릴 전체에 깔던 우측 방사형 스크림을 통째로 지웠다. 대신 액션 레일(ReelActionRail) 안에
아이콘 뭉치를 감싸는 배경 알약을 하나 넣었다. 처음엔 흐릿하게 비치는(blur) 반투명 스크림으로
했는데, 사용자가 "음영 말고 아예 대비되는 불투명한 검은 배경으로 넣어 달라"고 해서 blur를 빼고
불투명한 검은(스크림색) 알약으로 바꿨다.

여기서 쌓는 순서 문제를 만났다. 알약을 레일의 첫 자식으로 넣었는데 아이콘들을 덮어 버렸다.
position 있는 요소(absolute 알약)가 static인 형제(아이콘 버튼들)보다 위에 그려지는 CSS 페인팅
규칙 때문이다. `-z-10`을 줘서 아이콘 뒤로 보냈다. 레일 컨테이너에 `drop-shadow`(필터)가 걸려
stacking context가 만들어져 있어서, 음수 z여도 릴 배경 뒤로까지는 안 빠지고 레일 안에서만 뒤로
간다. 그 덕에 안전하게 아이콘 뒤에 깔렸다.

그다음 "너무 검다, 70%쯤으로 투명도 살짝 높여라" → `color-mix`로 스크림 70%. "밑 얼라인을 기자
이름까지 내려라" → 기자 줄 바닥을 브라우저에서 재(릴 바닥 108px) 레일 `bottom`을 거기 맞췄다.
"배경을 더 작게" → 알약 inset과 라운드를 줄여 아이콘에 더 붙게 했다.

## 트윗 본문 글자 줄이기

"트위터 임베드 글자 크기를 좀 줄일 수 있나?" react-tweet은 폰트 크기용 CSS 변수를 안 내주고,
본문은 rem이라 컨테이너에 `font-size`를 줘도 안 줄어든다(theme를 13px로 낮춰도 본문은 20px 그대로,
실측). 그래서 본문 `<p>`를 클래스 부분일치(`p[class*="tweet-body-module"]`)로 잡아 globals.css에서
`font-size`를 직접 줄였다(값은 이후 사용자가 0.8rem으로 더 낮췄다). 앞서 "더 보기" 때 CSS의
`line-clamp: var()`가 Lightning CSS에서 안 먹던 것과 달리, 이건 평범한 `font-size` 값이라 전역
규칙으로 잘 붙었다.

## 임베드 영역 아래선을 태그 아래(제목 위)로

임베드가 태그 윗선에서 끊기던 걸, 사용자가 "제목·아이콘에 이미 가독성용 어두운 배경이 있으니 태그
위로 높이를 제한할 필요 없다, 태그까지 영역에 포함해 제목 바로 위까지로 최대 제한을 넣어라"고 했다.
그래서 영역 아래선을 정보 블록 top(=칩 윗선)이 아니라 제목(헤드라인) 버튼의 top으로 바꿔 쟀다.
이제 임베드가 태그(칩) 뒤로도 겹쳐 내려오고 제목 바로 위에서 멈춘다. 측정은 `getBoundingClientRect`
차(섹션 바닥 − 제목 top)로 하되, 시트가 떠 제목이 translateY로 올라가 있는 동안은 재지 않는다 —
임베드는 고정 뒤 레이어라 시트에 반응하면 안 되고, transform은 rect에 잡히기 때문이다.

## 잠깐 갔다가 접은 길 — 사진 트윗의 "더 보기"

중간에 "사진 있는 게시물에 본문이 세 줄 넘으면 X의 Show more처럼 '더 보기'로 줄이자"는 요청이
있어 한 번 만들었다. react-tweet 본문 `<p>`를 클래스 부분일치로 찾아 `-webkit-line-clamp`로 줄이고,
실제로 잘렸을 때만 "더 보기"를 마지막 줄에 겹쳐 띄워 누르면 펴지게 했다. 전역 CSS 규칙으로는
Tailwind(Lightning CSS)가 `line-clamp: var()`를 흘려 안 먹길래 인라인 스타일로 직접 걸어 동작까지
확인했다. 그런데 곧바로 사용자가 "그냥 취소하고 모든 글이 다 보이게 해"라고 해서 이 부분은
통째로 되돌렸다. 릴 임베드는 다시 전문을 그대로 보여준다. 기록만 남긴다.

## 검증

BE(localhost:8080)가 떠 있어 실제 릴 데이터로 확인했다. 다크·라이트 둘 다 봤고(라이트는 흰
배경 + 고정 다크 스크림으로 흰 글자가 읽힌다), 시트를 열고 닫으며 임베드가 정말 안 움직이는지,
제목 스크림이 제목과 함께 오르내리는지 봤다.

Turbopack dev 서버가 HMR을 여러 번 거치며 컴파일 캐시가 꼬여 지운 상수(`SHEET_MEDIA_TRANSITION`)를
계속 참조하는 스테일 청크를 물고 있었다. 소스는 깨끗한데 콘솔에만 옛 에러가 쌓였다. `.next`를 지우고
서버를 다시 띄워도 한동안 남아서, 결국 DOM을 직접 읽어 현재 렌더가 맞는지 확인하고 넘어갔다.
클린 프로덕션 빌드는 처음부터 통과했으니 실제 코드 문제는 아니었다. dev 증분 캐시에 속지 말라는
교훈을 또 한 번 얻었다.

format:check, lint, check-types, build 전부 통과했다.
