# 0117. KAN-435 — 토론·투표를 VS로 리브랜딩하고 기사 탭을 LIVE로 교체

## 무엇을 했나

티켓은 두 줄짜리였다. 하나, UI에서 토론·투표라는 워딩을 전부 VS로 바꾼다. 둘, 모바일 하단
탭의 기사 자리를 LIVE(라이브 스코어, 아직 준비 중)로 바꾸고 웹은 내브바에 LIVE를 추가만
한다(기사는 유지).

간단해 보였는데 막상 시작하니 "전부"의 범위를 정하는 게 일이었다. 그래서 먼저 apps와
packages를 통째로 훑어 토론·투표가 들어간 자리를 전수 조사했다. 렌더링되는 문자열, metadata
title, aria-label, SEO description까지 스무 곳 남짓 나왔고, 나머지 수십 곳은 코드 주석이었다.
주석은 손대지 않기로 했다. 주석 속 "토론"은 기능 설명이지 사용자에게 보이는 워딩이 아니고,
KAN-418 같은 과거 맥락을 지우면 오히려 역사를 읽기 어려워진다.

## 워딩 교체의 기준

기계적으로 치환하면 한국어가 무너지는 자리가 있었다. "투표는 로그인한 사용자만 할 수
있어요"를 "VS는 로그인한…"으로 바꿀 수는 없다. 그래서 기준을 하나 세웠다. 기능의 이름으로
쓰인 토론·투표는 VS로 바꾸고, 투표라는 행위 자체를 가리키는 자리는 참여·선택으로
풀어쓴다. 이렇게 하면 화면에서 토론·투표라는 단어 자체가 사라지면서도 문장이 자연스럽다.

- 탭·GNB 라벨, 페이지 title, h1: 토론 → VS
- "지금 뜨거운 투표" → "지금 뜨거운 VS", "아직 열린 토론이 없어요" → "아직 열린 VS가 없어요"
- "투표는 로그인한 사용자만" → "VS 참여는 로그인한 사용자만"
- VoteCard 메타 라인: "N명 투표" → "N명 참여", "투표하면 결과가 열려요" → "참여하면 결과가
  열려요", "내 투표 반영됨" → "내 선택 반영됨"
- 릴 배지 칩 "토론 중" → "VS 진행 중"
- SEO description(`PAGE_DESCRIPTIONS.debates`)도 같은 결로 다시 썼다. 이건 도메인 패키지라
  web·mobile이 동시에 바뀐다.

라우트 이름(`/debates`)과 컴포넌트 이름(DebatesScreen, VoteCard 등), 쿼리키, 서버 액션은
그대로 뒀다. 워딩 티켓이 코드 식별자까지 요구한다고 보지 않았고, BE 엔드포인트가
`/api/v1/debates/…`인 이상 코드가 debate를 말하는 건 자연스럽다. URL을 바꾸면 사이트맵과
canonical, 웹·모바일 상호 alternate까지 연쇄로 밀리는데 그 비용을 워딩 티켓에서 낼 이유가
없었다.

## 아이콘 두 개를 새로 그렸다

하단 탭 아이콘도 VS로 바꾸라는 항목이 있어서 `@plick/ui` 아이콘 레지스트리의 DebateIcon
(말풍선)을 VsIcon으로 교체했다. 피그마 시안이 없는 교체라, NewsIcon·DebateIcon을 만들 때와
같은 방식으로 하단 탭 세트의 기하(24 그리드, 1.8 스트로크, currentColor)에 맞춰 직접 그렸다.
V는 직선 두 획이라 쉬운데 S가 문제였다. 스트로크 아이콘에서 글자 S는 베지어 곡선을 손으로
쳐야 해서, c 커맨드의 상대 좌표를 종이에 그려가며 끝점을 추적해 맞췄다. 렌더해 보니 탭
크기(22px)에서 VS로 읽힌다.

LIVE 아이콘은 방송 전파 모양(가운데 점 + 좌우 호 두 겹)으로 그렸다. 점만 fill이고 나머지는
스트로크라 MoreIcon처럼 fill·stroke를 섞었다. 신문 모양 NewsIcon은 이제 아무도 안 써서
지웠다. 죽은 export를 남기면 다음 감사(/audit)에서 걸릴 자리다.

## 기사 탭을 빼면서 딸려 나온 것들

기사 탭을 TABS에서 빼고 나니 TabBar에 기사 탭 전용 장치가 두 개 고아로 남았다.

하나는 `articlesHref` — 기사 탭의 목적지를 마지막으로 보던 팀 URL로 바꿔주던 코드(KAN-386)다.
또 하나는 Tab 타입의 `surface` 필드 — 기사 세부(`/articles/123`)에서 탭이 활성으로 빛나되
재탭(맨 위 + 새로고침)은 되지 않게 판정을 좁히던 장치인데, 쓰는 탭이 기사뿐이었다. 둘 다
걷어냈다. 단 view-state 스토어의 `articlesFilter`와 `useArticlesRefresh`, ScreenKey의
"articles"는 남겼다 — 기사 라우트 자체는 살아 있고(홈 피드와 VS 카드가 기사 상세로 링크한다)
기사 목록 화면의 당겨서 새로고침과 위치 복원이 계속 쓴다. 탭이라는 진입점만 사라진 것이지
화면이 사라진 게 아니다.

TopBarMenu(상단 햄버거)는 TABS를 그대로 읽어서 따로 손댈 게 없었다. 두 자리가 같은 목록을
보게 해 둔 KAN-297의 결정이 여기서 공짜로 회수됐다.

## LIVE 준비 중 화면

`/live` 라우트를 양쪽 앱에 만들었다. 라이브 스코어가 들어올 자리인데 지금은 준비 중 안내만
그린다. 모바일은 AppShell + TopBar + TabBar 뼈대에 남은 높이 가운데로 아이콘과 안내 문구를
띄웠고, 웹은 토론 리스트와 같은 GNB + 중앙 단일 컬럼(max-w-read) 뼈대에 h1과 안내 블록을
넣었다. 문구는 저장소의 빈 상태 관용(`text-body text-text-4 text-center`)을 따랐다.

메타데이터는 고민 끝에 `robots: { index: false }`만 달았다. 내용이 없는 페이지를 색인시키면
빈 스니펫이 잡히고, 준비 중 문구가 구글에 박제되면 콘텐츠가 들어온 뒤에도 한동안 그 스니펫이
따라다닌다. 사이트맵에도 넣지 않았다. 라이브 스코어가 실제로 붙는 시점에 description과
canonical, 모바일 alternate, 사이트맵 등재를 한 번에 하면 된다.

## 후속 피드백 — 부제는 투표로 되돌렸다

리스트 부제 "VS에 참여하고 팬들의 여론을 확인해보세요"는 피드백을 받아 "투표에 참여하고
팬들의 여론을 확인해보세요"로 바꿨다. 제목이 이미 VS인데 부제까지 VS로 시작하니 같은 단어가
두 줄 연달아 나왔고, 여기서의 투표는 기능 이름이 아니라 행위라 원래 세운 기준으로도 남길 수
있는 자리였다. VS는 이름에만 쓰고 행위 설명은 자연스러운 한국어로 둔다.

## 검증

lint, check-types, 양 앱 클린 빌드 통과. dev 서버를 모바일 뷰포트(375)로 띄워 /live의 준비 중
화면과 탭바(홈·LIVE·릴스·VS·MY), /debates의 새 워딩을 눈으로 확인했다. 웹은 1280에서 GNB
(홈·릴스·기사·LIVE·VS·MY)와 /live, /debates를 보고, 330px까지 줄여 가로 오버플로
0(scrollWidth == innerWidth)을 확인했다. 새 페이지가 정적이라 깨질 게 별로 없긴 했다.

## 남긴 것

- 라이브 스코어 본 기능. BE 계약이 생기면 `/live` 자리에 붙인다. 그때 색인 신호도 되살린다.
- 아이콘 두 개는 피그마 시안 없이 그린 것이라, 디자인 시안이 나오면 노드 벡터로 교체할 수
  있다(NewsIcon·DebateIcon 때와 같은 전제).
