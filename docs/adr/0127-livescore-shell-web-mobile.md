# 0127. 라이브 스코어 껍데기를 웹·모바일 양쪽에 다 깔았다 (KAN-446)

## 배경

지난 세션(ADR 0126)에서 라이브 스코어 모바일 실디자인 13장을 피그마에 그려 뒀다. 이번 세션의 목표는 그 디자인대로 껍데기(목데이터 퍼블리싱)를 전부 깔아 두고, 다음 세션부터 `/wire-api`로 실제 API를 스토리 단위로 붙이는 것이었다.

그런데 시작하자마자 문제가 하나 보였다. 모바일 디자인만 있고 웹(데스크톱) 디자인이 없었다. 웹 GNB에는 이미 LIVE 링크가 있는데(`NAV_LINKS`), `/live`는 "준비 중" 플레이스홀더였다. 사용자와 정리한 진행 순서는 이랬다. 먼저 웹 실디자인을 피그마에 우리 스타일로 그리고, 그걸 기준으로 웹·모바일 둘 다 퍼블리싱한다. 웹 레이아웃은 모바일 미러링이 아니라 2컬럼 대시보드로 가고, 티켓은 KAN-446을 새로 발급했고, PR은 하나로 묶기로 했다.

## 웹 실디자인 7장을 피그마에 그렸다

포트폴리오 피그마 파일의 plick 페이지에는 모바일 13장 섹션 말고도 KAN-200 때 만든 "PLickWeb — 데스크톱" 섹션이 있었다. 프레임이 864px 폭인데, 이건 1920 뷰포트를 0.45 배율로 줄인 규격이다(web-publishing 스킬에 있는 그 0.45다). 새 섹션 "LIVE 스코어 · 웹 실디자인"을 옆에 만들고 같은 규격으로 7장을 그렸다.

- LW1 라이브 · 경기일: 2컬럼 대시보드. 좌측에 날짜 스트립 + 대회 그룹 + 경기 카드 4상태, 우측 레일에 순위표 13행. 데스크톱은 순위를 별도 지면으로 빼지 않고 항상 옆에 둔다.
- LW2 경기 없는 날 / LW3 불러오기 실패: LW1의 좌측 컬럼만 빈 상태·에러 상태로 바꾼 변형.
- LW4 경기 상세 · 라이브: 모바일의 요약/라인업/스탯 탭을 데스크톱에선 탭 없이 다 펼쳤다. 좌측에 득점·타임라인·라인업(피치), 우측 레일에 경기 스탯 비교 막대.
- LW5 경기 상세 · 프리뷰: 결장자·상대전적(좌) + 리그 순위·직전 선발(우 레일).
- LW6 팀 스쿼드: 포지션 그룹 2컬럼 그리드.
- LW7 선수 시즌 스탯 모달: 모바일의 바텀시트 지면을 데스크톱에선 중앙 모달로 바꿨다. 스쿼드 위에 스크림 + 센터 다이얼로그.

그리는 방식은 0126 때와 같이 use_figma(플러그인 API)로 코드에서 그렸고, 몇 가지 요령이 추가로 쌓였다.

- 기존 W1 홈 프레임을 `clone()`해서 GNB(로고·내비·검색·아이콘)를 통째로 물려받고 본문만 비워 다시 채웠다. GNB엔 LIVE 항목이 없어서(디자인이 NAV_LINKS 확장 전 것이다) 기사 링크를 복제해 LIVE·VS를 끼워 넣고 LIVE를 활성 알약으로 바꿨다.
- `figma.createAutoLayout()`으로 만든 프레임은 기본 fill이 흰색이다. 다크 화면에 수십 개를 만들고 나서야 본문 전체가 흰 판이 된 걸 발견했고, "정확히 흰색 fill인 프레임 전부 fills=[] 처리" 스크립트로 일괄 수습했다. 이후 스크립트부터는 생성 헬퍼에서 바로 fill을 비웠다.
- 오토레이아웃 부모에 스크림·모달을 `appendChild`하면 오버레이가 아니라 흐름의 맨 아래로 들어가 프레임 밖으로 밀려난다(클리핑돼 안 보인다). `layoutPositioning = "ABSOLUTE"`로 바꿔야 진짜 오버레이가 된다.
- 빈 스페이서용 오토레이아웃 프레임은 자식이 없으면 기본 100px 높이로 남는다. 벤치 헤더 옆에 넣은 스페이서 하나가 카드 중간에 100px 공백을 만들었다.
- 색·간격·타이포는 모바일 13장에서 실측했다. L1 프레임의 텍스트 노드를 긁어 크기/색/웨이트 조합을 뽑아낸 게(예: 팀명 14.5 Medium #eef2f8, 상태 67' 14 Bold #f87171) 웹 프레임을 0.45 배율로 그릴 때 그대로 환산 기준이 됐다.

중간에 피그마 MCP가 Starter 플랜 호출 한도에 걸려 멈췄는데, 사용자가 플랜을 올려 줘서 이어서 끝냈다.

## 구현 — 타입과 목데이터는 domain으로 갔다

0126 핸드오프에는 타입을 `app/_types/live.ts`(모바일 전용)로 시작하고 web 이식이 생기면 ADR 0011 게이트로 승격을 판단하라고 적어 뒀다. 그런데 이번 세션에서 웹·모바일을 동시에 만들게 되면서 게이트가 시작부터 충족됐다. 그래서 처음부터 `@plick/domain`에 뒀다.

- `packages/domain/src/live.ts`: 라이브 도메인 타입 전부(MatchSummary, MatchDetail, StandingRow, TeamLineup, PlayerSeasonStats 등)와 표기 헬퍼. 명세의 함정들을 타입에 먼저 박았다 — `LiveTeam.id`/`code`가 null이면 빅6 밖, `score` null은 "-", `events.playerName` null 허용, 상세의 4개 블록(preview·events·lineups·stats) 전부 null 허용(서버가 조각 실패 시 그 조각만 빼고 내리는 Redis 설계), 시즌 스탯 무출전은 `competitions: []`. 헬퍼로는 평점 톤(7.5 이상 accent/미만 warn), 스탯 문자열("61%", "1.04") 파싱 실패 시 막대만 생략하는 `statHomeRatio`, 카드 상태 2줄 표기를 한 곳에 모은 `matchStatusLabel`을 뒀다. 웹·모바일 카드가 같은 문구를 쓰는데 앱마다 switch문을 복제하면 곧 어긋난다.
- `packages/domain/src/live-mock.ts`: 껍데기용 목데이터. 기준일 하루에 카드 4상태(라이브 LIV-MCI, 예정 TOT-MUN, 종료 CHE-Coventry, 연기 ARS-Brighton)를 다 넣고, 각 카드가 서로 다른 상태의 상세로 이어지게 했다. 종료 경기는 일부러 lineups를 null로 둬서 블록별 조건부 렌더가 실제로 도는 걸 확인할 수 있게 했다. 저장소에 목데이터 선례가 없어서 배치를 고민했는데, 앱마다 `_mocks/` 사본을 두면 그게 바로 감사(/audit) 대상이라 domain에 한 파일로 두고 양쪽이 소비하게 했다. 파일 머리에 "배선 때 삭제"를 박아 뒀다.

목데이터를 고치다 웹 빌드에서만 타입 에러가 우수수 나왔다. 웹 tsconfig에는 `noUncheckedIndexedAccess`가 켜져 있어서(모바일은 아니다) `MOCK_MATCH_DAYS[MOCK_TODAY][0]` 같은 인덱스 접근이 전부 `undefined` 가능성으로 걸린다. 경기 4개를 이름 있는 상수(LIVE_MATCH 등)로 빼서 목록과 상세가 같은 객체를 참조하게 바꾸니 타입도 데이터 정합도 같이 풀렸다.

## 모바일 — 라우트 4개, 시트는 새로 만들었다

라우트는 핸드오프 그대로 4개다. `/live`(목록), `/live/standings`(순위), `/live/matches/[matchId]`(상세), `/live/teams/[teamId]`(스쿼드). 서브탭(경기/순위)은 홈 팀 필터처럼 URL로 승격돼 있는데, 팀 필터의 `history.replaceState` 방식은 안 썼다. 그 방식은 같은 화면 컴포넌트를 두 라우트가 공유할 때(탭 전환이 리스트 필터일 뿐일 때) 서버 왕복을 아끼려는 것이고, 경기 목록과 순위표는 화면 구성이 완전히 달라 평범한 소프트 내비게이션이 맞다.

- 날짜는 `/live?date=YYYY-MM-DD` 쿼리. 기준일은 목데이터의 오늘(`MOCK_TODAY`)이고 날짜 스트립 7칸이 전부 실제 링크다. 기준일 칸은 쿼리 없는 `/live`로 보내 캐노니컬이 갈라지지 않게 했다.
- 상세의 요약/라인업/스탯 탭은 URL 승격 없이 컴포넌트 상태다. 한 경기 안의 보기 전환일 뿐이라 주소가 갈릴 이유가 없다.
- 라인업 피치는 `grid`("줄:칸", GK가 1줄)를 줄 단위로 묶어 어웨이는 위(정방향), 홈은 아래(줄 순서 reverse)로 그렸다. 선수 도트 색은 `TEAMS[code].colorVar`를 인라인 스타일로 쓰고 빅6 밖은 avatar 색으로 떨어뜨렸다.
- 바텀시트(선수 경기 스탯 L10, 시즌 스탯 L12·L13)는 기존 패턴을 뒤져 보고 판단했다(핸드오프 지침). `ReelDetailSheet`는 드래그 개폐 제스처에 결합돼 있고, `ShareDialog`류는 중앙 다이얼로그다. 하단 고정 + 탭/Escape 닫기만 필요한 이 지면엔 ShareDialog의 body 포털·스크림 관용을 하단 정렬로 옮긴 `LiveSheet`를 새로 만들었다. 드래그 개폐는 껍데기 범위 밖으로 미뤘다.
- 에러 지면(L4)은 컴포넌트(`LiveLoadError`)로 만들어 두고 `?demo=error`로만 열리게 했다. 실데이터가 없으니 자연스럽게 도달할 방법이 없는데, 지면 QA는 해야 해서다. 배선 세션에서 502 분기로 바꾸며 지운다.
- 팀 표식은 `LiveCrest`로 감쌌다. 빅6는 `TeamCrest`(로컬 webp), 빅6 밖은 축약 코드(COV, BHA)를 넣은 제네릭 원형. 실배선 때 CDN 로고가 붙으면 제네릭은 로드 실패 폴백으로 남는다.
- metadata는 전부 noindex를 유지했다. 콘텐츠가 생기면 canonical을 붙이기로 한 주석이 플레이스홀더에 있었는데, 목데이터는 아직 "콘텐츠가 생긴" 게 아니라고 봤다. description·canonical·sitemap 반영은 배선 세션 몫이다.

## 웹 — 대시보드 한 장으로 순위까지

- `/live`는 `PageContainer`(1200px) 안에서 `lg:grid-cols-[minmax(0,1fr)_320px]` 2컬럼. 우측 `StandingsRail`이 순위표 13행을 항상 보여주므로 웹에는 `/live/standings` 라우트를 만들지 않았다. lg 아래에선 레일이 목록 아래로 스택된다 — 요소를 숨기는 판단이 아니라 자명한 1열 스택이라 그대로 진행했다(web-publishing 규칙).
- 상세도 같은 그리드로, 좌측 득점·타임라인·라인업 + 우측 스탯 레일. 모바일의 탭 대신 전 블록 노출이다.
- 모바일 시트 지면은 전부 중앙 모달(`LiveModal`)로 바꿨다. 폭은 `max-w-auth`(460px) 토큰을 재사용했다.
- hover·focus-visible을 카드·행·도트 전부에 달았고, 330px까지 줄여 가로 오버플로 0을 확인했다(`scrollWidth === innerWidth`, 목록·상세·스쿼드 전부).

컴포넌트는 앱별로 뒀다. MatchCard·타임라인·스탯 막대가 양쪽에 비슷하게 존재하지만, 컨테이너 폭·hover 유무·시트/모달 분기 같은 레이아웃 결합이 커서 지금 `@plick/ui`로 승격하면 props 스위치 덩어리가 된다. 문구·상태 로직처럼 어긋나면 안 되는 부분만 domain 헬퍼로 공유하고, 마크업 승격은 API 배선 뒤 지면이 안정된 다음 ADR 0011 게이트로 다시 판단하기로 했다.

## 검증

`pnpm build`(web+mobile), `pnpm lint`, 양쪽 `check-types` 통과. 브라우저로 웹 7지면(대시보드·빈 날·에러·상세 라이브/프리뷰·스쿼드·모달 2종)과 모바일 전 지면(목록 4상태·순위·상세 3탭·프리뷰·연기·시트 2종·무출전 빈 상태)을 스크린샷으로 피그마와 대조했다. 숨겨진 브라우저 패널에서 스크롤·클릭이 리페인트를 못 받는 문제는 뷰포트를 세로로 길게(1280x2400) 잡아 전체를 한 번에 찍는 것과 JS 클릭으로 우회했다.

## 후속 피드백 — 날짜 시스템을 갈아엎었다

PR을 올리고 나서 사용자 피드백이 왔다. 기준일 좌우 3일씩 7칸 고정 스트립은 안 된다는 것. 요구는 이랬다. 스트립 위에 연-월 셀렉터가 있어서 누르면 드롭다운으로 연·월을 고를 수 있어야 하고, 스트립은 해당 월의 1일~말일 전체를 담되 오늘이 가운데 오는 슬라이드여야 하며, 웹은 좌우 화살표 버튼으로도 슬라이드할 수 있어야 한다.

DateStrip을 양쪽 다 다시 만들었다. domain에 월 헬퍼(`monthDateKeys`, `dateKeyYearMonth`, `monthLabel`)를 추가하고, 스트립은 `overflow-x-auto` 가로 슬라이드로 월 전체를 담았다. 연·월 드롭다운은 연도 스테퍼 + 12개월 그리드이고, 오늘이 속한 달을 고르면 오늘로, 다른 달은 1일로 이동한다. 스크롤 센터링과 드롭다운 상태 때문에 두 컴포넌트 다 클라 컴포넌트가 됐다. 날짜 칸은 여전히 실제 링크(`/live?date=`)다.

여기서 하나 제대로 막혔다. 선택 날짜를 가운데로 스크롤하는 로직을 처음엔 `scrollIntoView({inline:"center"})`로 했는데, 선택일이 왼쪽 끝에 반쯤 잘린 채 멈췄다. `getBoundingClientRect` 직접 계산으로 바꿔도 같은 증상이었다. 콘솔 로그를 심어 보니 이펙트가 도는 시점에 스트립 폭이 0으로 측정되고 있었다 — 하이드레이션 직후 그리드 레이아웃이 아직 안 잡힌 프레임이 있다. 폭이 0이면 rAF로 다음 프레임으로 미루는 재시도를 넣어 해결했다. `scrollIntoView`는 조상 스크롤(페이지)까지 건드리는 부작용도 있어 직접 계산 쪽을 최종으로 남겼다.

피그마도 같이 맞췄다. LW1~LW3의 날짜 스트립을 연월 셀렉터 + 월 슬라이드 + 화살표 형태로 교체했다. 모바일 13장 쪽 스트립(L1 계열)은 절대 배치 프레임이라 행 삽입 시 아래 요소 전부를 밀어야 해서 손대지 않았다 — 정본은 코드와 웹 섹션 쪽이다.
