# 0012 — 웹 마이페이지, 그리고 모바일 설정 조각을 공용으로 올리기

KAN-244로 데스크톱 마이페이지(피그마 W4, node 208-2)를 만들었다. GNB 아래 좁은 컬럼 하나에 프로필 카드, 응원팀 줄, 알림·다크 모드 토글, FAQ, 로그아웃, 버전 라벨이 세로로 쌓이는 화면이다. 티켓엔 설명이 따로 없어서 요구사항은 전부 피그마에서 읽었다.

## 이미 모바일에 다 있었다

화면을 조각내서 재사용 조사를 하다가, 모바일에 `me` 페이지가 이미 통째로 있는 걸 발견했다(KAN-170). 프로필 카드, 설정 줄(`SettingRow`), 토글 스위치(`ToggleSwitch`), 알림·다크 카드(`PreferenceCard`)가 전부 `apps/mobile/app/me/_components`에 있었고, 데스크톱 디자인과 구조가 거의 1:1이었다. 배율만 다르지(피그마 데스크톱 프레임이 0.45배라 값을 0.45로 나눠 실제 px를 구한다 — 카드 라운드 16, 카드 간격 14, 아바타 52 전부 모바일과 똑같이 떨어졌다) 같은 컴포넌트였다.

그래서 새로 만들지 않고 이 네 개를 `@plick/ui`로 올렸다. 웹에 사본을 새로 두면 나중에 감사에서 중복으로 걸릴 게 뻔했다. 파일을 옮기고, 모바일 `me/page.tsx`의 import를 `@plick/ui/...`로 바꾸는 것까지 같은 PR에서 했다. 데스크톱은 포인터가 있으니 올리면서 `hover:`·`focus-visible:` 상태를 더했는데, Tailwind v4의 hover는 `@media (hover:hover)`로 감싸져서 터치 기기(모바일)엔 안 걸린다. 그래서 모바일 회귀 없이 데스크톱만 얻는다.

## 막힌 데: ProfileCard가 next/link를 쓰고 있었다

옮기고 나서 웹 빌드가 타입 체크에서 터졌다. `Cannot find module 'next/link'`. ProfileCard가 프로필 수정으로 넘어가려고 `next/link`를 import하고 있었는데, `@plick/ui`엔 next가 의존성에 없다(pnpm이라 패키지 밖 next를 못 찾는다).

두 갈래였다. `@plick/ui`에 next를 peer로 물리거나, 아니면 next 의존을 없애거나. 기존에 올라간 공용 컴포넌트(Logo, MediaThumb, TeamCrest, icons…)는 하나도 프레임워크에 묶여 있지 않았다 — 이 결을 깨고 싶지 않아서, ProfileCard를 순수 `<a>`로 바꿨다. 프로필→수정 이동이 클라이언트 전환에서 전체 리로드로 바뀌긴 하지만 설정 화면 진입에선 차이가 없고, 공용 패키지를 계속 프레임워크 중립으로 둘 수 있다. 겸사겸사 앱마다 다른 `User` 타입에 묶이던 것도 풀어서, 표시에 필요한 `nickname`·`handle`·`href`만 받게 했다.

참고로 웹엔 아직 `/me/edit`이 없다. 그래도 디자인의 화살표(수정 진입)와 모바일 동작에 맞춰 링크는 걸어뒀다. 웹 편집 화면은 다음 티켓 몫이고, 지금은 앞선 참조로 남긴다.

## 폭은 토큰으로

콘텐츠 컬럼은 640px(288 ÷ 0.45)였다. 기사 페이지의 `max-w-read`(860)보다 좁다. 웹 전용 CSS에 숨기지 않고 `theme.css`에 `--container-narrow: 640px`(→ `max-w-narrow`)로 넣었다 — `max-w-page`·`max-w-read`와 같은 자리에. 나머지는 전부 기존 토큰으로 발라서 하드코딩 색·px은 없다.

## 확인한 것

웹·모바일 둘 다 클린 빌드. 데스크톱(1280)에서 피그마와 대조했고, 330px까지 줄여도 가로 오버플로 0(`scrollWidth == innerWidth`), GNB는 햄버거로 접히고 카드는 1열 풀폭으로 잘 쌓였다. 라이트 모드는 토큰에서 저절로 파생돼 따로 손댈 게 없었다. 모바일 `/me`도 승격한 컴포넌트로 회귀 없이 그대로 떴다.
