# 0077. 기사 기자 여러 명 노출 — +N 배지와 기자별 원문 링크 목록 (KAN-365)

## 무엇을 했나

기사 상세 API가 원래부터 기자를 배열로 내려주고 있었는데(`reporters`, 대표 순서 정렬), 화면은
`[0]` 한 명만 골라 보여주고 있었다. 기사 하나가 여러 기자의 트윗을 합쳐 요약된 경우 나머지 기자와
그들의 원문 링크가 전부 버려지고 있었던 것이다. 이번 세션에서 이걸 전부 노출하게 바꿨다.

- 대표 기자 이름 오른쪽 위에 추가 인원을 `+N`으로 표시한다(두 명이면 +1, 세 명이면 +2, 한 명이면 없음).
- 그걸 누르면 기자 전원 목록이 팝오버로 열리고, 각 기자는 티어 배지와 함께 자기 원문 트윗으로
  나가는 링크다.
- 원문 버튼("원문", "출처 원문 보기")은 하던 대로 대표 기자(`[0]`)의 링크를 쓴다.
- 적용 범위는 기사 상세와 릴 세부(웹·모바일 다 합쳐 네 표면)이고, 기사 리스트는 건드리지 않았다.

## 데이터부터 확인했다 — 릴스 피드에는 배열이 없다

시작하자마자 실서버와 로컬 BE 응답을 다시 떠 봤다. 기사 상세(`GET /api/v1/articles/{id}`)만 기자가
배열이고, 릴스 피드(`GET /api/v1/reels`)와 기사 피드는 여전히 대표 한 명(`reporter` 단일 객체)에
최상위 `sourceUrl` 하나다. 즉 릴 세부 시트에서 기자 전원을 보여주려면 피드 데이터만으로는 안 되고,
어디선가 상세를 한 번 더 받아야 한다.

선택지는 둘이었다. 릴이 활성될 때마다 상세를 미리 받아 두거나, 시트가 열릴 때 받거나. 전자는 릴을
넘길 때마다 GET이 하나씩 더 나가는데 정작 시트를 안 여는 유저에게는 전부 낭비다. 시트를 여는 순간은
이미 댓글 목록을 클라에서 받는 시점이라(서버 씨앗 없이 열리는 구조), 상세 한 건을 같이 받는 게
자연스러웠다. 그래서 후자로 갔다. 받기 전이나 실패하면 기자 줄은 지금처럼 피드가 준 대표 이름으로만
서고, 도착하면 `+N` 버튼으로 바뀐다 — 실패해도 깨지는 게 아니라 기능이 하나 안 붙을 뿐이다.

릴 위(오버레이)의 기자 줄에는 안 붙였다. 거긴 탭하면 시트가 열리는 자리라 펼침 버튼을 또 두면 탭
타깃이 충돌하고, 배지 숫자 하나 보여주자고 릴마다 상세를 미리 받는 건 위에서 버린 선택지를 되사는
꼴이다. 시트가 릴의 "기사 세부"니까 시트에서 보여주면 충분하다고 판단했다.

## 도메인 타입 — `reporter`/`sourceUrl`을 지우고 `reporters`로

`ArticleDetail`에 `reporter`(대표 한 명)와 `sourceUrl`(대표의 링크)이 있었는데, 배열을 추가하면서
이 둘을 남겨 두면 같은 사실이 세 자리에 사는 꼴이 된다. 그래서 둘 다 지우고
`reporters: ArticleSourceReporter[]` 하나로 바꿨다. `ArticleSourceReporter`는 기존 `ArticleReporter`
(name·tier)에 `sourceUrl`을 얹은 확장 타입으로 `@plick/domain`에 새로 뒀다 — 상세에서만 기자가
자기 링크를 들고 오기 때문에 목록·핫이슈용 타입과 섞지 않았다.

소비처는 경계 변환 주석의 표현대로 "화면이 고르게" 했다. 기사 세부 컴포넌트(모바일 `ArticleBody`,
웹 `ArticleMain`)는 `article.reporters[0]`을 대표로 꺼내 원문 버튼과 기자 줄에 쓴다. 뜻밖의 소득도
있었는데, JSON-LD(`newsArticleJsonLd`)의 author가 그동안 대표 한 명만 실렸던 걸 기자 전원
Person 배열로 바꿀 수 있었다. 검색엔진 입장에선 이게 더 정확한 저자 표기다.

경계 변환에서 하나 더 잡았다. 실서버 상세 응답의 `sourceUrl`에 뒤공백이 섞여 온다
(`"https://x.com/... "`). 그대로 href에 넣으면 `%20`이 붙은 링크로 나간다. `toArticleDetail`에서
trim하고 빈 문자열은 null로 눕혔다. 지금까지는 대표 링크만 썼는데 그 행은 마침 공백이 없어서
안 밟혔던 문제다.

## UI — `ReporterListButton`과 `ReporterLine` 확장

네 표면이 전부 `@plick/ui`의 `ReporterLine`(티어 배지 + 이름 + 메타 한 줄)을 쓰고 있어서, 여기에
`reporters` prop을 추가하는 것으로 통일했다. 두 명 이상이면 배지·이름 자리가 새 클라 컴포넌트
`ReporterListButton`으로 바뀐다. `ReporterLine` 자체는 서버 컴포넌트로 남고(기사 세부는 서버 렌더),
상태를 드는 펼침 버튼만 `"use client"` 리프로 내려간다.

팝오버는 라이브러리 없이 `useState` + absolute 포지셔닝으로 만들었다. 바깥 탭과 Escape로 닫히게
document에 pointerdown·keydown 리스너를 여는 동안만 단다. 여기서 신경 쓴 게 릴 세부 시트와의
간섭이다. 모바일 시트의 기자 줄은 잡고 끌어내리면 시트가 닫히는 그랩 존인데, 팝오버가 그 안에서
열리므로 목록을 누르는 손짓이 시트 드래그로 이어질 수 있다. 그래서 팝오버 컨테이너에서
`onPointerDown={(e) => e.stopPropagation()}`으로 전파를 끊었다. 반대로 이름 버튼 자체는 전파를
막지 않았다 — 이름 위에서 시작하는 끌어내리기 닫기는 계속 돼야 하고, 탭(이동 없는 클릭)은 어차피
드래그 판정에 걸리지 않는다.

## 사용자 피드백으로 세 가지를 고쳤다

중간에 화면을 보여주면서 세 가지 피드백을 받았다.

1. 팝오버 배경이 반투명이라 밑 글자가 비쳤다. 처음에 `bg-elevate`를 썼는데 이 토큰이 알파 9%짜리
   반투명이라는 걸 놓쳤다 — 버튼처럼 배경 위에 앉는 표면용이지 떠 있는 층용이 아니다. 기존
   다이얼로그들(`ShareDialog`, `LoginPromptDialog`)이 전부 불투명 `bg-bg` + border인 걸 확인하고
   같은 조합으로 바꿨다.
2. 바깥 터치 닫힘 — 이미 구현돼 있어서 그대로 검증만 했다.
3. 숫자 표기. 처음엔 총 인원을 그대로 붙였는데(세 명이면 3), 한 명일 때는 아무것도 붙이지 말고
   두 명 이상일 때 대표를 뺀 추가 인원을 `+N`으로 붙이는 걸로 확정됐다. 분기는 `ReporterLine`이
   갖는다 — 한 명이면 예전 그대로 배지+이름 정적 표시라 버튼 자체가 안 생긴다.

## 검증 — 로컬 BE에 기자 여러 명인 기사가 없어서 DB를 뒤졌다

로컬 BE 피드 앞쪽 기사들이 전부 기자 한 명이라 눈으로 확인할 대상이 없었다. `scripts/be-verify/db.sh`
로 공유 DB에 붙어 `raw_articles`를 `article_summary_id`로 묶어 세어 보니(기사 하나에 원문 트윗이
여러 개면 행이 여러 개다) PUBLISHED 중 7816이 3명(James Pearce×2 + Match of the Day, 티어 A 포함)
이었다. 같은 기자가 트윗을 두 개 낸 경우라 "같은 이름이 두 행" 케이스까지 덤으로 확인됐다 — 행마다
링크가 다르니 이름으로 합치지 않고 그대로 두 행 보여주는 게 맞다.

확인 중 자잘하게 막힌 것들. 다른 세션의 dev 서버가 3001 락을 잡고 있어서(Next 16은 같은 디렉터리에
dev 서버 두 개를 안 띄워 준다) 처음엔 프로덕션 빌드를 3101에 띄워 확인했는데, 사용자가 기존
로컬호스트를 다 내리고 3000·3001로 확인하라고 해서 포트를 정리하고 dev로 다시 띄웠다. 릴 세부는
모바일에 딥링크 라우트가 없어서, 모바일은 첫 릴로 시트의 상세 fetch(네트워크 200)와 한 명일 때
표기 없음을 확인하고, 세 명짜리 7816은 웹 릴스에서 스크롤 스냅 컨테이너를 스크립트로 끝까지 내려
14번째 릴까지 페이지를 당긴 뒤 패널을 열어 확인했다. 브라우저 패널의 합성 클릭이 웹 탭에서 팝오버
토글에 안 먹는 일이 있어(같은 좌표를 JS `click()`으로 치면 정상 동작) DOM 상태 검사로 대체했다 —
컴포넌트 문제가 아니라 자동화 이벤트 쪽 문제다.

최종 확인 범위: 모바일 기사 세부(+2 배지, 불투명 팝오버, 바깥 탭 닫힘), 모바일 릴 시트(상세 fetch,
한 명 → 표기 없음), 웹 기사 세부 데스크톱(+2, 팝오버, Escape 닫힘), 웹 릴 패널(fetch 후 +2, 링크
3건 href 일치), 웹 330px(가로 오버플로 없음, 팝오버 안 잘림). `format:check`·`lint`·`check-types`·
`build`(양 앱) 통과.
