# 0014 — 웹 회원가입·로그인 화면 (KAN-246)

데스크톱 웹에 회원가입(`/signup`, 피그마 W7 205-2)과 로그인(`/login`, W6 206-2)을 얹었다.
홈·마이·기사까지 훑고 나니 남은 건 인증 쪽이었다. 처음엔 회원가입 한 장으로 시작했는데,
로그인이 카드가 거의 똑같아 이어서 같은 브랜치에 붙이고 카드를 공용으로 뺐다.

## 티켓이 노드랑 안 맞았다

작업을 `/web-screen KAN-245`로 시작했는데, 넘어온 피그마 노드는 205-2 "W7 회원가입"이었다.
그런데 KAN-245는 "웹 마이 수정 페이지"라 이미 지난 세션에 만들어 머지된 티켓이었다([ADR 0013]).
노드가 가리키는 건 회원가입이고, Jira를 뒤져보니 딱 맞는 티켓이 따로 있었다 —
KAN-246 "[FE] 웹 회원가입 페이지 구현"(상태: 해야 할 일). 티켓 키만 한 칸 어긋난 셈이라
추측으로 밀지 않고 사용자에게 물어 KAN-246으로 확정했다.

## 카드 하나에 모바일 조각을 그대로

회원가입은 로그인·마이처럼 새로 그릴 게 많은 화면이 아니다. 모바일에 이미 같은 화면
(`apps/mobile/app/signup`, [KAN-175])이 있고, 안에 든 건 로고·태그라인·소셜 버튼 두 개·약관·
로그인 링크가 전부다. 데스크톱이라고 달라지는 건 이걸 전체 화면에 세로로 펴는 대신 **다크 배경
가운데 카드 한 장**에 담는다는 것뿐이었다. 그래서 카피·간격·아이콘은 모바일 그대로 두고
바깥 껍데기만 카드로 바꿨다.

소셜 버튼은 모바일 `_components`에 있던 `SocialLoginButton`을 `@plick/ui`로 승격했다.
토큰 유틸만 쓰는 앱 중립 컴포넌트라 옮기기만 하면 양쪽에서 그대로 도는 조각이다. 사본을 만들면
감사 대상이 되니 파일을 옮기고 모바일 signup·login의 import를 같은 PR에서 `@plick/ui`로 갈아끼웠다.
데스크톱엔 포인터가 있으니 `hover:opacity-90`과 `focus-visible` 링을 붙였는데, Tailwind v4의 hover는
`@media(hover:hover)`라 모바일 터치엔 영향이 없어 안심하고 공용 컴포넌트에 넣었다.

## 카드 폭은 토큰으로 뺐다

피그마 카드는 0.45 배율 프레임에서 207px, 실제로는 460px다. 버튼 높이(23.4→52=h-13)나 로고
글자(19.8→44)로 배율을 검산해보니 0.45가 맞았다. 이 460px을 웹 CSS에 숨기지 않고
`--container-auth`(→ `max-w-auth`) 토큰으로 `theme.css`에 넣었다. 마이 컬럼을 `max-w-narrow`로
뺐던 것과 같은 결. 로그인 화면(다음 티켓)이 이 카드를 그대로 재사용할 테니 인증 카드 폭은
반복되는 시맨틱 값이 맞다. 나머지 색·간격·라운드는 전부 기존 토큰(`bg-elevate-2`·`border-border`·
`rounded-hero`·`gap-gap`)에 그대로 얹혔다. 카드 라운드는 피그마 24px인데 딱 맞는 토큰이 없어
가장 가까운 큰-면 토큰 `rounded-hero`(22)로 스냅했다 — 2px 차이라 눈에 안 띄고, 카드 하나 때문에
전용 토큰을 새로 파는 건 과했다.

로고 크기만 좀 애매했다. 피그마 워드마크 글자 박스는 53px인데 `Logo` 벡터는 글리프 딱 맞는
비율(3.13)이라 같은 높이로 맞추면 폭이 안 맞는다. 그래서 높이 대신 폭(118px)으로 역산해
`height={38}`로 잡았다 — 모바일 인증(34)보다 살짝 크게.

## 로그인 링크는 앞선 참조

"이미 계정이 있으신가요? 로그인"은 `/login`으로 걸어뒀는데 웹엔 아직 로그인 라우트가 없다.
KAN-244 마이 화면이 `/me/edit` 나오기 전에 프로필 카드 링크를 미리 걸어둔 것과 같은 방식 —
로그인은 다음 티켓이라 링크만 앞세웠다.

## 검증

- `pnpm --filter web build` / `pnpm --filter mobile build` 둘 다 클린(공유 패키지 `@plick/ui`·
  tokens를 건드려서 양쪽 확인). `/signup` 정적 생성 확인.
- 데스크톱(1280×800) 다크: 피그마와 대조 OK. 라이트 토글: 카드·로고 반전, 카카오/구글 브랜드색
  유지, accent 링크 전환 OK. 콘솔 에러 없음.
- 330px: 가로 오버플로 0(`scrollWidth==innerWidth`), 카드가 `px-edge` 여백 안에서 폭에 맞춰
  줄고 태그라인·약관 문구가 2줄로 접힘, 버튼 풀폭·겹침 없음.

## 로그인은 카드만 공용으로 빼면 끝이었다

회원가입을 올리고 나서 로그인(W6)을 같은 브랜치에 이어 붙였다. 두 노드를 나란히 놓고 보니
카드 형태·간격·버튼·색이 완전히 같고, 다른 건 넷뿐이었다 — 태그라인 한 줄, 버튼 동사
("회원가입"↔"로그인"), 약관 문구 유무(로그인엔 없다), 하단 전환 링크(문구+목적지). 그래서
카드 전체를 `apps/web/app/_components/AuthCard.tsx` 한 컴포넌트로 빼고, 이 네 가지를 props로
받게 했다(`terms`는 회원가입만 `true`). 두 `page.tsx`는 이제 props만 넘기는 열 줄짜리 껍데기다.

`AuthCard`를 `@plick/ui`가 아니라 웹 `_components`에 둔 건, 이 카드가 데스크톱 중앙 카드 레이아웃
(`min-h-dvh` 중앙 정렬 + `max-w-auth`)에 결합돼 있어서다. 모바일 인증은 `AppShell` 기반 전체 화면
스택이라 뼈대가 다르다 — 프레젠테이션 조각(`SocialLoginButton`)은 이미 `@plick/ui`로 공유하지만,
레이아웃까지 묶은 카드는 웹 안에서만 도는 게 맞다([ADR 0011]의 앱 결합 판단과 같은 결).

로그인 하단 링크는 `/signup`, 회원가입은 `/login` — 두 화면이 서로를 가리켜 왕복이 완성됐다.
전 세션에서 `/login`을 앞선 참조로 걸어뒀던 게 이번에 실제 라우트로 채워졌다.

## 검증 (로그인 추가분)

- `pnpm --filter web build` 클린, `/login`·`/signup` 둘 다 정적 생성. 공유 패키지는 이번 턴에
  안 건드려 web만 빌드.
- 데스크톱(1280×800): 로그인 피그마 W6 대조 OK(약관 줄 없음 확인). 로그인 "회원가입" 링크 클릭 →
  `/signup` 이동, 리팩터한 회원가입도 그대로 렌더(회귀 없음).
- 330px 로그인: 가로 오버플로 0, 카드 폭 맞춤·버튼 풀폭·겹침 없음.
