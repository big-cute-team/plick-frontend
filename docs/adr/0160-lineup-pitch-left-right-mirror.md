# 0160. 라인업 피치 아래쪽 팀 좌우반전 수정 (KAN-551)

- 날짜: 2026-09-19
- 브랜치: `feature/KAN-551-lineup-grid-mirror`
- 관련: [ADR 0126](0126-livescore-figma-design.md)(라인업 grid 규약 첫 기록),
  [ADR 0127](0127-livescore-shell-web-mobile.md)(피치 렌더 첫 구현),
  [ADR 0011](0011-shared-code-boundary.md)(공용화 게이트)

## 증상

지라에 올라온 티켓은 한 줄이었다. 스쿼드(라인업) 바둑알 위치가 이상하다, 예를 들어 포로가 왼쪽에
있고 로버트슨이 오른쪽에 있다, 두 팀 중 아래 팀에서만 생기는 것 같으니 싹 다 확인해서 배치를
제대로 고쳐라.

포로는 오른쪽 풀백이고 로버트슨은 왼쪽 풀백이다. 화면 아래쪽에 있는 팀은 위로 공격하는 모양으로
그리니까 내가 보는 왼쪽이 그 팀의 왼쪽이어야 하고, 그러면 로버트슨이 왼쪽·포로가 오른쪽에 와야
맞다. 지금은 정반대로 나온다는 얘기다.

첨부 이미지는 지라 API로는 못 받아서(첨부 content URL이 별도 인증을 요구한다) 코드와 실데이터로
원인을 좁혔다.

## 코드가 하던 일

라인업 피치는 모바일 `LineupPitch.tsx`와 웹 `LineupCard.tsx`에 거의 같은 코드로 들어 있었다.
둘 다 `gridLines`라는 로컬 함수가 선수 배열을 `grid`("줄:칸", GK가 1줄)의 줄 번호로만 묶었다.
칸 번호는 아예 안 봤다. 한 줄 안에서의 좌우 순서는 BE가 준 배열 순서를 그대로 썼다.

줄 순서는 어웨이(위쪽 팀)는 정방향, 홈(아래쪽 팀)은 `reverse()`로 뒤집어 GK가 아래 끝에 오게
했다. 여기까지는 [ADR 0127](0127-livescore-shell-web-mobile.md) 때 만든 대로다. 그때는 상하
반전만 생각했고 좌우는 생각을 못 했다.

## 실데이터로 규약 확정

칸 번호 1이 팀 기준 왼쪽인지 오른쪽인지를 알아야 어느 팀을 뒤집을지 정할 수 있다. 원본
API(API-Football) 문서 예시가 기억에 어렴풋이 있었지만 기억에 기대기 싫어서 prod에서 직접 뽑았다.

로컬 BE는 안 떠 있었고 dev 사이트(dev.plick.co.kr)는 403이 떨어졌다(공개 ALB가 dev 호스트에
`/ws/*`만 열어 둔 것과 같은 맥락이다). 대신 prod 웹(plick.co.kr)은 열려 있었고, 웹 경기 상세의
`MatchDetailScreen`이 클라 컴포넌트라 첫 상세 씨앗(`initial`)이 RSC 페이로드에 통째로 직렬화돼
HTML에 박혀 있다. `self.__next_f.push([1,"..."])` 조각을 이어 붙여 JSON 문자열을 풀면 선수별
`grid`가 그대로 나온다.

오늘 경기 토트넘 대 아스톤 빌라(1557416)에서 뽑은 값이다.

| 팀        | 선수           | 포지션 | grid |
| --------- | -------------- | ------ | ---- |
| TOT(홈)   | Pedro Porro    | RB     | 2:4  |
| TOT(홈)   | A. Robertson   | LB     | 2:1  |
| AVL(원정) | A. Wan-Bissaka | RB     | 2:4  |
| AVL(원정) | M. Ruggeri     | LB     | 2:1  |

브렌트포드 대 첼시(1557408)도 같았다(Kayode RB 2:4, Lewis-Potter LB 2:1). 그래서 규약은 이렇다.

- 칸 1은 그 팀이 상대 골문을 볼 때 왼쪽이다. 번호가 커질수록 그 팀의 오른쪽이다.
- BE 배열은 칸 내림차순으로 온다(2:4, 2:3, 2:2, 2:1). 이건 원본 API 배열 순서를 BE가 그대로
  흘려보낸 것이지 약속된 건 아니다.

배열 순서 그대로 그리면 포로(2:4)가 맨 왼쪽에 온다. 위쪽 팀은 아래로 공격하니까 그 팀의 오른쪽이
내 왼쪽이라 우연히 맞고, 아래쪽 팀은 위로 공격하니까 그 팀의 오른쪽이 내 오른쪽이라 뒤집혀
보인다. 티켓이 아래 팀에서만 난다고 한 것과 정확히 들어맞았다.

## 고친 것

배열 순서에 기대는 걸 없애고 칸 번호로 정렬하되, 팀이 공격하는 방향에 따라 오름차순·내림차순을
갈랐다.

- 아래쪽 팀(`up`, 위로 공격): 칸 오름차순 = 화면 왼쪽→오른쪽. 로버트슨(1)이 왼쪽, 포로(4)가 오른쪽.
- 위쪽 팀(`down`, 아래로 공격): 칸 내림차순. 완비사카(4)가 왼쪽, 루게리(1)가 오른쪽.

이 로직을 `@plick/domain/live`에 `lineupPitchLines(players, facing)`로 올렸다. 원래 모바일과
웹에 똑같은 `gridLines`가 복붙돼 있었고 이번 수정도 둘 다 똑같이 손봐야 했다. 도메인 타입
`LineupPlayer`만 받는 순수 함수이고 사용처가 둘이라 [ADR 0011](0011-shared-code-boundary.md)
게이트를 넘는다. `ratingTone`, `groupAbsenteesByTeam`이 이미 거기 있어서 자리도 자연스러웠다.
`PitchFacing` 타입(`"up" | "down"`)도 같이 뒀다.

홈/어웨이가 아니라 `facing`으로 받은 이유는, 뒤집을지 말지를 정하는 건 팀의 소속이 아니라 피치에서
어느 쪽을 보고 있느냐이기 때문이다. 나중에 홈을 위에 그리기로 바꾸더라도 호출부에서 방향만 바꾸면
된다.

줄 순서 `reverse()`는 컴포넌트에 남겼다. 그건 피치 위아래 배치의 문제라 렌더 쪽 관심사고, 헬퍼는
줄 배열을 GK부터 주는 걸로 일관되게 뒀다.

## 검증

로컬 BE가 없어 화면으로는 못 봤다. 대신 prod에서 뽑은 두 팀 라인업을 BE 배열 순서 그대로 헬퍼에
넣고 찍어 봤다.

```
--- AVL (위, down): 화면 위→아래
Suzuki
Wan-Bissaka  Lindelöf  Mings  Ruggeri
Kamara  Gomes
McGinn  Manzambi  Buendía
Jackson
--- TOT (아래, up): 화면 위→아래는 reverse
Solanke
Marmoush  Fernandes  Sávio
Tonali  Bentancur
Robertson  van de Ven  van Hecke  Porro
Kinský
```

위 팀은 전과 같고 아래 팀만 좌우가 바뀌었다. 배열을 무작위로 섞어 넣어도 결과가 같은 것도
확인했다. 이제 BE가 배열 순서를 바꿔도 화면은 안 흔들린다.

이 스크립트를 돌리는 데 잠깐 막혔다. `packages/domain`은 확장자 없는 import(`./constants`)라
Node 22의 `--experimental-strip-types`로 바로 실행이 안 됐고, esbuild는 pnpm 스토어에서 경로가
안 잡혔다. 헬퍼가 다른 모듈에 의존하지 않아서 `live.ts`에서 import 줄만 걷어낸 사본을 만들어
돌렸다. 도메인 패키지에 테스트 러너가 없다는 건 이번에 다시 느꼈는데, 이 정도 순수 함수가 쌓이면
vitest 하나 붙이는 게 맞겠다.

`pnpm format`, `pnpm lint`, `pnpm check-types`, `pnpm build`를 돌렸다.
