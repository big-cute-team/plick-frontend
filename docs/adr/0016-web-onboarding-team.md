# 0016 — 데스크톱 웹 온보딩 팀 선택 단계 (KAN-248)

닉네임(KAN-247) 다음이자 온보딩의 마지막인 팀 선택 화면(피그마 W9, node 224-2)을 데스크톱 웹에 붙였다. 스텝 표시가 `2 / 2`라, 이걸 고르고 "시작하기"를 누르면 홈으로 떨어지는 흐름이다. 빅6 팀을 2열 그리드로 늘어놓고, 고른 카드에는 초록 테두리와 체크 배지가 붙는다.

## 껍데기는 바로 전 단계를 그대로 물려받았다

이번엔 고민할 게 별로 없었다. 직전에 만든 W8 닉네임 카드와 온보딩 껍데기가 완전히 같았기 때문이다. 가운데 정렬 + 다크 배경, `border-border bg-elevate-2 rounded-hero max-w-onboarding` 카드, `min-h-170`(680px)으로 높이를 잡아 하단 버튼을 `flex-1` + `justify-end`로 바닥에 밀어 두는 구조까지 동일했다. 스텝 표시 `2 / 2`, 제목(`text-headline`), 안내 문구도 자리가 같아서, 닉네임 카드의 뼈대를 그대로 두고 가운데 입력 칸만 팀 그리드로 갈아 끼웠다. W8에서 판 `--container-onboarding` 토큰이 여기서 바로 두 번째 손님을 받은 셈이라, 그때 "단계가 더 남았으니 반복될 것 같다"고 토큰으로 올려 둔 판단이 맞아떨어졌다.

## 그리드는 모바일에 있었지만, 그대로 승격하진 않았다

팀 그리드는 모바일 온보딩(A6)에 `TeamSelectGrid`로 이미 있었다. 처음엔 이걸 `@plick/ui`로 올릴까 했는데, 뜯어보니 그 컴포넌트가 모바일 `_lib`의 `TEAMS`·`TEAM_ORDER` 상수와 `useTeamSelection` 훅에 묶여 있어서 "그대로 옮기면 되는" 잎(leaf) 컴포넌트가 아니었다. 프레젠테이션만 뽑아 props로 일반화하려면 API를 새로 설계하고 모바일 import까지 같은 PR에서 갈아야 하는데, 그 대가로 얻는 게 크레스트 크기(데스크톱 40px vs 모바일 51px)와 hover 유무가 갈리는 두 화면을 억지로 하나로 묶는 거였다.

그래서 바로 앞 W8 닉네임에서 택한 것과 같은 길을 갔다 — 화면 전용 컴포넌트를 라우트 `_components/`에 두되, 잎 컴포넌트(`TeamCrest`, `CheckIcon`)만 `@plick/ui`에서 재사용한다. 웹은 이미 자기 `_lib/constants.ts`에 `TEAMS`·`TEAM_ORDER`를 모바일과 같은 값으로 들고 있어서 그리드가 소비할 데이터도 새로 만들 게 없었다. 선택 상태는 훅까지 갈 것 없이 닉네임과 똑같이 로컬 `useState`로 뒀다(저장은 BE 전이라 미연결). 중복이 걱정되는 진짜 알맹이 — 구단 로고와 체크 아이콘 — 는 이미 공용이라, 남는 건 그리드 배치 몇 줄뿐이다.

## 피그마를 실제 px로

늘 하던 대로 0.45로 나눴다. 팀 버튼은 103.05 × 53.1 → 229 × 118px이라 높이를 `h-29.5`(118px)로 잡았고, 크레스트는 18 → 40px, 체크 배지는 9.9 → 22px에 카드 우상단 `right-3 top-2.5`(12/10px)로 앉혔다. 이 배지 위치·크기는 모바일 그리드가 쓰던 값과 정확히 같아서 그대로 가져왔다 — 배지 안 체크는 피그마가 텍스트 글리프 `✓`로 그려 뒀지만, 아이콘은 벡터로 쓰라는 규칙대로 `CheckIcon`(SVG)을 넣었다. 팀 순서(리버풀·토트넘·아스날·맨유·첼시·맨시티)는 `TEAM_ORDER`가 시안과 그대로 일치했고, 첫 선택 팀도 목데이터 `CURRENT_USER.myTeam`("LIV")이 시안의 리버풀 선택과 맞아 손댈 게 없었다.

## 데스크톱이라 hover를 더했다

모바일 그리드엔 없던 상태를 데스크톱에선 챙겨야 했다. 안 고른 카드에 `hover:border-text-4`로 테두리가 살짝 밝아지게 하고, 모든 버튼에 `focus-visible:ring`을 줘 키보드로도 어디 있는지 보이게 했다. 고른 카드는 `border-accent`라 hover가 끼어들지 않는다. "시작하기"는 홈으로 가는 이동이라 `<button>`이 아니라 `next/link`의 `Link`로 두고, 닉네임의 "다음" 버튼과 같은 accent pill 스타일(`hover:opacity-90`, `active:opacity-60`)을 입혔다. 팀은 항상 하나 선택돼 있어 disabled 상태는 필요 없었다.

## 검증

데스크톱(1280)에서 시안과 대조하고, 클릭으로 선택이 옮겨가는지(리버풀 → 맨시티로 테두리·배지가 따라감) 확인했다. 모바일 330px에서 가로 오버플로 0(`scrollWidth == innerWidth`)에 2열 그리드가 그대로 버티고, 제목이 두 줄로 접히며 버튼이 폭을 꽉 채웠다. 가운데 카드 한 장이라 다열→1열 재구성이 없어 반응형은 폭만 유연하게 두면 따라왔다. 라이트로 토글해도 색이 전부 토큰으로 자동 전환됐다. `@plick/ui`·tokens는 안 건드려서 웹 빌드만 클린 확인했다.

관련: 같은 온보딩 껍데기·`max-w-onboarding` 토큰의 출발점은 [ADR 0015](0015-web-onboarding-nickname.md), 공용 컴포넌트 승격 판단 기준은 [ADR 0011](0011-shared-code-boundary.md).
