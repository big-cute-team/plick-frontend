# 0041. 기사 디테일 화면 수정 (KAN-301)

## 무엇을 했나

KAN-301 티켓으로 기사 디테일 화면을 손봤다. 티켓 자체는 두 줄이었다. 트위터 임베드를
빼고, "함께 보면 좋은 기사"를 본문 글 밑으로 옮기면서 가로 정렬에 가로 스크롤로
바꾸라는 거였다. 작업 중에 피드백이 이어져서 최종 범위는 네 가지가 됐다.

1. 기사 디테일에서 트윗 임베드 폴백 제거
2. "함께 보면 좋은 기사"를 본문 밑에 가로 스크롤 카드로 (단, 데이터는 비워 둠)
3. 카드에 이동 단서용 체브론 아이콘 추가
4. 팀 태그·루머 단계 배지를 릴스와 같은 표시로 통일
5. (덤) 홈 "지금 올라온 소식" 스켈레톤을 실제 3줄 레이아웃에 맞춤

## 트윗 임베드 제거

원래 기사 디테일은 사진(`imageUrl`)이 null이면 원문 트윗 임베드(`TweetEmbed`)를
대신 그렸다(KAN-284에서 만든 폴백). 그런데 실제로 써 보니 본문 요약과 트윗 내용이
거의 같아서 화면만 무거워졌다. 티켓대로 임베드 분기를 통째로 걷어냈다. 이제 사진이
null이면(현재 발행 기사 전건이 그렇다) 미디어 없이 텍스트만 흐르고, 원문은 기자
라인의 "원문" 링크로만 연결된다.

`TweetEmbed` 컴포넌트 자체와 `/api/tweet/[id]` 라우트는 남겼다. 홈 히어로 카드와
릴스가 아직 쓰고 있어서다. 기사 디테일에서 import만 빠졌다.

## 함께 보면 좋은 기사 — 위치·모양·데이터

원래 이 섹션은 댓글까지 다 끝난 페이지 맨 밑에 "지금은 준비 중이에요" 문구로만
있었다. 티켓 요구는 본문 글 바로 밑으로 올리고 가로 스크롤로 만드는 것.
`ArticleBody`의 세로 흐름(문단 → 해시태그 → 액션 → 댓글) 안에서 해시태그와 액션
사이에 섹션을 끼웠다.

가로 스크롤은 홈 팀 필터 탭과 같은 `overflow-x-auto` + `no-scrollbar` 패턴이다.
본문이 `px-edge`(20px) 안에 있어서 스크롤 트랙만 `-mx-edge px-edge`로 화면 끝까지
풀었다. 이러면 마지막에 걸친 카드가 화면 모서리에서 잘려 보여서 "옆으로 더 있다"는
스크롤 단서가 공짜로 생긴다. 카드 폭은 고정 px 대신 트랙 기준 `w-[62%]`라 폴드
접힘부터 480px까지 어느 폭에서도 다음 카드가 살짝 걸친다.

카드 디자인은 두 번 뒤집었다. 처음엔 데스크톱 웹의 추천 카드(`SuggestedArticleCard`,
KAN-233)를 그대로 모바일로 옮겼다. 팀컬러 그라데이션 placeholder 위에 스크림 깔고
흰 글자 얹는 미디어 카드다. 화면에 띄워 보여줬더니 포털 뉴스 이슈 카드 스크린샷과
함께 "배경에 이상한 색 넣지 말라"는 피드백이 왔다. 사진이 전부 null인 현재 데이터에선
카드마다 시뻘건 그라데이션만 가득했으니 그럴 만했다. 그래서 배경색 없는 담백한
서페이스 카드(`bg-elevate` + `border-border`)로 다시 만들었다. 팀·단계 줄, 제목
두 줄, 기자·시각 줄이고, 사진이 있으면 우측에 `size-14` 썸네일로만 붙는다. 톤은
홈 "지금 올라온 소식"의 `NewsItem`과 맞췄다. 이어서 "탭하면 이동한다는 느낌"
피드백이 와서 첫 줄 우측에 `ChevronMiniIcon`(마이페이지에서 쓰던 공용 아이콘)을
`ml-auto`로 붙였다.

데이터는 결국 비웠다. 전용 추천 API가 아직 없어서(KAN-283 때부터 그랬다) 임시로
피드 API(`GET /api/v1/articles`)를 기사의 대표 팀으로 필터해 현재 기사만 빼고
6건을 채워 봤는데, "백엔드 API가 없으니 비워 놓으라"는 지시를 받았다. 그래서
`ArticleBody`의 `suggested` prop을 옵셔널(기본 빈 배열)로 두고, 페이지 서버
컴포넌트에는 추천 API가 생기면 여기서 fetch해 넘기라는 주석만 남겼다. 처음엔 빈
배열이면 섹션을 통째로 숨겼는데, 그러면 화면에서 섹션이 있는지도 모르게 사라진다는
피드백을 받고 제목은 그대로 두고 카드 자리에 "아직 준비 중이에요!" 문구를 보여주는
쪽으로 바꿨다. UI는 다 만들어져 있으니 나중에 데이터만 물리면 된다.

시각 확인은 임시로 피드 데이터를 물려서 했다. 커밋 전에 임시 코드를 제거했고,
빈 상태(섹션 미표시)와 다크·라이트 양쪽을 다시 확인했다.

## 배지를 릴스와 통일 (ReelBadges → PostBadges)

작업 중에 "팀 태그 버튼과 루머 단계 버튼도 릴스와 똑같이" 피드백이 왔다. 기사
디테일은 그동안 `PostChips`(알약 칩 — 팀 이름 텍스트 + 단계 칩)를 썼고, 릴스는
KAN-299에서 만든 `ReelBadges`(실제 구단 로고 `TeamCrest` + 알약 배경 없는 단계
글자)를 썼다.

`ReelBadges`는 릴스 라우트 전용이라 `app/reels/_components/`에 있었는데, 기사
디테일까지 쓰면 두 화면 공용이다. 컨벤션(2개 화면 이상 공용 → `app/_components/`)대로
`app/_components/PostBadges.tsx`로 올리면서 이름도 릴스 티가 안 나게 `PostBadges`로
바꿨다. `PostChips`와 나란한 이름이다. 릴스의 import 경로만 바꾸면 끝이었고, 기사
디테일에서는 `PostChips` 자리에 `PostBadges`를 넣었다.

부수 효과 하나. 원래 기사 디테일 팀 칩은 BE 해시태그 원문(`hashtags[0]`)을 그대로
보여줬는데, `PostBadges`는 팀 레지스트리 객체를 받아 로고를 그린다. 그래서 이제
해시태그 역산으로 얻은 대표 팀(`article.teams[0]`)의 로고가 나오고, 레지스트리에
없는 팀이면 로고 없이 단계 글자만 남는다.

`PostChips`는 데스크톱 웹(기사 세부·릴 카드)이 아직 쓰므로 `@plick/ui`에 그대로
있다. 모바일에서만 안 쓰게 됐다.

## 덤 — 홈 소식 리스트 스켈레톤 줄수 맞추기

같은 브랜치에 넣어 달라는 요청으로 홈 "지금 올라온 소식"의 `NewsItemSkeleton`도
고쳤다. 실제 줄(`NewsItem`)은 팀·시각 / 제목 / 기자·조회·댓글의 3줄인데 스켈레톤은
제목을 2줄로 잡아 4줄이었다. 바를 3개로 줄이고, 브라우저에서 실제 줄 높이를 재서
(1줄 제목 기준 85px) 바 높이·간격을 맞췄다. 제목 바만 `h-5`로 키워 84px, 실제와
1px 차이라 데이터 도착 시 리스트가 튀지 않는다.

## 막힌 데 — dev 서버가 파일 변경을 안 먹었다

시각 검증에서 한참 헤맸다. 코드를 고치고 브라우저를 새로고침해도 계속 옛 화면이
나왔다. curl로 서버 HTML을 직접 떠 보니 진짜로 옛 마크업을 주고 있었다. 오래
떠 있던 next dev(Turbopack) 프로세스가 파일 워처가 죽었는지 HMR을 아예 안 하는
상태였다. 프로세스를 죽이고 dev 서버를 새로 띄우니 바로 반영됐다. 스크린샷이
안 바뀌면 브라우저 캐시부터 의심했는데, 서버 쪽이 묵은 경우도 있다는 걸 배웠다.
다음부터는 curl로 서버 응답을 먼저 확인하는 게 빠르다.
