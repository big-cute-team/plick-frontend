# 0159. 급상승이 키워드 단위로 바뀐 데 맞춰 이슈 상세 문구 수정 (KAN-533)

- 날짜: 2026-09-19
- 티켓: KAN-533 (상위 에픽 KAN-518 "이슈 단위 실시간 급상승")
- 브랜치: `feature/KAN-533-keyword-trend-copy`
- 관련: [ADR 0156](0156-story-trend-widget.md) (급상승을 이슈 단위로 바꾼 작업), [ADR 0157](0157-hot-card-border-reel-tap-comment-count.md)

## 무엇을 했나

백엔드가 실시간 급상승의 집계 단위를 바꿨다. 전에는 "손흥민 사우디 이적설"처럼 이적설 하나를 묶은 이슈였는데,
이제는 "히샬리송", "포든 퇴장", "맨체스터 더비" 같은 짧은 키워드다. API 계약은 그대로라 화면 코드는 손댈 게 없었고,
옛 설명이 남아 있는 문구와 주석만 고쳤다.

고친 곳은 다섯 군데다.

- `apps/web/app/stories/[storyId]/page.tsx`의 메타 description. "관련 프리미어리그 이적 루머 기사 N건 모아보기"에서
  "관련 기사 N건 모아보기"로 바꿨다. 키워드가 "맨체스터 더비"나 "잉글랜드 명단"처럼 이적설이 아닐 수 있어서 기사 종류를
  못 박으면 틀린 설명이 된다. 같은 파일 주석의 예시 "손흥민 사우디 이적설"도 키워드 예시로 바꿨다.
- `packages/core/src/trends.ts` 머리 주석. "순위 변동은 한 시간 전 회차와 비교한 값"이 옛 설명이었다. 지금은 항목마다
  최근 24시간 안에서 가장 최근에 순위가 움직인 변동을 준다. 3위에서 1위로 오르면 다음에 또 움직일 때까지 UP 2칸이
  유지된다. NEW는 비교한 회차에 그 항목이 없었다는 뜻이고 최대 24시간 남는다. 10분 전(KAN-501)에서 한 시간 전(KAN-522)을
  거쳐 여기까지 온 이력은 괄호로 한 줄 남겼다.
- `apps/web/app/_components/TrendingSection.tsx` 주석의 "손흥민 사우디 이적설 1위" 예시. 티켓에는 없었지만 같은 옛
  예시라 함께 키워드로 바꿨다.
- `packages/domain/src/types.ts`의 `TrendDirection`과 `Story` 주석. 각각 "직전 회차 대비"와 "같은 이적설을 다룬 기사
  묶음"이라고 돼 있어 위와 같은 이유로 고쳤다. `Story` 주석에는 기사 하나가 키워드 두 개에 속할 수 있고 제목이 짧아질 수
  있다는 것도 적어 뒀다. 나중에 같은 기사가 두 이슈 상세에 나오는 걸 버그로 오해하지 않게 하려는 것이다.

## 그대로 둔 것

`StoryHeader.tsx`의 라벨 "이슈"와 페이지의 "이 이슈의 기사"는 손대지 않았다. 티켓이 "키워드"로 바꿀지는 기획 판단이라고
했고 동작에는 문제가 없다. 사용자에게 보이는 단어라 내가 임의로 정하지 않았다.

## 알아 둘 것

- 키워드 이름은 기사가 붙으면서 짧아질 수 있다("포든 퇴장"에서 "포든"). 링크는 id 기준이라 화면 영향은 없다.
- dev의 옛 이슈 id(57 이하)는 키워드로 다시 채우면서 없어져 옛 링크는 404가 난다. 이슈 상세는 이미 404를 not-found로
  보내고 있어서 따로 할 일은 없었다.
- 티켓은 `packages/core/src/trends.ts`를 가리켰는데 이 레포에 `packages/core`가 실제로 있다. CLAUDE.md의 구조 표에는
  `domain`까지만 적혀 있어 처음에 잠깐 헷갈렸다.

## 검증

`pnpm format:check`, `pnpm lint`, `pnpm check-types`, `pnpm build`를 로컬에서 돌려 통과를 확인했다. 문구와 주석만
바뀐 작업이라 브라우저 확인은 하지 않았다.
