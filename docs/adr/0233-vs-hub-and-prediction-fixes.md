# VS 개편과 예측 카드 레이아웃 수정

2026-11-02, KAN-703. 사용자가 데브 화면에서 찾은 예측 UI 문제를 현재 develop 작업 공간에서 수정했다. 처음에는 두 레이아웃 버그였지만 같은 대화에서 투표 메뉴를 VS로 바꾸고 밸런스게임·승부예측·랭킹을 묶는 요청까지 이어졌다. 이 문서는 같은 작업의 변경 이유와 검증 범위를 함께 남긴다. 커밋과 배포는 하지 않았다.

## 0명 예측과 카드 높이

경기가 끝났고 참여자가 0명인 화면에서 분포 바가 왼쪽에 짧게 남았다. overflow로 잘린 것이 아니라 세 구간의 flex-grow가 모두 0이어서 최소 너비만 차지하는 문제였다. 공개 분포가 전부 0일 때만 세 구간에 같은 성장 비율을 줬다. 숫자는 여전히 0%다. 데이터가 없는 상태를 33%의 예측처럼 보이게 만들지 않았다. 정상 분포와 비공개 분포는 기존 규칙을 유지했다.

홈 트랙은 대표 의견이 있는 카드와 없는 카드의 높이가 달랐다. 각 li와 링크를 flex로 연결하고 공용 카드가 링크 너비와 높이를 채우게 했다. 참여자 수에는 margin-top: auto를 줘 바닥을 맞췄다. 처음에는 의견 없는 행을 제거하는 정책을 유지했지만, 이후 사용자가 참여 유도 문구를 요청해서 의견 영역도 일정한 최소 높이를 차지하도록 바꿨다. 공개 상태에서 의견이 없으면 빈 상태를, 미참여 상태에서는 블러 실루엣과 안내를 보여준다.

홈은 경기 카드당 대표 의견 최대 한 개다. 기존 예측 API는 적중률순 대표 의견 앞 40자를 내려주고 프런트는 한 줄로 말줄임한다. 더 많은 의견은 카드를 눌러 경기 예측 상세에서 확인한다. 기존 홈 설계는 [ADR 0229](0229-home-prediction-section.md)에 있다.

## VS에서 상세까지

메뉴 이름을 VS로 바꾸고 밸런스게임, 승부예측, 랭킹 세 탭을 넣었다. 기존 /debates 경로를 유지했다. 기본 탭의 내부 키 open도 남겨 기존 URL을 깨지 않게 했지만 진행 중·마감 탭은 제거했다. 예전 tab=closed 주소도 이제 합친 밸런스게임 목록으로 들어간다. 새 예측 탭은 tab=prediction이다.

밸런스게임 목록은 제목, 양쪽 선택지와 가운데 VS, 하나로 이어지는 비율 바, 대표 댓글 한 줄, 참여자 수 순서로 그린다. 목록에서 누르는 것은 투표 실행이 아니라 게시물 진입이다. 전체 카드를 링크로 만들고 링크에는 게시물 제목을 포함한 접근성 이름을 줬다. 예측 목록도 같은 방식으로 경기 예측 상세를 연다. 경기 상세에서는 예측을 지원하는 경기의 첫 탭을 예측으로 바꿨다. 예측 미지원 경기나 연기·취소 경기의 기존 탭 규칙은 유지한다.

마감은 FINISH 또는 closesAt 도달로 판단한다. 원본 배열을 바꾸지 않는 stable partition으로 진행 중인 항목을 먼저 놓고 마감된 항목을 뒤로 보낸다. stable partition은 같은 그룹 안에서는 서버가 준 순서를 유지하며 둘로 나누는 방식이다. 화면을 오래 열어 둬도 마감 시간이 지나면 정렬과 공개 여부가 바뀌도록 가장 가까운 마감에 타이머를 잡았다.

## 참여 전과 마감 후 댓글

사용자에게 마감 후 공개 정책을 확인했고, 참여 여부에 관계없이 모두 결과와 의견을 읽는 것으로 확정했다. 진행 중에는 참여 전 댓글 영역에 “참여하고 여론을 확인하세요!”를 표시한다. 실제 댓글을 CSS로 흐리게 만들면 DOM에서 본문을 읽을 수 있으므로 회색 실루엣만 그린다. 상세의 댓글 목록과 작성기는 게이트가 열릴 때까지 마운트하지 않아 조회도 시작하지 않는다. 일반 기사 댓글에는 이 조건을 적용하지 않는다. 기사 상세와 릴 상세에 같은 규칙을 적용했다.

투표 UI는 원래 서버 응답 전에 선택 상태를 바꾸는 낙관적 갱신을 쓴다. 이 상태만 보고 댓글 잠금을 풀면 첫 투표 요청이 실패해도 응답 전에 댓글을 조회할 수 있었다. 투표 뮤테이션에 토론별 키를 부여하고 게이트에서 진행 중인 요청의 이전 투표를 확인한다. 이전 투표가 없으면 성공 응답까지 잠금을 유지한다. 이미 참여한 사람이 선택을 바꾸는 경우에는 기존 열람 권한을 유지한다. 성공 후 목록을 무효화해서 대표 의견도 다시 받게 했다.

이것은 프런트 화면 정책이다. 직접 댓글 API를 호출하는 접근까지 막으려면 서버가 참여 여부를 확인해야 한다. 해당 변경은 백엔드 티켓에 별도로 요청했다.

## 아직 백엔드가 필요한 부분

[요청 티켓 KAN-704](https://whoru3918.atlassian.net/browse/KAN-704)를 만들었다. 밸런스게임 목록에 topOpinion 필드를 추가하고, 미참여자의 진행 중 댓글 읽기·쓰기를 서버에서 제한하며, 마감된 예측까지 이어 보는 목록 API를 요청했다. 대표 댓글은 좋아요 많은 원댓글 우선으로 제안했으며 삭제·숨김·차단 제외와 동률 정렬 기준을 함께 적었다. 이는 기존 예측의 적중률순 대표 의견과 별도 규칙이다.

현재 밸런스게임 API에는 대표 댓글이 없다. 선택 필드로 매핑해 계약 추가 후 바로 표시되도록 했고, 필드가 빠진 구버전 응답에서는 공개 카드에 “의견 보기”를 표시한다. null이 명시적으로 내려오는 경우는 실제 빈 상태인 “아직 의견이 없어요”로 구분한다. 서버 데이터 없이 대표 댓글을 만들어 넣지 않았다.

예측 목록은 GET /api/v1/predictions?size=20&cursor=... 계약을 요청했다. 기존 홈 카드 형태의 items와 nextCursor를 받는다. 첫 페이지가 404인 동안만 기존 홈 API로 대체한다. 서버 오류나 다음 페이지 실패를 홈 데이터로 덮으면 실패를 감추거나 중복 목록을 만들므로 그런 경우에는 재시도 UI를 보여준다. 이 호환 동작 때문에 백엔드 배포 전에는 홈 API가 제공하는 경기만 보이며 전체 마감 이력은 아직 제공되지 않는다. 목록 전체에서 진행 중이 먼저 오도록 서버 정렬과 커서 안정성도 요청했다.

예측 쓰기 뒤에는 새 목록 캐시도 무효화한다. 쿼리 훅은 [ADR 0232](0232-prediction-query-hooks-promotion.md)의 공용 core 구조를 그대로 확장했다. 랭킹은 [ADR 0230](0230-prediction-ranking-tab.md)의 기존 화면을 세 번째 탭에 유지했다.

## 확인한 것과 남은 검증

단위 테스트 279개, 저장소 훅 테스트 40개가 통과했다. 타입 검사 6개 작업과 린트 5개 작업, 웹·모바일 프로덕션 빌드 2개 작업도 통과했다. 새 테스트는 마감 정렬, 마감 시각 경계, 두 앱의 첫 경기 탭, 예측 목록의 첫 404 대체와 다른 오류 전파, 커서 전달을 확인한다. 기존 E2E의 메뉴 이름과 카드 선택자도 새 UI에 맞췄지만 배포 환경 E2E 실행은 하지 않았다.

프로덕션 빌드의 컴파일·타입 검사·페이지 생성은 성공했지만, 빌드 환경의 백엔드 연결은 ECONNREFUSED로 실패했다. 홈·경기 등 정적 데이터는 기존 오류 대체 경로로 생성됐다. 따라서 빌드 성공은 실제 API 연결 성공을 뜻하지 않는다. E2E 코드의 별도 TypeScript 검사도 통과했다.

처음 단위 테스트에서 웹의 명시적 상태별 탭 배열을 빠뜨린 것이 드러났다. 모바일 헬퍼만 바꾸면 웹은 여전히 프리뷰가 첫 탭이었다. 웹 배열도 수정한 뒤 통과했다. 타입 검사에서는 retryUnlessClientError 함수를 호출하지 않고 그대로 전달한 오류를 잡았고 기존 쿼리와 같은 호출 형태로 고쳤다. 최초 샌드박스 빌드는 출력 없이 멈춰 이번 작업의 빌드 프로세스만 종료한 뒤 일반 실행 환경에서 다시 돌렸으며 두 앱 모두 빌드됐다.

브라우저에서는 실제 공유 컴포넌트의 0/0/0, 일반 60/0/40, 비공개 바를 sm/lg로 확인했다. 444px에서 0% 세 구간은 각각 약 146.5px였다. 홈 카드의 의견 있음·없음·비공개 조합은 320px와 480px 컨테이너에서 높이와 참여자 수 하단이 같았다. 임시 렌더링 페이지는 확인 후 제거했다.

VS는 모바일 375px에서 카드 잘림 없이 제목, 양쪽 선택지, 비율 바, 안내가 보였다. 카드 전체를 눌러 상세로 이동했고 미참여 상태에서는 댓글 대신 안내가, 마감 게시물에서는 실제 댓글이 보였다. 경기 상세를 쿼리 파라미터 없이 열어 예측이 기본 선택된 것도 확인했다. 웹에서는 세 탭 전환과 예측 목록, 시즌 랭킹 표시를 확인했다.

로컬 백엔드 목업에는 개인 기사 상태 조회가 없어 투표 성공 후 개인 캐시가 채워지고 댓글이 열리는 전체 연동 검증에는 한계가 있었다. 실제 API에서의 투표 성공·실패, 익명/게스트/소셜 계정별 서버 권한, 새 대표 의견 응답과 전체 마감 목록은 KAN-704 배포 후 확인해야 한다. 로컬 UI 확인을 데브 배포 완료로 기록하지 않았다.

## 이어서 홈의 정보 순서를 바꿨다

같은 작업 중 사용자가 홈을 실검, 라이브 경기, 승부예측, 투표, 채팅방, 기사 순으로 바꿔 달라고 했다. 핫이슈 상자와 한 줄짜리 VS 배너는 홈에서 제거했다. 기사 목록과 광고, 팀 허브 소개는 유지했고 팀 허브도 같은 홈 구성으로 바뀐다. 홈에서 핫이슈 컴포넌트를 마운트하지 않으므로 핫이슈 기사와 이미지 보강 요청도 더 이상 나가지 않는다.

실검은 기존 trends API를 사용한다. 원래 웹 우측 레일의 목록을 홈 맨 위 한 줄로 옮겼고 모바일에도 같은 순환 UI를 넣었다. STORY 미지원 400일 때만 TEAM으로 대체하며 그때는 실검 대신 구단 순위라고 표시한다. 404나 서버 장애를 다른 순위로 감추지는 않는다. 웹에서 쓰던 순위 변동 배지와 계산 함수를 ui와 domain으로 옮겨 둘이 같은 표시를 쓰게 했다.

공용 RotatingLine은 실검을 4.5초, 경기를 5.5초 간격으로 한 항목씩 아래로 전환한다. 항목 전체를 겹쳐 두고 링크까지 숨기는 방식 대신 현재 항목 하나만 접근 가능한 링크로 그린다. 순서가 끝나면 처음으로 돌아가며 한 항목이면 제어 버튼과 자동 전환이 없다. 빈 경기 목록은 띠를 그리지 않는다. 순서 버튼으로 다음 항목을 수동 확인하고 멈춤 버튼으로 자동 전환을 끌 수 있다. 마우스가 올라가거나 키보드 포커스가 들어온 동안, 화면 밖이나 배경 탭, 움직임 줄이기 설정에서는 자동 전환을 멈춘다. 호버와 포커스를 따로 관리해서 마우스를 밖으로 옮겨도 포커스된 링크가 바뀌지 않게 했다.

진행 중인 경기가 있으면 그 경기들만 서버 순서대로 순환한다. 없으면 예정 경기를 먼저, 끝난 경기를 뒤에 둔 오늘 일정을 보여준다. 기존에는 대표 경기 하나만 골랐지만 이제 라이브 경기 여러 개를 같은 높이에서 확인한다. 점수와 진행 시간은 화면이 보일 때 20초마다 다시 받는다. KST 날짜가 바뀌면 새 날짜 키로 이동하고 운영상 스코어 중단 플래그도 유지한다.

투표는 VS 목록에서 만든 밸런스게임 카드를 홈 가로 트랙에 재사용했다. 승부예측처럼 다음 카드가 걸쳐 보여 가로로 더 볼 수 있고 전체를 누르면 상세로 들어간다. 웹은 좁은 폭에서 한 카드와 다음 카드 일부, 넓은 폭에서 두세 장을 배치한다. 두 카드만 있을 때는 두 칸으로 가로 공간을 채운다. 웹의 우측 실검과 채팅은 본문 순서로 옮겨 중복으로 표시하지 않는다. 웹 채팅은 홈 안에서 바로 읽고 쓸 수 있는 기존 패널을 짧은 높이로 재사용했다.

생동감은 실제 참여 가능 상태와 데이터 변화에 연결했다. 예측 중·투표 중 표식에 점이 천천히 밝아지고, 실제 마감 시각으로 남은 시간을 계산한다. 비율은 값이 바뀔 때 전환하고 참여 수는 변경 시 짧게 등장한다. 숫자나 댓글을 임의로 늘리는 연출은 넣지 않았다. 예측과 투표는 화면에 보일 때 30초마다 갱신하고, 실검은 1분마다 새 집계를 확인한다. 기존 모바일 useOnScreen을 core로 옮겨 화면 밖과 배경 탭에서 폴링을 중단한다. 홈을 당겨서 새로고침할 때도 기사뿐 아니라 이 네 영역을 갱신한다.

첫 모바일 확인에서 서버의 익명 HTML과 브라우저에 남은 내 투표가 달라 하이드레이션 오류가 났다. 스트리밍된 홈 투표 경계보다 인증 상태가 먼저 준비되면 첫 클라이언트 그림에서 이미 투표한 카드가 나왔다. BalanceGameItem이 useHydrated로 첫 렌더를 익명 상태에 맞추고 그 뒤 내 표를 적용하게 고쳤다. 늦게 도착한 카드도 서버 HTML과 같은 상태로 시작한다.

추가 검증에서는 단위 테스트 282개와 훅 테스트 40개가 통과했다. 타입 검사와 린트, 로컬 목업 API를 연결한 웹·모바일 production build도 통과했다. 실검 API가 없는 목업은 404 오류 안내로 처리됐다. 실제 API에서 실검을 받아오는 전체 검증과 목업이 지원하지 않는 채팅 연결은 별도 확인이 필요하다. 별도 임시 화면에서 실제 공용 순환 컴포넌트로 여러 항목의 자동 전환, 수동 다음 항목, 멈춤 유지, 단일 항목과 빈 목록을 확인하고 검증 경로는 제거했다. 모바일 402px와 웹 1280px에서 배치를 확인했고, 웹 330px에서 본문이 겹치지 않고 문서 가로 폭이 330px인 것도 확인했다.

홈 개편 자체는 기존 API로 처리했다. 대표 의견은 이전에 만든 KAN-704의 topOpinion 계약을 홈 투표에서도 소비하므로 그 백엔드 의존성은 그대로 남는다. KAN-703에 홈 개편 범위와 검증 제한을 이어 기록했다. 이 단계에서도 커밋·배포는 하지 않았다.

## 제안 계약이 반영되는 것을 전제로 마무리했다

사용자가 KAN-704의 백엔드 변경이 적용될 것으로 보고 작업을 이어 달라고 했다. 앞에서는 미배포 환경에서도 목록이 보이게 첫 404를 홈 API로 대체했지만, 이제 이 경로가 남으면 전체 마감 이력이 없는 상태를 정상 목록처럼 보여줄 수 있다. VS 목록은 제안한 `/api/v1/predictions?size=20&cursor=...`만 사용하게 바꿨다. 첫 페이지 404도 기존 실패·재시도 화면으로 전달한다. 따라서 새 FE를 배포할 때에는 KAN-704 목록 API를 먼저 또는 함께 배포해야 한다. 제안 계약을 실제 배포 확인과 혼동하지 않도록 목 응답 검증이라고 기록했다.

밸런스게임의 `topOpinion`도 선택 필드에서 필수 nullable 필드로 바꿨다. 이 말은 모든 응답에 필드가 있고, 잠겼거나 댓글이 없으면 값이 null이라는 뜻이다. 미지원 필드일 때 따로 보여주던 “의견 보기” 처리는 제거했다. 예측의 대표 의견은 공용 경계 변환에서도 revealed가 false면 null로 만든다. 서버가 잘못 본문을 붙여 보내더라도 화면용 쿼리 캐시에 비공개 미리보기를 옮기지 않게 했다. 서버에서 본문 자체를 차단하는 책임은 여전히 KAN-704에 있다.

댓글과 투표 목록의 fetch에는 no-store를 명시했다. 참여·마감에 따라 응답이 달라지므로 브라우저 HTTP 캐시나 Next 데이터 캐시가 이전 잠금 응답을 재사용하지 않게 하는 조치다. TanStack Query의 화면 캐시는 그대로 쓰며, 투표 성공 후 목록 무효화도 유지한다. 이는 BE의 사용자별 캐시 분리 요구를 대신하지 않는다.

마감 타이머도 한 군데 보완했다. 기존 타이머는 프런트의 공개 상태와 정렬만 바꿨다. 미참여자에게 내려온 대표 의견은 null이므로, 화면이 마감으로 바뀌어도 새로운 공개 의견은 아직 없었다. 공용 useDebateClock에 마감 시 콜백을 받게 하고 홈과 VS의 두 앱 목록에서 refetch를 연결했다. 32비트 타이머 한도 때문에 실제 마감보다 먼저 깨는 경우에는 재조회하지 않는다. 댓글 상세는 마감 시 컴포넌트를 마운트하며 원래의 조회를 시작하므로 목록의 콜백을 붙이지 않았다.

새 계약 테스트는 실제 fetcher에 목 HTTP 응답을 넣어 확인했다. 투표 미참여 null, 참여 후 대표 의견, 마감 후 익명 공개, 실제 0표와 빈 의견, 예측의 두 페이지와 마지막 null 커서, 특수문자가 든 커서 전달, 비공개 예측 의견 제거, 댓글 403 오류 코드 보존을 다뤘다. 기존 404 대체 테스트는 첫 404·401·500이 그대로 전달되는 검사로 고쳤다. 단위 테스트 286개, 타입 검사 6개 작업, 린트 5개 작업, 웹·모바일 빌드 2개 작업이 통과했다. 이번 검증은 제안 계약 기준이며 실제 KAN-704 배포 후 통합 검증을 대신하지 않는다. 기존 목업 서버는 신설 목록과 대표 의견 계약을 아직 지원하지 않으므로 그 서버의 정상 화면을 최종 계약 검증으로 쓰지 않았다.

## 커밋과 푸시 준비

사용자가 PR은 직접 만들고 커밋과 푸시까지 진행해 달라고 했다. develop과 같은 커밋을 기준으로 codex/KAN-703-home-vs 브랜치를 만들고 이번 구현·테스트·ADR만 모았다. 기존 launch 설정, 모니터링 대시보드, 다른 ADR과 작업 스크립트는 포함하지 않았다. 전체 format:check와 훅 테스트 40개가 통과했고 커밋 훅의 웹·모바일·공용 UI 린트와 포맷도 통과했다.

푸시 전 저장소의 pr-review.sh를 실행했지만 Claude CLI의 세션 사용 한도로 exit 3이 반환됐다. 자동 리뷰는 완료되지 않았으므로 통과로 기록하지 않았다. 대신 커밋 diff에서 홈 데이터 흐름, 참여 게이트와 첫 투표 실패, 마감 재조회, 커서 목록과 오류 처리, 쿼리 무효화, 경기 탭 기본값을 직접 점검했다. 새로운 코드 수정이 필요한 확정 오류는 찾지 못했다. 자동 리뷰가 남았다는 제한은 사용자에게 전달한다.
