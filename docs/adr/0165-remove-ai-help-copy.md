# 0165. 라이브 화면의 "도움 문구"를 걷어낸다 (KAN-559)

날짜: 2026-09-21
브랜치: `feature/KAN-559-remove-help-copy`

## 무엇을 했나

라이브 대시보드와 경기 상세, 순위표, 시즌 스탯 시트, 실시간 급상승 카드 아래에 붙어 있던 안내 캡션을
모바일과 웹에서 모두 지웠다. 티켓이 콕 짚은 문구는 다섯 개였다.

- "라이브 경기는 20~30초마다 자동 갱신돼요" (경기 목록 하단)
- 실시간 급상승 카드의 "N시간 전 집계"
- 순위표 범례에 붙은 "· 1시간마다 갱신돼요"
- "경기가 끝났어요 · 선수 평점은 확정 값이에요" / "라이브 중에는 20초마다 자동 갱신돼요" (요약·스탯 탭 캡션)
- "전반·후반 분리 스탯은 제공되지 않아요" (스탯 카드 하단)

그리고 "등 말도 안 되는 AI 티 나는 글 삭제, 쓸데없는 도움 문구 삭제"라는 말이 붙어 있어서 같은 결의 문구를
더 찾아 함께 지웠다.

- "시즌 누적 스탯이에요 · 하루 1번 갱신돼요" (시즌 스탯 시트·모달)
- "선수를 누르면 경기 스탯을 볼 수 있어요" (모바일 벤치 카드, 웹 라인업 카드)
- "선수를 누르면 시즌 스탯을 볼 수 있어요" (웹 팀 프로필 스쿼드)

## 왜 이 문구들이 생겼고 왜 지우나

라이브 화면을 만들 때 폴링 주기나 데이터 한계(전후반 분리 스탯 없음, 순위 1시간 캐시, 시즌 스탯 하루 1회)를
사용자에게 알려 주는 게 친절하다고 생각해 캡션으로 달았다. 피그마 L6·L9에도 비슷한 자리가 있었다. 그런데
실제로 화면에서 보면 이 문구들은 사용자가 알고 싶은 정보가 아니라 구현자가 변명하는 문장에 가까웠다.
"20~30초마다 갱신돼요"는 사용자가 신경 쓸 일이 아니고, "확정 값이에요"는 스코어가 끝난 경기의 값이
확정이라는 당연한 말이다. "선수를 누르면 ~를 볼 수 있어요"는 누르면 열리는 걸 한 번 누르면 알게 되는데
매번 자리를 차지한다. 이런 문장이 카드 하나마다 붙어 있으니 화면 전체가 챗봇 답변처럼 읽혔다.

## 어떻게 지웠나

grep으로 "갱신돼요", "확정 값", "분리 스탯", "볼 수 있어요" 같은 어미를 쓸어 후보를 모은 다음, 빈 상태 문구
("아직 댓글이 없어요"), 에러 안내("잠시 후 다시 시도해 주세요"), not-found 문구, 다이얼로그 설명은 제외했다.
그건 상태를 설명하는 UI 카피라 지우면 화면이 비거나 뜻이 사라진다. 지운 건 데이터가 정상으로 뜬 화면
아래에 덧붙은 부연 캡션만이다.

파일별로는 이렇게 됐다.

- `MatchDayList` (m·w): 하단 `<p>`를 지웠다. 모바일은 그 `<p>`가 `pb-4`로 목록 아래 여백을 담당하고
  있어서 컨테이너에 `pb-4`를 옮겼다.
- `MatchDetailTabs` (m·w): 요약·스탯 탭 아래 `Caption` 컴포넌트를 통째로 지웠다. 처음엔 스탯 탭 자리만
  지우고 lint를 돌렸는데 요약 탭에도 하나 더 있어서 `'Caption' is not defined`로 걸렸다. grep이 정의 위치만
  보여 줘서 사용처를 놓친 것이다. 두 번째 자리도 지웠다.
- `StatsCard` (w): 캡션 두 개(전후반 안내, 폴링·확정 안내)를 지우니 `status` prop을 쓰는 곳이 없어졌다.
  prop과 `MatchStatus` import를 빼고, 캡션을 카드 밖에 두느라 씌웠던 `div` 래퍼도 벗겨 `section` 하나로
  돌렸다. 호출하는 `MatchDetailTabs`도 `status`를 안 넘긴다.
- `StatsCompare` (m), `SeasonStatsSheet` (m), `SeasonStatsModal` (w): 하단 `<p>`만 지웠다.
- `StandingsTable` (m), `StandingsRail` (w): 범례 문장에서 "· 1시간마다 갱신돼요" 뒤 절만 잘랐다. 앞의
  "챔피언스리그 진출권"은 accent 막대가 무슨 뜻인지 알려 주는 범례라 남겼다.
- `TrendingSection` (w): `collectedAt`으로 "N시간 전 집계"를 그리던 `<p>`를 지우고
  `formatRelativeTime` import도 뺐다. 프래그먼트가 `<ol>` 하나만 감싸게 돼서 프래그먼트도 벗겼다.
  `collectedAt` 자체는 도메인 타입과 core 매퍼에 남아 있다. 화면이 안 쓸 뿐이고 응답 shape은 그대로다.
- `BenchList` (m), `LineupCard` (w), `SquadGrid` (w): 제목 옆 힌트 span을 지웠다. 제목과 힌트를 양끝
  정렬하던 `flex justify-between` 래퍼도 필요 없어져서 `h2`만 남겼다.

## 남긴 것과 이유

`PreviewBlocks`·`PreviewGrid`의 "예상 라인업이 아니라 직전 경기의 확정 선발이에요"는 같은 어미지만 남겼다.
코드에 "명세가 요구하는 FE 표기다, 지우지 말 것"이라는 주석이 붙어 있고, 실제로 이 카드는 예상 라인업으로
오해할 여지가 있어서 부연이 뜻을 바꾼다. 웹 라이브 페이지 헤더의 "프리미어리그 경기와 순위를 한눈에 볼 수
있어요"도 페이지 소개 문장이라 두었다. 시즌 스탯 빈 상태의 "경기에 출전하면 대회별 기록이 여기에 쌓여요"는
빈 상태 보조 문구라 두었다.

이 판단은 내 기준이라 사용자가 보고 더 지우자고 하면 같은 ADR에 이어 쓴다.

## 검증

`pnpm format:check`, `pnpm lint`, `pnpm check-types`, `pnpm build`를 로컬에서 돌렸다. 빌드 로그에
`fetch failed`가 여럿 찍히는데 이건 로컬 BE가 꺼져 있어 정적 생성 단계의 초기 로드가 실패하는 기존
현상이고 빌드 결과에는 영향이 없었다. 브라우저 확인은 문구 제거만이라 생략했다.
