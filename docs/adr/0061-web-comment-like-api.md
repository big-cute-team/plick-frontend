# 0061 — 웹 댓글 좋아요 API 이식 (KAN-331)

- 상태: Accepted
- 날짜: 2026-07-29
- 범위: `apps/web`. 댓글·대댓글 좋아요 등록·취소(`POST`·`DELETE /api/v1/comments/{commentId}/like`)를
  기사 세부와 릴 세부 패널의 댓글 목록에 붙인다. KAN-329에서 "그 이식 티켓 몫"으로 미뤄 둔
  표시 전용 하트를 진짜 버튼으로 바꾸는 일이다.
- 관련: [ADR 0045 모바일 댓글 좋아요](0045-comment-like-api.md) · [ADR 0060 웹 좋아요 이식](0060-web-article-like-api.md) ·
  [ADR 0058 웹 댓글 API](0058-web-comments-api.md) · [ADR 0011 공용 경계](0011-shared-code-boundary.md)

---

## 예고된 대로 흘러간 티켓

ADR 0060을 닫으며 "그 티켓은 `useCommentLike`와 `comment-likes.ts`만 복제하면 된다"고 적어 뒀는데,
정말 그대로였다. 계약은 모바일 코드가 들고 있고(KAN-309, ADR 0045), 웹엔 이미 `useLikeToggle` 뼈대와
`LoginPromptDialog`, `LIKE_LOGIN_PROMPT`까지 KAN-330에서 다 들어와 있었다. `be-verify`를 부를 조건
(새 엔드포인트, BE 변경 정황)도 없었다.

계약을 다시 적어 두면 이렇다. 기사 좋아요와 완전히 같은 모양이다.

- `POST`·`DELETE /api/v1/comments/{commentId}/like`, 봉투를 벗기면 `{ likeCount }` 하나.
- 둘 다 멱등. 이미 누른 댓글에 POST를 또 보내도 409가 아니라 200에 현재 카운트가 온다.
- 에러는 401 `AUTH_REQUIRED`, 404 `COMMENT_NOT_FOUND`, 400 `COMMON_INVALID_PARAM`.
- 원 댓글과 대댓글이 같은 엔드포인트다. 조회 응답에서 대댓글이 부모의 `replies`에 인라인으로
  딸려 올 뿐 좋아요 계약은 같다.
- 소프트 삭제된 댓글도 BE는 200으로 받아 준다. 막는 건 화면 몫인데, 웹 `CommentThread`도 모바일과
  같이 tombstone이면 액션 줄을 아예 안 그리므로 손댈 게 없었다.

## 승격할 게 남아 있지 않았다

web 이식의 본편은 승격 판단인데, 이번 엔드포인트가 쓰는 조각은 전부 앞 티켓들이 정리를 끝내 놨다.

| 조각                           | 상태                                         |
| ------------------------------ | -------------------------------------------- |
| `LikeState`·`ToggleLikeResult` | KAN-330에서 `@plick/domain/types` 승격 완료  |
| `apiFetch`·`ApiError`          | KAN-318에서 `@plick/core/client` 승격 완료   |
| `commentKeys`                  | KAN-329에서 `@plick/core` 승격 완료          |
| `_services/comment-likes.ts`   | web에 복제 — `"use server"` 파일은 안 올린다 |
| `useCommentLike`               | web에 복제 — 훅은 앱별 복제라는 네 번째 반복 |

그래서 이 PR의 새 파일은 복제 둘(`comment-likes.ts`, `useCommentLike.ts`)이 전부고, 승격 이동은 없다.
서버 액션을 안 올리는 이유(쿠키 이름이 앱 상수라 게이트 A 실격)와 훅을 안 올리는 이유(승격분을 걷어내면
얇은 껍데기)는 ADR 0060에 적은 그대로다.

## 화면은 자리만 채우면 됐다

웹 `CommentThread`는 KAN-329에서 댓글 읽기를 붙일 때 좋아요 하트를 표시 전용으로 그려 뒀고, 주석에
"댓글 좋아요는 별도 엔드포인트라 그 이식 티켓 몫"이라고 박아 뒀다. 그 `span`을 모바일과 같은
`CommentLikeButton`으로 바꾸고, 데스크톱이라 hover와 focus-visible 스타일만 얹었다(모바일은
`active:opacity-60`, 웹은 답글 버튼과 같은 `hover:opacity-80` + 포커스 링).

원본이 캐시 하나뿐이라 단순하다는 모바일의 결론(ADR 0045)이 웹에서도 그대로 성립한다. 기사 세부는
서버가 첫 페이지를 씨앗으로 심고 릴 세부 패널은 클라에서 처음 받지만, 둘 다 `commentKeys.list(articleId)`
하나를 본다. `useCommentLike`가 캐시만 고치면 두 화면이 같이 맞는다. 릴 패널이 닫힘 애니메이션 때문에
마지막 릴을 붙들고 계속 마운트돼 있는 문제(ADR 0058)도 좋아요에는 안 걸린다 — 패널 로컬 state가 아니라
캐시가 원본이라 리셋할 게 없다.

대댓글 캐시 갱신(`applyLike`의 2단 순회)도 모바일 그대로다. 대댓글의 `replies`는 계약상 항상 빈
배열이라 재귀 없이 2단에서 멈추고, 안 바뀐 항목은 원래 객체를 돌려줘 무관한 댓글의 리렌더를 막는다.

## 검증 중에 사용자가 먼저 밟았다

이번에도 검증 표면부터 정리했다. 브라우저 패널은 KAN-330에서 확인한 대로 숨김 상태 뷰포트 0x0이라
하이드레이션이 진행되지 않는다. 이번엔 의심 없이 `read_page`로 뷰포트 0x0만 확인하고 바로 실제
Chrome으로 넘어갔다. 지난번 삽질이 이번 시간을 아꼈다.

재밌는 건 그다음이다. 검증용 일회용 유저를 만들고 토큰까지 민팅해 뒀는데, 실제 Chrome을 열어 보니
사용자가 이미 로그인된 세션으로 직접 눌러 보고 있었다. 기사 세부의 원 댓글 좋아요와 릴 패널의 댓글
작성·좋아요를 먼저 확인하고 "잘되는거확인했어"라는 메시지가 작업 중간에 도착했다. 민팅한 토큰은
쓸 일이 없어졌고, 남은 경로만 그 세션에서 마저 밟았다.

- 대댓글 좋아요: 답글 하트 클릭 → 그 답글만 0에서 1, 형제 답글과 부모는 그대로. BE 조회와
  `comment_likes` 테이블로 대조하고 다시 눌러 0으로 되돌렸다(행 삭제까지 확인).
- 릴 세부 패널: 사용자가 남긴 좋아요를 취소 → 재등록으로 왕복. 캐시 갱신이 패널에서도 즉시 반영됐고
  원래 상태(좋아요 1)로 복구해 뒀다.
- tombstone: 삭제된 댓글엔 하트가 아예 안 그려진다.
- 콘솔 에러 없음.

비로그인 팝업과 롤백 경로는 따로 안 밟았다. Chrome이 사용자 세션으로 로그인돼 있어 익명 클릭을
만들려면 로그아웃을 해야 하는데, 남의(정확히는 사용자의) 세션을 검증 때문에 끊는 건 아니라고 봤다.
그 분기는 전부 `useLikeToggle` 안에 있고 KAN-330에서 같은 웹 코드로 검증된 경로라, 이번 버튼이 새로
보태는 코드가 아니다.

일회용 유저는 자식 행이 없는 걸 확인하고 지웠다. 검증으로 만든 좋아요는 전부 원상 복구했다.

`pnpm --filter web build`, `check-types`, `lint`, `format:check` 통과. 공용 패키지는 안 건드려
모바일 빌드 회귀는 볼 게 없다.

## 남은 것

- 이걸로 web-wiring §5 이식 순서의 6번(뮤테이션) 중 좋아요 계열은 다 끝났다. 남은 뮤테이션은
  조회수 정도다.
- 좋아요 실패 중 401이 아닌 것(없는 댓글, 순단)은 문구 없이 되돌리기만 한다. 모바일·기사와 같은 판단.
- 로그아웃 시 캐시 비우기(`queryClient.clear()`)는 KAN-318 웹 로그아웃에 이미 들어와 있어 모바일의
  "로그아웃 후 남의 하트" 버그(ADR 0045)는 웹에서 처음부터 막혀 있다.
