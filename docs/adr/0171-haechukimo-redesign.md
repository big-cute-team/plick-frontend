# 0171. 해축이모 리디자인. 라이트 토큰, Noto Sans KR, 브랜드 교체, 두 앱 전 화면 (KAN-567)

- 티켓: KAN-567 "[FE] UI 와 디자인토큰, 전체 개편"
- 브랜치: `feature/KAN-567-redesign`
- 입력: `~/Downloads/design_handoff_haechukimo/` (README + 웹·앱 프로토타입 HTML 두 벌 + 빅6 엠블럼 PNG)

## 어디서 출발했나

디자이너가 준 핸드오프 폴더 하나로 시작했다. README와 `source/*.dc.html` 두 파일이 전부인데, HTML은
스타일이 전부 인라인이고 하단 `<script data-dc-script>` 안 `class Component`에 상태 로직까지 들어 있어
텍스트로 열면 그 자체가 스펙이었다. 티켓은 "폴더 속 웹, 앱 html 파일과 다른 요소들을 전부 보고 최대한
새로운 디자인에 맞게 모든 디자인을 변경한다. UX 관련은 기존 것을 유지한다"였다.

먼저 폴더와 저장소를 읽고 네 가지를 물었다. 브랜드를 정말 "해축이모"로 바꾸는지(로고만인지 메타데이터까지인지),
시안이 현재 UX와 다른 곳(LIVE 목록 아래 순위표, 웹 목록의 표와 페이지 버튼, 경기별 채팅 대신 통합 채팅방, 기자
프로필, 웹 릴스 댓글 패널 상시 열림)을 어디까지 따라가는지, 작업 단위를 어떻게 나누는지, 폰트를 Noto Sans KR로
바꾸는지 Pretendard로 대체하는지. 답은 전부 해축이모로, 시안을 최대한 그대로 따라가되 BE가 필요한 건 백엔드용
티켓으로 목록화, 브랜치 하나에 PR 하나, Noto Sans KR 셀프호스팅이었다.

## 토큰을 어떻게 뒤집었나

`packages/tokens/theme.css`는 다크가 `:root`고 라이트가 `[data-theme="light"]` 오버라이드였다. 앱은 다크
고정이었고 라이트 블록은 "나중에 토글을 되살릴 때"를 위해 잠들어 있었다. README는 "라이트로 간다. theme.css의
light 블록을 살리는 방향"이라고 했는데, 그대로 하면 새 디자인 값을 전부 오버라이드 블록에 쓰고 `:root`에는 이제
아무도 안 쓰는 옛 다크 값이 남는다. 새 토큰(투표 카드 면, 피치색 등)마다 다크 짝도 채워야 한다. 그래서 반대로
했다. `:root`가 새 라이트 팔레트고, 옛 다크 팔레트를 `[data-theme="dark"]` 블록으로 옮겨 잠재웠다. 화면은
토큰만 쓰니 그 셀렉터가 살아나면 그대로 뒤집힌다는 성질은 같다.

토큰 이름은 최대한 유지했다. `bg-bg`, `text-text`, `text-text-3`, `border-border`, `bg-accent`, `text-danger`
같은 이름은 저장소 300여 파일이 쓰고 있어서, 값만 시안 팔레트로 바꾸면 손대지 않은 화면(로그인, 온보딩, 약관)도
라이트로 자동 전환된다. 다만 의미가 바뀐 것이 있다. `text-4`는 다크에서 가장 흐린 회색이었는데 시안이 "회색 글자
하한은 #767676"이라 그 값으로 못 박았다. `danger`는 에러색이었는데 시안의 빨강(#e8342a)이 댓글 수, 새 글, 하트,
BEST, VS, LIVE 전용이라 그 뜻으로 쓴다. 새로 추가한 건 면 네 종(`elevate`, `elevate-2`, `chip`, `input`이 시안에서
#f6f7f8, #f7f8f9, #f2f4f5, #f4f6f5로 미세하게 다르다), 선 네 종(섹션, 목록 행, 표 머리, 레일 테두리), 투표 카드
색 열 개, 피치와 비교 바 색, 딤 두 단계, 웹 릴 카드용 어두운 면이다.

글자 크기는 시안 픽셀을 그대로 이름 붙였다. 10, 10.5, 11, 11.5, 12, 12.5, 13.5, 14, 15, 16, 17, 19, 21, 22,
23, 24, 30, 38, 46. 소수점 값도 시안 값이다. 자간은 em 단위 일곱 개. 라운드는 저장소 토큰 여섯 개가 시안 값과
정확히 같아 그대로 두고, 웹은 `apps/web/app/globals.css`에서 `@theme`로 라운드 토큰을 전부 0으로 덮었다.
README의 "웹은 전부 각진 상태를 유지하고 앱만 모서리를 쓴다"를 컴포넌트마다 분기하지 않고 토큰 층에서 끝낸
것이다. `@plick/ui`의 `VoteCard`가 `rounded-card`를 써도 웹에서는 각지게 나온다.

`px-edge`는 20에서 16으로 줄었다. 시안 앱 셸의 좌우 여백이 16이다. 목록 오른쪽 기자 칼럼 88px은 `w-reporter`
토큰으로 뺐다.

## 폰트

시안은 Noto Sans KR 400, 500, 700, 900이다. README가 Pretendard 대체를 허용했지만 사용자가 Noto를 골랐다.
저장소는 KAN-421에서 Pretendard를 `next/font/local`로 셀프호스팅하고 있었고(KS X 1001 서브셋 285KB) 그 배관을
그대로 쓰기로 했다. google/fonts 저장소의 가변 TTF(10MB)를 받아 fonttools로 서브셋했다.

여기서 한 번 틀렸다. KS X 1001 완성형 2,350자를 뽑으려고 파이썬 `euc_kr` 코덱으로 인코딩되는 음절만 걸렀는데
11,172자가 전부 통과했다. 파이썬의 euc-kr은 KS X 1001 밖 음절을 8바이트 조합형으로 인코딩해 버린다. `cp949`로
인코딩한 바이트가 0xB0A1~0xC8FE 범위인지로 다시 걸러 2,350자를 얻었다. 결과는 가변 woff2 329KB다. 전 음절이면
1.06MB였다.

fonttools는 시스템 파이썬을 더럽히지 않으려고 `pip install --target`으로 스크래치 폴더에만 설치했다. 절차는
`scripts/fonts/subset-noto.sh`와 README로 남겼다. OG 이미지는 satori(next/og)가 woff2와 가변 폰트를 못 읽어
700·900 정적 인스턴스를 TTF로 따로 만들어 `apps/web/assets/og`에 뒀다.

## 브랜드

`packages/domain/src/brand.ts`의 상수를 전부 바꿨다. 로고는 SVG 워드마크에서 글자 로고로 바뀌었다. "해축"은
강조색, "이모"는 제목색, 900에 자간 -.06em. `@plick/ui` `Logo`가 `height` 대신 `size`(px)를 받는다. 정적 OG
이미지와 파비콘도 다시 그렸다. 파비콘은 강조색 둥근 사각 위 흰 "해" 한 글자다. resvg가 글자를 그리려면 폰트
파일이 필요해 favicon 스크립트가 OG용 Noto Black TTF를 읽게 했다. 동적 OG 카드(`OgCard`)는 흰 바탕에 팀 컬러
세로 띠, 로고 워터마크는 라이트라 불투명도를 0.3에서 0.12로 낮췄고, 루머 단계 배지는 시안 규칙대로 뺐다.

## 공용 UI

`VoteCard`는 시안의 "투표 카드" 항목을 그대로 옮겼다. 트랙 높이가 투표 전 36, 결과 40, 내 선택 44(sm은 4씩
작게)이고 fill은 A가 딥 그린, B가 밝은 그린이다. 전에는 B가 파랑(info)이었다. 모프 애니메이션 구조(같은 DOM에서
width, height, background-color만 .8s 전환)는 ADR 0108 그대로다.

`NewBadge`는 accent 틴트 "NEW"에서 빨간 바탕 흰 "N"으로, `DebateLiveChip`(번쩍이는 VS 칩)은 빨간 글자 하나인
`VsMark`로 바뀌었다. 시안이 "투표가 붙은 이슈는 빨간 VS 글자로만 표시한다"고 못 박아서다. `LiveCrest`의 빅6 밖
폴백은 회색 원(#eceef0 바탕, #767676 글자)이다.

모바일 셸은 상단 바 46px(로고 19 + 햄버거 20), 세부 화면용 `SubTopBar`(뒤로 22 + 왼쪽 정렬 제목 13.5/700 +
오른쪽 액션), 하단 탭 54px(아이콘 22 + 라벨 10/700, 활성 강조색)이다. 전에는 화면마다 가운데 정렬 제목 상단바가
따로 있었는데(ProfileTopBar, MatchTopBar, EditTopBar, BlockedTopBar, ActivityTopBar, DocTopBar) 시안이 한
모양이라 하나로 모았다. 확인이 필요한 행동은 팝업이 아니라 바텀 시트(radius 26, 그랩 핸들)라 `BottomSheet`를
만들고 신고, 차단, 삭제 확인, 로그인 안내, 공유가 전부 그 위에 내용만 얹는다.

## 화면 작업을 어떻게 나눴나

두 앱 전 화면이라 혼자 순서대로 하면 하루로 안 끝난다. 기반(토큰, 폰트, 브랜드, 공용 UI, 셸, 홈)을 먼저 끝내
커밋하고, 나머지를 다섯 묶음으로 나눠 서브에이전트에 동시에 맡겼다. 모바일은 기사·댓글·릴스 / LIVE / 투표·MY·
프로필·인증 세 묶음, 웹은 셸·홈·기사·레일 / 릴스·MY·LIVE·투표·프로필 두 묶음이다. 공통 브리프에 토큰 매핑표
(시안 hex → 유틸), 시안 파일의 화면별 줄 범위, 이미 끝난 조각, 지울 것(단계 라벨, 기자 등급, 외 N명, 칩 세 종),
문구 규칙, 파일 소유권을 적어 서로 같은 파일을 만지지 않게 했다. 웹의 공용 조각(LiveStrip, TrendingRail,
ChatRail, SiteFooter)은 한 에이전트가 만들고 다른 에이전트는 자리에 TODO 주석만 남겨 내가 나중에 붙였다.

(이하 에이전트 결과와 검증, API 공백 목록은 작업이 끝나는 대로 이어 쓴다)
