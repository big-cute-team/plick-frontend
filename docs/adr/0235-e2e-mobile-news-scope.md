# 홈 개편 뒤 모바일 기사 E2E의 탐색 범위를 좁혔다

2026-11-02, KAN-703 후속. 홈 개편 뒤 dev E2E가 두 번 연속 실패해 실행 로그와 실패 당시 접근성 스냅샷을 확인했다. 16:53과 18:15(KST)에 시작한 실행 모두 18개 중 16개는 통과했고, 모바일 기사 상세 진입과 팀 해시태그 이동 두 시나리오만 실패했다. 재시도에서도 같은 요소를 찾다 45초 제한에 걸렸다.

테스트는 페이지의 첫 `article`을 뉴스 카드라고 가정하고 그 안의 `h3` 안에서 링크를 찾았다. KAN-703이 홈 뉴스보다 위에 투표 카드 트랙을 추가하면서 이 가정이 깨졌다. 투표 카드도 독립된 콘텐츠를 나타내는 HTML `article` 태그를 쓴다. 링크는 카드 전체를 바깥에서 감싸므로 제목 안에는 링크가 없다. 실패 기록에서도 첫 `article`은 투표 카드였고 실제 뉴스 목록은 그 아래 정상적으로 있었다. 이번 실패를 게스트 예측 403이나 투표 503으로 볼 근거는 없었다.

화면 순서나 카드 태그를 바꾸는 대신 테스트가 목적에 맞는 영역을 찾게 했다. `fixtures/locators.ts`에 `mobileNewsFeed`를 두고, `지금 올라온 소식`이라는 정확한 2단계 제목을 가진 `section`으로 범위를 좁혔다. 해당 섹션에는 접근성 이름이 없어 `getByRole("region", { name })`을 바로 쓸 수 없다. 기존 화면에 있는 제목으로 좁히면 앱 재배포를 기다리지 않고 현재 dev에서도 수정한 테스트를 검증할 수 있다.

첫 기사 제목 확인과 상세 이동뿐 아니라 팀 필터 선택, 이동한 팀 허브의 기사 표시, 더 보기 전후 기사 개수 비교도 같은 영역을 쓰게 했다. 특히 페이지 전체의 `article` 개수를 세면 투표 카드의 늦은 로딩이 기사 증가로 오인될 수 있다. 이제 더 보기 버튼과 개수 측정이 같은 뉴스 영역을 기준으로 동작한다. 특정 기사 ID나 카드 순번을 하드코딩하지 않았고, 기존 단언과 타임아웃도 유지했다.

실패 근거는 [E2E 41419149848](https://github.com/big-cute-team/plick-frontend/actions/runs/41419149848), 관련 홈 변경은 [ADR 0233](0233-vs-hub-and-prediction-fixes.md)에 남아 있다.

수정 후 실제 dev를 대상으로 `pnpm --filter @plick/e2e exec playwright test --project=mobile specs/mobile/articles.spec.ts --workers=2`를 실행했다. 기사 상세, 팀 해시태그, 팀 필터, 더 보기, 옛 목록 주소 이동까지 5개가 7.3초에 모두 통과했다. 투표나 댓글을 제출하는 시나리오는 실행하지 않았다. 전체 18개 E2E 재실행은 하지 않았으며 이번에 수정한 기사 파일을 검증했다.

`format:check`, `lint`, `check-types`, `test:hooks` 40개, `test:unit` 286개도 통과했다. `build`는 웹과 모바일 모두 기존 성공 결과의 Turbo 캐시를 사용했다. 앱 소스와 빌드 입력은 바뀌지 않았고 이번 변경은 테스트 두 파일과 이 기록뿐이다.
