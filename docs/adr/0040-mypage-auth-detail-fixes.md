# 0040. 마이페이지·인증 화면 디테일 수정 (KAN-300)

KAN-300 티켓을 받아서 마이페이지와 로그인·회원가입 화면의 디테일 두 가지를 손봤다.

1. 로그아웃하면 로그인 화면이 아니라 홈으로 보낸다.
2. 로그인·회원가입 화면의 우측 상단 "둘러보기" 버튼을 없애고, 하단에 "로그인 없이 이용하기"
   버튼을 새로 만들었다. 누르면 바로 이동하지 않고 비로그인 제한 안내 팝업을 먼저 띄운다.

## 1. 로그아웃 후 홈으로

로그아웃은 `app/_services/auth.ts`의 `logout()` 서버 액션이 처리한다. 여기서 서버 액션이란
`"use server"`가 붙은 함수로, 클라이언트에서 함수 호출처럼 보이지만 실제로는 서버로 POST 요청이
날아가 서버에서 실행되는 함수다. 토큰 쿠키가 HttpOnly라(브라우저 JS가 읽지도 지우지도 못하는
쿠키) 삭제도 서버에서 해야 하고, 그래서 로그아웃 전체가 서버 액션으로 되어 있다.

수정 자체는 한 줄이었다. 액션 마지막의 `redirect("/login")`을 `redirect("/")`로 바꿨다.
이 `redirect()`는 페이지 리로드가 아니라 소프트 내비게이션이다. 서버 액션 응답에 리다이렉트
지시가 실려 오면 Next 라우터가 클라이언트에서 해당 경로의 RSC 페이로드를 받아 화면만 갈아끼운다.
쿠키 삭제(`Set-Cookie`)가 같은 응답에 실려 있으니, 갈아끼운 홈은 이미 비로그인 상태로 렌더된다.
`LogoutButton`의 JSDoc에 남아 있던 "`/login`으로 redirect" 문구도 같이 고쳤다.

## 2. 둘러보기 → 로그인 없이 이용하기

로그인·회원가입 화면은 `AuthScreen` 하나를 카피만 주입해 공용한다. "둘러보기"는 로그인 화면만
`homeHref="/"`를 넘겨서 우측 상단에 떴는데, 이번에 `homeHref` prop 자체를 없앴다. 상단바는
이제 회원가입의 뒤로가기(`backHref`)가 있을 때만 렌더되고, `justify-between`으로 양끝 정렬하던
`innerClassName`도 좌측 하나만 남아 필요 없어져 지웠다.

새 진입 경로는 하단이다. `app/_components/GuestEntryButton.tsx`를 만들어 `BottomActionBar`의
전환 링크("처음이신가요? 회원가입") 아래에 넣었다. 로그인·회원가입이 화면을 공용하니 버튼도
양쪽에 다 뜬다. 티켓이 "로그인 및 회원가입 화면에서"라고 했으니 의도에 맞다.

버튼을 누르면 바로 홈으로 보내지 않고 팝업을 띄운다. 팝업은 이미 앱에 있던 스크림 + 카드 관용을
그대로 따랐다. `LogoutButton`의 로그아웃 확인 팝업, `ErrorDialog`와 같은 구조다. 범용 Dialog
프리미티브가 아직 없어서 이번에도 컴포넌트 안에 인라인으로 넣었는데, 같은 관용이 세 번째로
반복된 셈이라 다음에 손볼 일이 생기면 공용 컴포넌트로 빼는 걸 고려할 만하다.

문구는 처음에 "응원팀 설정, 프로필 같은 일부 기능"으로 썼는데, 작업 중에 좋아요와 댓글도 못 쓴다는
피드백을 받아 "좋아요, 댓글, 응원팀 설정 같은 일부 기능을 사용하지 못할 수 있어요"로 바꿨다.
"계속하기"를 눌러야 `router.push("/")`로 홈에 간다. 서버를 거칠 일이 없는 단순 이동이라 서버
액션이 아니라 클라이언트 라우터 호출로 충분하다.

## 검증

lint, check-types, 클린 빌드를 통과했고, dev 서버(:3001)를 모바일 뷰포트로 띄워 로그인 화면에서
둘러보기가 사라진 것, 하단 버튼과 팝업, 계속하기로 홈 이동, 회원가입 화면의 뒤로가기 유지까지
스크린샷으로 확인했다. 로그아웃 → 홈 이동은 사용자가 본인 계정으로 직접 확인했다.

## 추가: 홈 캐러셀 스크림 높이 축소

PR을 올린 뒤 같은 세션에서 피드백이 하나 더 왔다. 홈 핫이슈 캐러셀(`HotHeroCard`)의 제목 뒤
음영이 카드 중간 너머까지 올라와 트윗 임베드를 너무 많이 가린다는 거였다. 릴에서 KAN-299 때
스크림 범위를 배지 줄까지로 줄인 것과 같은 방향의 수정이다.

`HotHeroCard`의 스크림은 릴과 구조가 다르다. 릴은 스크림 전용 div가 `h-[60%]` 같은 높이를
갖고 따로 깔리는데, 히어로 카드는 하단 정보 블록 자체에 그라데이션 배경을 입혀서 블록의
`padding-top`이 곧 스크림 윗선이다. `pt-16`(64px)이라 배지 줄보다 한참 위부터 어두웠고,
이걸 `pt-6`(24px)으로 줄여 팀·루머 단계 줄 조금 위까지만 어둡게 했다.

확인 중에 브라우저 콘솔에 hydration mismatch 에러가 떴는데, 서버 HTML은 `pt-16`이고 클라는
`pt-6`이라는 내용이었다. 새로고침해도 그대로라 curl로 서버 응답을 직접 받아 보니 정말 `pt-16`이
나왔다. 소스는 이미 `pt-6`인데 먼저 떠 있던 dev 서버가 서버 컴포넌트 렌더 결과를 캐시에서
계속 내보내고 있던 것이다. hydration mismatch란 서버가 만들어 준 HTML과 클라이언트 React가
같은 컴포넌트를 다시 그린 결과가 달라서 나는 경고인데, 이번엔 코드 문제가 아니라 서버 쪽이
낡은 빌드 산출물을 물고 있어서 난 것이라 dev 서버를 재시작하면 사라진다. 클린 빌드가 통과하는
것으로 소스 정합성은 확인했다.
