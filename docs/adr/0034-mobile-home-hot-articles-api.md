# ADR 0034 — 홈 핫이슈 캐러셀 API 연결과 자동 넘김 (KAN-282)

- 날짜: 2026-07-22
- 브랜치: `feature/KAN-282-hot-articles-api`
- 관련: [ADR 0030 기사 피드 API](0030-mobile-home-articles-feed-api.md) ·
  [ADR 0011 공용 경계](0011-shared-code-boundary.md) · `api-integration` 스킬

## 무엇을 했나

홈 상단 핫이슈 캐러셀을 목데이터에서 `GET /api/v1/articles/hot`으로 갈아탔다. KAN-271에서 홈 소식
리스트를 실 API로 바꿀 때 캐러셀만 남겨뒀었다. 당시 BE에 인기·정렬 개념이 없어서 무엇을 "핫"으로
볼지 근거가 없었는데, 이제 전용 엔드포인트가 생겨서 마저 붙였다. 티켓에는 API 연결 말고 UI 요구도
둘 있었다. 갯수가 N개라 유동적으로 그려져야 하고, 캐러셀이 자동으로 넘어가다가 마지막에서는 다시
처음으로 되감겨야 한다.

## 계약 확인 — 피드와 닮았지만 같지 않았다

늘 하던 대로 be-verify 서브에이전트한테 계약 검증을 맡겼다. 티켓도 스웨거도 믿지 않는 게 규칙인데,
이번에도 그 규칙이 밥값을 했다.

응답의 큰 틀은 예상대로였다. `{ code, message, data }` 봉투에 `data`가 바로 카드 배열이고(피드처럼
`items` 래핑이나 `nextCursor`가 없다), `size` 파라미터는 1~10에 기본 5, 페이지네이션은 없다. 선정
로직은 BE 소스까지 까서 확인해줬는데, 최근 48시간 발행분 중 조회수 상위 N건이고 부족하면 최신순
폴백이다. 폴백 덕에 기사가 아예 없지 않는 한 빈 배열이 올 일이 없다.

문제는 카드 shape였다. 피드 카드와 닮았는데 미묘하게 다르다.

- `summary`, `sourceUrl`, `hashtags`가 없다.
- 이미지가 `mainImageUrl`/`detailImageUrl` 쌍 대신 단일 `imageUrl`이다.
- 기자가 `{ enName, koName, tier }` 대신 `{ name, tier }`다. 같은 매핑 함수를 재사용할 수 없다.

스웨거와 실제가 다른 데도 있었다. 스웨거 `Reporter` 스키마에는 `sourceUrl`이 있는데 실제 응답에는
그 키 자체가 안 온다. null로 오는 게 아니라 직렬화 자체가 안 된다.

인증 쪽에도 함정이 있었다. 익명 허용 API인데 Authorization 헤더를 실으면 검사를 한다. 만료 토큰이면
401 `AUTH_EXPIRED_TOKEN`으로 죽는다. 피드 연결 때(KAN-271) 이미 겪은 패턴이라 이번에도 토큰을
일부러 안 싣는다. 익명 허용인데 토큰 때문에 죽는 건 억울하니까.

하나 더. 조회수·좋아요·댓글 카운트가 전부 0으로 온다. be-verify가 일회용 유저로 실제 like 행을
DB에 넣고 재조회까지 해봤는데도 0이었다. BE 소스를 보니 `NoopArticleEngagementProvider`라는 자리
구현이 집계를 전부 0/false로 내리고 있었다. 의도된 미구현이다. 카드에 "조회 0"이 찍히는 게 지금은
정상이고, BE가 실집계를 붙이면 화면 수정 없이 살아난다. 타입 주석에 이 사정을 남겨뒀다.

## 타입 — ArticleCard를 줄여 쓰지 않고 따로 팠다

처음엔 `ArticleCard`를 재사용할까 했다. 필드 대부분이 겹치니까. 그런데 없는 필드(`summary`,
`hashtags`, `sourceUrl`)를 옵셔널로 풀거나 빈 값으로 때우는 순간 타입이 거짓말을 시작한다. 화면이
`summary`를 읽으면 컴파일은 통과하는데 런타임엔 항상 빈 문자열인 상황이 생긴다. 그래서 실제 계약을
그대로 담는 `HotArticle`을 `_types/articles.ts`에 따로 뒀다. 경계 변환 함수 `toHotArticle`도
`toArticleCard`와 별개로 만들었다. reporter shape가 달라서 어차피 재사용이 안 됐다.

팀 id → 코드 변환과 루머 단계 매핑(`STAGE_BY_BE_VALUE`)은 피드와 같은 테이블을 그대로 썼다. BE가
미국식 `RUMOR`를 주고 도메인 타입이 영국식 `RUMOUR`인 한 글자 차이 함정은 KAN-271 때 밟아둔 거라
이번엔 그냥 지나갔다.

## 페칭 — 서버 fetch로 충분했다

스킬 §0 표에 대면 고민할 게 없었다. 한 번 읽고 렌더 끝나는 단발 읽기다. 클라에서 이어 부를 일도,
뮤테이션도 없다. 서버 컴포넌트 fetch로 갔고 TanStack Query는 안 붙였다.

대신 홈 페이지의 fetch 구조를 조금 손봤다. 기존에는 피드 하나만 `await`했는데 핫이슈가 추가되면서
둘을 순서대로 기다리면 워터폴이 생긴다. `Promise.allSettled`로 병렬로 받고, 한쪽이 실패해도 다른
쪽은 그리게 했다. `all`이 아니라 `allSettled`인 게 중요한데, `all`은 하나가 reject되면 전체가
터져서 멀쩡한 섹션까지 길동무가 된다.

에러와 빈 상태는 섹션 자리에서 처리했다. 핫이슈를 못 받으면 그 자리에만 "핫이슈를 불러오지
못했어요"가 뜨고 소식 리스트는 정상 동작한다. 빈 배열이면 "아직 핫이슈가 없어요"인데, 위에서 말한
최신순 폴백 때문에 사실상 볼 일 없는 화면이다. 그래도 분기는 뒀다. 계약상 가능한 상태는 다 그린다.

## 캐러셀 자동 넘김 — 인터벌 하나에 ref 둘

기존 캐러셀은 손으로 넘기는 센터 스냅 + 점 인디케이터였다. 여기에 자동 넘김을 얹었다.

구현 자체는 단순하다. `setInterval`로 4초마다 다음 카드 위치로 `scrollTo({ behavior: "smooth" })`
하고, 인덱스는 `(현재 + 1) % 길이`로 돌려서 마지막 다음이 처음이 되게 했다. 티켓이 요구한 되감기
효과가 이 나머지 연산 하나다.

ref를 두 개 뒀다. `activeRef`는 인터벌 콜백이 현재 인덱스를 읽는 통로다. state만 쓰면 콜백이
클로저에 갇힌 옛 값을 봐서, 유저가 손으로 세 번째 카드까지 넘겨놨는데 자동 넘김이 두 번째로
되돌리는 사고가 난다. onScroll이 state와 ref를 같이 갱신해서 자동 넘김이 항상 유저가 보고 있는
카드 기준으로 이어진다. `pausedRef`는 손가락이 트랙에 닿아 있는 동안 true가 돼서 자동 넘김이
유저 스크롤을 뺏지 않게 한다. `document.hidden`일 때도 쉰다. 백그라운드 탭에서 헛돌 이유가 없다.

카드가 한 장 이하면 인터벌 자체를 안 건다. 갯수 유동 요구는 원래 구조가 이미 충족하고 있었다.
카드도 점도 배열 map이라 5건이 오면 5개, 3건이 오면 3개가 그려진다.

## 검증에서 막힌 것 — 히든 탭에서는 아무것도 안 움직인다

화면 검증은 브라우저로 직접 하는 게 규칙이라 dev 서버를 브라우저 패널로 열었다. 성공 상태는 바로
확인됐다. 실데이터 5건, 점 5개, 아스날 OFFICIAL 배지, 기자명, "1일 전", 조회 0까지 다 그려졌다.

그런데 4.5초를 기다려도 캐러셀이 안 넘어갔다. 코드를 의심하다가 `document.visibilityState`를
찍어보니 `hidden`이었다. 브라우저 패널이 화면에 전면으로 떠 있지 않으면 크롬이 탭을 백그라운드
취급한다. 그러면 세 겹으로 막힌다. 내가 넣은 `document.hidden` 가드가 정직하게 쉬고 있었고,
smooth 스크롤은 rAF 기반이라 히든 탭에서 애니메이션이 아예 안 돌고, scroll 이벤트 디스패치도 rAF에
묶여 있어 안 온다. 탭을 전면으로 올려도(`tabs_select`) visibilityState가 hidden 그대로였다.

그래서 로직만이라도 실증하기로 했다. `document.hidden`을 defineProperty로 덮고, 트랙의 `scrollTo`를
가로채서 호출 인자를 기록하며 `behavior: "instant"`로 바꿔 실행하게 했다. instant는 rAF 없이 즉시
적용되니까 히든 탭에서도 움직인다. 결과로 세 가지가 확인됐다. 인터벌은 꼬박꼬박 발화한다. scroll
이벤트를 수동 디스패치해서 activeRef를 1로 올리자 다음 틱이 정확히 2번 카드 위치(665px)로 갔다.
현재 위치 기준으로 이어가는 로직이 맞다는 뜻이다. 마지막 카드 위치로 옮기고 이벤트를 쏘자 다음
틱이 0으로 되감았다. 루프도 맞다. smooth 애니메이션 자체는 브라우저 표준 동작이라 보이는 탭에서는
당연히 돈다. 검증 후 페이지를 리로드해서 몽키패치를 다 걷어냈다.

콘솔 에러는 없었다. `formatRelativeTime`은 서버와 클라 렌더 시각이 달라 하이드레이션 경고가 날 수
있는 자리인데, NewsItem이 하던 대로 `suppressHydrationWarning`을 붙여서 조용했다.

## 목 정리와 공용화 판단

`HOT_POSTS`는 이 PR에서 지웠다. 마지막 소비자가 사라졌으니 규칙(KAN-264)대로다. `POSTS` 목 자체는
기사 세부 페이지가 아직 써서 파일은 남는다. 파일 헤더에 "기사 세부 API가 붙으면 파일째 지운다"고
적어뒀다. 이 교체로 `FeedPost`를 소비하던 홈 컴포넌트가 다 사라져서, 홈은 이제 실계약 타입만 쓴다.

공용화는 안 했다. `HotArticle`과 `getHotArticles`는 모바일 홈만 쓴다. ADR 0011 게이트 C(두 번째
실사용처) 미달이라 앱 로컬에 뒀고, web이 핫이슈를 붙이는 날 `ArticleCard` 계열과 함께 승격을
재검토한다. 이미 ADR 0011 §7에 열려 있는 후보 항목과 같은 운명이다.

## 후속 피드백 — 인터벌이 유저 스와이프를 뺏는다

PR을 올리고 바로 피드백이 왔다. 사람이 스와이프하는 와중에도 타이머대로 자동으로 넘어간다는 거다.
잡고 있거나 직접 넘기며 보고 있을 때는 타이머를 리셋하고, 떼는 순간부터 다시 세라고 했다.

맞는 지적이었다. 처음 구현은 `setInterval`이 4초마다 무조건 발화하고 `pausedRef`가 발화 순간에만
틱을 건너뛰는 구조였다. 손가락이 닿아 있는 그 순간만 피할 뿐 타이머 자체는 계속 돌아서, 유저가
스와이프를 마치고 0.5초 뒤에 틱이 예정돼 있었다면 카드를 보기도 전에 넘어가 버린다. 관성 스크롤이
아직 도는 중에 틱이 끼어들면 스크롤을 뺏는 것처럼 보이기도 한다.

`setInterval`을 버리고 리셋되는 `setTimeout` 체인으로 바꿨다. `schedule()`이 기존 타이머를 지우고
새로 걸며, 세 곳에서 불린다. 자동 넘김이 스스로 다음을 걸 때, 손가락을 뗄 때(release), 그리고
스크롤 이벤트가 일 때마다. 마지막이 핵심인데, 스와이프 관성이 도는 동안 scroll 이벤트가 계속
들어오니 타이머가 계속 뒤로 밀리고, 움직임이 멎은 시점부터 온전한 4초를 센 뒤에야 넘어간다.
자동 넘김 자신의 smooth 애니메이션도 scroll 이벤트를 내는데, 그것도 똑같이 타이머를 밀어서
애니메이션이 끝난 시점부터 다음 간격이 시작된다. 오히려 자연스럽다. 잡고 있는 동안(`holdingRef`)은
타이머를 아예 걸지 않다가 떼는 순간 release가 새로 건다.

여기서 이벤트 함정을 하나 만났다. 처음엔 pointerdown/pointerup 쌍으로 잡음을 감지하려 했는데,
터치 기기에서 스크롤 제스처가 시작되면 브라우저가 스크롤을 가져가면서 pointercancel을 쏜다.
pointer 쌍만 믿으면 손가락이 아직 화면에 있는데 release로 오인해 타이머가 돌기 시작한다. 그래서
터치는 touchstart/touchend/touchcancel로 잡고, pointer 이벤트는 `pointerType === "mouse"`일 때만
반응하게 갈랐다. 마우스 드래그는 pointercancel 문제가 없어서 그쪽은 pointer 쌍으로 충분하다.

이벤트 리스너가 6개가 되면서 JSX prop 대신 이펙트 안에서 `addEventListener`로 붙이고 클린업에서
걷어내는 쪽으로 옮겼다. 타이머 변수도 ref 대신 이펙트 로컬 변수로 충분해졌다. 검증은 전과 같은
방식으로 했다. touchstart를 쏘고 10초를 기다려도 자동 넘김이 0회, touchend 후 첫 넘김이 +4.5초,
scroll 이벤트를 쏠 때마다 다음 넘김이 그 시점 기준 온전한 4초 뒤로 밀리는 것까지 숫자로 확인했다.

## 남긴 것

- 조회수 카운트가 "조회 0"으로 보이는 건 BE Noop 구현 때문이고 FE는 손댈 게 없다. BE가 실집계를
  붙이는 티켓이 생기면 그때 숫자가 살아난다.
- `imageUrl`이 시드 데이터에서 전부 null이라 카드가 항상 팀 컬러 placeholder다. 타입과 변환에는
  담아뒀으니 BE가 이미지를 채우면 `MediaThumb`에 `<img>` 얹는 작업만 남는다.
- `size` 파라미터는 안 실었다. BE 기본 5건이 시안과 맞아서다. 건수를 바꾸고 싶으면 fetcher에
  파라미터만 열면 된다(1~10 범위 밖은 400).
