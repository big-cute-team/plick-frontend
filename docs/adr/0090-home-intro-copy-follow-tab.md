# 0090. 홈 하단 소개 문구가 팀 탭을 따라가게 하기

## 무슨 문제였나

KAN-384에서 홈 맨 아래에 크롤러블 소개 문구를 넣었다. 전체 탭이면 서비스 소개, 팀 허브면
"토트넘 핫스퍼의 이적 루머와 오피셜 소식을 모은 페이지예요" 같은 팀 문구가 나온다. 그런데
쓰다 보니 이상한 게 보였다. 팀 탭을 바꾸고 맨 밑으로 내려도 문구의 팀 이름이 안 바뀌었다.
새로고침을 해야만 지금 보는 팀 이름이 나왔다. 웹과 모바일의 마지막 문구가 서로 달라 보이는
것도 사실 같은 원인이었다. 두 앱 다 같은 `homeIntroCopy` 함수를 쓰는데, 각자 처음 연 URL에
문구가 굳어 있으니 보고 있는 탭이 같아도 문구는 제각각이 됐다.

## 왜 그랬나

문구를 서버 컴포넌트(`HomeScreen`)에서 렌더했기 때문이다. 홈의 팀 탭 전환은 KAN-350에서
`history.replaceState`로 만들었다. 서버 왕복 없이 URL만 바꾸고, 클라이언트 컴포넌트들이
`usePathname`으로 그 URL을 읽어 필터와 쿼리를 갈아 끼우는 구조다. 리스트(`NewsFeed`,
`PostFeed`)는 클라 컴포넌트라 잘 따라오는데, 소개 문구는 서버 컴포넌트가 요청 시점의
`team` prop으로 굳혀 놓은 HTML이라 다시 그려질 일이 없었다. 서버 컴포넌트는 서버에서
한 번 렌더된 결과물이지 클라에서 상태 따라 다시 실행되는 코드가 아니라는 걸 다시 확인했다.
같은 이유로 문서 제목도 이미 클라에서 `document.title`을 직접 맞추고 있었다
(`teamHubTitle`). 문구만 빼먹은 셈이다.

## 어떻게 풀었나

문구를 `HomeIntro`라는 작은 클라이언트 컴포넌트로 빼서 두 앱의 `(home)/_components/`에
각각 두었다. `usePathname`으로 지금 URL을 읽고 `teamFilterFromPathname`으로 필터를
구해 `homeIntroCopy`를 그린다. 탭 전환이 URL을 바꾸면 문구도 즉시 따라온다. 문구 자체는
계속 `@plick/domain/brand`의 `homeIntroCopy`가 단일 출처라 웹과 모바일이 항상 같은
문장을 낸다.

걱정했던 건 SEO였다. 이 문구의 존재 이유가 크롤러가 읽을 본문 텍스트(KAN-384)인데,
클라 컴포넌트로 바꾸면 첫 HTML에서 빠지는 게 아닌가 싶었다. 결론은 괜찮았다. `"use client"`
컴포넌트도 SSR 대상이라 서버가 요청 경로 기준으로 렌더한 HTML에 문구가 그대로 실린다.
`curl`로 `/teams/tottenham`을 받아 팀 문구가 들어 있는 걸 확인했다.

컴포넌트를 `@plick/ui`로 승격할까도 잠깐 생각했는데 하지 않았다. 로직이 usePathname 한 줄
글루라 얇고, 감싸는 section의 패딩이 앱마다 다르다(모바일 `px-edge pt-6 pb-4`, 웹은
PageContainer 안이라 `pt-10`). 공용화할 실속이 문구 함수에 이미 다 있어서 앱별 사본이
감사에 걸릴 만한 중복도 아니라고 봤다.

## 검증

두 앱 dev 서버를 띄워 전체 → 토트넘 → 아스날 → 전체로 탭을 오가며 하단 문구가 즉시
바뀌는 걸 확인했다. 브라우저 패널이 hidden이라 클릭이 타임아웃 나서, JS로 탭 링크를
클릭해 URL과 문구를 같이 읽는 식으로 검증했다. SSR HTML은 curl로 확인했고,
check-types·lint·양쪽 클린 빌드 다 통과했다.
