# 0066. UI 수정 4종 — 헤더 정리, 사이드바 재배선, 핫이슈 캐러셀 승격, 리스트 팀 로고 (KAN-338)

KAN-338은 UI 수정 방향 티켓 하나에 네 가지 작업이 묶여 있었다. 헤더에서 기능 없는
장식을 걷어내고, 홈 사이드바를 실데이터로 갈아타고, 웹 핫이슈를 모바일과 같은
캐러셀로 바꾸고, 기사 리스트에 팀 로고를 붙이는 일이다. 순서대로 했고, 하나의
브랜치에서 처리했다.

## 1. 헤더 정리 — 눌러도 아무 일도 안 일어나는 버튼들

웹 GNB(`SiteHeader`)에는 "팀, 선수, 기자 검색" 인풋 모양 버튼과 알림 종, 프로필
아이콘이 있었다. 셋 다 퍼블리싱 때 시안대로 만들어 둔 껍데기였고 대응하는 기능이
없다. 눌러도 아무 일도 안 일어나는 버튼을 계속 두는 것보다 걷어내는 게 낫다고
티켓이 정리해 줬다.

지우고 나니 딸려 있던 것들이 줄줄이 정리됐다. 알림 뱃지 숫자를 받던 `notif`
prop은 쓰는 호출부가 하나도 없었고(모두 `<SiteHeader />`), 아이콘 import 세 개도
빠졌다. 재미있는 건 레이아웃 스페이서였다. 원래 모바일 뷰에서 검색·내비가 숨을 때
아이콘 클러스터를 우측으로 밀던 `flex-1 lg:hidden` 스페이서가 있었는데, 이제 우측에
남는 게 햄버거(`MobileNav`) 하나뿐이라 스페이서를 `flex-1`로 단순화했다. 데스크톱에선
햄버거가 숨으니 스페이서가 있어도 아무 영향이 없다.

## 2. 사이드바 — 마이팀 박스 삭제, 실시간 인기를 실데이터로

홈 우측 사이드바(`HomeSidebar`)는 이 저장소에서 마지막까지 목데이터로 남아 있던
자리였다. 마이팀 카드와 실시간 인기 랭킹 둘 다 `_mocks/posts.ts`를 읽고 있었고,
파일 헤더에도 "남은 소비자는 사이드바 하나"라고 적혀 있었다.

마이팀 박스는 삭제. 실시간 인기는 전용 BE 엔드포인트가 없어서 계약 공백으로
남아 있었는데, 티켓이 핫이슈와 같은 API(`GET /api/v1/articles/hot`)를 쓰라고
정리해 줬다. 생각해 보면 의미도 같다 — 핫이슈가 "최근 48시간 조회수 상위"라
실시간 인기라는 이름과 정확히 겹친다.

연결 방식은 고민할 게 없었다. 홈 페이지가 이미 핫이슈 섹션용으로
`getHotArticles()`를 받아 두고 있으니, 그 값을 사이드바에 prop으로 내려주면
추가 fetch가 0이다. 사이드바는 서버 컴포넌트 그대로고, 실패(null)와 빈 배열
상태만 문구로 처리했다.

이 재배선의 진짜 소득은 죽은 코드 정리다. `_mocks/posts.ts`를 지우자
`@plick/domain`의 `FeedPost`와 `User` 타입이 소비자를 잃었고, 따라가 보니
`Reporter`, `Debate`, `ContentType`도 `FeedPost` 안에서만 쓰이던 타입이었다.
전부 지웠다. 퍼블리싱 시절 BE 목표 shape를 추정해 만들었던 타입 계층이
실계약 타입(`ArticleCard`, `HotArticle`)에 완전히 자리를 내주고 사라진 순간이다.
`Debate` 주석에 "모바일 릴에서 소비"라고 적혀 있었지만 grep 해 보니 이미 아무도
안 쓰고 있었다 — 주석은 코드보다 빨리 낡는다.

## 3. 핫이슈 캐러셀 승격 — 서버 컴포넌트 경계에서 render prop이 안 되는 이유

웹 홈 핫이슈는 히어로 1장 + 서브 2장 데스크톱 그리드(`HotIssueGrid`)였는데,
티켓이 모바일과 동일한 캐러셀로 바꾸라고 했다. 모바일에는 이미 잘 만들어진
`HotCarousel`(센터 스냅 + 점 인디케이터 + 자동 넘김)이 있으니, 웹이 두 번째
소비자가 되는 셈이라 ADR 0011 게이트를 통과한다. `@plick/ui`로 승격했다.
`@plick/ui`에 들어간 첫 `"use client"` 컴포넌트다.

승격에서 제일 재미있었던 설계 지점은 카드 주입 방식이다. 캐러셀 트랙(스냅,
타이머, 점)은 양쪽이 완전히 같지만 카드는 다르다 — 모바일은 `HotHeroCard`,
웹은 `HotCard`를 쓰고 둘은 각자 앱의 `TweetEmbed`에 의존한다. 처음 떠올린 건
`renderCard: (article) => ReactNode` render prop이었는데, 이건 안 된다. 양쪽 홈
페이지가 서버 컴포넌트고 캐러셀은 클라이언트 컴포넌트라서, 서버에서 클라이언트로
넘기는 props는 직렬화 가능해야 한다. 함수는 직렬화가 안 되니 render prop을 넘기는
순간 빌드가 깨진다.

대신 children으로 받았다. 서버 컴포넌트가 `hot.map(a => <HotHeroCard ... />)`처럼
카드를 서버에서 미리 그려서 엘리먼트 트리로 넘기면, React가 이 트리를 RSC
payload로 직렬화해 클라이언트 경계를 그대로 통과시킨다. 캐러셀은
`Children.toArray`로 받아 래퍼(폭 86% + 비율 박스)에 앉히고 개수만큼 점을 그린다.
카드 컴포넌트들이 서버 컴포넌트로 남는 부수 효과도 있다 — 전에는 클라이언트
컴포넌트(캐러셀)가 import했으니 카드까지 전부 클라이언트 번들이었다.

카드 기하 상수(`CARD_W`, `GAP`, 자동 넘김 간격)는 모바일 `_constants/home.ts`에
있었는데, 트랙 마크업의 `w-[86%]`·`gap-2.5`와 짝을 이루는 값이라 컴포넌트 파일
안으로 옮기고 상수 파일은 지웠다. 컴포넌트 밖에서 이 값을 알 필요가 없다.

두 가지 함정이 있었다.

하나는 CSS다. `snap-x-carousel`과 `no-scrollbar`는 Tailwind 유틸이 아니라 모바일
`globals.css`에 정의된 커스텀 클래스다. 승격된 컴포넌트가 이 클래스를 쓰는데 웹
`globals.css`에는 정의가 없으니, 웹에서는 스냅이 아예 안 걸린다. ADR 0005에서
겪은 "스타일만 실종" 함정과 같은 계열이라 웹 globals에 같은 정의를 추가했다.
컴포넌트 JSDoc에도 앱 globals 요구사항을 적어 뒀다.

다른 하나는 데스크톱 카드 크기다. 모바일 기하(폭 86%, 비율 181/131)를 1200px
컨테이너에 그대로 얹으면 카드가 977×700px가 된다. 화면 절반이 카드 하나로
차는 건 아니다 싶어서 카드 비율만 `lg:aspect-video`로 낮추는 `cardClassName`
prop을 뒀다(기본값은 모바일 기하). 그래도 크다는 피드백을 받아서 웹 쪽 트랙에
`lg:max-w-5xl`을 걸어 카드를 880px 정도로 줄였다 — 캐러셀 기하(86%, 스냅 계산)는
건드리지 않고 트랙 폭만 줄이는 방식이라 승격 컴포넌트는 그대로다. 카드 타이포도
lg 미만은 모바일 히어로와 같은 밀도(`p-4`·`text-title`), lg 이상은 데스크톱
스케일(`px-6`·`text-hero`)로 반응형 처리했다.

웹 `HotCard`는 그리드 시절의 lg/sm 사이즈 변형이 필요 없어져 단일 스타일로
접었고, `HotIssueGrid`는 삭제했다.

## 4. 리스트 우측 팀 로고

웹 `PostListItem`(홈 news·기사 페이지 article 변형)과 모바일 `NewsItem`의 행
우측에 대표 팀 로고(`TeamCrest`)를 붙였다. BE가 팀을 다중으로 주니 기존 관례대로
첫 팀을 대표로 쓰고, 팀이 없으면 로고 자리도 그리지 않는다. 썸네일이 있는 행은
[텍스트 | 썸네일 | 로고] 순서로 로고가 맨 오른쪽, 세로는 행 중앙(`self-center`)이다.
크기는 웹 news 32 / article 28 / 모바일 24로 행 밀도에 맞췄다.

BE가 `logoUrl`을 내려주지만(매핑에서 버리는 중) 로컬 `/teams/*.webp` 정적 에셋
방식(`TeamCrest`)이 기존 패턴이라 그대로 따랐다. 팀 이름 텍스트가 빅6만 나오는
것과 같은 제약이니 일관성은 맞다. 빅6 밖 팀이 생기면 그때 `logoUrl` 매핑을
살리는 게 맞겠다.

## 5. 검증에서 만난 것들

정적 검증(format·lint·check-types·양쪽 클린 빌드)은 다 통과했는데, 시각 검증에서
두 번 헤맸다.

먼저 브라우저 패널이 숨겨진 상태에서 JS로 스크롤한 뒤 스크린샷을 찍으면 새까만
이미지가 나왔다. 처음엔 레이아웃이 깨진 줄 알고 DOM을 뒤졌는데, 측정해 보니
`html` 폭 자체가 0이었다 — 숨김 패널이 뷰포트를 0으로 붕괴시킨 환경 문제였다.
뷰포트를 다시 지정하니 정상으로 돌아왔고, 이후 픽셀 검증은 리로드 직후 캡처로,
나머지는 DOM 수치(`getBoundingClientRect`, `scrollWidth`)로 확인했다.

다음은 dev 서버 워처였다. 캐러셀 승격까지는 HMR이 잘 따라왔는데, 마지막
`max-w-5xl` 래퍼 추가만 아무리 리로드해도 반영이 안 됐다. 파일에는 있는데 서빙
HTML에는 없고, dev 로그에도 컴파일 기록이 안 찍혔다. 파일 touch도 소용없어서
서버를 재시작하니 바로 반영됐다. 장시간 떠 있던 Turbopack 워처가 파일 변경
감지를 놓치는 상태였던 것 같다. 원인을 더 파진 않았지만, "코드가 안 먹는다"
싶으면 워처 생존부터 의심하는 게 빠르다는 걸 다시 확인했다.

확인 항목: 데스크톱(1280) 헤더·캐러셀·사이드바·기사 페이지 로고, 웹 330px
모바일 뷰(가로 오버플로 0, 사이드바 숨김, 캐러셀 모바일 기하), 모바일(375)
홈 캐러셀·리스트 로고, 콘솔 에러 0. 실시간 인기는 hot 5건이 순위대로 나왔다.
