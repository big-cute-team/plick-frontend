# 0120 - VS 탭 아이콘을 icons8 PNG에서 벡터로 따라 그리고, 기사 리스트 칩을 VS 칩으로 바꾸다

## 배경

VS 탭 아이콘이 계속 마음에 걸렸다. KAN-435에서 토론을 VS로 리브랜딩하면서 피그마 시안 없이
V·S 글자만 스트로크로 그려 넣었는데, 글자 두 개만 덩그러니 있으니 탭 아이콘이라기보다 그냥
텍스트처럼 보였다. 그래서 icons8에서 "머리에 머리"(head to head)라는 아웃라인 아이콘을 골라
PNG로 받아 뒀다. 머리(원) 두 개가 위에 있고, 아래에 어깨가 맞붙은 몸통 안에 VS가 들어 있는
모양이라 토론 탭의 대결 느낌과 정확히 맞았다.

문제는 받은 게 PNG(48px, 96px)라는 점이었다.

## PNG를 그대로 안 쓰고 벡터로 따라 그린 이유

하단 탭 아이콘은 전부 인라인 SVG 컴포넌트(`packages/ui/src/icons.tsx`)다. stroke와 fill을
`currentColor`로 두면 CSS의 글자색을 그대로 물려받는데, TabBar가 활성 탭이면 accent(초록),
비활성이면 회색 토큰을 글자색으로 깔아 주니까 아이콘이 상태 색을 공짜로 따라간다.

PNG를 `<img>`로 넣으면 이게 전부 깨진다. 색이 파일에 구워져 있어서 활성/비활성 틴트를 못
입히고(CSS filter로 흉내 낼 수는 있지만 토큰 색을 정확히 맞추기 어렵다), 96px 래스터라
고배율 화면에서 확대되면 흐려진다. 다크 고정인 지금은 검은 아이콘이라 아예 안 보였을 거다.

그래서 PNG는 원본 참고용으로만 쓰고, 기존 탭 세트의 기하(24 그리드, 1.8 스트로크,
`currentColor`)에 맞춰 SVG 패스를 직접 그렸다. LiveIcon과 이전 VsIcon을 만들 때와 같은
경위인데, 이번에는 손에 원본 그림이 있다는 점이 달랐다.

## 따라 그리기

96px 원본은 너무 작아서 `sips`로 4배 확대해 형태부터 뜯어봤다. 구성은 세 덩어리였다.

- 머리: 원 두 개. `circle` 두 개로 끝.
- 몸통: 위는 라운드 사각형인데 아래가 두 개의 둥근 어깨 로브로 갈라지고, 가운데가 살짝
  위로 파인다. 한 붓 패스로 그렸다 — 가운데 파임(y=19.4)에서 시작해 왼쪽 로브를 cubic으로
  내려갔다가 arc로 왼쪽 벽을 타고 올라가고, 라운드 모서리(r=2.5)로 윗변을 건너 오른쪽을
  대칭으로 내려온다.
- VS 글자: 기존 VsIcon의 레터폼을 축소해 몸통 안에 넣었다. 1.8 스트로크는 4.6 높이 글자에
  너무 두꺼워서 글자만 1.6으로 낮췄다.

중간 확인에서 한 번 막혔다. 스크래치 폴더의 비교용 HTML을 브라우저 패널로 열었더니 프로젝트
밖 파일이라 정적 스냅샷으로 렌더돼 스크린샷이 안 잡혔다. 우회로 macOS QuickLook 썸네일러
(`qlmanage -t`)로 SVG를 PNG로 떠서 원본과 나란히 비교했는데, 브라우저 없이 SVG를 빠르게
눈으로 확인하는 용도로 꽤 쓸 만했다.

`VsIcon`은 하단바(`_constants/tabs.ts`)에서만 쓰여서 컴포넌트 이름 그대로 패스만 교체했다.
dev 서버로 확인하니 비활성 회색, 활성 초록 다 정상이고 20px로 줄어도 머리·몸통·VS가 읽힌다.

## 기사 리스트 칩: "투표 진행 중" → VS 칩

작업을 보던 중에 피드백이 하나 더 들어왔다. 기사 리스트의 "● 투표 진행 중" 칩이 AI 냄새가
난다는 거였다. 듣고 보니 맞는 말이었다 — 깜빡이는 점에 상태 설명문을 붙인 조합은 어느
서비스에나 있는 기계적인 패턴이다.

칩은 `DebateLiveChip`(@plick/ui)인데 릴 화면(기본 label "VS 진행 중")과 기사 리스트가
같이 쓴다. 릴 쪽 워딩은 건드리지 말아야 해서 칩에 슬롯을 열었다. 처음에는 `emoji` prop으로
`🔥` + "HOT"을 넣었는데, 화면에 띄워 보니 이쪽이 오히려 더 별로라는 피드백을 받았다.
이모지가 칩의 솔리드 그린과 따로 놀았고, HOT이라는 워딩도 핫이슈 섹션(🔥 핫이슈)과 겹쳐서
이게 투표 신호라는 정보가 사라졌다.

그래서 방금 만든 하단바 VS 아이콘을 그대로 재사용하는 쪽으로 틀었다. prop을 `emoji: string`
대신 `icon: ReactNode`로 바꾸고, 기사 리스트(`NewsItem`)가 `icon={<VsIcon size={13} />}`
`label="VS"`를 준다. VsIcon이 currentColor라 칩 글자색(on-accent)을 그대로 따라가서 색 작업이
따로 없었고, 탭 아이콘과 칩이 같은 모티프를 공유하니 "이 기사에 VS(투표)가 열려 있다"는
연결이 워딩 설명 없이 생긴다. 아이콘에는 pulse를 걸지 않았다 — 점은 단색 도트라 깜빡여도
담백한데, 그림 아이콘이 깜빡이면 지저분해진다. 칩 전체의 accent 글로우(`debate-live-chip`
키프레임)는 그대로라 진행 중이라는 신호는 유지된다.

## 후속: 아이콘을 쌍검으로 다시, 그리고 재해석하지 말라는 교훈

머리 둘 + VS 아이콘이 이상하다는 피드백이 와서 원본이 icons8 "전투"(교차한 쌍검) PNG로
바뀌었다. 여기서 한 번 크게 혼났다.

처음에 나는 쌍검을 라인 아이콘 관습대로 재해석했다 — 날을 단일 선으로, 가드를 짧은 획으로,
폼멜을 작은 원으로. 탭 세트가 1.8 스트로크 라인 아이콘이니 그 문법에 맞추는 게 낫다고
멋대로 판단한 거다. 바로 지적이 왔다: "니맘대로 아이콘을 왜 바꿔, 선으로 이루어진 검이 아니고
검모양이잖아." 원본은 날에 폭이 있고 흰 속이 비치는 면 도형인데 내가 뼈대만 남긴 거였다.

면이 있는 검신으로 다시 그렸더니(v3) 이번에는 사용자가 레퍼런스 이미지를 직접 붙여 줬다 —
칼몸만이 아니라 가드·그립·폼멜까지 전부 외곽선 면으로 그려진 스타일. 그 구조대로 다시
구성했다(v4): 검마다 면 도형 4~5개(날·가드·그립·폼멜)를 회전된 사각 폴리곤으로 좌표 계산해서
그리고, 뒷검 날은 앞검이 지나가는 자리에서 두 조각으로 끊었다.

시행착오에서 남은 것 둘.

- 형태가 스펙이다. 사용자가 원본 이미지를 줬으면 그 실루엣을 그대로 따라 그려야지, 아이콘
  세트 문법에 맞춘답시고 면을 선으로 단순화하는 재해석을 하면 안 된다. 피그마 노드 벡터를
  그대로 옮기라는 기존 규칙과 같은 원리라, `screen-publishing` 스킬에 이미지 원본에도 똑같이
  적용된다고 명시해 뒀다.
- 스트로크는 형태를 지키는 쪽으로 양보한다. 면 도형의 흰 속은 1.8 스트로크에서 다 메워져
  실루엣만 남는다. 세트 기본을 깨고 이 아이콘만 1.2로 낮췄고, 이유를 JSDoc에 남겼다.

반복 확인은 브라우저 없이 macOS QuickLook(`qlmanage -t`)으로 SVG를 PNG로 떠서 원본과 나란히
보는 식으로 돌렸다. 20px로 축소한 버전도 같이 떠서 탭 크기 가독성을 매번 확인했다.

## 후속: 칩을 아웃라인으로

칩에도 피드백이 이어졌다: 안쪽 색(솔리드 그린)을 없애고 테두리만 남기고, 라운드도 pill 말고
사각형 느낌으로, 깜빡임은 유지. `DebateLiveChip`에 `variant` prop을 추가했다 — 기본 `solid`는
릴 위에서 혼자 튀라고 뒤집은 솔리드 그린(ADR 0108 결정)이라 그대로 두고, 기사 리스트만
`outline`(투명 배경 + accent 테두리·글자 + `rounded-badge` 6px)을 쓴다. 글로우 키프레임
(`debate-live-chip`)은 box-shadow 기반이라 배경이 없어도 똑같이 번쩍여서 깜빡임 유지에 별도
작업이 없었다.

## 검증

- `pnpm --filter @plick/ui check-types`, `pnpm --filter mobile check-types` 통과(교체마다).
- dev 서버(:3001) 모바일 뷰포트로 홈·/debates 화면 확인 — 쌍검 탭 아이콘 비활성/활성 색,
  리스트의 아웃라인 VS 칩 렌더 확인. 릴 칩은 solid 기본값이라 영향 없음.

## 남은 것

- 데스크톱 웹은 VS 탭 자체가 없어서 이번 교체의 영향이 없다. 웹에 토론 진입점이 생기면
  같은 아이콘을 쓰면 된다(이미 @plick/ui에 있다).
