# 0043. 댓글 UX 수정 — 답글 접기와 placeholder 제거 (KAN-307)

KAN-303에서 댓글 GET/POST를 붙이고 나서 실제로 써 보니 두 가지가 거슬린다는 피드백이 왔다.
하나는 답글이 처음부터 다 펼쳐져 나오는 것, 다른 하나는 댓글 입력바의 "팬 반응 남기기…" placeholder였다.
유튜브 숏츠 댓글창을 레퍼런스로 잡고 고쳤다.

## 답글을 접었다

지금까지 `CommentThread`는 원 댓글 밑에 `comment.replies`를 무조건 다 렌더했다. 답글이 몇 개만 달려도
목록이 금방 길어지고, 원 댓글 단위로 훑어 내려가는 흐름이 끊겼다. 유튜브 숏츠는 답글을 숨겨 두고
"답글 N개"를 눌러야 펼쳐 준다. 그대로 따라갔다.

구현 자체는 단순하다. 스레드마다 `expanded` 상태를 하나 두고, 답글이 있으면 "답글 N개" 토글 버튼을
그린 다음 `expanded`일 때만 답글들을 렌더한다. 상태를 `CommentList`가 아니라 `CommentThread`에 둔
이유는 기존 `replying`(인라인 답글 입력바 열림)과 같다. 스레드 여러 개가 각자 열려 있어도 서로
간섭하면 안 되고, 부모가 전 스레드의 열림 상태를 알아야 할 이유가 없다.

버튼 색은 액션류(답글·좋아요)에 쓰던 `text-text-4` 대신 `text-accent`를 썼다. 유튜브도 답글 토글만
파란색으로 구분해 준다. 접힘 표시는 기존 `ChevronMiniIcon`을 재사용했는데, 이 아이콘은 오른쪽을
보는 벡터라 접혔을 때 `rotate-90`(아래), 펼쳤을 때 `-rotate-90`(위)로 돌렸다. 새 벡터를 받을 일은
아니라고 봤다. 아이콘 신규 반입 규칙(피그마 벡터 그대로)은 형태가 스펙인 새 아이콘 얘기지, 있는
아이콘 회전까지 막는 건 아니다.

한 가지 신경 쓴 엣지가 있다. 답글이 접힌 상태에서 내가 답글을 새로 달면 어떻게 되나. 작성
뮤테이션(`useCreateComment`)은 성공 응답을 쿼리 캐시의 부모 밑에 끼워 넣는데, 접힌 채로 두면 방금
쓴 내 답글이 안 보인다. 쓴 사람 입장에선 등록이 씹힌 걸로 오해하기 딱 좋다. 그래서 답글 등록
성공(`onPosted`) 때 `expanded`를 켜서 바로 보이게 했다. 유튜브도 같은 동작이다.

## placeholder를 뺐다

티켓 두 번째 항목은 "팬 반응 남기기… placeholder 제거"였다. `CommentComposer`의 원 댓글 입력바
placeholder를 그냥 없앴다(`undefined`). 답글 입력바의 "답글 남기기…"는 티켓 범위 밖이라 그대로
뒀다. 답글 입력바는 "답글" 버튼을 눌러야 생기는 거라 맥락이 분명하고, 뭘 쓰는 자리인지 알려 주는
역할이 아직 있다.

처음엔 placeholder 제거 이유를 input attribute 자리에 주석으로 남기려다 두 번 헤맸다. JSX 여는
태그 안(attribute 사이)에는 `{/* */}`도 `//`도 못 쓴다. 표현식 컨테이너는 attribute 위치에서 spread
(`{...x}`)만 허용되기 때문이다. 결국 컴포넌트 JSDoc에 한 줄로 옮겼다.

## 릴 시트 입력바도 위로 (후속 피드백)

PR을 올리고 나서 피드백이 하나 더 왔다. 릴 세부 시트는 댓글 입력바가 시트 하단에 고정 바로
붙어 있었는데, 기사 페이지처럼 댓글 헤더 바로 밑으로 올려 달라는 것이었다.

`ReelDetailSheet`에서 하단 고정 바(`border-t` + safe-area padding을 계산하던 래퍼)를 통째로
걷어내고, `CommentComposer`를 스크롤 영역 안 `CommentsHeader`와 `CommentList` 사이로 옮겼다.
`ArticleComments`가 정확히 이 순서(헤더 → 입력바 → 목록)라 두 화면이 같은 모양이 됐다.

잃는 것도 있다. 하단 고정 바는 목록을 아무리 내려도 입력바가 항상 보인다는 장점이 있었고,
같이 걷어낸 safe-area 하단 패딩도 고정 바였을 때나 필요한 것이었다(스크롤 영역은 자체 `pb-6`으로
충분하다). 대신 댓글을 쓰려는 사람은 어차피 댓글 섹션 맨 위에서 시작하고, 두 화면의 배치가
갈라져 있는 게 더 어색하다는 판단이었다.

## 검증

로컬 BE(:8080)를 붙인 dev 서버에서 답글 1개 달린 기사(7290)로 확인했다. 접힘 기본값, "답글 1개 ⌄"
탭 시 펼침과 chevron 방향 전환, placeholder 빈 입력바까지 스크린샷으로 봤다. 릴 시트도 같은
기사의 릴에서 열어 헤더 → 입력바 → 목록 순서와 하단 고정 바 제거를 확인했다. 콘솔 에러 없음.
`pnpm format`·`lint`·`check-types`·`--filter mobile build` 통과.

덧. 이번 세션은 백엔드가 이미 떠 있었는데 Docker가 꺼져 있었다. 확인해 보니 이 BE에서 Docker는
Testcontainers(테스트용 일회용 Postgres)에만 쓰고, 런타임 DB는 공유 Supabase다. 그러니 Docker를
켜는 건 테스트를 위한 준비지 서버 구동 조건이 아니었다. 데몬만 올리고 컨테이너는 따로 띄울 게
없었다.
