# 0035. 사진이 null로 올 때의 화면별 폴백 — 트윗 임베드 도입 (KAN-284)

## 배경

BE가 내려주는 기사·릴 데이터의 이미지 필드가 아직 전부 null이다. 지금까지는 모든 화면이
`MediaThumb`라는 팀 컬러 그라데이션 placeholder만 그리고 있었고, 실제 `<img>`를 그리는 코드가
리포지토리 어디에도 없었다. KAN-284는 이 상태를 정리하는 티켓이다. 사진이 null일 때 화면별로
어떻게 대체할지를 정했다.

1. 홈 핫이슈 캐러셀: 원문 링크를 이용한 트위터 임베딩으로 대체
2. 홈 "지금 올라온 소식": 사진 부분을 아예 렌더링하지 않음
3. 릴스 큰 화면: 트위터 임베딩으로 대체
4. 릴스 상세 패널을 열었을 때: 작아진 사진 크기에 맞춰 리사이징
5. 기사 상세: 아직 미구현이라 이번 범위에서 제외

티켓은 "null일 때의 대안"이지만, 대안이 있으려면 null이 아닐 때의 경로도 있어야 했다. 그래서
`MediaThumb`에 `imageUrl` prop을 추가해 사진이 있으면 `<img>`, 없으면 기존 그라데이션으로
폴백하는 구조를 먼저 깔았다. `MediaThumb`의 문서 주석에 원래 "BE 연동 시 `<img>`로 교체한다"고
예고돼 있던 자리라, 공용 컴포넌트(@plick/ui)를 건드리는 판단이 어렵지 않았다. prop이 옵셔널이라
web 쪽 8개 사용처는 아무 영향이 없다.

## 시작 전에 확인한 것 — 핫이슈에는 원문 링크가 없다

구현 전에 be-verify 서브에이전트로 실제 응답을 다시 확인했다. 세 가지가 나왔다.

- `GET /api/v1/articles/hot`의 실응답에는 `sourceUrl` 키 자체가 없다. KAN-282 때는 "스웨거엔
  있는데 실응답엔 없다"였는데, 그 사이 스웨거 스키마에서도 빠져서 문서와 실응답이 일치하는
  상태가 됐다. 즉 핫이슈 카드의 트윗 임베드는 지금 BE로는 불가능하다.
- 피드·릴스의 `sourceUrl`은 전 건 `https://x.com/<핸들>/status/<숫자ID>` 형태로 일관됐다.
- 이미지 필드(`mainImageUrl`/`detailImageUrl`/`reelsImageUrl`/`imageUrl`)는 여전히 전부 null이다.

핫이슈를 어떻게 할지 고민했다. be-verify는 "핫 카드 타입에 sourceUrl을 넣지 않는 게 안전하다"고
했지만, 그러면 티켓 1번이 통째로 미구현이 되고 BE가 필드를 추가하는 순간 FE를 또 고쳐야 한다.
반대로 `HotCardResponse`에 `sourceUrl?: string | null`로 옵셔널하게 받아 두고 `?? null`로
매핑해 두면, 지금은 항상 null이라 그라데이션 폴백으로 동작하다가 BE가 필드를 추가하는 순간
화면 수정 없이 임베드가 켜진다. 후자를 골랐다. 대신 타입 주석에 "당분간 항상 null"이라고
박아서 다음 사람이 헷갈리지 않게 했다.

## 트위터 임베딩 방식 선택 — widgets.js 대신 react-tweet

트윗을 웹페이지에 박는 방법은 크게 셋이다.

1. 공식 widgets.js: `platform.twitter.com`에서 외부 스크립트를 로드해 iframe을 심는다.
   스타일을 거의 못 만지고, 로딩이 느리고, 레이아웃 시프트가 있다. 웹뷰 환경에서 외부
   스크립트 로드는 리스크다.
2. iframe 직접 임베드(`platform.twitter.com/embed/Tweet.html?id=...`): 높이를 알 수 없어
   postMessage로 받아야 하고, 역시 스타일 제어가 안 된다.
3. react-tweet(Vercel): 트위터의 신디케이션 API에서 트윗 데이터를 JSON으로 받아 React
   컴포넌트로 직접 그린다. iframe이 없어서 CSS 변수로 완전한 스타일 제어가 되고, 우리
   레이아웃 안에서 크기 계산도 자유롭다.

3번을 골랐다. PLick은 사진 자리라는 정해진 박스에 트윗을 "사진처럼" 넣어야 해서 크기와 색을
우리가 쥐고 있어야 했다. 신디케이션 API가 비공식이라 언젠가 깨질 수 있다는 리스크는 있지만,
Vercel이 관리하는 라이브러리라 그때는 같이 고쳐질 가능성이 높다고 봤다.

### 프록시 라우트가 필요했던 이유

react-tweet의 클라이언트 경로를 뜯어 보니(`dist/hooks.js`), `apiUrl`을 안 주면 기본으로
`https://react-tweet.vercel.app/api/tweet/:id`를 부른다. 이건 react-tweet 데모용 공용
엔드포인트라 rate limit을 같이 탄다. 우리 릴스와 캐러셀은 클라이언트 컴포넌트 트리 안이라
(핫 캐러셀은 자동 넘김 때문에, 릴스는 Embla 때문에 이미 "use client") RSC 경로로 직접
fetch하는 방식을 못 쓴다. 그래서 `app/api/tweet/[id]/route.ts`를 만들었다. `react-tweet/api`의
`getTweet()`으로 우리 Next 서버가 신디케이션 API를 직접 받아 `{ data }` 모양 그대로
돌려주고, 클라이언트의 `<Tweet apiUrl>`이 이걸 부른다. 트윗 본문은 사실상 불변이라 성공
응답에 `Cache-Control: public, max-age=86400`을 얹어 하루 재사용하게 했다.

### 테마 — 라이브러리 팔레트 대신 PLick 토큰

react-tweet의 theme.css는 라이트가 기본이고 `[data-theme='dark']`나
`prefers-color-scheme: dark`일 때 다크로 바뀐다. PLick은 반대로 다크가 기본(`:root`)이고
라이트가 `[data-theme="light"]` 오버라이드다. 첫 진입처럼 `data-theme` 속성이 아예 없는
상태에서 OS가 라이트인 사용자는 다크 앱 안에 흰 트윗 카드가 뜨게 된다.

그래서 라이브러리의 라이트/다크 분기를 아예 쓰지 않고, globals.css에서 `--tweet-*` CSS
변수를 전부 PLick 토큰(`--plk-bg`, `--plk-text`, `--plk-border-strong`, `--plk-accent` 등)으로
덮었다. PLick 토큰 자체가 `data-theme`에 따라 뒤집히니까 임베드도 자동으로 따라온다. 색을
토큰으로만 쓴다는 컨벤션과도 맞는 방향이다.

여기서 특이도 문제를 하나 넘어야 했다. 라이브러리 셀렉터가
`:is([data-theme='light'], .light) :where(.react-tweet-theme)` 같은 (0,1,0) 특이도인데,
Next의 CSS 번들 순서는 import 그래프에 따라 달라져서 "우리 선언이 뒤에 오니까 이긴다"에
기댈 수 없다. `.react-tweet-theme.react-tweet-theme`로 클래스를 두 번 겹쳐 (0,2,0)을 만들어
순서와 무관하게 이기게 했다.

## 화면별 구현

### 홈 핫이슈 — 중첩 앵커 문제로 카드 구조를 바꿨다

`HotHeroCard`는 카드 전체가 `<Link>`였다. 그 안에 트윗 임베드를 넣으면 임베드가 내부에
`<a>`를 여러 개 그리므로 앵커 안에 앵커가 중첩된다. HTML 파서는 중첩 `<a>`를 만나면 바깥
앵커를 강제로 닫아 버려서 SSR HTML이 하이드레이션과 어긋날 수 있다. 지금은 임베드가
클라이언트에서 데이터를 받은 뒤에야 그려져 SSR HTML에는 안 들어가지만, DOM 유효성 문제는
그대로라 구조를 바꿨다. 미디어(사진/임베드/그라데이션 + 스크림/텍스트)를 아래 층에 두고,
투명한 `<Link>`를 `absolute inset-0`으로 맨 위에 얹었다. 링크 안에 텍스트가 없어진 대신
`aria-label`로 제목을 달았다. 임베드 자체는 `pointer-events-none`이라 탭은 전부 링크가
받는다.

### 지금 올라온 소식 — 조건부 렌더 한 줄

사진이 null이면 56px 썸네일 `MediaThumb`를 아예 안 그린다. 텍스트가 전체 폭을 쓴다. 지금
BE 데이터가 전부 null이라 리스트에서 썸네일이 전부 사라지는데, 이게 티켓이 의도한 상태다.

### 릴스 — 임베드 층과 시트 연동 리사이징

릴 한 장은 풀스크린 `MediaThumb` 위에 스크림과 정보 블록이 얹힌 구조다. 사진이 null이고
`sourceUrl`이 있으면 미디어 자리에 임베드 층을 깐다. 층 구조는 이렇다.

- 바깥 층: `absolute inset-x-0 top-0`에 높이만 애니메이션한다. 평소 100%, 세부 시트가 떠
  있으면 `1 - SHEET_HEIGHT_RATIO`(27%)로 줄어든다. 트랜지션은 시트 슬라이드와 같은
  `320ms cubic-bezier(0.32, 0.72, 0, 1)`이라 시트와 한 호흡으로 움직인다
  (`SHEET_MEDIA_TRANSITION`).
- 안쪽 박스: 위는 safe-area + 12px, 아래는 30%를 비워 하단 정보 블록(제목·기자)과 겹치지
  않게 했다.
- 그 안에서 `TweetEmbed`가 트윗 카드를 fit-scale로 축소해 넣는다.

fit-scale은 `useFitScale` 훅으로 뺐다. 트윗 카드는 자연 높이가 콘텐츠(글 길이, 사진 유무)에
따라 제각각이라 고정 박스에 그냥 넣으면 잘린다. 컨테이너와 콘텐츠 양쪽에 ResizeObserver를
걸고 `min(1, 가로비, 세로비)`로 transform scale을 계산한다. 이 방식의 좋은 점은 변화의
출처를 가리지 않는다는 것이다. 임베드가 로딩을 마쳐 콘텐츠가 자라도, 시트가 열려 컨테이너
높이가 트랜지션 중이어도(트랜지션 프레임마다 RO가 발화한다) 같은 경로로 따라간다. 시트
개폐 여부는 이미 ReelItem에 내려오던 `titleMotion`(시트가 떠 있는 동안만 non-null)을 그대로
읽어서 새 prop 없이 해결했다. 닫힘은 시트 트랜지션이 끝나고 motion이 언마운트된 뒤에
복원되는데, 320ms 늦는 정도라 눈에 거슬리지 않았다.

임베드는 사진의 대체물이므로 상호작용을 받지 않는다. `pointer-events-none`으로 탭·세로
스와이프(Embla)가 전부 뒤의 릴로 통과하고, `aria-hidden`으로 스크린리더 중복도 막았다.
원문으로 가는 길은 기존처럼 세부 시트의 "출처 원문 보기" 링크가 맡는다.

## 막힌 데들

### 임베드가 안 뜨는데 에러도 없다 — 정규식 경계 버그

첫 화면 검증에서 릴스에 임베드가 아예 안 떴다. 콘솔 에러도 없고 `/api/tweet` 요청 자체가
없었다. react-tweet CSS 청크는 로드됐으니 컴포넌트는 마운트된 것이고, 그럼 fetch를 막은 건
트윗 ID 추출뿐이다. 정규식을 다시 보니 도메인 앞 경계를 `(?:^|\.)`로 잡아서 문자열 시작이나
서브도메인 점만 허용하고 있었다. 실제 링크는 `https://x.com/...`라 `x.com` 앞이 `/`다.
경계에 `/`를 추가해(`(?:^|[/.])`) 해결했다. fakex.com 같은 도메인을 거르려던 의도 자체는
유지했다.

### TweetNotFound는 null을 못 돌려준다

임베드 실패 시 조용히 그라데이션으로 폴백하려고 `TweetNotFound: () => null`을 넘겼더니
타입 에러가 났다. react-tweet의 컴포넌트 오버라이드 타입이 반환을 `Element`로 강제해서
null이 안 된다. 빈 프래그먼트(`() => <></>`)로 바꿨다.

### 쓰지도 못할 eslint-disable

`MediaThumb`의 `<img>`에 습관처럼 `eslint-disable-next-line @next/next/no-img-element`를
달았다가 뗐다. packages/ui의 린트 설정(react-internal)에는 next 플러그인이 없어서 이 규칙이
존재하지 않고, ESLint 9은 아무것도 억제하지 않은 disable 주석을 unused directive 경고로
잡는다. lint 스크립트가 `--max-warnings 0`이라 경고 하나로 실패한다. 규칙이 없는 환경에선
주석도 없는 게 맞다.

### 브라우저 검증 중 유령 스크롤

세부 시트를 열었더니 상단 스트립에 도킹된 제목도 축소된 임베드도 안 보였다. 한참 들여다보다
DOM을 재 보니 레이아웃은 전부 정상이었고(층 높이 27%, scale 0.18, 제목 transform까지 다
계산대로), 릴 섹션 자체가 y=-223px에 가 있었다. 브라우저 자동화 도구가 요소를 클릭하면서
`overflow: hidden` 컨테이너를 스크롤시킨 것이다. overflow가 hidden이어도 scrollTop은
프로그램적으로 움직일 수 있다는 걸 잊고 있었다. 실사용 제스처로는 재현되지 않는 도구
부작용이라 코드는 손대지 않았다.

## 검증

- 홈: 핫이슈는 그라데이션 폴백(핫 API에 sourceUrl이 없어 의도된 상태), 소식 리스트는
  썸네일 없이 텍스트 전체 폭. 스크린샷 확인.
- 릴스: 실데이터 x.com 링크로 임베드 렌더 확인. 다크 토큰 팔레트(초록 accent 링크) 적용
  확인. 세부 시트 개폐 시 층 높이와 scale이 계산대로 움직이는 것을 DOM 측정으로 확인.
- `pnpm check-types`, `pnpm lint`, `pnpm --filter mobile build` 통과.

## 남긴 것

- 핫이슈 임베드는 BE가 `/articles/hot` 응답에 `sourceUrl`을 추가해야 실제로 켜진다.
  FE는 준비돼 있다. BE에 필드 추가 요청이 필요하다.
- 기사 상세(티켓 5번)는 화면 자체가 아직 API 연동 전이라 이번 범위에서 뺐다. 연동 때 같은
  `TweetEmbed`를 쓰면 된다.

## 후속: 카드 전체 축소 대신 본문 말줄임 (같은 PR)

첫 구현을 보여주자 바로 피드백이 왔다. 트윗이 길면 fit-scale이 카드 전체를 줄여버려서
글자가 못 읽을 만큼 작아진다는 것이다. 원하는 동작은 명확했다 — 카드와 사진 크기는
가급적 유지하고, 본문 텍스트를 `...`로 줄여서 박스에 맞추되, 컴포넌트 내부가 잘리면 안
된다.

`useFitScale`을 `useTweetFit`으로 갈아엎었다. 우선순위를 뒤집은 게 핵심이다. 카드가
박스보다 크면 (1) 본문 줄수를 계산해 `-webkit-line-clamp`로 말줄임하고, (2) 최소
2줄까지 줄여도 사진 때문에 안 들어가는 잔여분만 기존처럼 scale로 축소한다. 결과적으로
대부분의 트윗은 사진이 원래 크기 그대로 나오고 본문만 두어 줄로 접힌다.

### 본문에 어떻게 손대나 — components 오버라이드가 안 열려 있다

react-tweet의 `components` prop은 `TweetNotFound`/`AvatarImg`/`MediaImg`만 바꿀 수 있고
본문(TweetBody)은 못 바꾼다. dist 소스를 열어 DOM 구조를 확인하니
`div.react-tweet-theme > article > p`가 본문이었다(직계 체인이라 인용 트윗의 본문 p는
안 잡힌다). 이 p에 ResizeObserver 콜백에서 직접 스타일을 건다. React 밖에서 DOM을
만지는 건 내키지 않지만, 라이브러리가 열어주지 않는 자리라 선택지가 없었다.

### ResizeObserver 루프를 피하는 계산

"클램프를 풀고 자연 높이를 재고 다시 건다"를 순진하게 구현하면 RO 콜백에서 매번 스타일이
두 번 바뀌어 관찰이 재발화하고, 그게 또 콜백을 부르는 루프가 된다. 클램프를 풀지 않고
역산하는 걸로 풀었다.

- 잘려 숨은 높이 = `p.scrollHeight - p.clientHeight` (클램프된 채로 읽을 수 있다)
- 카드 자연 높이 = 현재 카드 높이 + 숨은 높이
- 본문 외 카드 몫(헤더·사진·액션) = 현재 카드 높이 − `p.clientHeight` (클램프와 무관)
- 허용 줄수 = `floor((박스 높이 − 카드 몫) / line-height)`, 최소 2줄

이 계산은 같은 입력이면 같은 결과라, "값이 달라질 때만 스타일을 쓴다" 가드와 합치면
고정점에 수렴하고 루프가 안 생긴다. 릴 세부 시트가 열려 박스가 27%로 트랜지션되는
동안에도 프레임마다 줄수가 줄어들며 따라간다.

### 다시 뒤집다 — X Display Requirements 위반

말줄임 구현을 올리고 나서 "지금 방식이 트위터 임베드 사용 규정에 어긋나는 게 있는지
찾아봐 달라"는 요청을 받았다. X의 Display Requirements를 읽어 보니 두 가지가 정면으로
걸렸다.

- 본문은 수정 없이(unmodified) 표시해야 하고 잘라내면(truncate) 안 된다 — 방금 만든
  line-clamp 말줄임이 정확히 이 조항 위반이다.
- 답글·마음·리포스트 액션과 작성자·타임스탬프 링크는 보이고 동작해야 한다 —
  `pointer-events-none`으로 전부 막아둔 것도 위반이다.

react-tweet이 쓰는 신디케이션 API 자체도 문서화되지 않은 엔드포인트라 회색 지대지만,
이건 Vercel이 만들어 관리하는 라이브러리라 감수하기로 했다.

그래서 크기 맞춤을 한 번 더 뒤집었다. 본문은 절대 건드리지 않고, 카드가 박스를 벗어나면
미디어(사진)를 숨긴다. 어차피 사진이 없으면 전문이 다 보이고, 노트 트윗은 react-tweet이
Show more 링크를 단다. 구현도 오히려 깨끗해졌다 — DOM에 스타일을 직접 걸던 line-clamp
코드를 걷어내고, `useTweet`으로 데이터를 직접 받아 넘칠 때 `mediaDetails`를 벗긴 트윗
객체를 `EmbeddedTweet`에 넘기는 순수 React 방식이 됐다(인용 트윗의 미디어도 함께 뺀다).
미디어를 숨기기 직전의 카드 높이를 기억해 두고 박스가 그만큼 다시 커지면 복원한다.
사진 없이도 안 들어가는 경우(시트가 열려 박스가 27%일 때)만 scale 축소가 남는데, 내용을
자르지 않으므로 규정 문제는 없다.

상호작용 차단도 풀었다. 릴스는 임베드 층이 정보 블록 아래라 겹치는 구간만 정보 블록이
우선하고, 나머지는 트윗 링크가 새 탭으로 열린다. 핫이슈 카드는 투명 Link가 카드 전체를
덮으면 임베드를 다시 막게 되므로, 임베드가 보일 때는 Link를 하단 텍스트 구간(40%)으로
좁혔다 — 제목 쪽을 탭하면 릴스로 가고, 트윗 쪽을 탭하면 트윗이 동작한다.

### 시트 탭 영역을 제목·기자 줄로 좁히다

상호작용을 풀고 나니 새 충돌이 보고됐다. 트윗 카드가 길어 하단 정보 블록 근처까지
내려오면, 카드의 Read replies를 눌러도 트위터로 가는 게 아니라 세부 시트가 열렸다.
정보 블록 전체가 하나의 `<button>`이고 그라데이션 리드인(pt-30)과 칩 줄까지 전부 탭
영역이라, 위에 겹친 임베드보다 버튼이 우선 잡히는 구조였기 때문이다.

블록을 `<div>`로 바꾸고 `pointer-events-none`을 걸어 시각(그라데이션·레이아웃)만 남긴
뒤, 시트를 여는 탭 타깃을 제목 버튼과 기자 줄 버튼 둘로 좁혔다. 칩·그라데이션 영역
탭은 이제 아래 임베드로 통과한다. 제목 버튼의 pointer-events는 시트가 떠 있는 동안
none으로 꺼서(부모의 none은 자식 auto를 못 막으므로 버튼 자신에 걸어야 한다) 기존
동작을 유지했다. elementFromPoint 히트 테스트로 Read replies → 트윗 링크, 제목·기자 →
시트 버튼, 칩 → 통과를 확인했다.

자동화 브라우저로 시트 열림 상태를 확인하는데 시트가 안 올라왔다. 시트 transform이
`translateY(0)`인데 화면상 위치는 100% 아래 그대로였고, CSS 트랜지션의 `currentTime`이
몇 초가 지나도 0에 머물렀다. 한참 파다가 `requestAnimationFrame`을 600ms 세어 봤더니
0회였다. 브라우저 페인이 백그라운드 상태라 프레임 생산 자체가 멈춘 것이다. rAF 더블
호출로 shown을 켜는 시트 모션도, CSS 트랜지션도 전부 프레임이 있어야 진행된다.
스크린샷 촬영이 프레임을 강제로 만들어서 찍을 때만 한 칸씩 움직이는 괴상한 상태였다.
코드 버그가 아니라 자동화 환경 문제였고, 실기기 브라우저에서는 정상 동작을 확인했다.

JS로 정보 블록 버튼을 집으려고 `section button`을 잡았더니 트윗 임베드 안의 Copy link
버튼이 먼저 걸렸다. 임베드 레이어가 DOM에서 정보 블록보다 앞이라서다. 포인터 이벤트는
`pointer-events-none`이 막아주지만 프로그램적 `.click()`은 그대로 통한다. 실사용에는
영향이 없지만, 사진 자리 대체물이 버튼을 품고 있다는 걸 잊으면 안 된다는 걸 배웠다.
