# 0157. 핫이슈 카드 테두리와 텍스트 카드 축소, 릴 전체 탭으로 시트 열기, 댓글 수 표시

- 날짜: 2026-09-18
- 티켓: KAN-525
- 관련: [ADR 0155](0155-hot-issue-cards-two-up-and-hot-badge.md)(핫이슈 카드 개편), [ADR 0156](0156-story-trend-widget.md)

## 받은 요청

세 줄짜리 수정 티켓이었다.

1. 핫이슈 카드에 큰 테두리를 넣고, 사진 없는 핫이슈는 핫이슈 태그를 빼고 제목과 부제목만 남겨 높이를 줄인다.
2. 릴스는 지금 제목을 눌러야만 세부 패널이 열리는데, 화면 어디를 눌러도 열리게 한다. 공유 버튼 같은 건 제 기능을 유지하고, 배경을 누르면 닫히는 것과 끌어내려 닫는 것도 그대로 둔다.
3. 기사 옆에 `[숫자]`로 보여주는 걸 조회수 대신 댓글 수로 바꾼다. 0이면 아예 보여주지 않는다.

이번 세션에서는 이 셋과 함께, 작업 방식 하나를 저장소 규칙으로 바꿨다. 클로드가 PR을 직접 올리지 않고 제목과 본문을 채팅에 써 주면 사용자가 직접 PR을 만드는 방식이다. 아래 마지막 절에 적었다.

## 1. 핫이슈 카드 테두리와 텍스트 카드 축소

"핫이슈 자체에 큰 테두리"가 어디를 가리키는지부터 정해야 했다. 같은 문장 뒤에 "노이미지 핫이슈엔"이 붙어 있으니 앞의 "핫이슈 자체"는 사진 있는 캐러셀 카드(`HotHeroCard`)로 읽었다. 섹션 전체를 액자처럼 두르는 해석도 가능하지만, 지난 개편(ADR 0155)에서 두 장이 나란히 서게 되면서 어두운 사진끼리 경계가 묻힌다는 게 눈에 보이는 문제였고, 테두리는 그걸 푸는 장치라고 봤다.

테두리 색은 조금 골랐다. 본문 톤 `border-border`(슬레이트 12%)는 어두운 사진 위에 얹으면 거의 안 보인다. `border-border-strong`도 16%라 큰 차이가 없다. 토큰 목록에 `media-chip-border`(흰색 22%)가 있었다. 릴 위에 뜨는 팀 칩처럼 미디어 위에 얹는 요소의 테두리용이라 정확히 이 자리다. 두께는 Tailwind `border-2`(2px)로 잡았다. 카드가 162px 폭이라 그 이상은 액자가 된다.

사진 없는 카드(`HotTextCard`)는 KAN-515에서 게시판 행처럼 줄였던 걸 한 번 더 걷었다. 머리 줄(깜빡이는 핫이슈 배지 + 단계 라벨)을 통째로 빼고 제목과 한 줄 요약만 남겼다. 패딩도 `p-3.5`에서 `px-3.5 py-3`으로, 줄 간격은 `gap-1.5`에서 `gap-1`로 내렸다. 실측으로 카드 높이가 72.75px이 됐다. 배지 줄 하나가 약 20px, 패딩과 간격 축소가 약 6px이니 30px 가까이 줄었다. 페이저는 카드들을 `items-stretch`로 같은 높이로 맞추는데, 세 장 다 제목 한 줄과 요약 한 줄이라 출렁임 없이 같은 키였다.

배지를 빼면서 `HotBadge`와 `STAGE_META` import가 모바일 텍스트 카드에서 빠졌다. `HotBadge` 자체는 웹 텍스트 카드가 아직 쓰니 `@plick/ui`에 그대로 있다.

웹 텍스트 카드는 손대지 않았다. 높이를 줄여야 하는 이유(홈 첫 화면을 사진 캐러셀과 텍스트 페이저가 너무 먹는다)가 모바일 전용이고, 웹은 3열 그리드라 배지 줄이 있어도 키가 문제가 아니다.

## 2. 릴 화면 어디를 눌러도 시트 열기

릴 한 장은 `ReelItem`의 `<section>`이다. 그 안에 뒤 레이어로 사진이나 트윗 임베드가 깔리고, 그 위에 스크림, 정보 블록(팀 칩·제목·기자 줄), 우측 액션 레일(좋아요·댓글·공유)이 있다. 원래 시트를 여는 탭 타깃은 제목 버튼, 기자 줄 버튼, 댓글 아이콘 셋이었다. 정보 블록 컨테이너는 `pointer-events-none`이라 글자 밖을 누르면 아무 일도 없었다.

가장 단순한 길은 `<section>`에 `onClick`을 다는 것이다. 뒤 레이어의 사진, 빈 배경, 스크림, 정보 블록의 빈 자리 전부 이벤트가 섹션까지 버블링된다. 문제는 걸러야 할 게 셋이라는 점이다.

첫째, 제 기능이 있는 요소. 액션 레일의 버튼 셋, 제목·기자 줄 버튼, 트윗 임베드 안의 링크(react-tweet가 그리는 프로필·원문 링크). 이건 `event.target.closest("a, button, input, textarea")`로 걸렀다. 버튼은 이미 각자 시트를 열거나 팝업을 띄우니 섹션 핸들러가 한 번 더 열 이유가 없고, 임베드 링크는 브라우저 기본 동작대로 x.com으로 가야 한다.

둘째, 포털로 뜨는 팝업. 공유 팝업(`ShareDialog`)과 비로그인 팝업(`LoginPromptDialog`)은 `createPortal`로 `document.body`에 그린다. 레일에 걸린 `drop-shadow` 필터 때문에 릴 안에서 `fixed`를 쓰면 기준 상자가 레일이 돼서 그렇다(KAN-312 때 결정). DOM으로는 섹션 밖인데, React의 합성 이벤트는 DOM이 아니라 React 트리를 따라 버블링한다. 팝업이 `ReelItem`의 자식으로 렌더되니 팝업 배경을 눌러 닫는 클릭이 섹션 `onClick`까지 올라온다. 그러면 공유 팝업을 닫는 순간 시트가 열린다. `e.currentTarget.contains(e.target)`으로 DOM 포함 여부를 한 번 더 확인해 걸렀다. 포털 안의 요소는 섹션의 DOM 자손이 아니라 여기서 걸린다.

셋째, 세로 스와이프. 릴을 넘기려고 끌었다 떼면 브라우저는 `click`을 쏠 수 있다. Embla가 이걸 처리한다는 걸 소스에서 확인했다. Embla는 뷰포트 노드에 `click` 리스너를 캡처 단계로 걸어 두고, 포인터가 `dragThreshold`(우리 옵션에서 8px)를 넘겨 움직였으면 `preventClick` 플래그를 세운 뒤 그 click에 `stopPropagation()`과 `preventDefault()`를 건다. 캡처 단계 리스너는 대상 요소보다 먼저 불리니 React 루트의 버블 리스너까지 도달하지 않는다. 그래서 넘기다 손을 떼도 섹션 핸들러는 불리지 않는다. 8px 미만으로 움직인 탭은 click이 살아 시트를 연다. 탭과 스와이프의 경계가 곧 Embla의 드래그 판정 경계다.

시트가 떠 있는 동안은 시트 층(`z-20`, `inset-0`)이 섹션을 통째로 덮어 클릭이 섹션에 닿지 않는다. 그래도 `titleMotion`이 있으면 빠져나가는 보험을 한 줄 뒀다.

배경 탭으로 닫기는 사실 없던 기능이었다. 시트 컴포넌트의 바깥 div가 화면 전체를 덮지만 `onClick`이 없었다. 티켓은 "유지"라고 썼지만 실제로는 X 버튼, 그랩 존 드래그, 본문 최상단 드래그(KAN-358) 셋만 있었다. 릴 화면 전체가 탭 타깃이 된 지금 이 층이 탭을 받아 주지 않으면, 시트 위 빈 곳을 누른 사용자는 "왜 아무 일도 없지"가 된다. 바깥 div에 `onClick`을 달고 `e.target === e.currentTarget`일 때만 `requestClose()`를 부른다. 시트 본체 안의 클릭은 target이 본체 쪽 요소라 걸리지 않는다. `requestClose`는 `shown`을 false로 내리고, 시트가 아래로 내려가는 transition이 끝나면 `onTransitionEnd`가 언마운트한다. 기존 X 버튼과 같은 경로다.

끌어내려 닫기는 손대지 않았다. `useReelDetailMotion`의 그랩 존 포인터 핸들러와 본문 스크롤 영역의 네이티브 터치 핸들러가 그대로다.

제목·기자 줄 버튼은 남겼다. 섹션 `onClick`만으로는 키보드와 스크린리더가 시트를 열 길이 없어서다. 눈으로 보는 사람에겐 둘 다 같은 시트를 여는 중복 타깃이지만, 버튼은 `closest("button")`에 걸려 섹션 핸들러가 두 번 열지는 않는다.

## 3. 조회수 대신 댓글 수

`HotArticle` 타입에 `commentCount`가 이미 있었다. `GET /api/v1/articles/hot`이 `viewCount`·`likeCount`·`commentCount`를 같이 주고 `toHotArticle`이 셋 다 매핑한다. 화면만 `article.views`에서 `article.commentCount`로 바꾸고 0이면 `<span>` 자체를 그리지 않게 조건을 걸었다. 제목과 숫자는 flex 형제라(ADR 0155) 숫자가 빠져도 제목이 그 폭을 그냥 가져간다.

이건 웹 텍스트 카드에도 같이 적용했다. `[X]` 꼴 자체를 KAN-515에서 두 앱에 같이 넣었고, 같은 자리에 한쪽은 조회수, 한쪽은 댓글 수가 서 있으면 숫자의 뜻이 앱마다 달라진다. 웹의 사진 캐러셀 카드(`HotCard`)는 조회수를 눈 아이콘과 함께 메타 줄에 따로 보여주는 자리라 그대로 뒀다.

## 검증

로컬 BE는 떠 있지 않았고 공유 DB에는 기사 사진이 한 장도 없어(ADR 0155와 같은 사정) 캐러셀이 안 그려진다. 스크래치에 20줄짜리 node 프록시를 8081에 띄웠다. 모든 요청을 `https://dev.plick.co.kr/be`로 넘기되 `/api/v1/articles/hot` 응답의 `withImage`가 비어 있으면 `withoutImage` 앞 네 건을 복사해 채운다. 홈 서버 컴포넌트가 `withTweetPhotos`로 원문 사진을 채워 실제 사진 카드처럼 보인다. `mobile-dev-mock`(3031, `API_BASE_URL=8081`) dev 서버로 확인했다. 프록시는 커밋하지 않았다.

- 홈 375px: 사진 카드 162.5 x 135px에 계산 스타일 `2px rgba(255,255,255,0.22)` 테두리. 텍스트 카드 세 장 모두 72.75px, 내용은 제목과 `[4]`·`[3]`, 요약 한 줄. 가로 오버플로 없음, 콘솔 에러 없음.
- 릴스: 트윗 임베드 위 빈 자리를 탭하면 시트가 열림(`role=dialog` 확인, transform 0). 시트 위 배경을 탭하면 닫힘. 공유 아이콘을 탭하면 공유 팝업만 뜨고 시트는 안 열림. 공유 팝업 배경을 탭하면 팝업만 닫히고 시트는 안 열림.
- `pnpm check-types`, `pnpm lint`, `pnpm format:check`, `pnpm build` 통과.

댓글 0건인 핫이슈는 dev 데이터에 없어 `[0]`이 빠지는 분기는 눈으로 못 봤다. 조건 한 줄이라 코드로 갈음했다. 트윗 임베드 안 링크가 x.com으로 가는 것과 실제 손가락 스와이프 뒤 click 억제는 브라우저 패널에서 못 밟았다. 후자는 Embla 소스로 확인했고, 실기기 감은 사용자가 본다.

## 규칙 변경: PR은 채팅으로

이 세션부터 클로드가 PR을 올리지 않는다. 사용자가 직접 PR을 만들고 싶다고 해서다. 커밋과 push까지 하고, PR 제목과 본문(`pr-writing` 스킬의 5절 틀)을 채팅에 그대로 쓴다. CI는 PR이 없으니 로컬에서 `format:check`·`lint`·`check-types`·`build`를 돌려 대신한다.

CLAUDE.md의 Git·PR 절, `pr-writing` 스킬, `/screen`·`/web-screen`·`/wire-api`·`/web-wire-api` 커맨드, `api-integration` 스킬의 마지막 단계에서 `gh pr create`를 걷어냈다. 병합 금지는 그대로다.
