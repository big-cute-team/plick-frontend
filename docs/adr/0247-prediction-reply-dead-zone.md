# 0247. 예측 의견의 `답글`이 눌리지 않던 걸 고쳤다 (KAN-737)

## 무엇을 했나

경기 상세 예측 탭에는 다른 사람들의 예측 의견이 줄지어 서고, 의견마다 답글을 달 수 있다(KAN-697, KAN-698).
웹은 의견 행을 누르면 그 아래로 회색 답글 영역이 펼쳐지고, 앱은 의견 상세 화면으로 넘어간다. 티켓의 신고는
이랬다. "답글 버튼을 누르면 이상해진다. 답글을 누르고 다른 답글을 누르면 안 눌리는 것 같고, 처음 답글을 누를
때도 렉이 걸리는 느낌이다." 요구는 셋이었다. 근본 원인을 찾을 것, 다른 댓글 지면에도 같은 문제가 있으면 같이
고칠 것, 답글을 연 뒤 다른 답글이나 다른 곳을 누르면 답글 상자가 접히게 할 것.

결과부터 적으면 원인은 렉이 아니었다. `답글`이라는 글자가 버튼처럼 생겼는데 버튼이 아니었고, 그 글자가 놓인
줄 전체가 클릭을 삼키고 있었다. 눌러도 아무 일이 없으니 "안 눌린다", "한 박자 늦다"로 느껴진 것이다. 웹과 앱
두 곳의 의견 행이 같은 구조라 둘 다 고쳤고, 웹에는 바깥을 누르면 접히는 동작을 새로 붙였다.

## 재현부터 했다

증상 설명이 "이상해진다", "렉 같다"처럼 느낌에 가까워서 코드를 읽고 바로 고치지 않았다. 전에 모호한 설명에
내 가설을 끼워 맞췄다가 진짜이긴 하지만 엉뚱한 버그를 고친 적이 있어서다(KAN-379). 이번에는 코드를 읽어 후보를
추린 다음 실제 화면에서 눌러 보고 증상과 맞는 것만 원인으로 삼기로 했다.

코드에서 `답글`이 나오는 자리는 넷이었다. 웹 예측 의견 행의 `답글 [n]`, 앱 예측 의견 행의 `답글 [n]`, 의견
상세와 펼친 영역 안 답글 행의 `답장`, 그리고 기사와 릴스 댓글 스레드(`CommentThread`)의 `답글` 토글이다.

검증 환경은 BE mock 프로필(8081)에 `web-dev-mock`(3030), `mobile-dev-mock`(3031)을 붙인 것이다. mock은 경기
900001에 의견 다섯 건과 답글 세 건을 준다. 브라우저에서 의견 행의 `답글` 글자에 클릭 이벤트를 보내고
`aria-expanded`가 바뀌는지 봤다.

| 누른 곳                              | 웹 (고치기 전)   | 앱 (고치기 전)   |
| ------------------------------------ | ---------------- | ---------------- |
| 의견 행의 `답글` 글자                | 아무 일 없음     | 아무 일 없음     |
| 의견 본문                            | 답글 영역 펼쳐짐 | 상세 화면으로 감 |
| 하나를 펼친 채 다른 행의 `답글` 글자 | 아무 일 없음     | 해당 없음        |

티켓 문장과 그대로 맞았다. 처음 누를 때 반응이 없으니 렉처럼 느껴지고, 본문 어딘가를 눌러 한 번 열린 뒤에 다른
의견의 `답글`을 누르면 또 반응이 없다. 게다가 웹에서는 그 글자 위에서 커서가 손가락 모양(pointer)이었다. 눌릴
것처럼 보이는데 안 눌리는 자리였다.

## 왜 안 눌렸나

의견 행은 통째로 누르는 대상인데 그 안에 하트, 신고, 차단 버튼이 들어 있다. HTML은 `<button>` 안에
`<button>`을 넣는 걸 허용하지 않아서, 행은 `<div role="button">`에 `onClick`을 달아 만들었다. 이렇게 하면
문제가 하나 생긴다. 안쪽 하트를 누른 클릭이 위로 올라가(버블링) 행의 `onClick`까지 닿아, 공감을 눌렀는데 답글이
펼쳐지거나 화면이 넘어간다.

그래서 KAN-698 때 하트와 신고, 차단이 놓인 하단 액션 줄 전체에 `onClick={(e) => e.stopPropagation()}`을
달았다. 이 줄에서 난 클릭은 행까지 올라가지 않는다. 가드를 버튼마다가 아니라 줄에 건 데는 이유가 있었다.
신고 팝업이나 차단 확인은 `createPortal`로 `document.body`에 그려지는데, React의 합성 이벤트는 DOM 트리가
아니라 React 컴포넌트 트리를 따라 올라간다. 팝업은 DOM으로는 행 바깥이지만 React 트리로는 액션 줄의 자식이라,
팝업 안에서 누른 클릭이 행의 `onClick`까지 올라온다. 줄에 건 가드 하나가 그것까지 막아 줬다.

문제는 그 줄에 `답글 [n]`도 같이 있었다는 점이다. 이건 버튼이 아니라 `<span>`이었다. 원래 뜻은 답글 수를
보여 주는 표시였을 텐데, 하트 버튼 바로 옆에 같은 크기와 색으로 놓여 누가 봐도 누르는 것이다. 사용자가 그걸
누르면 클릭은 span에서 시작해 액션 줄로 올라가고, 거기서 `stopPropagation`에 걸려 멈춘다. 행의 토글은 불리지
않는다. span 자체에는 핸들러가 없으니 결과는 아무 일도 없음이다.

`답글` 글자만이 아니었다. 줄 가운데를 벌려 놓는 빈 `<div className="flex-1" />`도, 줄의 위쪽 패딩도 전부 같은
가드 안이었다. 행 전체에 `cursor-pointer`가 걸려 있어 그 빈 자리에서도 커서는 손가락인데, 누르면 먹지 않는 띠가
행 아래쪽에 한 줄 깔려 있던 셈이다. "가끔 안 눌린다"는 느낌은 여기서도 나왔을 것이다.

정리하면 가드의 범위가 너무 넓었다. 막아야 할 건 "버튼과 팝업의 클릭"인데 실제로 막은 건 "이 줄에서 난 모든
클릭"이었다.

## 어떻게 고쳤나

가드를 없애지는 않았다. 포털 팝업의 클릭을 한 곳에서 막아 주는 역할은 여전히 필요하다. 대신 두 가지를 바꿨다.

첫째, `답글 [n]`을 진짜 `<button>`으로 바꾸고 행과 같은 동작을 부르게 했다. 웹은 `onToggle`(펼치기와 접기),
앱은 `open`(상세 화면으로)이다. 버튼의 클릭도 액션 줄에서 멈추니 행의 핸들러가 한 번 더 불려 열렸다 닫히는
일은 없다. 웹은 `aria-expanded`를 달고 hover에 글자를 진하게 했고, 앱은 다른 글자 버튼처럼 세로 패딩으로 터치
목표를 넓혔다.

둘째, 줄의 빈 자리는 행처럼 동작하게 했다. 액션 줄의 핸들러를 이렇게 바꿨다.

```tsx
onClick={(e) => {
  e.stopPropagation();
  if (e.target === e.currentTarget) onToggle();
}}
```

`e.target`은 실제로 눌린 요소이고 `e.currentTarget`은 이 핸들러가 달린 요소(액션 줄)다. 둘이 같다는 건 줄
안의 어떤 자식도 아닌 줄 자신, 그러니까 패딩이나 요소 사이 틈을 눌렀다는 뜻이다. 그때만 토글한다. 버튼을
눌렀으면 `target`이 버튼이고, 팝업 안을 눌렀으면 `target`이 팝업 안의 요소라 둘 다 조건에 걸리지 않는다.

이 조건이 성립하려면 줄 안에 "아무것도 아닌 자식"이 없어야 한다. 가운데를 벌리던 `flex-1` 빈 div가 그런
자식이었다. 그걸 누르면 `target`이 그 div라 줄 자신이 아니게 된다. 그래서 빈 div를 빼고 신고와 차단을
`ml-auto`가 걸린 묶음으로 감쌌다. 오른쪽으로 미는 건 같고, 가운데 빈 공간은 이제 줄 자신의 영역이다. 겉모습은
픽셀까지 그대로다.

## 바깥을 누르면 접히게

웹은 펼친 의견 id를 목록(`PredictionOpinions`)이 하나만 들고 있어서, 다른 행을 누르면 먼저 것이 접히는 건 원래
됐다. `답글`이 버튼이 되면서 "다른 답글을 누르면" 쪽은 저절로 풀렸다. 열려 있던 상자가 접히고 누른 쪽이 열린다.
남은 건 "다른 곳을 누르면"이다. 의견 목록 바깥, 예컨대 채팅 레일이나 페이지 여백을 눌렀을 때 접히는 동작은
없었다.

`useOutsideClick` 훅을 만들어 펼친 행에 달았다. `document`에 클릭 리스너를 걸고, 눌린 요소가 행 안이 아니면
콜백을 부른다. 구현은 짧은데 판단할 자리가 셋 있었다.

하나는 어떤 이벤트를 들을지다. 바깥 클릭 감지는 흔히 `pointerdown`이나 `mousedown`으로 한다. 누르는 순간
반응해서 빠릿하다. 그런데 여기서는 그게 버그를 만든다. 브라우저는 `click`을 "누른 요소와 뗀 요소가 같을 때"
그 요소에 준다. 위쪽 의견 A가 펼쳐진 상태에서 아래쪽 의견 B의 `답글`을 누른다고 하자. `pointerdown`에서 A를
접으면 A의 답글 영역 높이만큼 B가 위로 올라간다. 손가락은 그 자리에 그대로인데 밑의 요소가 바뀌었으니, 뗄 때
포인터 밑에는 B의 `답글`이 아니라 다른 요소가 있다. 누른 곳과 뗀 곳이 달라 B의 `답글`에는 `click`이 가지
않는다. 티켓이 신고한 "다른 답글이 안 눌린다"를 내 손으로 다시 만드는 꼴이다. 그래서 `click`을 듣는다.
`click`은 손을 뗀 뒤에 오니 그 사이에 레이아웃이 움직이지 않는다.

둘은 순서다. A가 펼쳐진 채 B를 누르면 두 핸들러가 같은 클릭에 반응한다. B의 토글(React 핸들러)과 A의 바깥
클릭 리스너(`document`)다. React는 이벤트를 루트 컨테이너에서 받아 처리하고, `document`는 그보다 바깥이라
버블링에서 더 늦게 닿는다. 그래서 B의 토글이 먼저 돌아 펼친 id가 B로 바뀌고, 그다음 A의 리스너가 "닫아라"를
부른다. 여기서 무작정 `setExpandedId(null)`을 하면 방금 연 B가 닫힌다. 그래서 행이 받는 `onClose`는 "내가
아직 펼쳐져 있을 때만 접는다"로 만들었다.

```tsx
onClose={() => setExpandedId((id) => (id === opinion.id ? null : id))}
```

함수형 갱신이라 인자 `id`는 그 시점의 최신 값이다. B의 토글이 먼저 반영돼 `id`가 B면 A의 `onClose`는 아무것도
바꾸지 않는다.

셋은 "바깥"으로 치면 안 되는 클릭이다. 두 가지가 있다.

팝업 안의 클릭이 그렇다. 펼친 영역에서 답글을 등록하려다 로그인 팝업이 뜨거나, 답글을 신고하려고 신고 팝업을
열면 그 팝업은 포털이라 DOM으로는 행 밖이다. `document` 리스너는 React 트리가 아니라 DOM을 보니
`row.contains(target)`이 false가 되고, 팝업 버튼을 누르는 순간 뒤의 답글 영역이 접히면서 쓰던 답글도 날아간다.
웹의 팝업은 전부 `aria-modal="true"`를 달고 있어서 `target.closest('[aria-modal="true"]')`이면 건너뛰게 했다.

처리 도중 DOM에서 사라진 요소의 클릭도 그렇다. 내 답글의 `수정`을 누르면 React가 그 자리를 수정 폼으로 바꾸면서
`수정` 버튼을 DOM에서 뗀다. 이 일은 React 핸들러 안에서 끝나므로, `document` 리스너가 불릴 때 `target`은 이미
어디에도 붙어 있지 않은 요소다. `row.contains(target)`은 false이고 리스너는 바깥 클릭으로 오판한다. 수정을
눌렀더니 답글 영역이 통째로 접히는 것이다. 수정 폼의 `취소`, 팝업의 닫기 버튼도 같은 경우다. 어디서 눌렸는지
알 수 없는 클릭이니 `target.isConnected`가 false면 건너뛴다.

## 다른 댓글 지면

티켓은 다른 댓글에도 같은 문제가 있으면 같이 고치라고 했다. 같은 문제의 조건은 "행 전체가 누르는 대상이고, 그
안의 액션 줄이 클릭을 통째로 막는다"이다. 두 앱에서 `role="button"`과 `stopPropagation`을 전부 찾아보니 이
구조는 예측 의견 행 둘(웹, 앱)뿐이었다. 기사와 릴스의 `CommentThread`는 행이 누르는 대상이 아니고 `답글`이
처음부터 `<button>`이라 해당하지 않는다. 잠금 지면(`PredictionLockedList`)의 `stopPropagation`은 버튼 하나에
걸린 것이라 죽은 자리를 만들지 않는다. 그래서 다른 지면은 건드리지 않았다.

기사 댓글의 답글 입력줄에 "바깥을 누르면 접힘"을 붙일지도 생각했다. 붙이지 않았다. 그쪽은 스레드마다 열림
상태를 따로 들고 여러 개를 동시에 펼쳐 두는 게 의도된 동작이고(KAN-307), 티켓이 요구한 건 예측 답글 상자다.

## 확인

고친 뒤 같은 mock 환경에서 다시 눌렀다.

웹(3030, 경기 900001)

- `답글`을 누르면 펼쳐진다. 한 번 더 누르면 접힌다.
- A를 펼친 채 B의 `답글`을 누르면 A가 접히고 B가 펼쳐진다. 합성 이벤트뿐 아니라 실제 마우스 클릭으로도 봤다.
  A가 접히며 B가 위로 올라가는 배치였는데 클릭이 먹었다.
- 액션 줄의 빈 자리를 누르면 행처럼 토글된다. 하트, 신고, 차단은 토글하지 않는다.
- 펼친 영역 안의 입력줄, `답장`(입력줄에 `@닉네임 `이 채워지고 포커스), 내 답글의 `수정`과 `취소`를 눌러도
  접히지 않는다.
- 신고 팝업을 열고 팝업 안을 누르거나 닫아도 접히지 않는다.
- 목록 바깥(머리글, 페이지 여백)을 누르면 접힌다.

앱(3031, 같은 경기)

- `답글 [3]`을 누르면 의견 상세(`/live/predictions/1002?match=900001`)로 간다.
- 하트를 눌러도 화면이 넘어가지 않는다.
- 375px에서 액션 줄 배치는 전과 같다. `답글` 버튼의 터치 높이는 46px이다.

`pnpm lint`, `pnpm check-types`, `pnpm format:check`, `pnpm test:unit`, `pnpm test:hooks`, `pnpm build`를 돌렸다.
결과는 PR 본문 검증 절에 적었다.

못 본 것도 있다. mock은 PUT과 DELETE를 저장하지 않아 답글 등록 직후의 화면은 확인하지 않았다. 이번 변경은
등록 흐름을 건드리지 않는다. 브라우저 패널은 터치가 아니라 마우스 클릭이라 실제 기기의 탭은 밟지 않았다.

높이뿐이라는 지적은 맞지만 웹의 다른 액션 버튼(하트, 신고, 차단)도 같은 높이라 이 버튼만 키우면 줄이 어긋난다.
세 번째는 클릭이 줄의 핸들러까지 올라가 `target` 판정을 거친다는 설명이었고 조치할 게 없었다.

## 남은 것

- 바깥을 눌러 접으면 쓰던 답글 초안도 같이 사라진다. 행을 다시 눌러 접을 때도 원래 그랬고, 티켓이 요구한 동작이
  접힘이라 그대로 뒀다. 초안이 있을 때는 접지 않거나 초안을 남기는 쪽이 낫다는 판단이 서면 후속으로 한다.
- 이 동작을 지키는 E2E 시나리오가 없다. dev에 의견이 쌓이면 `/e2e web`으로 `답글` 토글을 넣을 만하다.
