# 0089. 모바일 글자·요소 크기 한 단계 키우기 (KAN-385)

## 무슨 작업이었나

모바일 화면을 실기기로 보던 중 "다 너무 작다"는 피드백을 받았다. 구체적으로 세 군데였다.

1. 홈 "지금 올라온 소식" 리스트 — 팀 필터 탭(전체·리버풀…) 글자도, 리스트 각 줄의 요소들도 전부 작다.
2. 릴스 — 좌측 하단의 제목·기자·시각 글자와 팀 로고, 우측의 좋아요·댓글·공유 버튼 뭉치가 작다.
3. 기사 세부 페이지 — 요소들을 조금 더 키워도 된다.

디자인 잡던 초기에 피그마 수치를 그대로 옮겼는데, 피그마 프레임을 축소해 보면서 잡은 크기라 실기기에서는 전반적으로 한 단계 작게 느껴졌던 것 같다.

## 어떻게 키울지부터 정했다

제일 먼저 갈림길이 하나 있었다. 토큰 스케일 자체(`--text-body: 13.5px` 같은 값)를 올릴 것이냐, 화면마다 쓰는 토큰을 한 단계 위 것으로 바꿀 것이냐.

토큰 값을 올리는 쪽이 손은 덜 가지만 바로 접었다. `packages/tokens/theme.css`는 web(데스크톱)과 mobile이 같이 쓰는 단일 출처라, 값을 올리면 요청받지 않은 데스크톱 화면까지 전부 커진다. 게다가 "탭은 12→15로 세 단계, 시각은 11→12로 한 단계"처럼 요소마다 올릴 폭이 달라서 스케일을 일괄로 올려서는 원하는 모양이 안 나온다.

그래서 각 컴포넌트가 쓰는 토큰 유틸을 한 단계씩 위로 바꾸는 방식으로 갔다. 하드코딩 px 금지 규칙은 그대로 지켜진다 — 바꾸는 건 어느 토큰을 쓰느냐뿐이다.

## 홈 리스트

- 팀 필터 탭(`TeamFilterTabs`): `text-label`(12) → `text-body-lg`(15). 한 단계가 아니라 세 단계인데, 필터 탭은 이 화면의 1차 내비게이션이라 포털 뉴스 앱들 탭 크기(15~16)에 맞췄다.
- 리스트 한 줄(`NewsItem`): 팀 이름·시각·하단 통계 줄 `text-caption`(11) → `text-label`(12), 제목 `text-body`(13.5) → `text-body-lg`(15), 썸네일 `size-14`(56px) → `size-16`(64px), 우측 팀 로고 30 → 34.
- 스켈레톤(`NewsItemSkeleton`)도 실제 줄 높이에 맞춰 막대 높이를 올렸다 — 안 맞추면 데이터 도착 순간 리스트가 튄다.
- 섹션 헤더("지금 올라온 소식")는 `text-body-lg` → `text-title`(17)로 올렸다. 탭이 15가 되면서 헤더와 같은 크기가 돼 위계가 사라졌기 때문이다. 같은 클래스를 쓰는 "🔥 핫이슈" 헤더도 같이 올라간다 — 헤더 둘이 크기가 다르면 그게 더 이상하다.

## 릴스

- 제목: `text-headline`(24) → `text-hero`(26). hero는 원래 데스크톱 핫이슈 히어로 카드용으로만 쓰던 토큰인데, 스케일에 24 위가 이것뿐이라 가져다 썼다. headline에 내장돼 있던 자간(-0.4px)이 hero에는 없어서 `tracking-heading`(-0.3px)을 같이 달았고, theme.css의 토큰 주석에 모바일 릴·기사 제목도 쓴다고 적어 뒀다.
- 기자 이름: `text-body` → `text-body-lg`, 시각: `text-label` → `text-body`.
- 우측 액션 레일(`ReelActionRail`): 아이콘 28/27 → 32/31, 라벨 `text-caption` → `text-label`.
- 팀 로고·루머 단계·기자 티어 배지는 공용(`@plick/ui`) 컴포넌트 안에 크기가 박혀 있어서 그냥 바꿀 수 없었다. 아래 참고.

## 기사 세부

- 제목: `text-headline` → `text-hero` + `tracking-heading` (릴 제목과 같은 조합).
- 본문 문단: `text-body-lg`(15) → `text-title`(17). 행간·자간은 기존 `leading-body-lg`·`tracking-snug` 그대로다. 데스크톱 본문이 16.5(`text-read-body`)인 걸 생각하면 모바일 17이 과하지 않다.
- 기자 없는 기사의 메타 줄: `text-label` → `text-body`.
- 좋아요·공유 알약 버튼: `text-body` → `text-body-lg`, 높이 h-9 → h-10, 아이콘 15 → 17.
- "함께 보면 좋은 기사" 카드(`SuggestedArticleCard`): 홈 리스트 줄과 같은 폭으로 전부 한 단계씩 (제목 15, 메타 12, 썸네일 64px). 이 카드는 처음부터 NewsItem과 톤을 맞춘 물건이라 같이 안 올리면 어긋난다.
- 댓글 영역은 손대지 않았다. "조금 더 크게 해도 됨" 정도의 요청이었고, 댓글 컴포넌트(`CommentList`·`CommentThread`·`CommentComposer`)는 릴 세부 시트와 공용이라 건드리는 순간 검증 범위가 확 넓어진다. 필요하면 다음에 따로.

## 공용 컴포넌트는 prop으로 뚫었다

릴에서 키워야 하는 팀 로고·루머 단계 글자(`PostBadges`)와 기자 티어 배지(`ReporterTierBadge`)는 `@plick/ui`에 있고 web 기사 세부·릴 패널도 같은 컴포넌트를 쓴다. 여기 박힌 `text-caption`이나 `size-5`를 직접 올리면 web까지 조용히 커진다 — 이번 요청은 모바일이다.

그래서 둘 다 기본값이 기존과 동일한 옵션 prop을 냈다.

- `PostBadges`에 `stageTextClass = "text-caption"` — 이미 있던 `crestSize` prop("표면마다 스케일이 달라 앱이 정한다")과 같은 철학이다. 모바일 릴은 `crestSize={34} stageTextClass="text-label"`, 모바일 기사 세부는 `stageTextClass="text-label"`을 넘기고, web 호출부는 안 건드렸으니 그대로다.
- `ReporterTierBadge`에 `sizeClassName = "size-5 text-micro"` — 릴만 `size-6 text-caption`을 넘긴다.

크기 결정을 공용 컴포넌트가 아니라 호출하는 앱이 하게 두는 것. ADR 0011의 앱 중립성 게이트와도 결이 맞는다.

## 걸렸던 것들

- 릴 제목을 키우면 세부 시트의 제목 도킹이 깨지지 않을까 확인했다. 다행히 도킹 이동 거리는 상수가 아니라 탭 시점에 `getBoundingClientRect`로 재는 구조(`titleLiftDistance`)라 제목이 몇 줄이 되든 알아서 맞는다. `_constants/reels.ts`에도 제목 높이를 가정한 값은 없었다.
- `NewsItem` 하트 아이콘은 안 키웠다. 주석에 남아 있던 대로, 캡션 크기에 맞춰 줄였다가 선 두께가 1px 아래로 내려가 줄마다 흐리게 보였던 전적이 있는 아이콘이다. 기본값 13이 12px 라벨 옆에서 여전히 자연스럽다.
- 검증은 dev 서버(:3001)를 모바일 뷰포트(375px)로 띄워 홈·기사 세부·릴스 세 화면을 스크린샷으로 확인했다. 브라우저 패널이 숨겨진 상태에서는 클릭이 타임아웃으로 죽어서(패널이 hidden이면 상호작용이 얼어 있다), 링크 href를 읽어 URL로 직접 이동하는 식으로 우회했다. 클린 빌드(`pnpm --filter mobile build`)와 lint·check-types도 통과.
