# 0143. "지금 올라온 소식" 앞의 빨간 점과 30분 NEW 태그 (KAN-481)

2026-09-15. 브랜치 `feature/KAN-481-live-dot-new-badge`.
관련: [ADR 0108](0108-vote-ui-figma-mockups.md) 릴스 토론 칩(번쩍이는 칩의 전례),
[ADR 0018](0018-audit-driven-refactor.md) 포맷 유틸을 `@plick/domain`에 두는 이유.

## 티켓은 두 줄이었다

KAN-481은 "[FE] 홈, 기사리스트 페이지 관련"이라는 제목에 본문이 두 줄이다.

1. "지금 올라온 소식" 앞에 live 반짝이는 애니메이션
2. 30분 전 게시물들은 new 태그 붙이기

피그마 링크는 없었다. 그러니 생김새는 앱 안에 이미 있는 것들에서 빌려 와야 했다. 홈과 기사
리스트는 모바일과 웹 양쪽에 있고 제목 문구도 네 군데("지금 올라온 소식" 모바일 홈 h2, 모바일 기사
h1, 웹 홈 h2, 웹 기사 h1)가 같아서, 점과 태그를 앱마다 따로 그리면 사본이 넷·둘이 된다. 처음부터
`@plick/ui`에 두기로 했다.

## 점 색을 무엇으로 할지

"live"라는 말을 보고 먼저 떠오른 건 브랜드 초록(accent)이었다. 릴스의 토론 칩이 accent로 번쩍이고
있으니 같은 계열로 맞추면 무난해 보였다. 그런데 리스트 한 줄을 보면 이미 초록이 둘이다. 토론 중인
기사에 붙는 VS 칩이 accent 테두리고, 이번에 새로 다는 NEW 태그도 루머 단계 칩과 같은 accent
틴트다. 제목의 점까지 초록이면 화면 위쪽이 전부 같은 색 신호로 뭉개진다.

앱 안에서 "라이브"가 이미 어떤 색인지 찾아봤다. 라이브 스코어의 경기 헤더 칩
(`MatchHeaderBlock`·`MatchHeaderCard`)이 `bg-danger` 점 + "LIVE" 글자다. 진행 중인 경기를 빨간 점으로
알리는 규약이 이미 있으니 그걸 따랐다. 결과적으로 제목의 빨간 점, 행 안의 초록 VS 칩과 NEW
태그가 색으로 갈려서 서로 안 겹친다.

## 번쩍임은 키프레임을 새로 안 만들었다

토론 칩(`DebateLiveChip`)은 글로우가 box-shadow라 전용 키프레임 `debate-live`가 필요했고, 그게
두 앱 `globals.css`에 복제돼 있다(HotCarousel의 `snap-x-carousel`과 같은 규약). 이번 점은 그냥 링이
퍼져 나가면 되는 거라 Tailwind 내장 `animate-ping`으로 끝난다. 점 하나 위에 같은 색 원을 겹쳐 놓고
위 원에만 ping을 걸었다. 키프레임을 앱에 복제할 필요가 없어서 `@plick/ui` 컴포넌트 하나로
닫힌다. 장식이라 `aria-hidden`이고, 제목 크기에 따라 지름만 `size` prop으로 바꾼다. 웹 기사 페이지는
제목이 hero(26px)라 한 단계 키웠다.

## 30분 판정은 어디서 하나

"30분 전 게시물"은 발행 시각(`publishedAt`)이 지금으로부터 30분 안이면 NEW다. 판정 함수는 상대
시각 글자(`formatRelativeTime`)가 사는 `@plick/domain/format`에 `isRecentlyPublished`로 두고, 창
길이는 `constants`의 `NEW_ARTICLE_WINDOW_MS`로 뺐다. 태그 컴포넌트(`NewBadge`)는 판정을 모른다.
그리기만 한다.

한 가지 일부러 열어 둔 게 있다. `now - publishedAt`이 음수여도 NEW로 본다. BE 시계보다 기기
시계가 몇 초 느리면 방금 올라온 기사가 미래 시각이 되는데, 음수를 거르면 그 기사만 NEW를
놓친다. 방금 올라온 기사가 NEW를 놓치는 게 이 기능에서 제일 이상한 경우라 그쪽을 막았다.

## 하이드레이션 경계

여기서 좀 걸렸다. 판정이 렌더 시각 기준이라 서버가 HTML을 만든 시각과 클라가 하이드레이션하는
시각이 다르다. 상대 시각 글자도 같은 문제가 있어서 `suppressHydrationWarning`을 달아 뒀는데, 그건
텍스트나 속성 차이만 덮는다. NEW 태그는 요소가 있냐 없냐라서 덮이지 않는다.

정확히 30분 경계를 SSR과 하이드레이션 사이 몇 초 안에 넘는 기사가 있어야 생기는 일이다. 그때
React 19는 에러를 찍고 그 트리를 클라에서 다시 그린다. 화면은 맞게 나오고 잠깐 콘솔에 남을
뿐이다. 이걸 막으려면 태그를 클라 effect 뒤에 그리거나(첫 페인트에 태그가 없다가 튀어나온다)
`data-*` 속성과 CSS로 우회해야 하는데, 확률에 비해 손이 너무 많이 간다. 감수하고 `NewsItem`
JSDoc에 이유를 적어 뒀다.

## 검증

dev 서버로 모바일(375) 홈·기사, 웹(1280) 홈·기사, 웹 330px를 봤다. 점은 `getComputedStyle`로
`animationName: ping`, 색 `rgb(248,113,113)`(다크 danger), 지름 8px을 확인했다. 330px에서
`scrollWidth === innerWidth`로 가로 넘침이 없다.

NEW 태그는 로컬 BE 데이터가 전부 7월 것이라 정상 판정으로는 안 보인다. 창을 400일로 잠깐
넓혀 태그가 시각 옆, VS 칩 앞에 놓이는 걸 보고 30분으로 되돌렸다. 되돌린 건 grep으로 다시
확인했다. `check-types`·`lint`·`build` 전부 통과.
