# 0180. 새 로고를 쓰임새별 크기로 잘라 두 앱에 심는다

KAN-583. 2026-09-30.

## 무슨 일이었나

KAN-567 리디자인([ADR 0171](0171-haechukimo-redesign.md))에서 브랜드를 "플릭 PLick"에서 "해축이모"로
바꿀 때 로고는 글자였다. `@plick/ui`의 `Logo`가 "해축"을 강조색, "이모"를 제목색으로 Noto Sans KR 900에
자간 -0.06em으로 찍는 텍스트 컴포넌트였고, OG 이미지도 같은 규칙으로 폰트를 렌더해 만들었다. 시안에 로고
그래픽이 아직 없어서 글자로 때운 상태였다.

이번에 피그마 Plick 파일의 "해축이모 리디자인" 섹션에 로고 프레임(`1126:2`)이 올라왔다. 보라색 사자
캐릭터에 초록 글자를 붙인 로고 세트다. 앱 아이콘 캐릭터형과 글자형(정사각 240), 캐릭터 전신과 얼굴(높이
240), 가로형(227×80)까지 다섯 종이고, 아래에 쓰임 크기 규칙이 있다. 앱 상단 바는 가로형을 높이 32로,
웹 GNB는 높이 40으로 맞춘다는 것이다. 요청은 이걸 화면마다 사이즈에 맞게 뽑아 넣되 쓸데없이 크게 넣지
말라는 것이었다.

## 어디에 로고가 있나부터 셌다

코드에서 `Logo`를 부르는 자리는 모바일 상단 바(`TopBar`), 모바일 로그인·회원가입(`AuthScreen`), 모바일
404(`not-found`), 웹 상단 바(`SiteHeader`), 웹 로그인 카드(`AuthCard`) 다섯 곳이었다. 여기에 컴포넌트를
안 거치는 자리가 셋 더 있다. 앱 아이콘 파일(`app/icon.png` 512, `apple-icon.png` 180, `favicon.ico`),
정적 OG 이미지(`app/opengraph-image.png`, `scripts/og-image/render.mjs`가 만든다), 그리고 기사·팀 허브의
동적 OG(`OgCard`가 satori로 글자 워드마크를 그린다)다. 로고를 바꾼다면 여덟 자리를 다 바꿔야 브랜드가
한 벌로 보인다.

피그마의 크기는 메타데이터에서 읽었다. 로고 프레임 아래 "실제 화면" 섹션에 dev 캡처 위에 새 로고를 얹은
목업이 40장쯤 있는데, 그 인스턴스 크기를 훑으면 화면별 높이가 나온다. 모바일 상단 바는 93.6×33(스펙
프레임은 32), 웹 GNB는 113.5×40, 모바일 로그인과 회원가입은 190×67을 가운데 두고, 웹 로그인 카드는
144.7×51이다. 404는 목업이 없어서 웹 GNB와 같은 40으로 정했다. 상단 바는 1px 차이라 스펙 프레임의 32를
따랐다.

## 벡터가 아니었다

처음 계획은 SVG였다. 로고를 SVG로 뽑아 두면 크기별 파일을 만들 필요가 없고 어느 해상도에서도 깨끗하다.
그런데 `download_assets`로 가로형 심볼을 받아 보니 `svgAssets`가 비어 있고 `rawImages`에 PNG 한 장이
있었다. 심볼 안에 벡터 레이어가 없고 이미지 채움(image fill) 하나로 된 프레임이라는 뜻이다. 프레임 설명에도
"투명 로고는 원본의 연회색 배경을 지우고 내용에 딱 맞게 잘랐다"고 적혀 있었다. 즉 로고 원본이 래스터다.

그러면 두 가지가 정해진다. 화면에는 PNG를 쓰고, 큰 원본 하나를 필요한 크기로 줄여 두는 쪽이 맞다.
심볼 프레임을 4배로 export하면 됐지만 그 결과물엔 흰 배경이 깔려 있었다(프레임 fill이 흰색이다). 배경이
투명해야 `bg-nav`가 어두워지는 다크 토큰이나 로그인 화면의 연회색 바탕(`bg-elevate`)에서 네모가 안 보인다.
그래서 export 대신 `rawImages`의 원본 채움 PNG(1393×491, 투명)를 쓰기로 했다. 앱 아이콘도 마찬가지로
원본 채움(804×804 정사각, 초록 바탕)을 받았다.

가로형 원본에는 글자 둘레에 흰 외곽선이 있다. 로고 프레임 아래에 "테두리 없음" 판이 따로 있었지만
실제 화면 목업이 전부 외곽선 있는 `Logo/가로형`을 쓰고 있어서 그 판을 따랐다. 흰 바탕에서는 어차피 안
보이고, 연회색 바탕 예시는 시안이 그 판으로 직접 보여 준다.

## 크기를 어떻게 정했나

한 화면 최대 사용 높이가 67px(모바일 로그인)이다. 요즘 폰이 3배 밀도라 200px 높이면 어디서도 흐리지
않고, 상단 바 32px에는 6배가 넘는 여유다. 그래서 가로형은 높이 200 한 장(581×200, 40KB)만 두고 화면은
`height`만 다르게 받는다. 화면별 파일을 만들면 관리만 늘고, 4배 export(908×320, 160KB)를 그대로 넣으면
"쓸데없이 크게"에 정확히 걸린다.

앱 아이콘은 세 파일의 규칙이 다르다. `icon.png`(512)는 manifest와 파비콘 링크가 쓰는데, 예전 파일이
모서리를 둥글게 깎은 투명 PNG였고 시안도 "모서리는 한 변의 22%"라고 해서 그대로 22% 라운드로 깎았다.
`apple-icon.png`(180)는 정사각 그대로 둔다. iOS가 홈 화면에 올릴 때 마스크를 직접 씌우기 때문에 미리 깎아
두면 모서리가 검게 남는다. `favicon.ico`는 32와 16 두 엔트리를 라운드로 넣었다. 16px에서 사자 얼굴이
읽히진 않지만 보라색 덩어리가 탭에서 구분은 된다. 시안이 "작은 크기에서도 글자가 읽힐 때" 쓰라고 둔
글자형 아이콘은 이번엔 안 썼다. 캐릭터형이 "앱 아이콘 기본"이고, 파비콘 하나 때문에 아이콘 두 종을 섞으면
브랜드가 갈라진다.

## 생성 스크립트로 남겼다

`scripts/brand-assets/`에 원본 두 장(`src/logo-horizontal.png`, `src/app-icon.png`)과 `build.mjs`를
뒀다. `scripts/og-image/team-logos.mjs`와 같은 방식으로 sharp를 쓴다. 가로형은 알파 8 기준으로 trim한
뒤 높이 200으로 줄이고, 아이콘은 SVG 둥근 사각형을 `dest-in`으로 합성해 모서리를 깎는다. 팔레트 PNG로
저장해 용량을 줄였다(512 아이콘 156KB).

ICO는 sharp가 못 쓴다. 패키지를 하나 더 넣는 대신 컨테이너를 손으로 만들었다. ICO는 6바이트 헤더, 엔트리당
16바이트 디렉터리, 그 뒤에 이미지 바이트가 이어지는 단순한 포맷이고 엔트리 내용으로 PNG를 그대로 넣을 수
있다(Vista 이후 규격). 현행 브라우저는 전부 읽는다. `file`로 확인하니 "2 icons, 32x32 with PNG image
data, 16x16 with PNG image data"로 잡혔다.

이 폴더는 pnpm 워크스페이스(`apps/*`, `packages/*`, `tests/e2e`) 밖이라 `npm install`을 따로 한다.
처음에 package.json 없이 `npm install --no-save sharp`를 돌렸더니 npm이 상위 루트 package.json을 찾아
올라가서 knip 피어 의존성 충돌로 죽었다. 폴더에 `type: module`만 적은 최소 package.json을 두니 그 폴더가
자기 프로젝트 루트가 되어 해결됐다.

산출물은 두 앱 `public/brand/logo-horizontal.png`, `app/icon.png`, `app/apple-icon.png`,
`app/favicon.ico`, 그리고 `apps/web/assets/og/logo-horizontal.png` 사본이다.

## 컴포넌트는 img 하나가 됐다

`@plick/ui`의 `Logo`는 `size`(글자 px) 대신 `height`를 받는 `<img>`가 됐다. 너비는 원본 비율(581/200)로
계산해 속성에 박는다. width와 height가 둘 다 있어야 이미지가 오기 전에 브라우저가 자리를 잡아 두고,
상단 바처럼 모든 화면 첫 줄에 있는 요소가 로드 순간 밀리지 않는다.

`next/image`는 안 썼다. 이 패키지는 next에 의존하지 않고, 원본이 이미 화면 최대 높이의 3배로 잘려 있어
최적화 엔드포인트(`/_next/image`)를 거칠 이유가 없다. 오히려 거치면 서버가 요청마다 리사이즈를 한 번
더 한다. 경로는 두 앱 `public/`에 같은 이름으로 둬서 컴포넌트가 앱을 몰라도 된다. 팀 로고
(`public/teams/`)와 같은 관용이다.

글자 워드마크 시절의 `LOGO_PARTS`(`@plick/domain/brand`)와 `--tracking-logo` 토큰은 쓰는 곳이 없어져
지웠다.

## 웹 상단 바 높이가 2px 늘었다

웹 GNB 목업은 로고 40을 위아래 10씩 두고 첫 줄이 60이었다. 기존 첫 줄은 58(`h-14.5`)이라 `h-15`로
바꿨다. 이 바는 sticky고 아래 sticky 요소(팀 탭·표 머리 `PostFeed`, 우측 레일 `SideRail`)가 `top`을
`--site-header-h`에서 파생하므로 `globals.css`의 값을 `calc(6rem + 2px)`에서 `calc(6.125rem + 2px)`로
같이 올렸다. 브라우저 패널에서 첫 줄이 66으로 찍혀서 잠깐 의심했는데 루트 폰트가 17.6px(패널 110% 확대)
이라 60×1.1이었다. 헤더 전체도 109.8로 100×1.1이다.

## OG는 satori와 resvg에 각각 이미지로 앉혔다

동적 OG(`OgCard`)는 satori가 그리는 JSX다. 글자 워드마크 `OgWordmark`를 지우고 `<img>`로 바꿨는데,
satori는 외부 URL을 못 받고 폰트도 바이트로 넘겨야 하는 것처럼 이미지도 data URI가 안전하다. 팀 로고를
읽는 `loadTeamLogo`와 같은 꼴로 `loadBrandLogo`를 `og-assets.ts`에 추가했다. `process.cwd()` 기준 리터럴
경로로 `assets/og/logo-horizontal.png`를 읽어야 Next 파일 추적이 standalone 산출물에 포함시킨다. `public/`
에 둔 파일은 standalone에 안 들어가서 사본이 필요했다. 카드 하단 로고 높이는 64로, 46px 워드마크와 비슷한
자리를 차지한다. 로고는 필수 prop이라 두 라우트(기사, 팀 허브)의 폴백 카드까지 다 넘긴다.

정적 OG(`render.mjs`)는 resvg가 SVG 문자열을 PNG로 굽는다. SVG `<image href="data:image/png;base64,…">`
를 넣으면 resvg가 래스터를 앉힌다. 글자 워드마크 150px 자리에 로고 높이 180을 가운데 두고 태그라인을
아래로 내렸다. 돌려서 두 앱 `opengraph-image.png`를 다시 썼다(19KB에서 100KB로 늘었다. 글자 두 줄이
캐릭터 그림이 됐으니 어쩔 수 없다).

## 확인

웹은 dev 서버(3050)에서 로그인 카드 148×51, 상단 바 116×40, 팀 허브 OG 라우트의 하단 로고를 눈으로
봤다. 모바일은 다른 세션의 `next dev`가 `apps/mobile`을 잠그고 있어서(Next 16은 같은 폴더에 dev 서버
둘을 안 띄운다) prod 빌드 후 `next start`(3101)로 봤다. 상단 바 93×32, 404 화면 높이 40이 맞았다.
모바일 로그인 화면은 빌드에 박힌 BE 주소(8082)가 안 떠 있어 프로필 조회에서 500이 났다. 로고와 무관한
오류라 같은 `Logo` 컴포넌트를 쓰는 404와 웹 카드로 갈음했다.

lint, check-types, format:check, test:unit, 두 앱 build까지 로컬에서 통과했다.

## 리뷰가 잡은 찌꺼기

커밋 뒤 헤드리스 리뷰(`scripts/review/pr-review.sh`)를 돌렸다. 첫 실행은 기본 12턴을 다 쓰고 결과 없이
끝나서 24턴으로 다시 돌렸고, CRITICAL 없이 WARN 둘이 나왔다. 둘 다 로고를 이미지로 바꾸면서 쓸모가
없어졌는데 손대지 않은 것들이다.

하나는 `loadOgFonts`가 Bold 700과 함께 워드마크용 Black 900을 계속 읽어 satori에 넘기던 것이다.
`OgCard`에서 900을 쓰는 글자가 없어졌으니 요청마다 532KB를 읽어 넘길 이유가 없다. Black 항목을 빼고
`assets/og/NotoSansKR-Black.ttf`도 지웠다. 그러자 이 폰트를 쓰던 `scripts/favicon/`(글자 "해"를 초록
사각 위에 얹던 옛 파비콘 생성기, ADR 0070·0074)이 남는데, 파비콘은 이제 `scripts/brand-assets`가 만드니
폴더째 지웠다. `scripts/fonts/subset-noto.sh`도 700 인스턴스만 만들게 줄였다.

다른 하나는 `screen-publishing` 스킬 문서가 지운 `--tracking-logo` 토큰을 여전히 자간 목록에 안내하던
것이다. 다음 화면 작업 때 없는 토큰을 쓰라고 안내받을 뻔했다. 한 줄 지웠다.
