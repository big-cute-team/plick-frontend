# 0166. 웹 핫이슈 카드의 트윗 임베드가 카드를 따라 커지게 하기 (KAN-560)

## 무엇이 이상했나

웹 홈 핫이슈 캐러셀은 lg(1024px) 아래에서 모바일과 같은 한 장짜리 캐러셀로 바뀐다. 카드 폭이 컨테이너의 86%라 940px 창에서는 카드가 717×519px까지 커진다. 그런데 사진을 못 구해 원문 트윗 임베드로 메운 칸은 카드가 커져도 임베드가 왼쪽 위 550px 상자에 그대로 머물렀다. 임베드 상자 색도 카드 바탕과 달라서, 큰 카드 안에 작은 어두운 상자가 따로 떠 있는 모양이 됐다.

원인은 단순했다. 웹 `HotCard`는 임베드 폴백을 넣을 때(KAN-514) `<TweetEmbed>`를 카드 안에 맨몸으로 놓았다. react-tweet 라이브러리의 카드 루트는 `max-width: 550px`, `min-width: 250px`가 기본이고 배경은 우리가 전역 CSS로 `--plk-bg`를 물려 둔 상태였다. 카드 바탕은 `bg-reel-bg`라 두 색이 다르다. 모바일 `HotHeroCard`는 KAN-525에서 임베드를 카드를 덮는 상자에 넣고 `reel-embed hot-embed`로 배경색과 치수를 맞춰 뒀는데, 웹은 그 손질을 안 받은 채였다.

## 어떻게 풀었나

모바일과 같은 구조로 갔다. 임베드를 `absolute inset-0` 상자에 넣어 카드를 덮게 하고, 그 상자를 flex 세로 정렬로 `[justify-content:safe_center]`를 줘 임베드가 카드 세로 가운데에 서게 했다. `safe center`는 내용이 상자보다 길 때 위쪽을 잘라먹지 않고 위에 붙이는 정렬이다. 웹 릴 임베드가 이미 같은 방식이라 화면 간 모양이 맞는다. 상자에 `overflow-hidden`을 줘 카드보다 긴 임베드는 아래가 잘린다.

CSS는 웹 `globals.css`에 `.hot-embed` 규칙을 새로 뒀다. 라이브러리 max-width와 min-width를 풀고 배경을 `--plk-reel-bg`로 카드와 맞췄다.

### 축소를 뷰포트가 아니라 카드 폭으로 건 이유

웹 핫이슈 카드는 폭이 두 갈래로 크게 갈린다. lg 아래는 한 장이 컨테이너의 86%라 700px을 넘고, lg 이상은 네 장이 한 줄에 서서 300px 남짓, 1024px 창에서는 222px까지 준다. 큰 칸에서는 라이브러리 기본 크기(본문 20px, 아바타 48px)가 X에서 보는 트윗과 같아 자연스럽고, 좁은 칸에서는 그 크기가 카드를 넘친다.

처음엔 릴 임베드용 `reel-embed`를 같이 달아 본문 14px로 줄였는데, 717px 카드에서 14px 트윗은 큰 상자 한가운데 작은 글씨가 놓인 꼴이라 오히려 허전했다. 그래서 큰 칸은 기본 크기를 두고 좁은 칸만 줄이기로 했고, 그 경계를 뷰포트 미디어 쿼리가 아니라 컨테이너 쿼리로 잡았다. 임베드 상자에 Tailwind `@container`(`container-type: inline-size`)를 달고, `@container (max-width: 360px)` 안에서 모바일 `.hot-embed`와 같은 치수(본문 0.7rem, 아바타 24px, 패딩 축소, X 로고와 Follow 숨김)를 건다. 카드가 lg 네 장 줄이든 나중에 다른 배치가 되든 카드 폭만 보고 알아서 줄어드니 캐러셀 배치가 바뀌어도 이 CSS는 손댈 일이 없다.

## 검증

dev 원격 BE(`web-dev-remote`)로 띄워 실제 임베드 폴백 칸(사진 없는 Simon Stone 기사 두 건)으로 봤다.

- 940px: 카드 717×519, 임베드 717px 전폭, 세로 가운데(위 137px), 본문 20px, 배경이 카드와 같은 색.
- 1280px(lg): 카드 266×193, 임베드 전폭, 본문 11.2px, 아바타 24px, X 로고 숨김.
- 1024px(lg 경계): 카드 222px, min-width 해제로 오른쪽 잘림 없음.
- 640px: 카드 459px, 임베드 전폭에 기본 크기.

prettier, eslint, tsc, next build 통과.

## 막혔던 곳

`globals.css`를 고쳐도 dev 서버(Turbopack)가 서빙하는 CSS 청크에 새 규칙이 안 실렸다. TSX 변경은 바로 반영되는데 CSS만 옛 내용이 나왔고, `touch`로 다시 건드려도 그대로였다. 서버를 껐다 켜니 실렸다. 이번 세션에서 두 번 겪었다. 전역 CSS를 고칠 때는 HMR을 믿지 말고 서빙 청크에 규칙이 있는지 확인한 뒤 판단해야 한다. 안 실린 상태에서 화면만 보고 "규칙이 안 먹는다"고 CSS를 더 고치면 엉뚱한 데를 판다.
