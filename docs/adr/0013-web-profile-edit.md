# 0013 — 데스크톱 프로필 수정 화면 (KAN-245)

마이페이지(0012)에서 프로필 카드를 누르면 `/me/edit`로 넘어간다. 그 도착지인 데스크톱 프로필 수정 화면(피그마 W5, node 207-2)을 만들었다. 아바타·기본정보 카드·응원팀 선택 그리드·저장 버튼이 max-w-narrow(640px) 좁은 컬럼에 세로로 쌓인 단순한 폼이다.

## 모바일에 이미 다 있었다

시작하자마자 재사용 조사를 돌렸더니 모바일에 `me/edit` 화면이 통째로 있었다. `AvatarField`, `InfoCard`, `TeamPicker`, 그리고 온보딩의 `TeamSelectGrid`까지. 그래서 이번 작업은 "새로 만들기"보다 "무엇을 가져다 쓰고, 무엇을 데스크톱용으로 다시 짤지" 고르는 일이 됐다.

가장 깔끔한 건 아바타였다. 모바일 `AvatarField`는 큰 원형 아바타 + 우하단 카메라 배지가 전부고, 토큰 유틸만 쓴다. 앱 레이아웃에 묶인 데가 없어서 그대로 `@plick/ui/AvatarField`로 올리고 모바일 import만 갈아끼웠다. 데스크톱 피그마의 배지가 모바일보다 6px쯤 작긴 한데(28 vs 34), 아바타 본체와 아이콘 크기는 똑같아서 공용 컴포넌트 하나로 두는 값이 그 차이보다 크다고 봤다. 사본을 두 개 만들면 나중에 감사 대상이 될 뿐이다.

## 팀 그리드는 왜 안 올렸나

응원팀 그리드는 온보딩 `TeamSelectGrid`와 사실상 같은 카드다. 크레스트 로고 + 이름, 선택 시 accent 보더 + 우상단 체크 배지까지 판박이. 그런데 이걸 `@plick/ui`로 올리려니 걸리는 게 몇 개 있었다. 온보딩은 2열인데 데스크톱 W5는 3열이고, 크레스트 크기(51 vs 40)·타일 높이도 다르다. 게다가 그 컴포넌트는 모바일 `_lib`의 `TEAMS`·`useTeamSelection`에 묶여 있어서, 공용으로 올리려면 팀 배열·선택 콜백을 전부 prop으로 빼는 리팩터가 필요했다. 그러면 이미 배포된 온보딩 화면까지 건드리고 다시 검증해야 한다.

승격의 값이 그 비용을 넘지 못한다고 판단했다(ADR 0011의 경계 기준). 대신 진짜 재사용 가능한 조각들 — `TeamCrest`, `CheckIcon`, 웹 `_lib`의 `TEAMS`/`TEAM_ORDER` — 은 이미 공용이라 그걸 조립해서 화면 전용 `FavoriteTeamPicker`를 만들었다. 3열 배치와 저장 버튼을 한 컴포넌트에 담고, 선택 상태는 훅을 가져오는 대신 `useState` 두 줄로 끝냈다. 그 정도는 중복이라 부를 것도 아니다.

정보 카드도 비슷한 이유로 웹 로컬로 뒀다. 모바일 `InfoCard`는 구분선을 `mx-4` 안쪽으로 넣는데 데스크톱 피그마는 전폭 border-t다. 이 차이 때문에 공용화하면 둘 중 하나의 피그마를 어기게 된다. 이미 나간 모바일 화면을 흔들지 않으려고 전폭 구분선 버전을 웹에 따로 뒀다.

## 나머지는 관성대로

레이아웃은 0012에서 굳혀둔 패턴을 그대로 따랐다 — `SiteHeader` + `max-w-narrow mx-auto px-6 pt-9 pb-22`, 섹션은 `gap-gap-lg` 세로 스택. 0.45 배율 프레임이라 피그마 값을 전부 0.45로 나눠 실제 px를 잡았고(제목 26 → `text-hero`, 타일 118px → `min-h-29.5`, 저장 버튼 52px → `h-13`), 색·간격은 손대지 않고 토큰 유틸만 썼다.

반응형은 이 화면이 애초에 좁은 단일 컬럼이라 크게 걱정할 게 없었다. 3열 그리드가 330px에서도 타일당 86px씩은 확보돼 크레스트가 안 깨진다. GNB는 `SiteHeader`가 알아서 햄버거로 접었다. 330px에서 `scrollWidth == innerWidth`(가로 오버플로 0) 확인했고, 데스크톱·모바일·다크·라이트·팀 선택 토글까지 브라우저로 다 돌려봤다. 웹·모바일 빌드 둘 다 클린(`@plick/ui`를 건드렸으니 모바일도 확인).
