# 0108. KAN-413 투표 기능 UI — 피그마 시안 (토론 탭 · 릴스 토론 중 · 투표 패널)

## 무엇을 했나

KAN-413(투표 기능 UI 구현) 티켓을 열어 보고, 코드가 아니라 피그마에 먼저 시안을 그렸다.
대상은 제품 디자인 페이지의 `PLick` 섹션(node 498:1386)이고, 결과물은 새 행에 추가한 모바일
프레임 3장이다.

- `T1 토론 · 투표 리스트`: 하단 탭바에 토론 탭이 활성화된 투표형 게시물 리스트 화면
- `T2 릴스 · 토론 중`: 릴스 화면의 배지 행에 `● 토론 중` 칩이 붙은 상태
- `T3 릴스 · 투표 패널`: 릴스 위로 딤 + 바텀시트가 올라와 실제 투표를 하는 화면

티켓의 TODO를 다시 읽어 보면 (1) 기사 페이지의 투표 UI, (2) 릴스의 토론 중 표시와 디테일
패널 투표, (3) 토론 탭 리스트, (4) 투표 전/후 상태 반영, 이렇게 네 덩어리다. 그런데 섹션을
훑어 보니 (1)과 (4)는 이미 있었다. 이전 세션에서 만든 `V3 오늘의 투표 · 투표 전/후/진영 댓글`
프레임 3장이 기사 페이지에 투표 카드가 박힌 모습과 투표 전/후 상태를 벌써 다루고 있었다.
그래서 이번 세션은 빠진 (2)와 (3)만 채우는 걸로 범위를 잡았다.

웹 화면도 티켓에 있지만 이번엔 안 그렸다. 이 피그마 파일을 다 뒤져 봤는데 데스크톱 프레임이
단 한 장도 없다. 홈, 릴스, MY 전부 모바일만 있다. 이 파일의 컨벤션 자체가 "모바일 시안만
남긴다"인 셈이라, 웹은 모바일 시안을 검증된 계약 삼아 코드에서 바로 푸는 기존 흐름(ADR 0011의
공용 경계 판단, `web-wire-api`식 이식)을 따르는 게 맞다고 봤다.

## 기존 프레임이 0.55 스케일이라는 발견

새 프레임을 그리기 전에 기존 프레임 하나를 뜯어 봤다. `D1 홈`의 텍스트 폰트 크기가 9.35,
6.325, 5.5 같은 소수점 값이었다. 처음엔 왜 이런가 했는데, 프레임 폭이 221.1인 걸 보고 감이
왔다. 402(iPhone 논리 폭) × 0.55 = 221.1이다. 섹션의 모든 프레임이 실물 크기의 0.55배로
축소돼 있었다. 폰트도 마찬가지로 17 × 0.55 = 9.35 식이다.

이걸 알고 나니 선택지가 갈렸다. 실물 크기(402×874)로 새로 그리고 마지막에 0.55배로 줄이느냐,
아니면 처음부터 축소 좌표계로 그리느냐. 나는 셋째 길을 골랐다. 기존 프레임을 통째로 클론해서
내용만 고치는 것. 스케일이 어긋날 일이 원천적으로 없고, 상태바·다이나믹 아일랜드·홈
인디케이터·탭바 같은 껍데기를 공짜로 얻는다. 색과 배지 스타일도 기존 노드에서 fills를 읽어
그대로 썼다. 특히 이 파일은 배지 색이 피그마 변수(디자인 토큰)에 바인딩돼 있어서, 클론하면
바인딩까지 따라온다.

- T1은 `D1 홈`을 클론해서 헤더와 본문을 갈아 끼웠다
- T2와 T3는 `L5 릴스 (항상 다크)`를 클론했다
- T3의 투표 카드는 `V3 투표 전`의 카드 노드(740:2)를 통째로 클론해 바텀시트에 옮겨 심었다.
  기사 페이지와 릴스 패널의 투표 UI가 픽셀 단위로 같은 모양이 되는 게 이 방식의 덤이다

## 탭바: 피그마의 옛 탭 대신 앱의 실제 탭을 따랐다

클론한 프레임들의 탭바는 홈·검색·릴스·알림·MY 5개였다. 그런데 실제 앱의
`_constants/app.ts` TABS는 홈·기사·릴스·MY 4개다. 검색과 알림 탭은 기능이 없어서 이미
뺐다(KAN-297). 피그마 시안이 코드보다 뒤처져 있던 것이다.

시안끼리의 일관성(옛 5탭 유지)이냐 구현 가이드로서의 정확성이냐를 놓고 후자를 골랐다. 새
프레임 3장의 탭바는 홈·기사·릴스·토론·MY로 바꿨다. 검색 자리를 기사로(신문 아이콘을
사각형+줄 3개로 새로 그림), 알림 자리를 토론으로(말풍선 아이콘) 교체했고, T1에서는 토론 탭을
초록 활성 상태로, 클론 원본이 홈이라 켜져 있던 홈 탭은 비활성 색으로 눌렀다. 비활성 색은
하드코딩하지 않고 기존 검색 탭 라벨의 fill을 읽어 그대로 썼다.

## 화면 구성

T1 토론 리스트는 헤더 타이틀 `토론`, 섹션 라벨 `🔥 지금 뜨거운 투표`, 필터 칩(전체/진행
중/마감), 그리고 투표 카드 4장이다. 카드에 상태를 일부러 섞었다. 티켓 4번(투표 전엔 내용만,
후엔 내 투표가 반영된 결과)이 리스트에서도 보여야 한다고 생각해서다.

- 투표 전 카드 2장: 질문 + 선택지 미니 버튼 2개(초록/파랑 틴트), "투표하면 결과가 열려요"
- 투표 후 카드 1장: 결과 바 2개, 내가 고른 쪽에 `✓ 지운다` 표시와 테두리 하이라이트
- 마감 카드 1장: 바 투명도를 낮추고 상태 텍스트를 회색 `마감`으로

T2는 릴스 배지 행(리버풀 · RUMOUR)에 `● 토론 중` 칩을 추가한 것이 전부다. RUMOUR 배지를
클론한 뒤 솔리드 초록 배경 + 다크 텍스트로 뒤집어서, 틴트 배지들 사이에서 혼자 튀게 했다.
릴스에서는 이 칩이 "이 게시물은 투표형"이라는 유일한 신호다.

T3는 릴스 위에 검정 55% 딤을 깔고, 하단에서 라운드 바텀시트가 올라온 모습이다. 시트 안은
드래그 핸들, V3에서 클론한 투표 카드, `기사 전문 보기 →` 링크, 그리고 "투표하면 댓글을 남길
수 있어요" 잠금 입력창. 딤과 시트는 홈 인디케이터보다 아래 z-순서에 끼워 넣어서 인디케이터가
시트 위에 뜨게 했다.

## 막힌 곳들

`figma.createAutoLayout()`으로 만든 프레임의 기본 배경이 흰색이라는 걸 잊었다. 카드 스택을
다 만들고 스크린샷을 찍었더니 다크 화면 위에 흰 띠가 줄줄이 깔려 있었다. 새로 만든 컨테이너
중 fill을 명시하지 않은 것들이 전부 흰색이었던 것. 본문 서브트리에서 순수 흰색 SOLID fill을
가진 프레임을 일괄 검색해 fills를 비우는 스크립트로 한 번에 정리했다. 다크 UI를 스크립트로
그릴 땐 컨테이너를 만들 때마다 `fills = []`부터 박는 게 맞다.

T3에서는 헤더가 이중으로 생겼다. 패널에 "오늘의 투표 배지 + 남은 시간" 헤더 행을 직접 만들어
놓고, 그 아래에 V3 카드를 클론해 넣었는데 카드 안에 이미 똑같은 헤더가 들어 있었다.
스크린샷을 찍고 나서야 보였다. 패널 쪽 헤더를 지우고 패널 y를 다시 하단에 붙였다. 클론
재사용은 편하지만 원본이 뭘 품고 있는지 먼저 확인했어야 했다.

작업 중 `get_metadata`를 섹션에 그대로 쐈다가 40만 자짜리 응답을 받았다. 섹션엔 프레임이
29장 있었으니 당연했다. 파일로 저장된 걸 `jq`로 최상위 프레임 목록만 추려서 봤다. 큰 섹션은
전체 메타데이터를 받지 말고 깊이를 좁혀 조회하는 게 낫다.

## 이어서: 프로토타입 파일로 이식 + 데스크톱 시안

위까지 하고 나니, 데스크톱 시안이 다른 파일에 있다는 걸 알게 됐다. 유저 플로우 프로토타입
파일(PLick 프로토타입 — 유저 플로우)에 `PLickWeb — 데스크톱` 섹션이 있고 W1~W12 데스크톱
프레임이 다 거기 있었다. 그래서 요청이 이어졌다. 아까 그린 모바일 3장을 프로토타입 파일로
옮기고, 데스크톱 버전은 그 파일에 새로 그려 달라는 것.

### 옮기기: 파일 간 복사가 안 되니 다시 짓는다

피그마 플러그인 API에는 파일 간 노드 복사가 없다. clone()은 같은 파일 안에서만 된다.
스크린샷을 이미지로 박는 방법도 있지만 그건 편집 불가능한 그림이라 별로였다. 다행히
프로토타입 파일의 `PLick` 모바일 섹션이 원본 파일과 같은 구조였다. D1 홈, L5 릴스 같은
베이스 프레임이 같은 0.55 스케일로 그대로 있었다. 그래서 "옮기기"를 "같은 레시피로 다시
짓기"로 바꿨다. 어차피 T1~T3는 베이스 클론 + 스크립트 편집으로 만든 거라, 노드 ID만 이
파일 걸로 바꿔 같은 스크립트를 다시 돌리면 된다. 흰 배경 함정도 이번엔 처음부터
`fills = []`를 박아 피했다.

한 가지 차이는 V3 투표 카드가 이 파일에 없다는 점. 원본에서는 카드를 클론해 썼지만 여기선
앞서 읽어 둔 스펙(패딩 8.25, 간격 5.5, 라운드 9.9, slate 6% 배경 16% 테두리, 질문 9.075
Extra Bold, 버튼 라운드 7.15에 서브라벨)대로 처음부터 지었다. 노드를 클론하기 전에 fills와
패딩 수치를 읽어 기록해 둔 게 여기서 돈이 됐다.

### 데스크톱: W13 토론 리스트, W14/W15 기사 투표 전·후

데스크톱 섹션 컨벤션도 클론 기반으로 갔다. 티켓의 웹 요구는 상단 내브바에 토론 메뉴,
투표 리스트 화면, 기사 페이지 투표 UI(전/후)라서 3장을 새 행(y=3077)에 놓았다.

- `W13 토론 · 투표 리스트`: W10 기사 목록을 클론. 타이틀·부제 교체, 팀 필터를
  전체/진행 중/마감으로 줄이고, 기사 행들을 걷어낸 자리에 모바일 T1과 같은 투표 카드
  4장(전/후/마감 섞음)을 데스크톱 스케일(0.6)로 다시 그렸다. GNB는 기사를 비활성으로
  내리고 토론을 활성 필로 추가했다
- `W14 기사 상세 · 투표 전`: W11 기사 상세를 클론, 본문 태그 행과 액션 행 사이에 투표
  카드를 끼웠다. GNB에는 토론을 비활성으로 추가(기사 페이지니 기사 탭이 활성 유지)
- `W15 기사 상세 · 투표 후`: 같은 자리에 결과 바 카드(✓ 지른다 · 내 선택 63% / 과하다
  37%)를 넣고, 댓글 헤더 아래에 진영 필터 칩(전체 318 / 지른다 201 / 과하다 117)을 달았다

### 막힌 곳들 (2차)

데스크톱 프레임의 폰트가 Pretendard Variable인데, MCP 실행 환경에 이 폰트가 없어서
`loadFontAsync`가 실패했다. 파일을 만들 때는 로컬에 설치돼 있었겠지만 지금 환경엔 없는 것.
피그마는 폰트를 로드하지 않으면 기존 텍스트의 `characters`를 못 바꾼다. 그래서 텍스트
수정이 필요한 노드(페이지 타이틀, 부제, 필터 라벨, GNB 링크)는 고치는 대신 같은
크기·색·자리에 Inter로 새 텍스트를 만들고 원본을 지우는 교체 방식으로 우회했다. 색만
바꾸는 건(기사 탭 비활성화) 폰트 로드가 필요 없어서 그대로 됐다. Inter는 한글 글리프가
없어 폴백으로 렌더되지만, 이 파일의 모바일 섹션 전체가 이미 Inter라 위화감은 없다.

W13에서 카드 리스트가 폭 120px로 쪼그라드는 문제도 겪었다. 기존 기사 행들은 고정폭이라
리스트 컨테이너가 hug여도 상관없었는데, 내 카드는 전부 FILL이라 hug 부모 + FILL 자식
조합이 최소 콘텐츠 폭으로 수렴해 버렸다. 결과 바의 % 텍스트는 절대 배치라 바가 줄면서
클리핑돼 안 보이기까지 했다. 리스트를 FILL로 바꾸고 바 폭 기준으로 % 위치를 재계산해서
풀었다. auto-layout에서 FILL 자식을 쓸 거면 부모 체인의 sizing부터 확인해야 한다는 교훈.

## 이어서: 색 피드백과 최종 커레이션

시안을 보여주니 색이 너무 AI 티가 난다는 피드백이 왔다. 틴트 배경에 반투명 테두리를 두르는
조합이 문제였다. 생각해 보면 맞는 말이다. 낮은 불투명도 fill + 같은 색 stroke 조합은 AI가
그린 다크 UI에서 유독 자주 보이는 패턴이다. 방향은 테두리를 다 걷어내고 단색 느낌의 필만
남기는 것.

일괄 수정은 스크립트로 했다. 내가 만든 투표 요소들은 이름 규칙(VoteCard/, Opt/, Side/,
Bar/, Badge, Chip, CommentGate)이 있어서 정규식으로 골라 strokes를 비우고, 테두리가 빠진
만큼 선택지 버튼 fill 불투명도를 0.16 → 0.22로, 카드 배경을 0.06 → 0.08로 올려 형태가
뭉개지지 않게 보정했다. 아이콘의 선(stroke로 그린 벡터)이나 기사 헤더 배지는 건드리지
않았다.

그 사이 사용자가 최종 구성을 직접 커레이션했다. 프로토타입 파일에서 T3(릴스 투표 패널)를
지우고, 원본 파일의 V3 3장(투표 전/후/진영 댓글)을 수동 복붙으로 T2 옆에 붙여서
T1 · T2 · V3×3 다섯 장 라인업으로 확정했다. 나는 그걸 모르고 T3를 다시 만들었다가
"얘들로 쓸거야" 메시지를 받고 지웠다. 파일 상태는 사용자도 동시에 바꾼다는 걸 잊으면 안
된다. 노드 ID가 null로 돌아오면 삭제됐을 가능성부터 의심할 것.

복붙된 V3 3장은 옛 테두리 스타일 그대로였어서 같은 처리를 했다. V3 내부 요소도 이름
규칙(Vote Card, Side/, Res/, Pill/, Tag/, Badge)이 잡혀 있어서 투표 요소만 정확히 골라낼
수 있었다. 원본 디자인 파일의 V3 원본과 T3는 손대지 않았다. 최종 기준은 프로토타입 파일의
다섯 장 + 데스크톱 W13~W15다.

## 이어서: 내 선택 강조 방식 결정

테두리를 걷어내고 나니 이번엔 내가 투표한 항목의 강조가 사라졌다는 피드백이 왔다. 원래
강조가 테두리 하이라이트였으니 당연한 결과다. 어떻게 할지 물어와서, 말로 설명하는 대신
후보 3개를 실제 크기로 나란히 그린 비교 프레임을 만들어 보여줬다. A는 내 선택 바만 진한
솔리드 필 + 다크 글자, B는 좌측 2px 액센트 스트립, C는 % 옆 내 선택 솔리드 칩.

A로 결정됐고, 피드백이 둘 더 붙었다. 하나는 A 시안에서 글자에 색이 없으니 AI 티가 덜
난다는 것. 그래서 투표 요소의 컬러 글자(초록·파랑 라벨, % 숫자, 배지 텍스트)를 전부
무채색으로 바꿨다. 색은 면(fill)만 갖고, 글자는 흰색 아니면 솔리드 위 다크만 쓴다.
'오늘의 투표' 배지와 댓글 진영 태그는 틴트+컬러글자 대신 솔리드 그린+다크 글자로 뒤집었다.
다른 하나는 내 선택 바를 살짝 키우라는 것. 높이를 1.22배로 키우고 fill 불투명도를 0.95로
올렸다.

적용 도중 회색으로 내린 서브 라벨이 가독성을 해친다는 피드백이 하나 더 왔다. 선택 안 한
항목이어도 글자는 그냥 흰색으로 해 달라는 것. 옵션 버튼과 결과 바 안의 회색 계열 텍스트를
전부 흰색으로 올렸다. 판정은 무채색 중간 밝기(채널 차 0.2 미만, 0.25~0.9 대역)를 회색으로
보는 휴리스틱으로 했다. 카드 밖 메타 라인(참여 수 안내)과 상태 텍스트는 원래 위계대로
슬레이트를 유지했다.

부수로, W14·W15에서 기사 컬럼이 고정 높이 GRID 셀을 넘쳐 아래 '함께 보면 좋은 기사'와
겹치는 걸 발견했다. 투표 카드가 들어가며 컬럼이 ~110px 자랐는데 그리드는 h555 고정이라
넘친 것이다. 자식들의 실제 바닥 좌표를 재서 그리드 높이를 콘텐츠에 맞게 늘렸다(665/689).
auto-layout과 달리 GRID는 자식이 자라도 따라 늘지 않는다는 걸 처음 알았다.

최종 스타일 규칙을 정리하면: 테두리 없음, 색은 면으로만, 글자는 흰색/다크 2단, 내 선택은
솔리드 + 확대. 프로토타입 파일의 T1·V3×3·W13~W15와 원본 파일의 T1·T3에 모두 반영했고
비교 프레임은 지웠다.

## 이어서: 투표 전 레이아웃을 상하 스택으로

선택 시 애니메이션 계획이 공유됐다. 좌우 2버튼에서 결과 바로 바뀌는 게 아니라, 투표 전에도
결과와 같은 상하 스택이고 선택하면 그 바에 색이 차오르면서 높이가 커지는 모프를 생각하고
있다는 것. 그래서 투표 전 상태를 전부 바꿨다. 좌우로 나란한 Opt/Side 버튼 행을 걷어내고,
결과 바와 같은 지오메트리(높이·라운드·패딩·간격)의 무채색 트랙 두 개를 세로로 쌓았다.
서브 라벨이 있는 카드(V3, W14)는 결과 바의 득표수 라인 자리에 서브를 놓아, 투표 전후로
글자 자리까지 1:1 매핑되게 했다. 이러면 구현 때 같은 DOM에 fill 폭·높이·색만 트랜지션하면
그림 그대로 모프된다.

프레임별 지오메트리는 스크립트에 테이블(GEO)로 박아 T1 13.2/4.4, V3 29.1/6.6, W13
14.4/4.8, W14 16.8/5.4를 각자 결과 바 규격에 맞췄다. V3는 투표 후 프레임의 Res 바에서
라운드를 실측해 따랐다. 카드가 세로로 자라면서 W14 기사 컬럼이 또 그리드를 넘칠 뻔해서
그리드 높이 재계산을 한 번 더 돌렸고, 원본 파일 T3는 패널 높이가 자라 하단 정렬을 다시
잡았다. 반영 범위는 프로토타입 T1·V3 투표 전·W13·W14와 원본 T1·T3다.

후속으로, 투표 전 트랙이 무채색이면 밋밋하다는 피드백이 와서 투표 전 바에도 진영 색의
어두운 배경(초록/파랑 22%)을 깔았다. 선택하면 그 색이 밝은 솔리드로 전환되며 차오르는
그림이라 애니메이션 서사와도 맞는다. 결과 바(RECTANGLE fill 보유)는 건너뛰고 투표 전
트랙만 골라 칠했다.

## 이어서: 댓글과 투표 분리

기획이 하나 정리됐다. 댓글은 투표와 무관하게 달 수 있고, 투표에서 뭘 골랐는지도 댓글에
반영하지 않는다. V3의 원래 컨셉이던 진영별 댓글(댓글마다 지른다/과하다 태그, 진영 필터)이
빠지는 것이라 관련 UI를 걷어냈다. 댓글 옆 진영 태그(Tag/\*)와 입력창의 내 진영 태그 전부
삭제, 진영 필터 필 행(Pill/전체·지른다·과하다)과 W15의 SideFilter 칩 행 삭제, 게이트
문구도 수정했다. "투표하면 댓글을 남길 수 있어요" → "팬 반응 남기기...", 카드 캡션의
"투표하면 결과와 진영별 댓글이 열려요" → "투표하면 결과가 열려요"(결과 공개는 여전히 투표
게이트). '진영 댓글' 프레임은 이름을 'V3 오늘의 투표 · 댓글'로 바꿨다. 원본 파일 쪽은 T3
게이트 문구만 같이 고쳤다.
