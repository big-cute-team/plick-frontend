# 0229. 홈에 승부예측 카드 슬라이드를 붙인다 (KAN-700, 웹과 모바일 함께)

## 티켓

KAN-700은 "[FE] 웹 홈 승부예측 섹션 연동"이다. 홈에서 앞으로 7일 안의 예측 가능 경기를 가로 슬라이드로
보여 주고 바로 예측할 수 있게 한다. `GET /predictions/home`을 붙이고 홈 헤더에 내 순위
(`GET /me/prediction-stats`)를 적는다. 완료 조건은 카드 전부 가로 슬라이드에 서버 순서 유지(마이팀 앞,
킥오프 순), 픽 버튼을 누르면 작성 시트가 그 픽을 고른 상태로 열림, `revealed: false`면 `?%`와 `?명 예측`에
`topOpinion` 블러, `topOpinion`은 앞 40자만 오니 말줄임에 null이면 영역 숨김, 이미 예측한 경기는 분포와
내 픽, OPEN이 없을 때의 SETTLED 카드와 빈 목록, ISR 화면이면 익명 응답과 내 상태 오버레이를 분리해
사용자별 값이 캐시되지 않게, dev API 검증이다. 참고에 "팀 `name`은 사전의 전체 이름이다(맨체스터
유나이티드). 줄여 보이려면 `code`나 FE 표기를 쓴다"가 있다.

KAN-699를 끝낸 세션에서 사용자가 "KAN-700도 웹 모바일 둘다"라고 해서 이어서 했다. 브랜치는 develop에서
새로 땄다. KAN-699 코드에 기대는 게 없다. 시안 가이드 §2 H1과 §5.2가 이 화면의 규칙이다.

## 무엇이 이미 있었나

KAN-695가 홈 카드 타입(`PredictionHomeCard`), 읽기 fetcher(`getPredictionHome`, `getMyPredictionStats`),
쿼리 키(`home`, `myStats`)를 깔아 뒀고, 예측 등록·취소 뒤 무효화(`invalidateAfterPredictionWrite`)가 이미
홈 키와 내 기록 키를 다시 받는다. 3분할 바 `PredictionBar`는 KAN-696에서 공용으로 섰다. 그러니 이번 일도
화면이다.

## 어디에 무엇을 두었나

- `@plick/domain/prediction`: 킥오프 표기 `predictionKickoffLabel`(`오늘 22:30`, `9월 22일 20:30`), 맨 아래
  줄 `predictionHomeFooter`(정산이면 `예측한 사람 중 55% 적중`), 내 결과 `predictionHomeVerdict`(카드는
  `result`를 안 줘 픽과 결과를 맞춰 본다), 내 순위 표기 `predictionRankLabel`, 예측 탭 경로
  `matchPredictionPath`와 쿼리 이름 `PREDICTION_TAB_QUERY`. `predictionStatusLine`의 `opensAt`을 선택으로
  풀어 홈 카드(UPCOMING이 안 온다)도 같은 상태 줄을 쓴다. 테스트 `tests/unit/prediction-home.test.mjs` 5건.
- `@plick/ui/PredictionHomeCard`: 카드 한 장. 앱과 웹이 같은 모양이라 처음부터 공용이고 `size`로 엠블럼과
  패딩만 가른다. 링크는 앱이 `next/link`로 감싼다. ui 패키지는 next에 기대지 않는다.
- 앱마다 훅 둘. `usePredictionHome`(카드 목록, 씨앗 받아 마운트 뒤 재조회)과
  `useMyPredictionStats`(소셜 계정일 때만 켠다).
- 앱마다 `PredictionSection`(서버, 익명 씨앗), `PredictionHomeTrack`(클라, 제목 줄과 슬라이드),
  `PredictionSectionSkeleton`. 모바일은 LIVE·VS 띠 아래 채팅방 띠 위, 웹은 핫이슈 위다.
- 경기 상세 `MatchDetailScreen`(두 앱)이 `?tab=prediction`을 읽어 예측 탭을 먼저 연다.

## 익명 씨앗과 내 상태 오버레이

두 앱 홈은 익명 ISR(20초)이다. 빌드 출력에 `○ /  20s`로 선다. 요청마다 쿠키를 읽으면 동적 렌더로 돌아가
CloudFront 문서 캐시가 깨지고, 읽은 값을 HTML에 실으면 처음 캐시를 채운 사람의 내 픽이 모두에게 나간다.
티켓이 "익명 응답과 내 상태 오버레이를 분리"라고 한 게 이 얘기다.

그래서 서버 컴포넌트 `PredictionSection`은 토큰 없이 `getPredictionHome`을 받는다. 이 응답은 OPEN 카드가
전부 `revealed: false`고 `myPick`이 없다. 누구에게 보여 줘도 되는 값이다. 그걸 클라 `PredictionHomeTrack`에
씨앗으로 넘기고 `usePredictionHome`이 `initialData`로 첫 그림을 바로 그린 뒤, `staleTime: 0`이라 마운트
때 `/be` 프록시로 다시 받는다. 프록시가 HttpOnly 쿠키의 토큰을 Bearer로 실어 주니 그때 응답이 그 사람
기준이다. 예측한 경기는 `revealed: true`에 분포와 내 픽이 오고 마이팀 경기가 앞으로 온다. 예측 요약
(KAN-696)과 키플레이어(KAN-699)가 간 길과 같다. 바는 `?%` 균등에서 실제 비율로 `transition`이 걸려 그
변화가 퍼지는 움직임으로 보인다.

mock에서 그대로 봤다. 서버 HTML은 두 카드 다 `?%`였고, 브라우저가 다시 받은 뒤 토트넘 대 브라이턴 카드가
31, 14, 55에 412명 예측으로 바뀌었다. 첫 카드는 mock이 비공개로 둔 경기라 `?%`와 블러가 남았다.

내 순위는 아예 서버에서 받지 않는다. `/me/prediction-stats`는 토큰 없이 401이라 씨앗이 될 수 없고 유저별
값이다. `useMyPredictionStats`를 소셜 계정일 때만 켜고(`enabled`), 게스트와 비로그인은 부르지 않는다.
실패해도 던지지 않고 글자를 뺀다.

## 홈에서 작성하지 않는다

티켓 완료 조건에 "픽 버튼을 누르면 작성 시트가 그 픽을 고른 상태로 열림"이 있다. 시안 가이드 §5.2는 반대로
"카드, 바, 대표 의견 어디를 눌러도 그 경기 예측 탭으로 간다. 홈에서 바로 작성하지 않는다"고 하고, 시안
스크립트도 카드의 `showPicks: false`로 픽 버튼을 꺼 뒀다. 가이드 첫머리가 "이 문서와 시안이 다르면
시안을 따른다"라 시안 쪽을 골랐다. 카드 전체를 `Link` 하나로 감쌌고 작성 흐름은 예측 탭이 다 든다. 픽
버튼을 되살리려면 작성 시트와 로그인·연동 분기를 홈에 한 벌 더 세워야 하는데, KAN-699 프리뷰 묶음에서도
같은 이유로 예측 탭으로 보냈다.

대신 가이드 §3 "홈 카드에서 들어오면 예측 탭으로 바로 연다"를 붙였다. 앞선 두 ADR이 "홈 카드 티켓에서
탭 쿼리 파라미터를 붙인다"고 남겨 둔 자리다. 카드 링크는 `/live/matches/{id}?tab=prediction`이고 경기
상세가 그 쿼리를 읽어 `selected`를 예측 탭으로 둔다.

읽는 자리가 문제였다. 경기 상세 페이지는 익명 ISR이라 서버에서 `searchParams`를 읽을 수 없다. 읽는 순간
동적 렌더다. 클라의 `useSearchParams`는 정적 라우트에서 가장 가까운 Suspense 경계까지를 클라 렌더로
돌리는데, 그러면 KAN-683이 서버 HTML에 실어 둔 라인업·스탯·순위 탭 본문이 크롤러에게서 사라진다. 그래서
마운트 뒤 `useEffect`에서 `window.location.search`를 직접 읽는다. 서버 렌더와 첫 하이드레이션은 첫 탭
그대로고 바로 다음 렌더에 예측 탭으로 넘어간다. 요약이 아직 안 와 예측 탭이 없는 순간이면 `active`가 첫
탭으로 접히고, `selected`에 "prediction"이 남아 있어 탭이 생기는 순간 넘어간다. 홈 카드를 누르면 서버
씨앗에 요약이 있어 실제로는 처음부터 예측 탭이다.

## 카드 폭과 팀명

앱은 가이드대로 카드 84%에 `scroll-snap-type: x mandatory`, 좌우 16px이다. 트랙을 `-mx-edge px-edge
scroll-px-edge`로 두어 카드가 화면 끝까지 흐르고 스냅이 패딩 안쪽에 멈춘다. 웹은 가이드가 `calc((100% -
40px) / 3)`에 간격 20px인데 그건 1280 기준이다. 핫이슈 캐러셀은 `sm`(640)부터 세 장인데 같은 규칙을 쓰니
800폭 패널에서 왼쪽 컬럼이 480이라 카드 하나가 145px이 되고 팀명이 한 글자만 남았다. 사진 카드와 달리
팀 줄과 3분할 바가 있어 좁으면 못 읽는다. `lg`(1024)부터 세 장, `sm`부터 두 장, 그 아래는 한 장 반으로
가른다. 1024에서 왼쪽 컬럼이 646이라 세 장이면 200px인데 레일이 그때 붙어 어쩔 수 없다.

팀명은 BE가 사전 전체 이름(맨체스터 유나이티드)을 준다. 빅6는 레지스트리(`TEAMS`)의 짧은 한글 표기
(맨유)로 바꾸고 빅6 밖은 그대로 말줄임한다. mock의 "애스턴 빌라"가 앱 카드에서 `애스…`로 잘렸다. 약어
코드(AVL)를 쓰면 엠블럼 자리의 회색 원에 이미 같은 글자가 있어 두 번 보인다. 빅6 밖 팀은 예측 경기의
한쪽에만 올 수 있으니 그대로 뒀다.

## mock에서 본 것과 못 본 것

KAN-699와 같은 `web-dev-mock`(3030)과 `mobile-dev-mock`(3031), mock BE 8081이다. 같은 작업 트리라 브랜치를
바꾸면 그 코드가 서빙된다. 바꾼 직후 콘솔에 KAN-699 브랜치의 `TeamCompareTable`을 찾는 모듈 오류가
남았는데 Turbopack이 전 브랜치에서 컴파일한 모듈을 들고 있던 것이고 홈 렌더와는 무관했다.

모바일 375폭. 띠 둘 아래 `승부예측`과 오른쪽 `128위`(mock은 아무 Bearer나 로그인으로 쳐서 소셜로 잡힌다),
카드 `오늘 23:30`, 애스턴 빌라 대 아스날, `?%` 균등 바, 축구는과학 닉네임에 블러 걸린 본문, `?명 예측`.
오른쪽에 다음 카드(`11월 4일 21:00`, 토트넘)가 걸쳐 보인다. 카드를 누르면 경기 상세가 예측 탭으로 열렸다.

웹 800폭. 승부예측 한 줄이 핫이슈 위에 서고 두 번째 카드가 재조회 뒤 분포와 412명으로 바뀌었다. 카드를
누르면 경기 상세 예측 탭이다.

못 본 것. mock 홈은 OPEN 둘뿐이라 SETTLED 카드(`결과 1 - 2 맨시티 승`, 적중, `예측한 사람 중 55% 적중`)와
빈 목록, `topOpinion: null`은 코드와 단위 테스트로만 맞췄다. 마이팀 우선 순서는 BE가 하는 일이라 FE는
순서를 건드리지 않는다. 내 픽 체크가 바에 서는 건 KAN-696 바 그대로라 따로 안 봤다.

## 헤드리스 리뷰가 잡은 것

`scripts/review/pr-review.sh`는 CRITICAL 없이 WARN 넷, INFO 셋이었다.

- 웹 카드 링크의 `hover:bg-elevate-2`가 안쪽 카드의 `bg-elevate`에 가려 hover가 안 보였다. 링크의 불투명도를
  살짝 낮추는 쪽으로 바꿨다.
- 킥오프 `오늘` 판정이 서버 렌더(ISR 생성 시각)와 하이드레이션 시각 사이에 KST 자정이 끼면 달라
  hydration 불일치가 난다. 그 자리에 `suppressHydrationWarning`을 두었다. 마운트 뒤 재조회가 어차피 다시
  그려 맞춘다.
- 서버가 못 받아 씨앗이 없고 브라우저가 받는 동안 빈 칸만 섰다. 섹션 스켈레톤에서 카드 실루엣
  (`PredictionCardsSkeleton`)을 떼어 그 구간에도 그린다.
- `predictionHomeFooter`의 꼬인 조건식을 풀고, `?tab=prediction`의 값도 상수(`PREDICTION_TAB_VALUE`)로 빼서
  경기 상세 두 곳이 같은 값을 본다.

`?tab=` 자동 열림과 카드 컴포넌트의 테스트 공백은 맞다. 저장소에 React 컴포넌트 테스트 바닥이 없어 E2E
시나리오(`/e2e`)로 남겼다. 두 앱 훅이 바이트 단위로 같다는 INFO는 앞선 티켓들과 같은 복제 규약이라 두었다.

## 남긴 것

- 내 순위 `128위`는 글자뿐이다. 랭킹 화면(KAN-701)이 생기면 링크로 바꾸고 비로그인에도 `랭킹 >`을 둔다
- 시안 웹 홈에는 핫이슈가 없고 승부예측이 그 자리다. 핫이슈를 걷을지는 기획 결정이라 위에 두었다
- 투표 탭 경기 행, MY 기록 행에서 예측 탭으로 바로 여는 건 그 화면 티켓(KAN-701, 702) 몫이다.
  `matchPredictionPath`를 쓰면 된다
- 홈 카드의 픽 버튼(티켓 조건)은 시안을 따라 뺐다. 기획이 되살리면 작성 시트 상태를 훅으로 빼서 홈이
  같이 쓴다
- E2E에 `홈 카드 클릭 → 예측 탭 활성` 시나리오를 `/e2e`로 만든다. dev 배포 뒤 돈다
