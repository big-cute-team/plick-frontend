# 0222. 콘텐츠는 많은데 크롤러가 못 보던 것: 투표 목록, 프로필 탭, 경기 상세를 서버 HTML에 싣고 애드핏을 걷는다 (KAN-683)

2026-10-30. KAN-652(ADR 0220)와 KAN-682(ADR 0221) 다음이다.

## 애드핏을 걷었다

카카오 애드핏 가입 화면이 "인증코드는 합의된 계정에 대해서만 발급"이라 공개 가입이 닫혀 있었다. 제휴 문의를
넣어도 작은 신규 매체에는 답이 잘 안 온다는 걸 알고 사용자가 애드센스로 돌아가기로 했다. KAN-652에서 `AdUnit`에
넣은 `adfit` 필드와 `AdfitBox`, `adfitSize`·`adNetworkFor`, 테스트를 전부 걷어 KAN-652 이전 상태(`e210d10`)로
되돌렸다. 여덟 파일의 diff가 애드핏 추가뿐인 걸 확인하고 `git checkout e210d10 -- <파일들>`로 돌렸다.
ADR 0220의 애드핏 절은 역사라 그대로 둔다.

## "글 말고도 콘텐츠가 많은데"에서 시작했다

애드센스 재심사를 서두르려면 운영자 글을 더 써야 한다고 했더니 사용자가 "글 말고도 다른 콘텐츠가 많다"고 했다.
맞는 말이라 실사이트의 기능 페이지를 크롤러 UA로 받아 태그를 벗긴 글자 수를 쟀다. 처음 표는 틀린 데가 있었다.
웹 `/live/standings`를 226자라고 적었는데 웹에는 그 URL이 없어 404 페이지를 잰 것이었고, 팀 프로필 "링크 0개"는
모바일만 그랬다. 다시 잰 결과가 이렇다(UA를 바꿔도 같았다).

| 페이지                      | 글자 수 | 실제 상태                                         |
| --------------------------- | ------- | ------------------------------------------------- |
| m `/live/standings`         | 697     | 20팀 전부 서버 렌더됨. 숫자라 짧을 뿐             |
| `/live`                     | 1,595   | 서버 렌더. 그날 빅6 경기가 없어 "경기가 없어요"만 |
| 웹 `/teams/chelsea/profile` | 2,460   | 레일에 선수 링크 20개. 선수단·기록 탭은 없음      |

사용자가 "캐싱 때문에 브라우저에서 불러오게 했던 걸 되돌리는 게 아니냐"고 걱정했다. 그 결정은 ADR 0199와
0200에 있다. 루트 레이아웃이 쿠키를 읽어 전 라우트가 동적이던 걸 걷고, 사람마다 다른 값(내 좋아요, 내 표)만
브라우저에서 얹고 누구에게나 같은 데이터는 서버 ISR로 두는 구조다. 그러니 이번 일은 그 구조를 뒤집는 게
아니라, 그 구조 안에서 서버 HTML에 빠져 있던 조각을 채우는 것이다. 두 조사 에이전트가 파일 단위로 확인한
사실은 다음과 같다. 라이브 목록·경기 상세·순위표·팀 프로필·선수 프로필·투표는 전부 서버 컴포넌트가 토큰 없이
BE를 받아 씨앗으로 내려주고 있었다.

## 투표 목록이 비어 있던 이유: `useSearchParams`

`/debates`는 ISR(○ 20초·1분)인데 서버 HTML에 투표가 한 건도 없었다. `DebatesSection`(서버)이 `getDebates()`를
받아 `DebatesFeed`(클라)에 씨앗으로 넘기는데, `DebatesFeed`가 탭을 읽으려고 `useSearchParams()`를 부른다.
Next 문서대로, 정적으로 렌더되는 라우트에서 이 훅을 부르면 가장 가까운 Suspense 경계까지가 클라이언트
렌더로 미뤄진다. 서버 HTML에는 그 경계의 fallback(`DebateListSkeleton`)만 남고 씨앗은 RSC 페이로드로만
간다. KAN-667(ADR 0204)에서 웹 `/debates`를 ISR로 돌리려고 서버의 `searchParams` 읽기를 `useSearchParams`로
옮길 때 생긴 일이고, 그때 ADR에 "미루므로"라고 적혀 있었지만 서버 HTML이 스켈레톤뿐이라는 결과까지는
안 봤다. 브라우저에서는 멀쩡히 보이니 아무도 몰랐다.

고친 방법은 `useSearchParams`를 안 쓰는 것이다. 두 앱에 `useDebateTab` 훅을 두고, 서버와 하이드레이션 첫
렌더는 기본 탭(진행 중)으로 그린 뒤 마운트 효과에서 `window.location.search`를 읽어 맞춘다. 탭을 바꾸면
`history.replaceState`로 URL만 고치고 상태를 올린다(모바일이 이미 하던 방식). `popstate`도 듣는다.
`?tab=closed`로 바로 들어오면 진행 중 목록이 한 프레임 보였다가 마감으로 바뀌는데, 지금껏 스켈레톤이
보이던 것보다 낫다. 웹은 탭 줄(`DebateTabs`)도 따로 `useSearchParams`를 읽고 있어서 탭 줄을 `DebateTabBar`
하나로 합치고 `DebatesFeed`가 상태를 들고 같이 그리게 했다. 링크는 `?tab=` href를 그대로 두어 새 탭 열기와
크롤러는 URL을 쓰고, 보통 클릭만 가로챈다. `DebatesScreen`의 Suspense는 하나로 줄이고 fallback에 기본 탭
줄과 스켈레톤을 함께 둔다.

## 프로필 탭이 비어 있던 이유: `tab === key && …`

팀·선수 프로필은 ●(ISR)이고 데이터는 전부 서버에서 받는다. 그런데 `TeamProfileView`가 `useState("overview")`로
탭을 들고 `{tab === "squad" && <TeamSquadTable/>}`처럼 활성 탭만 그린다. 그래서 선수단(선수 페이지 링크
20여 개), 경기 탭(경기 상세 링크), 기록 탭이 서버 HTML에 없었다. 웹은 레일의 득점 리더·부상자 카드가 항상
그려져 링크 20개가 있었고 모바일은 레일이 없어 0개였다.

네 탭을 전부 그리고 비활성 탭을 `hidden` 속성으로 감추는 `TabPanel`을 두 앱 `_components/`에 두고 팀·선수
프로필 네 뷰를 바꿨다. `hidden` 속성은 UA 스타일의 `display: none`인데 요소에 `flex` 같은 display 유틸이
붙으면 그게 이긴다. Tailwind v4 preflight가 `[hidden]:where(:not([hidden='until-found'])) { display: none
!important }`로 못 박아 둬서 괜찮다. 구글은 모바일 우선 색인에서 탭·아코디언 안의 숨은 본문도 읽는다. 탭이
URL에 안 올라가고 열 때마다 개요로 시작하는 설계(ADR 0187)는 그대로다. 대회 선택기(`picker`)는 선수단과
기록 두 패널에 같은 React 엘리먼트를 넣는데 렌더되면 인스턴스가 둘이고 둘 다 같은 state를 보니 문제없다.

## 경기 상세: 링크가 없었고 요청마다 렌더였다

경기 상세는 서버 렌더되지만 사이트맵에 없고(시즌마다 바뀌는 임시 URL이라 뺐다) `/live`는 그날 경기만
보여 줘서 크롤러가 지난 경기에 닿을 길이 없었다. 위에서 팀 프로필 경기 탭(시즌 일정·결과, 경기 상세 링크)을
서버 HTML에 싣게 되면서 빅6 여섯 페이지가 그 시즌 경기 전부로 가는 링크 허브가 된다. 사이트맵은 안 건드렸다.
사이트맵은 빌드 때 굳는 정적 파일이라 BE를 못 부르고, 경기 id 목록을 얻으려면 날짜별 호출을 걸어야 한다.

대신 `/live/matches/[matchId]`를 익명 ISR로 바꿨다. 전에는 요청마다 렌더(ƒ, `no-store`)라 CloudFront가
문서를 못 들고 크롤러 방문마다 BE를 돌았다. `export const revalidate = 20`(라이브 폴링 주기
`LIVE_REVALIDATE_SECONDS`와 같은 값, 세그먼트 설정은 리터럴만 받는다)과 빈 `generateStaticParams`를 넣어
●(첫 요청에 그려 캐시)로 바꿨다. 라이브 경기는 씨앗의 `fetchedAt`이 ISR 생성 시각이라 20초 지나면
`initialDataUpdatedAt`으로 묵은 걸 알아채 마운트 때 다시 받고 폴링한다. 끝난 경기도 씨앗이 묵으면 마운트
때 한 번 더 받는데, 기사·릴 상세와 같은 절충이다. `allSettled`의 거절 사유를 보는 자리에 `unstable_rethrow`를
넣었다(ADR 0199 관행).

## 순위표에 데스크톱 URL을 만들었다

순위표는 모바일만 `/live/standings`가 있고 데스크톱은 `/live` 레일에 붙어 있어 고유 URL이 없었다. 모바일
순위표의 canonical이 `/live`를 가리켜 "프리미어리그 순위" 검색어가 내릴 자리가 없었다. 웹에
`/live/standings`를 만들어 레일과 같은 `StandingsSection`을 표 하나로 두고, 모바일 canonical을 거기로 돌리고,
두 사이트맵에 실었다. 모바일과 같은 이유로 `force-dynamic`이다. 쿼리도 쿠키도 없는 라우트라 기본값이면
`next build`가 CI 러너에서 BE를 불러 실패한 에러 지면을 정적 HTML로 굳힌다. 데이터는 `apiFetch` 익명 GET
캐시(60초)를 타니 요청마다 BE를 도는 건 아니다.

## 전환해도 되는지 따진 것

- BE 부하: 새 BE 호출이 없다. 투표·프로필은 이미 서버에서 받던 데이터를 HTML에 더 싣는 것이고, 경기 상세는
  ISR이 돼 오히려 준다. 모든 익명 GET은 `apiFetch`가 60초(라이브 20초) 데이터 캐시를 붙이고, `sharesDataCache`
  판정으로 `headers()`를 안 읽어 ISR을 안 깬다(ADR 0199의 "static to dynamic at runtime" 함정).
- 게스트 상한(KAN-680): 게스트 발급 라우트 얘기라 이 읽기들과 무관하다. BE 익명 IP 상한은 FE 인스턴스 IP로
  세는데 홈·팀 허브가 이미 같은 경로라 새로 생기는 위험은 없다.
- CloudFront 문서 캐시: 경기 상세가 `s-maxage=20, stale-while-revalidate`를 달게 된다. 첫 요청자는 묵은 문서를
  받을 수 있지만 클라 훅이 폴링과 재조회로 맞춘다. 투표·프로필은 이미 ISR이라 헤더가 안 바뀐다.
- dev BE 미응답 빌드: 경기 상세는 빈 `generateStaticParams`라 빌드 때 안 그린다. 순위표는 `force-dynamic`이라
  안 그린다. 투표·프로필은 전부터 빌드 때 그려지는 라우트라 달라지지 않는다.
- 되돌리기: 투표는 훅 하나, 프로필은 `TabPanel` 네 곳, 경기 상세는 설정 두 줄이라 각각 독립으로 되돌릴 수 있다.

## 경기 상세 탭도 같은 방식으로

빌드 뒤 재 보니 모바일 경기 상세의 서버 HTML이 185자였다. 헤더와 탭 이름뿐이고 요약·라인업·스탯이 전부
탭 state 뒤에 있었다(prod도 같다). 웹은 첫 탭(요약)이 그려져 1,817자였다. 웹 `MatchDetailScreen`에서 활성
탭 하나만 그리던 `MatchDetailTabs`를 탭마다 `TabPanel`로 감싸 전부 그리고 비활성은 숨겼다. 뉴스 탭만
예외다. 열릴 때 클라에서 받는 목록(`useMatchNews`)이라 숨겨 두면 모두에게 요청이 나가서, 활성일 때만
그린다. 끝난 경기 한 페이지가 4,145자에 선수 링크 40개가 됐다.

모바일은 손대지 않았다. 탭이 `SwipePager`(가로 스와이프 전환, 이웃 탭 미리보기)로 묶여 있어 전부 그리면
페이저 구조를 바꿔야 하고, 모바일 경기 상세의 canonical이 웹 URL이라 색인은 웹 HTML로 된다.

로컬 8080을 찾다 실패했고, 그 상태의 HTML을 재서 투표 0건이 나왔다. prod BE 환경을 실은
`web-prodbe-alt`로 다시 띄우니 맞게 나왔다. 첫 요청의 팀 프로필이 1,122자였던 것도 같은 서버의 첫 ISR
생성 타이밍이었고 두 번째부터 6,432자였다.

## 헤드리스 리뷰와 CI 빌드가 잡은 것

`./scripts/review/pr-review.sh develop`은 CRITICAL 0, WARN 3이었다.

첫째, 숨은 패널까지 마운트되면 그 안의 클라 효과와 요청이 모두 돈다는 지적. 팀·선수 프로필 탭 자식을 전부
확인했다. `"use client"`인 건 뷰 자체뿐이고 탭 자식(선수단 표, 기록, 경기 행)은 서버 노드거나 효과 없는
컴포넌트라 숨겨 둬도 요청이 나가지 않는다. 경기 상세는 뉴스 탭만 클라 fetch라 이미 활성일 때만 그린다.

둘째, `role="tabpanel"`이 탭 수만큼 생겼는데 탭과 짝이 없다는 지적. `TabPanel`이 `id`·`labelledBy`를 받고
`ProfileTabBar`(두 앱)와 웹 `MatchTabBar`의 탭 버튼이 `id`·`aria-controls`를 달아 짝을 맺게 했다. 접두어는
`team-profile`, `player-profile`, `match`다.

셋째, 경기 상세가 ISR이 되면서 BE 일시 장애 때의 에러 지면이 20초 캐시에 들어가고 CloudFront까지 붙는다는
지적. 전에는 씨앗 없이 내려보내 클라가 다시 받았지만 그 HTML은 크롤러가 색인할 수 있다. 404가 아닌 실패는
던지도록 바꿨다. 재생성 실패로 남아 직전 성공본이 그대로 나가고, 첫 요청이면 루트 `error.tsx`가 받는다.

리뷰 뒤 BE 없이 `pnpm build`를 돌리자(CI와 같은 조건) 모바일 `/debates` 프리렌더가 "fetch failed"로
깨졌다. 씨앗이 없을 때 `DebateList`의 `useSuspenseQuery`가 서버에서 BE를 직접 부르는데, 전에는
`useSearchParams` 바이아웃이 이 서브트리를 서버에서 아예 안 그려 숨어 있던 경로였다. prod BE 빌드에서는
씨앗이 있어 안 보였다. `useHydrated`(KAN-682)로 씨앗이 없으면 마운트 뒤에만 목록을 그리게 했다. 서버에서는
스켈레톤이고(전과 같다) 씨앗이 있으면 목록이 서버 HTML에 실린다. 고친 뒤 BE 없는 빌드가 통과했다.
